DeepSeek-V4 Attention 设计解读：压缩稀疏注意力（CSA）与重压缩注意力（HCA）

日期：2026-09-14　论文：DeepSeek-V4: Towards Highly Efficient Million-Token Context Intelligence

arXiv：arxiv.org/abs/2606.19348　官方代码：huggingface.co/deepseek-ai/DeepSeek-V4-Pro（inference/ 目录）

本地文件：paper/deepseek_v4.pdf（主论文，58 页）；paper/deepseek_v32.pdf、paper/deepseek_v41.pdf（演进参考）

TL;DR：DeepSeek-V4 面向 100 万 token 上下文，把注意力瓶颈从「KV cache 太大、二次方算力」两端同时下手：设计压缩稀疏注意力 CSA（先把每 m=4 个 token 的 KV 压成 1 条 entry，再用 Lightning Indexer 做 DSA 式 top-k 稀疏选择）与重压缩注意力 HCA（每 m'=128 个 token 压成 1 条，不做稀疏），两种层交错堆叠。压缩后的 KV entry 同时充当 attention 的 key 和 value（SKV-MQA，单 KV「头」），配合低秩 query、分组输出投影、部分 RoPE、滑窗分支与 attention sink。效果：1M 上下文下 V4-Pro 的单 token 推理 FLOPs 只有 V3.2 的 27%、KV cache 只有 10%；相对常用基线 BF16 GQA8（head_dim 128），KV cache 约为其 2%。官方推理实现在 HF 仓库 inference/model.py 与 inference/kernel.py（TileLang 稀疏注意力内核）。

1. 解决什么问题

V4 论文引言开门见山：推理模型把「测试时扩展」推到前台，但这一范式被vanilla attention 的二次方计算复杂度卡死，超长上下文和长链条推理因此变得不可行（论文 §1，p.4）。对 1M 级上下文，痛点具体落在三处：

  • KV cache 体积：每个 token 都要缓存 K、V，上下文越长占用越大，直接限制并发与上下文长度；
  • 注意力算力：解码时每个新 token 要与全部历史 KV 做点积，长上下文下注意力成为主导瓶颈（论文 §2.3 开头："the attention mechanism emerges as the dominant computational bottleneck"，p.9）；
  • 训练/推理精度与稳定：稀疏化、低精度（FP8/FP4）会带来 attention logits 爆炸、位置编码失真等次生问题。

DeepSeek 自己的注意力架构有一条清晰的演进线：

版本注意力方案思路量化效果
V2 / V3MLA（多头潜在注意力） K、V 联合低秩压缩进一个 latent 向量，只缓存 latent + 解耦 RoPE 键；每 head RoPE 64 维 KV cache 相比 MHA 减少 93.3%；压缩维度 c=512，每 token 缓存 576 个元素（512 latent + 64 RoPE）（DeepSeek-V2 论文，arXiv:2405.04434）
V3.2DSA（DeepSeek Sparse Attention） 在 MLA 之上加 Lightning Indexer（轻量索引头算每对 token 的索引分）+ top-k 精细 token 选择 核心注意力复杂度从 O(L²) 降到 O(Lk)，k≪L；indexer 本身仍是 O(L²) 但计算量远小于主注意力（V3.2 论文 §2.3）
V4CSA + HCA 混合 在 DSA 之前再增加「序列维压缩」：每 m=4 个 token 的 KV 压成 1 条 entry 再做 top-k 稀疏（CSA）；部分层用 m'=128 的重压缩、保持稠密（HCA） 1M 上下文：V4-Pro 为 V3.2 的 27% FLOPs、10% KV cache；V4-Flash 为 10% FLOPs、7% KV cache；相对 BF16 GQA8（head_dim 128）基线 KV cache 约 2%（V4 论文摘要、§2.3.4）

表 1｜DeepSeek 注意力架构演进。MLA 解决「entry 大小」（KV head 维度），GQA 解决「KV 头数」，而 V4 的 CSA/HCA 首次把「序列长度」也变成了可压缩维度——这一三维框架的表述亦见 V4.1 论文 §2.3（paper/deepseek_v41.pdf）。

2. 设计是什么

2.1 总体结构：CSA 与 HCA 交错混合

V4 不是单一注意力层，而是两种高效注意力的混合配置。以 DeepSeek-V4-Pro 为例（论文 §4.2.1，p.25；与官方 config.json 完全一致）：

  • 共 61 层；前 2 层用 HCA，其后 CSA（压缩率 m=4）与 HCA（压缩率 m'=128）逐层交错，最后 1 层无压缩分支（compress_ratios 以 [128, 128, 4, 128, 4, ... , 4, 0] 收尾）；
  • CSA 负责「稀疏 × 轻压缩」：KV entry 数量压到 1/4，再对压缩 entry 做 top-k=1024 的稀疏选择；
  • HCA 负责「重压缩 × 稠密」：KV entry 数量压到 1/128，但全部参与注意力，不做稀疏选择。

两者共享同一套「压缩池化 + 共享 KV 的 MQA + 分组输出投影」骨架，差别只在压缩率与是否稀疏。

图 1｜V4-Pro 的 61 层注意力配置（对应 config.json 的 compress_ratios = [128, 128, 4, 128, 4, …, 4, 0]）。开头两层用重压缩的 HCA「热身」，中段 CSA 与 HCA 逐层交错，最后一层不挂压缩分支。

2.2 CSA：先压缩，后稀疏

(a) Token 级压缩器（learned gated pooling）

设输入隐状态 \(H \in \mathbb{R}^{n \times d}\)。CSA 先算出两组 KV entry 与对应的压缩权重（式 9–10）：

\[ C_a = H \cdot W_a^{KV},\quad C_b = H \cdot W_b^{KV};\qquad Z_a = H \cdot W_a^{Z},\quad Z_b = H \cdot W_b^{Z} \]

其中 \(C_a, C_b \in \mathbb{R}^{n \times c}\)（c 为 head 维度，V4 中 c=512）。随后每 m 个 token 被压成 1 条 entry，采用重叠双分支设计：第 i 条压缩 entry 用 \(C_a\) 的第 \([mi,\ m(i+1)-1]\) 段和 \(C_b\) 的第 \([m(i-1),\ mi-1]\) 段（式 11–12）：

\[ [\,S_a^{mi:m(i+1)-1};\, S_b^{m(i-1):mi-1}\,] = \mathrm{Softmax}_{row}\!\left([\,Z_a^{mi:m(i+1)-1} + B_a;\, Z_b^{m(i-1):mi-1} + B_b\,]\right) \]
\[ C_i^{\mathrm{Comp}} = \sum_{j=mi}^{m(i+1)-1} S_j^a \odot C_j^a + \sum_{j=m(i-1)}^{mi-1} S_j^b \odot C_j^b \]

即对 \(2m\) 个候选做行内 softmax（每个 token 的压缩权重 \(Z\) 加上可学习位置偏置 \(B_a, B_b \in \mathbb{R}^{m \times c}\)），再按权重逐元素加权求和（\(\odot\) 为 Hadamard 积）。因为 \(C_b\) 在第 i 块的取材与 \(C_a\) 在第 i−1 块重叠，相邻压缩 entry 的边界更平滑，等效压缩率为 1/m（论文 p.10）。

图 2｜重叠双分支压缩（式 11–12，m=4）。每条 entry 由两个分支各取一个窗口拼成：C_a 取「本窗口」、C_b 取「前一窗口」，对 2m=8 个候选做行内 softmax 加权池化。相邻 entry 共享一个窗口（图中 t8–11），使压缩边界平滑、信息无硬切分；HCA（m′=128）则去掉重叠分支，直接单窗口池化。

(b) Lightning Indexer 稀疏选择（DSA 策略作用于压缩 entry）

Indexer 的 KV 也用同一压缩器压缩成 \(K^{\mathrm{I,Comp}} \in \mathbb{R}^{\frac{n}{m} \times c_I}\)（\(c_I = 128\)）。对查询 token t，先低秩降维再升维产生索引 query（式 13–14），同时用一条独立投影产生各索引头的权重（式 15–16）：

\[ c_t^Q = h_t \cdot W^{DQ},\qquad q_t^{\mathrm{I}} = c_t^Q \cdot W^{IUQ} \]
\[ w_t^{\mathrm{I}} = h_t \cdot W^{w};\qquad I_{t,s} = \sum_{h=1}^{n_h^{I}} w_{t,h}^{I} \cdot \mathrm{ReLU}\!\left( q_{t,h}^{\mathrm{I}} \cdot K_s^{\mathrm{I,Comp}} \right) \]

然后按索引分选 top-k 条压缩 entry（式 17）：\( C_t^{\mathrm{SprsComp}} = \{ C_s^{\mathrm{Comp}} \mid I_{t,s} \in \mathrm{Top\text{-}k}(I_{t,:}) \} \)。注意latent 向量 \(c_t^Q\) 由主注意力和 indexer 共享，这是一次降维、两处受益。

(c) SKV-MQA：压缩 entry 即 key 即 value

核心注意力按 MQA 方式进行：每条压缩 entry 同时充当 attention 的 key 和 value（式 18–19）：

\[ q_t = c_t^Q \cdot W^{UQ};\qquad o_{t,i} = \mathrm{CoreAttn}(\mathrm{query}=q_{t,i},\ \mathrm{key}=C_t^{\mathrm{SprsComp}},\ \mathrm{value}=C_t^{\mathrm{SprsComp}}) \]

查询头数 \(n_h\) 很大（V4-Pro 为 128），但 KV 只有 1「头」——KV entry 维度 c=512 与查询头维度相同。这是 V4 与 MLA 的本质区别：MLA 缓存的是「待解压的 latent」，解码时要上投影恢复多头 K/V；V4 直接把压缩 entry 当 K/V 用，缓存即所需，省掉解压步骤。

(d) 分组输出投影（Grouped Output Projection）

\(n_h\) 个头 × c=512 维的输出直接投影回 d 维代价太大，于是把 \(n_h\) 个输出分成 g 组，每组先降到 \(d_g\) 维中间量（\(d_g < c \cdot n_h / g\)），再拼起来投影到 d 维（V4-Pro：g=16，d_g=1024；论文 p.11）。

2.3 HCA：重压缩 × 稠密

HCA 与 CSA 同构，但压缩率 \(m' = 128 \gg m = 4\)，不做重叠、也不做稀疏选择，对全部压缩 entry 做稠密注意力（式 20–23）：

\[ C = H \cdot W^{KV},\quad Z = H \cdot W^{Z};\qquad S^{m'i:m'(i+1)-1} = \mathrm{Softmax}_{row}(Z^{m'i:m'(i+1)-1} + B) \]
\[ C_i^{\mathrm{Comp}} = \sum_{j=m'i}^{m'(i+1)-1} S_j \odot C_j \]

同样的低秩 query（式 24–25）与 SKV-MQA、分组输出投影。HCA 层的 KV cache 只有 CSA 层的 1/32，适合放在模型头尾对全局信息做「粗粒度但全覆盖」的稠密建模。

2.4 稳定性与位置的四个细节（§2.3.3）

  • Query / KV entry 归一化：核心注意力之前，对每个 query head 与唯一的压缩 KV「头」做 RMSNorm，防止 attention logits 爆炸——因此 V4 不再需要 Muon 的 QK-Clip 技巧（论文 §2.4）；
  • 部分 RoPE：只对 query 与 KV entry 的最后 64 维施加 RoPE。因为压缩 entry 既是 key 又是 value，输出 \(\{o_{t,i}\}\) 会带着 KV 的绝对位置旋转，所以对输出再施加位置 \(-i\) 的反旋转，让输出携带「query 与 KV entry 的相对距离」；
  • 滑窗分支：压缩块内的 token 彼此不可见（因果性被压缩破坏），且近处 token 更相关，因此额外保留最近 \(n_{win}=128\) 个 token 的未压缩 KV，与被选中的压缩 entry 拼接后一起参与核心注意力；
  • Attention sink：为每个 query head 设置可学习 sink logit \(z_h'\)，softmax 分母加上 \(\mathrm{Exp}(z_h')\)（式 27），让头的总注意力权重可以不为 1、甚至接近 0：
\[ s_{h,i,j} = \frac{\mathrm{Exp}(z_{h,i,j})}{\sum_k \mathrm{Exp}(z_{h,i,k}) + \mathrm{Exp}(z_h')} \]

3. 代码是怎么实现的

3.2 压缩器：公式 (9)–(12) 的逐行对应

class Compressor(nn.Module):
    """Compresses KV cache via learned gated pooling over `compress_ratio` consecutive tokens.
    When overlap=True (ratio==4), uses overlapping windows for smoother compression boundaries."""

    def __init__(self, args: ModelArgs, compress_ratio: int = 4, head_dim: int = 512, rotate: bool = False):
        super().__init__()
        ...
        self.compress_ratio = compress_ratio
        self.overlap = compress_ratio == 4
        coff = 1 + self.overlap
        self.ape = nn.Parameter(torch.empty(compress_ratio, coff * self.head_dim, dtype=torch.float32))
        # wkv and wgate in the checkpoint is stored in bf16, ...
        # When overlap, the first half of dims is for overlapping compression, second half for normal.
        self.wkv = Linear(self.dim, coff * self.head_dim, dtype=torch.float32)
        self.wgate = Linear(self.dim, coff * self.head_dim, dtype=torch.float32)
        self.norm = RMSNorm(self.head_dim, args.norm_eps)
        ...
    def forward(self, x: torch.Tensor, start_pos: int):
        ...
        kv = self.wkv(x)
        score = self.wgate(x)
        ...
        kv = kv.unflatten(1, (-1, ratio))
        score = score.unflatten(1, (-1, ratio)) + self.ape
        if overlap:
            kv = self.overlap_transform(kv, 0)
            score = self.overlap_transform(score, float("-inf"))
        kv = (kv * score.softmax(dim=2)).sum(dim=2)
        ...
        kv = self.norm(kv.to(dtype))
        apply_rotary_emb(kv[..., -rd:], freqs_cis)   # 只旋转最后 64 维
        if self.rotate:
            kv = rotate_activation(kv)               # Hadamard 旋转，供 FP4 量化
            fp4_act_quant(kv, fp4_block_size, True)  # indexer 的 KV 走 FP4
        else:
            act_quant(kv[..., :-rd], 64, ...)        # 主 KV：非 RoPE 维 FP8 存储

摘自 inference/model.py:279-372（有删节，均为连续行内摘录）。与论文的对应：wkv ↔ \(W^{KV}_{a/b}\)，wgate ↔ \(W^{Z}_{a/b}\)，ape ↔ 可学习位置偏置 \(B_a, B_b\)（CSA 时形状 \(m \times 2c\)，两分支各占一半维度）；kv * score.softmax(dim=2) 的加权求和即式 (11)(12) 的 \(\mathrm{Softmax}_{row}(Z+B) \odot C\) 池化；overlap_transform（model.py:307-314）把 \(C_a\) 整体错后一个窗口、\(C_b\) 保持原位，正是"第 i 条 entry 取 \(C_a\) 的 \([mi, m(i+1)-1)\) 与 \(C_b\) 的 \([m(i-1), mi)\)，两者重叠"的实现。压缩后立即 RMSNorm（§2.3.3 归一化）、RoPE 最后 64 维（部分 RoPE），并按用途量化：主 KV 非 RoPE 维 FP8（对应论文"RoPE 维度 BF16 + 其余 FP8"混合存储），索引器 KV 走 Hadamard 旋转 + FP4（对应"indexer FP4 计算"）。

论文中 \(C_a, C_b\) 是两条独立投影（\(W_a^{KV}, W_b^{KV}\)），而参考实现把两支折叠进一个 coff*head_dim 宽的 wkv 线性层（前半维给重叠分支、后半维给正常分支），数学上等价；「HCA 也可被视为 CSA 去掉 indexer 与重叠」的实现结构（ratio≠4 时 overlap=False 且 indexer=None）由源码与论文共同证实。

3.3 Lightning Indexer：公式 (13)–(17) 的逐行对应

class Indexer(torch.nn.Module):
    """Selects top-k compressed KV positions for sparse attention via learned scoring.
    Has its own Compressor (with Hadamard rotation) to build compressed KV for scoring."""

    def __init__(self, args: ModelArgs, compress_ratio: int = 4):
        super().__init__()
        ...
        self.wq_b = ColumnParallelLinear(self.q_lora_rank, self.n_heads * self.head_dim)
        self.weights_proj = ColumnParallelLinear(self.dim, self.n_heads, dtype=torch.bfloat16)
        ...
    def forward(self, x: torch.Tensor, qr: torch.Tensor, start_pos: int, offset: int):
        ...
        q = self.wq_b(qr)                                    # 从共享 latent c^Q_t 升维 → 式(14)
        q = q.unflatten(-1, (self.n_local_heads, self.head_dim))
        apply_rotary_emb(q[..., -rd:], freqs_cis)            # 索引 query 也只转最后 64 维
        q = rotate_activation(q)                             # Hadamard 旋转
        # use fp4 simulation for q and kv in indexer
        fp4_act_quant(q, fp4_block_size, True)               # 索引 Q 用 FP4
        self.compressor(x, start_pos)                        # 压缩索引 KV（同一压缩器逻辑）
        weights = self.weights_proj(x) * (self.softmax_scale * self.n_heads ** -0.5)   # 式(15)
        index_score = torch.einsum("bshd,btd->bsht", q, self.kv_cache[:bsz, :end_pos // ratio])
        index_score = (index_score.relu_() * weights.unsqueeze(-1)).sum(dim=2)         # 式(16)
        ...
        topk_idxs = index_score.topk(min(self.index_topk, end_pos // ratio), dim=-1)[1]  # 式(17)

摘自 inference/model.py:380-427（有删节）。qr 即主注意力算出的 latent \(c_t^Q\)（式 13，见下一段代码第一行），indexer 不再单独降维，实现"latent 共享"；einsum 得到每个索引头、每个压缩 entry 的内积，relu_() 对应论文选 ReLU 的"throughput 考虑"（V3.2 论文 §2.1 同款设计），按 weights 加权求和得索引分 \(I_{t,s}\)，最后 top-k。索引 KV 与主 KV 缓存在同一层内（self.kv_cache 与主注意力的 kv_cache[:, win:] 拼接共享缓冲，见 model.py:491）。

3.4 主注意力：低秩 Q、归一化、滑窗拼接与输出反旋转

class Attention(nn.Module):
    """Multi-head Latent Attention (MLA) with sliding window + optional KV compression.
    Uses low-rank Q projection (wq_a -> q_norm -> wq_b) and grouped low-rank O projection."""
    def __init__(self, layer_id: int, args: ModelArgs):
        ...
        self.attn_sink = nn.Parameter(torch.empty(self.n_local_heads, dtype=torch.float32))
        self.wq_a = Linear(self.dim, self.q_lora_rank)         # W^DQ：式(13)
        self.q_norm = RMSNorm(self.q_lora_rank, self.eps)
        self.wq_b = ColumnParallelLinear(self.q_lora_rank, self.n_heads * self.head_dim)  # W^UQ：式(18)
        self.wkv = Linear(self.dim, self.head_dim)             # 滑窗分支的未压缩 KV 投影
        self.kv_norm = RMSNorm(self.head_dim, self.eps)
        self.wo_a = ColumnParallelLinear(self.n_heads * self.head_dim // self.n_groups,
                                         self.n_groups * args.o_lora_rank, dtype=torch.bfloat16)
        self.wo_b = RowParallelLinear(self.n_groups * args.o_lora_rank, self.dim)  # 分组输出投影
        ...
    def forward(self, x: torch.Tensor, start_pos: int):
        ...
        # q
        qr = q = self.q_norm(self.wq_a(x))
        q = self.wq_b(q).unflatten(-1, (self.n_local_heads, self.head_dim))
        q *= torch.rsqrt(q.square().mean(-1, keepdim=True) + self.eps)   # 逐头 RMSNorm
        apply_rotary_emb(q[..., -rd:], freqs_cis)                        # 部分 RoPE
        # win kv & topk_idxs
        kv = self.wkv(x)
        kv = self.kv_norm(kv)
        apply_rotary_emb(kv[..., -rd:], freqs_cis)
        # FP8-simulate non-rope dims to match QAT; rope dims stay bf16 for positional precision
        act_quant(kv[..., :-rd], 64, scale_fmt, scale_dtype, True)
        topk_idxs = get_window_topk_idxs(win, bsz, seqlen, start_pos)
        if self.compress_ratio:
            offset = kv.size(1) if start_pos == 0 else win
            if self.indexer is not None:                       # CSA 层
                compress_topk_idxs = self.indexer(x, qr, start_pos, offset)
            else:                                              # HCA 层：全部压缩 entry，无稀疏
                compress_topk_idxs = get_compress_topk_idxs(ratio, bsz, seqlen, start_pos, offset)
            topk_idxs = torch.cat([topk_idxs, compress_topk_idxs], dim=-1)
        ...
        o = sparse_attn(q, kv, self.attn_sink, topk_idxs, self.softmax_scale)
        ...
        apply_rotary_emb(o[..., -rd:], freqs_cis, True)                  # 输出反旋转（位置 -i）
        # o
        o = o.view(bsz, seqlen, self.n_local_groups, -1)
        wo_a = self.wo_a.weight.view(self.n_local_groups, self.o_lora_rank, -1)
        o = torch.einsum("bsgd,grd->bsgr", o, wo_a)
        x = self.wo_b(o.flatten(2))
        return x

摘自 inference/model.py:436-543（有删节）。要点逐条对应论文：attn_sink 参数即式 (27) 的 \(z_h'\)；wq_a → q_norm → wq_b 是 MLA 式低秩 Q（式 13/18），latent qr 随后传给 indexer 复用；query 与 KV 各自 RMSNorm 后只转最后 64 维 RoPE；滑窗 KV 的非 RoPE 维以 FP8 模拟量化（QAT 一致性），注释原文写明"rope dims stay bf16 for positional precision"——正是论文混合存储策略；topk 索引 = 「滑窗 128 条 + 压缩 top-k」拼接；核心注意力交给 sparse_attn；输出先做位置 \(-i\) 的反旋转（inverse=True，对应论文"carry relative position embeddings"），再走 wo_a/wo_b 的两段式分组投影（式：\(o^G \to d_g \to d\)）。

4.3 训练如何驯服稀疏注意力（§4.2.2）

序列长度课程 4K → 16K → 64K → 1M；先用稠密注意力训练 1T token，再在 64K 序列长度处引入稀疏，且稀疏开启后先安排一个短暂阶段专门 warmup Lightning Indexer，然后全程稀疏训练。压缩分支 RoPE 使用独立 theta（config：compress_rope_theta=160000）。推理侧配套设计：因压缩率 4 与 128 的最小公倍数为 128，KV cache 块按 lcm 对齐（§3.5.1），SWA 与未满压缩块的 token 走"状态缓存"，压缩 entry 走经典分页缓存。
