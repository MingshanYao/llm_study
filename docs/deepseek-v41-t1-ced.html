TL;DR：现在的 AI Agent（智能体）工作负载有个鲜明特点：输入巨长、输出很短——每次调用工具，模型都要重新读几万字的上下文，却只回几百字。这导致「读入」（prefill）成了花钱大头。DeepSeek-V4.1-Flash 的解法是 CED（Causal Encoder-Decoder，因果编码器-解码器）架构：把 40 层 Transformer 劈成上下两半，下半 20 层是「因果编码器」，正常逐层算；上半 20 层「解码器」的全局 KV cache 不再从自己的隐状态算出，而是直接从编码器最后一层的隐状态投影出来——于是处理长输入时上半层几乎可以整体跳过。效果：总参数 552B 的 MoE 模型，prefill 每 token 只激活 8B 参数、decode 每 token 激活 16B，prefill 计算量近乎减半（复杂度从 \(O(NL)\) 降到约 \(O(NL/2)\)）；同时配合 CSA2 与 FP4 KV 缓存，全局 KV cache 压到每 token 890 字节，约为 DeepSeek-V4-Flash 的 1/4。性能却与参数量 1.6T 的 V4-Pro-Base 相当。

1. 铺路：decoder-only 与 encoder-decoder，主流大模型为什么长成 GPT 那样

本节是背景铺垫，帮零基础读者建立坐标系。先用三个词把 Transformer 讲清楚：

  • token（词元）：模型处理文字的最小单位，可以粗略理解成「半个词或一个字」。
  • Transformer 层：模型的「加工车间」。文本变成向量后要依次穿过几十层车间，每层做两件事——注意力（让每个 token 环顾四周、决定该参考谁的信息，像开会时每个人轮流发言并环顾全场）和前馈网络（对每个 token 独立做一次深加工）。层数越多、车间越大，模型通常越聪明。
  • KV cache：生成第 1000 个 token 时，注意力需要回头「看」前 999 个 token。如果每次生成都重新算前文，代价无法承受，所以模型把前文每层算好的两份中间结果——Key（K，可以理解成「每个人的名片」）和 Value（V，「每个人的发言内容」）——存起来复用。这份缓存就叫 KV cache。它是长文本推理中显存占用的最大头。

有了这三个词，两种模型形态的区别就清楚了：

维度decoder-only（GPT 式）encoder-decoder（T5 式）
结构只有一摞 decoder 层，从头到尾一条路一个 encoder（读入并「理解」输入）+ 一个 decoder（基于理解结果生成输出）
注意力方式因果注意力（causal attention）：第 i 个 token 只能看第 1..i 个 token，不能偷看未来encoder 内部双向（每个 token 可看全文），decoder 生成时再与 encoder 的输出交互
擅长任务开放式生成，训练目标（预测下一个 token）与使用方式完全一致输入明确、输出相对确定的转换类任务（翻译、摘要）
当前地位几乎所有主流 LLM（GPT、Llama、DeepSeek 全系）主流 LLM 中已很少见

为什么主流 LLM 都是 decoder-only？这是社区共识层面的判断，论文没有专门论证，我们把它作为背景知识归纳为三点（标注为通识归纳，非论文原文）：

  • 训练目标 = 使用目标：decoder-only 训练时就是「预测下一个 token」，推理时就是「接着往下生成」，训练与部署无缝对齐；
  • 工程简单、扩展性好：只有一个序列、一套 KV cache，流水线、并行、缓存复用都更简单；
  • 规模化验证充分：GPT-3 之后的大规模实验几乎都押注 decoder-only，生态与基础设施围绕它建立。
正因为 encoder-decoder 被「淘汰」，CED 的出现才显得反直觉：DeepSeek 在 V4.1-Flash 里把 encoder-decoder 的思想请了回来，但不是照搬 T5 的双向 encoder，而是造了一个「因果编码器」——encoder 内部依然是因果注意力、能无缝生成，只是在「上层解码器的全局 KV 从哪来」这一点上借用了 encoder-decoder 的分工思想。可以说 CED = decoder-only 的骨架 + encoder-decoder 的算力分工，这是理解本讲的关键。

2. V4.1-Flash 模型总览：552B MoE，prefill 8B / decode 16B

先解决两个术语。MoE（Mixture-of-Experts，专家混合）：把每层的一个大前馈网络换成一大群小专家网络，每个 token 只挑其中几个用——好比一家大医院有很多专科医生，每个病人只看其中几位。这样「总参数多（知识渊博）」和「每次计算少（便宜快速）」可以兼得（详见 DeepSeekMoE 解读 与 MoE 零基础系列）。激活参数：处理每个 token 时真正参与计算的参数量，区别于存着不用的总参数量。

3. 多模态怎么接：DeepSeek-ViT + MLP projector

V4.1-Flash 是原生多模态模型：能同时吃图像和文本。§2.1.1 描述的接入方式并不神秘，就是「把图变成一串特殊 token 塞进文本流」：

图 1｜多模态接入路径（对应论文 §2.1 与 §2.1.1，及 Figure 3 的多模态部分）。视觉支路产出的视觉嵌入被插到输入序列中「图像占位 token」的位置，之后图文一视同仁地穿过 40 层语言骨干。

三个值得记住的设计细节（§2.1.1 原文）：

  • DeepSeek-ViT 从零训练，基于 Vision Transformer 改造，可原生处理任意分辨率图像：用 2D-RoPE（二维旋转位置编码，给每个图块按行列位置标注「坐标」）替换绝对位置嵌入；patch 嵌入用线性投影替代卷积（为了兼容 Muon 优化器）；归一化用 RMSNorm、激活用 SwiGLU，向 LLM 的设计习惯看齐。
  • 3×3 pixel-unshuffle：把每个 3×3 邻域的空间像素沿通道维重排，空间分辨率缩小、通道变宽，视觉 token 数量减少 9 倍（3×3=9），从而支持最高约 1344×1344 像素的输入而不让 token 爆炸。图像 token 少，对后续所有注意力计算和 KV cache 都是直接利好。
  • 多模态辅助损失-free 负载均衡：图像和文本 token 的表达分布不同，路由偏好也不同；如果只看总负载，会掩盖模态内部的失衡。做法是给文本、图像各维护一套专家修正偏置，路由时按各自模态的偏置选专家（打分权重仍用原始路由分），训练中两套偏置按各自的专家负载独立更新。

4. CED 机制详解：上半层的 KV 从「抄」而不是「算」

4.1 问题：agentic 工作负载让 prefill 成了花钱大头

§2.2 开篇给出的场景：agent（智能体）频繁调用工具，每次调用都产生大量 prefill 请求——即把新上下文整段读一遍、建立 KV cache 的过程。当 KV cache 未命中（比如多轮会话间隔太久被清掉、或切换到新任务），这些读入就得全额重算，计算开销很大。而 agent 的典型形态恰恰是输入长、输出短：读 10 万 token 的工具输出和历史记录，只回几百字。常规 decoder-only 模型对每个 prefill token 都要走完全部 40 层——太浪费，因为大部分层的计算成果（全局 KV）在短输出场景下被复用得很少。

4.2 思想来源：YoCo 的「上半层共享下半层 KV」

论文明确说 CED inspired by YoCo（Sun et al., 2024）：YoCo 让模型上半部分的层直接复用下半部分层生成的 KV cache，以此削减 prefill 计算。CED 继承这个概念，并做了一系列结构改进，「以增强整体 KV cache 容量与 KV 生成计算深度」，最终在性能与基线相当的前提下砍掉近一半 prefill 计算（§2.2 原文）。YoCo 与 CED 的差别，论文只笼统说「一系列结构改进」，结合 §2.2 后文可具体化为两点：CED 的上半层不是原样复用下半层的 KV，而是每层用自己独立的投影矩阵从编码器末层隐状态投影出 KV（保留每层的表达差异）；同时 SWA（局部滑窗注意力）仍保持逐层正常计算，使局部 KV 的生成深度不打折。

4.3 核心公式（论文式 1）

记模型共 \(L\) 层（V4.1-Flash 中 \(L=40\)），第 \(l\) 层的隐状态为 \(H^l\)。对全局注意力而言，编码器就是下半层 \(l \le L/2\)，解码器是上半层 \(l > L/2\)。解码器各层的 KV 不再来自各自的隐状态，而是统一从编码器最后一层的隐状态 \(H^{L/2}\) 投影出来：

\[ C^l = H^{L/2}\, W^{KV}_l, \qquad Z^l = H^{L/2}\, W^{Z}_l, \qquad l > L/2 \tag{式 1} \]

逐符号解释：

  • \(H^{L/2}\)：第 20 层（编码器最后一层）输出的隐状态，形状「token 数 × 5120」。它是整段输入经过下半层充分加工后的「浓缩理解」。
  • \(W^{KV}_l\)：解码器第 \(l\) 层专属的 KV 投影矩阵——每层各有一套，互不共享，所以不同层能得到视角不同的 KV。
  • \(C^l\)：第 \(l\) 层的全局 KV entry（进入 KV cache 的主体）；\(Z^l\)：与 \(C^l\) 配套的压缩权重（供 CSA2 的压缩器使用，第 2 讲展开）。

这个设计带来的直接后果：在 prefill 阶段，解码器各层的全局 KV 只需「读一遍 \(H^{L/2}\)、做一次矩阵乘」就能得到——不需要让 token 逐层穿过上半部分的注意力与前馈网络。唯一不能跳过的是 SWA：§2.2 明确「对滑动窗口注意力，CED 在所有层保持常规逐层计算」——第 \(l\) 层的局部 K/V 依然取自本层隐状态 \(H^l\)。为什么？因为 SWA 是每层自己的「近视眼」，负责近处细节；保持逐层计算能「有效增加局部 KV 生成的计算深度」（论文原话），模型的表达能力不因全局 KV 抄近路而受损。

4.4 双路径对比：prefill 走短路，decode 走全路

图 2｜CED 的 prefill 路径 vs decode 路径（对应论文 §2.2 式 1 与 §3.2.2）。prefill 时解码器的全局注意力与 MoE 不逐 token 执行，全局 KV 由编码器末态一次性投影；decode 时每生成一个 token 走完整 40 层，全局 KV 也由当前 \(H^{L/2}\) 投影而来并写入缓存。

4.5 一个必须交代的小尾巴：Decoder SWA Bounded Replay

跳过解码器逐层计算有一个副作用：解码器各层的 SWA KV 本应由各层自己的隐状态算出，而 prefill 时这些隐状态根本没算。若要精确补齐，需把最后 \(n_{win} \times L/2\) 个 token（128 × 20 = 2560 个）送进解码器重放。对「每轮提示都很短」的多轮对话，这笔开销不可忽略。论文引用先前工作（Chen et al., 2025）指出 SWA 的实际有效感受野远小于理论值 \(n_{win} \times L/2\)，于是引入 Decoder SWA Bounded Replay：prefill 时只把提示词最后 \(n_{win}\)=128 个 token 送进解码器算 SWA KV，其余不做。细节与部署侧的 Encoder SWA Bounded Replay 归第 4 讲（§3.2.2），此处只需记住：正是这个有损但有界的小重放，让「prefill 在编码器处收工」成为可能。

4.6 复杂度结论（论文原文）

论文 §2.2 的总结论：对序列长度 \(N \gg n_{win}\) 的请求，

\[ \text{prefill 复杂度：}\; O(NL) \;\longrightarrow\; O\!\left(\tfrac{NL}{2} + \tfrac{n_{win} L}{2}\right) \approx O\!\left(\tfrac{NL}{2}\right) \]

即整体 prefill 计算近乎减半（论文摘要与 §2.2 两处均用 "nearly halves"）。配合「decode 每 token 激活 16B」的事实，就得到了开头那个反常的 8B/16B 不对称。

5. 省钱账：为什么 agentic 负载下这个不对称特别值钱

传统上 MoE 模型对每个 token 的激活参数是同一个数（如 V4-Flash 的 13B）。CED 把「激活多少」变成了随阶段而定的旋钮：prefill 8B、decode 16B。这笔账只有在「输入占比极高」的负载下才划算，而 agent 恰好就是这种负载。下面用一笔直觉账说明（论文给出的原始数字是 8B/16B 与 "nearly halves"；下面的具体乘法为推断核算，便于建立直觉）：

场景：100k 输入 + 1k 输出的请求常规 decoder-only（假设全程 16B/token）CED（prefill 8B / decode 16B）
prefill 激活参数·token100,000 × 16B = 1.6×10¹⁵100,000 × 8B = 8×10¹⁴
decode 激活参数·token1,000 × 16B = 1.6×10¹³1,000 × 16B = 1.6×10¹³
合计≈1.616×10¹⁵≈8.16×10¹⁴（约 50.5%）

表 3｜费用直觉账（推断核算：乘法基于论文的 8B/16B 数字与 "nearly halves prefill computation" 的定性结论；n_win×L/2=2560 token 的重放开销在此规模下占比不足 0.03%，忽略）。输入越长，节省比例越趋近 50%。

图 3｜输入重度负载下的激活量对比条形图（数值为表 3 的推断核算；"CED 省 ~一半 prefill 计算" 的定性结论出自论文摘要与 §2.2）。decode 那一格在两种方案下完全相同，因为 decode 阶段每 token 都要走完整 40 层。

反过来也要诚实指出边界（论文未展开，属推断）：如果负载是「输入短、输出长」（例如长文写作），prefill 占比小，CED 的收益就有限；而 decode 阶段每 token 要额外做 \(H^{L/2}\) 投影、模型又比 V4-Flash 大，单位 decode 成本未必更低。CED 是一把为 agentic / 长输入场景定制的刀，不是普适提速。

6. 与 DeepSeek-V4 的关系：streamline 精简了什么、继承了什么

7. §2.5 Optimization：训练优化如实讲

§2.5 讲的是「在 V4 优化配置之上的新修改」，共两件事加一组基础配置：

7.1 Head-wise Muon：每个注意力头一个 preconditioner

Muon 是一种优化器：可以把它粗略理解成「给梯度先做一次正交化再更新的 SGD」，对新纪元的矩阵参数更新比 AdamW 更省显存且效果好（论文引 Jordan et al., 2024；Liu et al., 2025）。V4.1 的新修改是 head-wise Muon：把 Query 权重按注意力头切分后再施加 Muon 更新。动机（§2.5 原话）：把 Muon 看作「带预条件子的梯度下降」，普通 Muon 对所有头共用一个预条件子，而 head-wise 版本给不同头配不同预条件子，更好地处理注意力头之间的异质性。论文报告观察到 head-wise Muon 优于普通 Muon，并指出该经验优势也在 GLM 5 与 Kimi-K3 中得到验证。Key 权重同样使用 head-wise Muon（§4.2.2）。

7.2 Sinkhorn 平衡更新：给巨大的 Embedding / 预测头 / Engram 表换掉 Adam

给 Engram 参数直接用 Adam 会显著增加优化器状态显存。V4.1 改用「动量更新 + Sinkhorn 平衡」来优化 Engram 嵌入表、token embedding 与预测头这三类大矩阵。Sinkhorn 平衡此前在 SinkGD（Scetbon et al., 2025）中用于线性层权重，本文将其推广到这些大参数矩阵。核心思想与 Muon 同构：Muon 用 Newton–Schulz 迭代做正交化，这里用 Sinkhorn 平衡替代。给定 Nesterov 动量更新 \(\widehat{G}_t\)，寻找对角缩放矩阵 \(D_r, D_c\) 使（论文式 7）：\[ \Delta_t = \sqrt{n}\, U^{(K)} = \sqrt{n}\, D_r\, \widehat{G}_t\, D_c,\qquad \frac{1}{n}\sum_{j=1}^{n}(\Delta_t)^2_{ij} \approx 1,\quad \frac{1}{m}\sum_{i=1}^{m}(\Delta_t)^2_{ij} \approx 1 \]

逐符号解释：\(m\) 是矩阵较大维（对嵌入表和预测头即词表大小），\(n\) 是隐藏维；\(U^{(K)}\) 是对 \(\widehat{G}_t\) 交替做行/列归一化 \(K\) 次（K 为奇数）后的结果；两条约束分别要求每一行、每一列的均方根（RMS）近似为 1——这里一行对应一个 token 索引或 n-gram 身份、一列对应一个隐藏特征，Sinkhorn 正是利用这种「token–特征」结构做双向归一化。实现细节（Algorithm 1）：动量系数与 Muon 相同（0.95），行 RMS 满足 \(\rho_i \le \tau\bar\rho\) 的近零行被掩蔽（\(\tau=10^{-3}\)，K=11，\(\varepsilon=10^{-20}\)）；\(\sqrt{n}\) 把单位行 ℓ2 范数换算成单位行 RMS；有效学习率调整为 \(\tilde\eta_t = \gamma\eta_t\)、\(\gamma=0.18\)（接近 Moonlight 的 0.2），以对齐 Adam 的更新幅度。效果（论文原话）：像 Muon 一样只需一份动量缓冲，且经验上优于 Adam。

7.3 基础配置（§4.2.2 与 §2.5 "Basic Configurations"）

  • RMSNorm 等归一化层权重及其他非矩阵参数（偏置、缩放因子）用 AdamW（\(\beta_1\)=0.9，\(\beta_2\)=0.95，\(\varepsilon\)=10⁻²⁰，weight decay=0.1）；线性变换权重矩阵（语言骨干、Engram 投影层、视觉-语言 projector）用 Muon（动量 0.95，weight decay 0.1，更新矩阵 RMS 重标定到 0.18 以复用 AdamW 学习率）；偏置与缩放因子不做 weight decay，归一化层权重做。
  • 训练全程 45T token、batch 固定 100.6M token，无不稳定现象；学习率线性预热 2000 步至 2.6×10⁻⁴，28T 前保持，28T–40T 余弦衰减到 2.6×10⁻⁵ 并保持到 45T。
  • 视觉编码器在预训练中冻结到学习率衰减阶段（其最终归一化层与视觉-语言 projector 保持可训练）；进入衰减阶段后解冻，与 LLM 联合训练、用较小学习率。
  • 辅助损失-free 负载均衡的偏置更新速度为 0.001（图像、文本相同），另保留权重 0.0001 的小型序列级均衡损失以防单序列内极端失衡。

8. 效果速览与 KV cache 对比

虽然 KV cache 的细账归第 2、4 讲，但作为架构篇应交代 CED 所在整体的战绩（全部为论文数字）：

  • 全局 KV cache（常驻 HBM）压缩到 890 字节/token，约为 DeepSeek-V4-Flash 的 1/4、DeepSeek-V1 的 1/437（摘要与 Figure 1(b)）。
  • 持久 KV cache（SSD 或主机内存）约为 V4-Flash 的 1/8——乘法分解：不再存 SWA KV（≈减半）× 全局 KV 压到 1/4（§3.2.1）。
  • Decode FLOPs 近乎恒定：上下文从 4K 扩到 1M（256 倍），单 token decode FLOPs 只增加 1/4（§1 与 Figure 2）。
  • 能力：Base 模型知识与推理能力与 1.6T 的 V4-Pro-Base 相当，held-out 评测高 5%–10%，仅用 1/3 总参数与 1/4 激活参数（§1）；推理/Agent/多模态三线表现见 §5.3（第 6 讲展开）。

9. 一句话带过 §2.3 与 §2.4（归属第 2、3 讲）

  • §2.3 CSA2（第 2 讲）：把 V4 的 CSA–HCA 混合换成纯 CSA2——沿「层」这个维度做复用：Full 模式层自己算全局 KV 并做索引；Reindex 模式层复用前层的全局 KV、用自己的索引器重新打分选出新的 Top-K；Reuse 模式层连索引结果一起复用。解码器还配了 Hierarchical Sparse Indexer：第一个 Full 层选出候选池（至多 2048 块 × 8 位置 = 16384 位置），后续索引器只在池内打分，使每个后续索引器每查询的打分量从「正比于上下文长度」变为「常数」。
  • §2.4 架构扩展（第 3 讲）：Single-Pass mHC（残留流混合改单 pass，配合 Mega-mHC kernel 把激活内存流量减半）、Engram（196B 参数的稀疏条件记忆，置于第 1、14 层）、DSpark（半自回归起草 + 置信度调度验证的投机解码）、FP4 主 KV cache（QAT + 量化后 RoPE 的 E2M1 格式，存储再减半）。

11. 本讲小结

  • 动机：agent 负载输入重、输出轻，prefill 计算成为成本大头；长上下文下 KV cache 的存储与搬运也成为瓶颈（§1）。
  • CED 的核心动作只有一句话：解码器 20 层的全局 KV 不从各自隐状态算，而是从编码器末层隐状态 \(H^{L/2}\) 用每层专属矩阵投影出来（式 1）；SWA 保持全层逐层计算，配 Decoder SWA Bounded Replay 把重放开销压到 \(n_{win}\)=128 个 token。
  • 效果：prefill 复杂度近乎减半；prefill 激活 8B/token、decode 16B/token 的不对称正中 agentic 负载要害；与 CSA2、FP4 KV 协力把全局 KV 压到 890 B/token（V4-Flash 的 1/4）。
  • 架构观：V4.1 是对 V4 的「精简 + 聚焦」——保留 SWA 局部分支与 DeepSeekMoE 骨架，把全局分支沿层维（CSA2）、精度维（FP4）、分工维（CED）三路压缩；mHC 升级为 Single-Pass、MTP 换成 DSpark、新增 Engram。
  • 训练面（§2.5）：head-wise Muon 处理注意力头异质性；Engram/embedding/预测头改用动量 + Sinkhorn 平衡更新，只留一份动量缓冲、效果优于 Adam。

12. 自测清单

Q1：CED 里「因果编码器」的「因果」体现在哪？它和 T5 的 encoder 有什么本质区别？

答：编码器的 20 层内部仍然是因果注意力——每个 token 只能看到自己之前的 token，与 decoder-only 完全一致，因此模型整体仍能自回归地生成。T5 式 encoder 内部是双向注意力（每个 token 可见全文），只能处理整段输入、不能直接参与逐 token 生成。CED 是「decoder-only 的骨架 + 编码器-解码器的算力分工」。

Q2：写出论文式 (1)，并说明解码器的全局 KV 是从哪个张量投影出来的。

答：\(C^l = H^{L/2} W^{KV}_l,\; Z^l = H^{L/2} W^Z_l,\; l > L/2\)。来源是第 L/2 层（编码器最后一层，第 20 层）的隐状态，而非解码器各层自己的隐状态；\(W^{KV}_l, W^Z_l\) 是每层独立的投影权重，\(C\) 是 KV entry、\(Z\) 是配套压缩权重。

Q3：为什么解码器的 SWA 不能像全局注意力那样跳过？跳过会怎样、论文怎么补救？

答：解码器各层的局部 K/V 必须由各层自己的隐状态导出；若不跑解码器前向，这些隐状态不存在，解码器的 SWA KV 也就缺失，而 decode 的第一步就需要它。精确补齐需重放 \(n_{win}\times L/2\)（128×20=2560）个 token，对短提示多轮场景开销可观。论文的补救是 Decoder SWA Bounded Replay：只重放最后 \(n_{win}\)=128 个 token、将 SWA 截断到重放段，接受近似状态（实验显示对回复质量影响可忽略，§3.2.2）。

Q4：V4.1-Flash 为什么设计成 prefill 8B / decode 16B？这个不对称对什么负载最有利？

答：prefill 时长输入只穿过下半 20 层（编码器），上半 20 层的全局 KV 由投影一次性得到，几乎不需要逐 token 的重型计算，故激活参数减半；decode 时每个输出 token 都要走完整 40 层，激活 16B。对「输入长、输出短」的 agentic 负载（频繁工具调用产生大量长 prefill）最有利——prefill 计算近乎减半，整体请求成本趋近减半；对输入短、输出长的负载收益有限（推断）。

Q5：相比 DeepSeek-V4，V4.1 在注意力与总体架构上分别「精简」了什么？

答：注意力上，用纯 CSA2（Full/Reindex/Reuse 三种静态模式，跨层共享全局 KV 与索引器 K、复用 Top-K 索引）替代 V4 的 CSA–HCA 混合架构；总体上，mHC 升级为 Single-Pass mHC（激活内存流量减半）、省略 MTP 改用骨干后单独训练的 DSpark、新增 Engram 条件记忆、主 KV cache 降到 FP4，同时保留 DeepSeekMoE 与每层 SWA 的骨架。

Q6：§2.5 中把 Engram/embedding/预测头的优化器从 Adam 换成「动量 + Sinkhorn 平衡」，动机和代价各是什么？

答：动机是省优化器状态显存——Adam 要为每个参数存两份状态，对巨大的嵌入表/预测头/Engram 表负担极重；Sinkhorn 方案像 Muon 一样只维护一份动量缓冲，且经验上优于 Adam。代价是需要 \(K\)=11 次交替的行/列归一化迭代（奇数次、含近零行掩蔽），并需用 \(\gamma\)=0.18 的学习率校正系数对齐 Adam 的更新幅度。
