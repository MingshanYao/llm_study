读者假设：知道 Llama、VLM、LoRA、tokenizer、量化大概是什么（不需要会用）；不需要任何机器人背景。所有行话第一次出现都会解释。

本讲目标：解剖最有影响力的开源 VLA——OpenVLA：它长什么样、吃了什么数据、考了多少分、怎么用一张卡微调；读完你应该建立「怎么微调一个 VLA」的完整心智模型，并知道去哪下权重、要准备多少显存。

TL;DR：OpenVLA（2024 年 6 月，斯坦福 / 伯克利 / Toyota Research Institute / 华盛顿大学等，arXiv:2406.09246）是第一个「开放权重 + 达到 RT-2-X 级性能」的 7B 参数 VLA：Llama 2 7B 主干 + DINOv2/SigLIP 双视觉编码器融合，在 Open X-Embodiment（OXE）数据集的 970k 条真实机器人轨迹上训练。在跨 2 个机器人平台共 29 个任务的评测中，它以 7 倍更少的参数把 55B 的闭源 RT-2-X 的绝对成功率高出 16.5 个百分点；用 LoRA 可以在单张 A100（最低约 27GB 显存）上微调出新任务策略。它把 VLA 从大厂专利变成社区公器——此后几乎所有学术开源 VLA（OFT、TinyVLA、RoboVLMs……）都拿它当基座或基线，至今仍是微调入门的事实标准。2025 年 2 月的 OpenVLA-OFT 进一步证明：把「离散动作 token + 自回归解码」换成「连续动作 + 并行解码 + 动作分块」，同一个基座在 LIBERO 仿真基准上能从 76.5% 提到 97.1%，推理吞吐提高 26 倍。

1. 为什么开源是关键一步：RT-2 跑不起，Octo 不够强

第 2 讲里我们见过 RT-2：Google DeepMind 把 55B 的 VLM 微调成机器人策略，效果惊艳——但它闭源。你拿不到权重、看不到训练代码和数据配方，只能通过内部 API 调用（OpenVLA 团队做对比实验时，用的还是 DeepMind 给的「alpha 访问」权限）。对一个想在自己机器人上做研究的实验室来说，这意味着：不能微调、不能魔改、不能复现。

2024 年 5 月，伯克利牵头的 Octo（arXiv:2405.12213）迈出了开源第一步：一个 93M 参数的 Transformer 策略（约 ViT-Base 规模的主干，语言指令用 T5-base 编码），配一个扩散动作头（diffusion action head——不预测离散 token，而是像去噪一样「画」出连续动作，第 4 讲细讲），在 OXE 的 800k 轨迹上训练（TPU v4-128 集群 14 小时），单张 24GB 的 A5000 消费级显卡就能微调。但 Octo 的问题是太小：它没有互联网规模的 VLM 主干，视觉和语言理解都从头学，缺少 RT-2 那种「见过世面」的语义泛化。在 OpenVLA 论文的同一套评测里，Octo 在 BridgeData V2 上零样本（zero-shot，不微调直接用）成功率只有 20.0%，很多任务里机械臂甚至「漫无目的地挥舞」。

于是社区处在一个尴尬的空档里：强的不开源，开源的不够强。OpenVLA 的定位正是填这个空档——「够强（继承互联网规模 VLM 先验）+ 可微调（单卡 LoRA）+ 可部署（量化后 7GB 显存）」三者兼得。它还第一次系统研究了「VLA 到底该怎么微调」这个此前没人认真回答的问题，这也是本讲把一半篇幅留给微调实操的原因。

「开源是 VLA 领域 2024–2025 年爆发的主催化剂」是我们基于生态时间线的判断：OpenVLA 发布后一年内，OFT、TinyVLA、RoboVLMs、FAST 等衍生工作几乎全部以它为基座或基线（见第 7 节生态表）。论文本身没有做这个因果声明。

2. 架构精读：从像素到动作 token 的全链路

OpenVLA 的骨架是一个标准的现代 VLM（视觉语言模型）：视觉编码器 → 投影层 → 语言模型。它的聪明之处在于什么都不新造——直接拿现成的 Prismatic-7B VLM（斯坦福/TRI 的 VLM 设计空间研究，arXiv:2402.07865）当底座，把「输出文字」改成「输出动作 token」。先看全链路：

图 3-1｜OpenVLA 全链路（对应论文 Fig. 2 与 §3.1–3.2，各模块维度经 openvla/openvla 仓库源码与 HF 模型卡核实，commit c8f03f4）。整条链路里没有任何机器人专用结构——就是一个 VLM，把「下一个词」换成了「下一个动作 bin」。

2.1 视觉：双编码器融合，语义 + 空间细节都要

OpenVLA 的视觉部分同时用两个预训练 ViT（Vision Transformer，把图像切成小方块 patch、每块当一个 token 处理的架构）：

  • DINOv2 ViT-L/14：Meta 的自监督视觉模型（不用文字标注，靠图像自身结构学习），特征是出了名的空间/几何细节好——物体边界、相对位置这类机器人最需要的低层信息；
  • SigLIP ViT-SO400M/14：Google 的图文对比学习模型（和 CLIP 同族，「SO400M」是它的形状优化版，约 4 亿参数），特征是语义与语言对齐好——知道「这是茄子」并且和文字「eggplant」挂钩。

注意两个细节（都来自源码，二手资料常写错）：其一，SigLIP 用的是 patch 14 的 SO400M 版本，不是常见的 ViT-L/16；其二，两个编码器对同一张 224×224 的图各自切出 16×16=256 个 patch 特征，然后在通道维度逐 token 拼接（1024 维 + 1152 维 = 2176 维），序列长度仍是 256，不会翻倍。拼接后的 256 个视觉 token 经过一个 3 层 MLP 投影到 Llama 2 的 4096 维词向量空间。

易错点不少博客把 OpenVLA 的视觉前端描述成「2×2 相邻 token 空间合并后得到 256 个视觉 token」。这不对：256 是 224÷14=16、16×16=256 的直接结果，OpenVLA 的检查点里根本没有空间合并（spatial merge）模块——我们在 openvla 仓库与 HF 版 modeling_prismatic.py 里全文搜索均无此代码（融合就是 torch.cat([dino_patches, siglip_patches], dim=2)，见 prismatic/models/backbones/vision/dinosiglip_vit.py:142-147）。「2×2 合并省 4 倍序列长度」是 Prismatic VLM 系列给更高分辨率模型准备的可选组件，与 OpenVLA-7B 无关。当然，「控制视觉 token 数量以省算力」这个思想本身是真实的：论文 §3.4 比较过 224px 与 384px 输入，性能无差别而后者训练时间 ×3，所以最终选了 224px。

为什么要两个编码器？Prismatic VLM 论文（arXiv:2402.07865）在 VLM 基准上系统比较过：DINOv2+SigLIP 融合在定位类、空间推理类任务上比单编码器高 5–10%。OpenVLA 论文自己也做了消融（附录 D.2，表 9）：在 BridgeData V2 的 8 个任务上，把 DINOv2 拿掉只留 SigLIP，平均成功率从 45.6% 掉到 40.6%——有用，但不算决定性；同一张表里，把 OXE 多机器人预训练拿掉（只用 Bridge 数据训），成功率从 76.3% 暴跌到 45.6%。结论：数据多样性 > 视觉编码器花活。

2.2 主干：Llama 2 7B 原封不动当「动作解码器」

语言主干是 Llama 2 7B 的 base 版（不是指令微调的 chat 版——Prismatic 的实验发现 instruct 模型更啰嗦、更容易幻觉，base 模型反而干净）。整个 VLM 底座来自 Prismatic-7B：先在约 100 万条图文/纯文本数据（LLaVA 1.5 数据配方）上把视觉-语言对齐训好，OpenVLA 再在这个 VLM 上用机器人数据微调。

训练目标就一句话：下一个 token 预测 + 交叉熵，但只对 7 个动作 token 计损失。提示文本和 256 个视觉 token 的位置 label 全部设为 -100（PyTorch 交叉熵的「忽略」标记），模型不需要学会复述指令，只需要在看完图和指令后接出正确的动作。HF 版实现里可以清楚看到视觉 token 的 label 被填充为 IGNORE_INDEX（modeling_prismatic.py:393-401，openvla-7b 模型仓库）。

2.3 动作表示：7 维 delta 动作 → 256 个 bin → 词表末尾 256 个冷门 token

第 2 讲讲过 RT-2 的核心发明：把连续动作离散成 bin，每个 bin 占用词表里一个几乎没人用的 token，让 LLM「把动作当词说出来」。OpenVLA 沿用同一思路，但有两个工程改进：

  • 动作定义：7 维 delta 末端执行器（EE）动作——末端执行器（end-effector）就是机械臂手腕末端的工具（通常是夹爪）；delta 指每一步输出的是「相对当前位姿的增量」：\((\Delta x, \Delta y, \Delta z, \Delta roll, \Delta pitch, \Delta yaw, \text{gripper})\)，前 3 维是位置增量，中间 3 维是姿态（旋转）增量，最后 1 维是夹爪开合。这是第 1 讲说过的最常用动作空间。
  • 归一化用分位数而非 min-max：每一维动作先用训练集里该维的 1% / 99% 分位数（q01 / q99）线性映射到 \([-1, 1]\)（RT-2 用的是最小/最大值）。好处是几个离谱的离群动作不会把整个区间撑大、让 256 个 bin 的分辨率被浪费。
\[ \hat{a}_j = \mathrm{clip}\!\left( \frac{2\,(a_j - q_{01,j})}{q_{99,j} - q_{01,j}} - 1,\; -1,\; 1 \right), \qquad a_j = \tfrac{1}{2}\,(\hat{a}_j + 1)\,(q_{99,j} - q_{01,j}) + q_{01,j} \]

公式 3-1｜左：训练时把真实动作 \(a_j\) 归一化到 \([-1,1]\)（源码 prismatic/vla/datasets/rlds/utils/data_utils.py:53,76-90 的 BOUNDS_Q99 方案）；右：推理时反归一化（modeling_prismatic.py:527-535）。每个数据集有自己的 q01/q99 统计量，存在模型配置里，用 unnorm_key 选取——这是微调时最容易踩的坑之一（见 §5.3）。

归一化后的每一维被均匀切成 256 个 bin，bin 编号映射到 Llama 词表末尾的 256 个 token（BPE 类分词器的词表按使用频率排序，末尾是最冷门的 token，直接覆盖它们的含义即可，不用扩词表——Llama tokenizer 只给微调预留了 100 个新 token 位，不够 256 个用，所以选择「改写」而不是「新增」）。一个时间步的动作 = 7 个 token，自回归逐个吐出。下面是训练侧动作 tokenizer 的真实源码（把连续动作变成 token）：

# openvla/openvla @ c8f03f4 — prismatic/vla/action_tokenizer.py:38-47
def __call__(self, action: np.ndarray) -> Union[str, List[str]]:
    """Clip & bin actions to *the last `n_bins` tokens* of the vocabulary."""
    action = np.clip(action, a_min=float(self.min_action), a_max=float(self.max_action))
    discretized_action = np.digitize(action, self.bins)   # 连续值 → bin 编号

    # bin 编号 i → token id = vocab_size − i（词表末尾 256 个位置）
    if len(discretized_action.shape) == 1:
        return self.tokenizer.decode(list(self.tokenizer.vocab_size - discretized_action))
    else:
        return self.tokenizer.batch_decode((self.tokenizer.vocab_size - discretized_action).tolist())

推理侧则反过来：生成 7 个 token → 换算回 bin 编号 → 取 bin 中心值作为归一化动作 → 用该数据集的 q01/q99 反归一化。HF 模型卡上的 predict_action() 把这一切包成了一个函数（源码 modeling_prismatic.py:506-536，节选）：

# openvla/openvla-7b (HF) — modeling_prismatic.py:518-536（节选）
generated_ids = self.generate(input_ids, max_new_tokens=self.get_action_dim(unnorm_key), **kwargs)

# token id → bin 编号 → bin 中心值（∈ [-1,1] 的归一化动作）
predicted_action_token_ids = generated_ids[0, -self.get_action_dim(unnorm_key):].cpu().numpy()
discretized_actions = self.vocab_size - predicted_action_token_ids
discretized_actions = np.clip(discretized_actions - 1, a_min=0, a_max=self.bin_centers.shape[0] - 1)
normalized_actions = self.bin_centers[discretized_actions]

# 用数据集统计量反归一化（mask 标记哪些维度参与，比如夹爪常是 0/1 直通）
action_norm_stats = self.get_action_stats(unnorm_key)
action_high, action_low = np.array(action_norm_stats["q99"]), np.array(action_norm_stats["q01"])
actions = np.where(mask, 0.5 * (normalized_actions + 1) * (action_high - action_low) + action_low,
                   normalized_actions)
return actions
与 RT-2 的两点不同① RT-2 训练时混入图文数据 co-fine-tuning 以保住语言能力，OpenVLA 只用机器人数据纯微调——代价是「语义泛化」（认互联网上新概念）这一类任务上 OpenVLA 略输 RT-2-X（Bridge 评测里唯一输的类别），其余类别全部持平或胜出；② 归一化统计从 min-max 换成 q01/q99 分位数。动作 tokenization 机制本身的完整来历见第 2 讲。

最终训练规模：64 张 A100 训 14 天（合计 21,500 A100 小时），batch size 2048。推理侧：bfloat16 加载约 15GB 显存，单张 RTX 4090 上约 6Hz（未用编译/投机解码等加速）；A100 上 OFT 论文实测每步动作延迟 0.24 秒，约 4.2Hz。对 5Hz 左右的机械臂控制回路刚好够用，但离 ALOHA 那类 25–50Hz 双臂平台还差一个数量级——这个矛盾是 §6 OFT 故事的引子。

澄清OpenVLA 不输入本体感知状态（proprioceptive state，即机器人自己的关节角/夹爪状态等低维读数），输入只有一张图 + 一句指令。但注意：论文并没有做过「加本体感知有没有用」的消融——它只是在 Limitations（§6）里把「支持多图、本体感知与观测历史」列为未来工作，OFT 后来才把机器人状态作为可选输入加了回来。网上流传的「消融显示本体感知帮助有限」在 OpenVLA 论文里找不到出处。

3. 训练数据配方：OXE 的 970k 条轨迹怎么挑

第 1 讲介绍过 OXE（Open X-Embodiment）：60+ 机构把各自机器人数据汇成的「机器人数据联合国」，原始规模 70+ 个数据集、200 万+ 轨迹。但不能全用——OpenVLA 的筛选分三步：

  1. 硬性过滤（统一输入输出空间）：只留操作类（manipulation）数据集；必须至少有一个第三人称相机（固定在桌面上拍全局视角的相机，区别于装在手腕上的腕部相机）；必须是单臂末端执行器控制。动作空间不兼容的（比如关节角控制、双臂）一律去掉——因为整个模型只认「7 维 delta EE 动作」这一种输出格式。
  2. 按 Octo 的配方加权采样：通过过滤的数据集不是等比例混合，而是沿用 Octo 论文调好的混合权重——大而单调的数据集降权（防止 Kuka 抓取这类海量单一场景数据主导训练），任务/场景多样性高的数据集升权。采样时按权重从各数据集抽取 transition（单步「图像-指令-动作」样本）。
  3. 针对性清洗与调整：BridgeData V2 里每条演示的第一步都记录了一个全零（no-op）动作，不清洗的话模型会学会「动不动就僵住」——OpenVLA 直接删掉每条演示的第一个 transition（附录 C 说这是它在 Bridge 评测上大幅超越 RT-2-X 的原因之一，RT-2-X 没做这个清洗）。新增的 DROID 数据集（76k 条高质量 Franka 数据）以 10% 权重加入，但训练全程其动作 token 准确率都上不去，最后 1/3 训练阶段干脆移除，权重重新分配给其他数据集。

图 3-2｜OXE 数据混合（论文附录 A 表 3）。前四大来源各占 10%+ 但没有一家独大——「降权大集、升权多样集」的采样策略让 Bridge、RT-1、Kuka 三种完全不同机器人平台的数据都能被充分学到。

关于「只用成功轨迹」：需要澄清口径——OpenVLA 预训练阶段没有报告 success-only 过滤的消融（OXE 各数据集本身多为演示数据）；「过滤失败演示」出现在它的 LIBERO 仿真微调实验里：每个任务套件的 500 条演示中分别删掉 68 / 46 / 72 / 121 条未完成任务的轨迹后再微调。OFT 论文的表 I 提供了一个间接量化：同样的 OFT 配方，用「过滤失败演示 + 剔除近零幅值动作」的清洗版数据得 97.1%，用原始未过滤数据得 94.5%——约 +2.6pp，但该清洗同时包含两种操作，不能全部归功于 success-only。

数据清洗（去 no-op、去失败轨迹）对 VLA 的收益被论文证据低估了：Bridge 全零动作清洗让 OpenVLA 免于「僵住」这种灾难性失败模式，量级远大于 +2.6pp 这种平均分差异。对微调实践者来说，「先清洗数据再谈模型」应该是默认动作。

4. 评测与结果：7B 打赢 55B

评测口径先说清楚（不然数字容易读歪）：所有对比都是 A/B 评测——不同模型在完全相同的任务、相同的初始物体摆放下轮流上场。零样本评测跨 2 个机器人平台共 29 个任务：WidowX 机械臂（BridgeData V2 水槽场景，17 任务 × 10 次 = 170 rollouts）和 Google Robot（RT-1/RT-2 用的移动操作机器人，12 任务 × 5 次 = 60 rollouts）。每次 rollout 记成功 1 / 失败 0（部分任务允许 0.5 的部分成功分）。

图 3-3｜零样本评测结果（论文 Fig. 3、Fig. 4 与表 4、表 6）。OpenVLA 以 7 倍更少的参数在两个平台上全面领先；唯一输给 RT-2-X 的子类是 Bridge 上的「语义泛化」（认互联网新概念），论文归因于 RT-2-X 的 co-fine-tuning 保住了更多互联网知识、且其 VLM 预训练规模更大。

几个值得展开的读数：

  • 泛化是分维度的：评测覆盖视觉泛化（新背景/干扰物）、运动泛化（新位置/朝向）、物理泛化（新尺寸/形状）、语义泛化（新物体/新指令/互联网概念）与语言定位（多物体场景下操作指令指定的那个）。OpenVLA 除语义泛化外全部第一。
  • OXE 预训练是命根子：消融（附录 D.1）显示只在 Bridge 单数据集上训的同架构模型，8 任务平均从 76.3% 掉到 45.6%。微调实验里，跳过 OXE 预训练直接拿 Prismatic VLM 微调（OpenVLA-scratch）也全面落后（Franka-Tabletop 平均 43.4% vs 67.2%）。
  • 微调后打赢从头训练的 SOTA：在 Franka 平台的 7 个新任务上（每任务 10–150 条演示），微调 OpenVLA 平均 67.2%（Franka-DROID 擦桌任务 58.3%），比从头训练的 Diffusion Policy 高 20.4pp（摘要口径），比微调 Octo 高约 24pp。它是唯一在所有任务上都 ≥50% 的方法。

int8 掉分的真相很有教学意义：论文的补充实验（附录 D.4）把控制方式改成「阻塞式」（机器人执行完当前动作再问下一个，消除推理速度差异）后，int8 恢复到 74.4%、与 bfloat16 无差。掉分不是量化损失了精度，而是推理太慢改变了系统动力学——5Hz 采集的演示数据配 1.2Hz 的控制回路，机器人动作节奏全乱。这提醒我们：VLA 评测里「模型质量」和「推理速度」是耦合的，频率不匹配本身就是性能杀手。

5. 微调实操：怎么把 OpenVLA 变成「你的机器人」的策略

这是本讲的重头戏。OpenVLA 团队把微调拆成两类场景，心智模型完全不同：

  • 场景 A：新任务 / 新场景，本体不变或相近（比如同一类 Franka 机械臂学擦桌子）→ 只需少量演示 + LoRA 微调，单卡搞定；
  • 场景 B：新本体（换机器人、换动作空间、加相机）→ 要动动作 tokenizer 的归一化统计、重算 bin、改数据管线，工程量大得多。

5.1 场景 A：LoRA 微调，单卡 10–15 小时

LoRA（Low-Rank Adaptation）对 LLM 读者是老朋友：冻结原权重 \(W_0\)，只训练一个低秩增量 \(\Delta W = BA\)（\(B \in \mathbb{R}^{d \times r}\)、\(A \in \mathbb{R}^{r \times k}\)，秩 \(r\) 远小于 \(d, k\)），推理时可合并回原矩阵、零额外延迟。OpenVLA 论文是第一个把 LoRA 和量化系统性用在 VLA 微调上的工作。它对比了五种微调策略（Franka-Tabletop 任务，batch 16）：

全参微调（Full FT）69.7 ± 7.2%7188.1M（100%）163.3 GB*论文实测需 8×A100（FSDP 分片），每任务 5–15 小时
只调最后一层30.3 ± 6.1%465.1M51.4 GB基本不可用

硬件账本（README 官方口径）：单张 A100 80GB 跑 batch 16 约 72GB 显存、10–15 小时；最低约 27GB（减小 batch size + 梯度累积保持等效批量，一张 32GB 的 V100/5090 级别卡即可）；脚本还支持 --use_quantization（4-bit 量化底座 + LoRA，即 QLoRA 思路）进一步压显存。数据量方面，论文任务用 10–150 条演示，README 建议目标域准备约 100 条演示。全参微调则需要一整节点 8×A100（FSDP），仅当目标分布与预训练分布差异极大时才值得。

5.2 场景 B：换新本体，要动的是「动作的语言」

换机器人（不同动作维度、不同量纲、不同相机）时，模型结构不用改——改的是动作与 token 之间的翻译规则：

  1. 定义动作空间：确定维度（7 维 delta EE 之外的本体需要自定义，比如双臂 14 维）与每一维的物理含义；
  2. 重算归一化统计量：对你的新数据集逐维计算 q01/q99（和 min/max/mean/std），训练脚本会自动完成并随检查点保存：
# openvla/openvla @ c8f03f4 — prismatic/vla/datasets/rlds/utils/data_utils.py:247-248（节选）
metadata = {
    "action": {
        ...
        "q01": np.quantile(actions, 0.01, axis=0).tolist(),   # 每个动作维度单独统计
        "q99": np.quantile(actions, 0.99, axis=0).tolist(),
    },
    "proprio": { ... 同样统计 ... },   # 本体感知统计也会算好存下，供 OFT 等使用
}
  1. bin 划分本身不用重训：256 个 bin 均匀铺在归一化后的 \([-1,1]\) 上，与具体机器人无关——换本体改变的是 q01/q99，不是 bin。推理时用新数据集名当 unnorm_key 取回新统计量即可；
  2. 数据转 RLDS 格式：官方管线吃 RLDS（TensorFlow 的机器人数据格式，OXE 全家都用它）；自定义数据用 rlds_dataset_builder 转换，再在 oxe/configs.py 与 oxe/transforms.py 注册数据集配置与变换函数；
  3. 相机数目：原版 OpenVLA 只吃一张第三人称图像（论文 §6 明确的限制）；想用腕部相机 + 第三人称双视角，请直接用 OpenVLA-OFT（§6），它的输入管线原生支持多图 + 机器人状态。

5.3 HuggingFace 生态：10 行代码跑起来

权重下载：huggingface.co/openvla/openvla-7b（MIT 协议，BF16 safetensors 约 15GB），加载走 transformers 的 AutoModelForVision2Seq（模型卡要求 trust_remote_code=True，因为架构是仓库自带的 modeling_prismatic.py）。README 的官方推理示例：

# openvla/openvla README「Getting Started」（真实代码）
from transformers import AutoModelForVision2Seq, AutoProcessor
import torch

processor = AutoProcessor.from_pretrained("openvla/openvla-7b", trust_remote_code=True)
vla = AutoModelForVision2Seq.from_pretrained(
    "openvla/openvla-7b",
    attn_implementation="flash_attention_2",   # 可选，需装 flash_attn
    torch_dtype=torch.bfloat16,
    low_cpu_mem_usage=True,
    trust_remote_code=True,
).to("cuda:0")

image = get_from_camera(...)                    # PIL Image，来自第三人称相机
prompt = "In: What action should the robot take to {<INSTRUCTION>}?\nOut:"
inputs = processor(prompt, image).to("cuda:0", dtype=torch.bfloat16)

# 一步出 7 维动作（内部完成：生成 7 token → 反 tokenize → 按 unnorm_key 反归一化）
action = vla.predict_action(**inputs, unnorm_key="bridge_orig", do_sample=False)
robot.act(action, ...)                          # 交给机器人控制器执行

OFT 微调过的检查点在 moojink/openvla-7b-oft-finetuned-libero-*（LIBERO 四个套件各一个），代码在 moojink/openvla-oft。

5.4 常见坑清单（每一条都有官方出处）

  • Prompt 必须一字不差：训练时模型只见过 "In: What action should the robot take to {...}?\nOut:" 这一种模板（部署代码里还有个细节：冒号后要补一个空 token id 29871，predict_action() 会自动处理，自己写推理循环的人常漏掉）；
  • 图像预处理必须与预训练一致：224×224、resize-naive 策略、DINOv2 与 SigLIP 各有各的归一化均值/方差（processor 会把两个编码器所需的 6 通道拼在一起）——自己手写 transform 几乎必错；
  • unnorm_key 用错 = 动作全错：反归一化统计量按数据集存取，选错数据集名，动作幅度直接错一个量级；微调后要用新数据集的统计量（训练脚本会自动保存进检查点）；
  • 控制频率要匹配：README 故障排查一节明确建议数据采集与控制都在 5–10Hz；50Hz 的高频数据要先降采样到 5Hz 再微调，否则模型学不会（原版无动作分块，见 §6）；
  • 演示里别停顿：数据里若有大量「几乎不动」的时间步，模型推理时会卡死在 no-op 上（和 Bridge 全零动作是同一类病）；采集时保持连续缓慢运动；
  • 先做两个 sanity check 再怪模型：① 回放演示动作，确认机器人能靠回放完成任务（数据管线没问题）；② 把微调集图像喂给推理管线，确认能复现训练时的 token 准确率 / L1 误差（推理管线没问题）。训练时日志里的 action_accuracy（预测 token 与真值 bin 一致的比例）是最有用的健康指标；
  • 解码用贪心：官方示例 do_sample=False；采样解码会给动作注入随机性，对控制回路通常有害。
从 GitHub Issues 与 README 专门增设故障排查章节（2024-10-15 更新）来看，「预处理/归一化统计/控制频率」三类问题是社区微调失败的主因——这也符合我们的经验判断：VLA 微调的坑大多在数据管线，而不在训练超参。

6. OpenVLA-OFT：同一个基座，换掉「动作怎么出来」

OpenVLA 最大的遗留问题是慢：自回归解码 7 个 token 要做 7 次串行前向，A100 上一步动作 0.24 秒（4.2Hz）。这带来两个连锁伤害：① 无法做动作分块（action chunking——一次预测未来 K 步动作、开环执行完再重新规划，这是 Diffusion Policy/ACT 证明过的提成功率利器），因为 K 步 × 7 维 = 7K 次串行前向，延迟不可接受；② 上不了 25–50Hz 的高频平台（ALOHA 双臂）。2025 年 2 月，OpenVLA 一作 Moo Jin Kim 等人发布 OpenVLA-OFT（Optimized Fine-Tuning，arXiv:2502.19645），用一组受控实验回答「微调 VLA 时，动作到底该怎么出来」，三个改动：

  • 并行解码（parallel decoding）：在输入序列末尾追加 K×D 个「空动作 embedding」，把因果注意力掩码换成双向注意力，一次前向同时输出整块动作——7 次串行变 1 次；
  • 连续动作 + L1 回归：抛弃 256-bin 离散化，在 LLM 顶层加一个小 MLP 动作头直接回归连续值，损失就是预测与真值的 L1 距离（对比扩散目标训练，见 第 4 讲）；
  • 动作分块：并行解码让分块变得可行，LIBERO 实验用 K=8，ALOHA 真机用 K=25；执行完整块再重新规划。

图 3-5｜自回归 vs 并行解码（OFT 论文 Fig. 2、表 I、表 II）。数字全部来自 OFT 论文在 A100 上的实测。

三个改动的贡献可以分开看（论文表 I，LIBERO 四套件平均）：仅「并行解码 + 分块」就把 76.5% 拉到 90.2%（+13.7pp）——分块本身就能减少累积误差、让轨迹更平滑，这和 Diffusion Policy 的经验一致；再换成连续动作 + L1 回归，又 +5.1pp 到 95.3%（离散 bin 的分辨率损失被消除）；有意思的是 L1 回归与扩散目标打平（95.3% vs 95.4%），但 L1 训练收敛更快、推理不用 50 步去噪。加上腕部相机与机器人状态输入、以及针对 ALOHA 的 FiLM 语言增强（把语言 embedding 调制进视觉特征，治「看图不看指令」的毛病）后，最终 97.1%，超过 π0 微调的 94.2%；真机 ALOHA 双臂任务上比 π0/RDT-1B/Diffusion Policy/ACT 最高领先 15pp。

OFT 的工程门槛也不高：推理 16GB 显存（LIBERO）/ 18GB（ALOHA），训练 1–8 张 27–80GB 的卡，仍走 LoRA（500 条演示量级）。

承上启下OFT 证明了「离散 bin + 自回归」不是 VLA 的唯一答案：连续动作 + 并行解码才是高频控制的方向。而连续动作头的两条技术路线——L1 回归与扩散/流匹配——各有何长短、数学上怎么工作，正是第 4 讲的主题（π0 用的流匹配就属于这一族）。本讲只需记住结论：OFT 用简单的 L1 就追平了扩散，说明「动作头怎么训」比「动作头多花哨」更关键。
