资料与核实：全部数字以 arXiv 原文为准（本地归档 paper/rt-1.pdf、paper/rt-2.pdf、paper/saycan.pdf、paper/palm-e.pdf、paper/open-x-embodiment.pdf、paper/rt-h.pdf）；代码片段来自 RT-1 官方开源仓库 google-research/robotics_transformer（commit 4569641，最后提交 2023-02-10，2026-10-21 抓取）。

一句话主线：Google Robotics 用两步把「机器人策略」变成了「大模型」。第一步 RT-1（2022.12）：一个只有 3500 万参数的专用 Transformer，靠 13 台机器人 17 个月攒下的约 13 万条真机演示，吃下 700 多条任务指令，证明「机器人数据也能喂出多任务大模型」，并且第一次把动作离散成 256 个 bin、当分类问题训练——「动作 tokenization」由此诞生。第二步 RT-2（2023.7）：不再造机器人专用模型，而是拿现成的 VLM（PaLI-X / PaLM-E，最大 55B）继续训练，把动作「写成文本」、借用 VLM 词表里的 token 输出——机器人第一次继承了互联网知识，出现符号理解、推理等涌现泛化能力。「vision-language-action model（VLA）」这个词就是 RT-2 论文正式提出的，本讲讲透它的出生过程。

1. 背景：2021–2022，「一个任务一个模型」的时代

在 RT-1 之前，机器人学习的主流工作流是这样的：想让机器人叠积木，就采一批叠积木的演示数据、训一个叠积木的模型；想开抽屉，就再采一批开抽屉的数据、再训一个模型——术语叫单任务 / 少任务策略。这和 2010 年代的计算机视觉一模一样：每个数据集各训各的分类器。而 NLP 和 CV 已经先后证明了另一条路：先用海量、任务无关的数据训一个大模型，再迁移到具体任务。机器人领域没跟上，原因很实际：互联网文本和图片几乎免费，机器人数据却要人握着遥控手柄一条条采——这个过程叫遥操作（teleoperation）：人远程操控机器人做示范，机器人的动作被录下来当训练数据（第 1 讲的数据采集部分讲过）。

Google Robotics（及其机器人子公司 Everyday Robots）手里有一份别人没有的资产：一支 13 台移动操作机器人的车队。每台机器人有 7 自由度机械臂（自由度 degree-of-freedom, DoF：可独立运动的关节数）、两指夹爪和一个可移动底座，部署在仿办公室厨房的「机器人教室」里，由专职团队连续 17 个月采集数据，累计约 13 万条演示轨迹（episodes）、覆盖 744 条不同的语言指令（论文 Table 1：pick、move near、place upright、knock over、open/close drawer、放入/取出容器等 12 类技能 × 大量物体）。「轨迹 / episode」指从任务开始到结束的一整段「观察 + 动作」记录。

「数据引擎先于模型」——先把大规模采数据的基础设施建起来，模型架构反而是后置的选择——是 RT 系列给整个领域留下的最重要规律之一。后来的 Open X-Embodiment、OpenVLA（第 3 讲）、π0（第 4 讲）全都踩在这条规律上：谁能攒到更大更杂的机器人数据，谁就定义下一代模型的上限。这是我对这段历史的归纳，论文本身没有这样表述。

有了数据，还需要两个前奏性的探索来回答「LLM / VLM 到底能在机器人系统里干什么」。这就是下面两篇。

2. 前奏两篇：SayCan 与 PaLM-E

2.1 SayCan（2022.4）：LLM 当规划器，但不碰手柄

SayCan（论文标题 Do As I Can, Not As I Say，「照我能做的做，别照我说的做」，arXiv:2204.01691）要解决的问题是：LLM 懂常识（知道「打扫洒掉的饮料」要先拿海绵、再擦、再扔垃圾桶），但不知道机器人此刻能做什么。它的方案是把两个分数相乘——先人工预建一个底层技能库（论文提出 551 个候选技能，如「拿起 X」「走到桌子旁」，每个技能都是一个独立训练好的小策略，并配一个值函数（value function）：强化学习里估计「当前状态下执行该技能的成功概率」的函数），然后每一步决策时给每个技能打分：

\[ \text{score}(\pi) \;=\; \underbrace{p_{\text{LLM}}(\ell_\pi \mid i, \ell_{\pi_0}, \dots)}_{\text{语义分：LLM 觉得下一步该做什么}} \;\times\; \underbrace{p_{\text{aff}}(c_\pi \mid s, \ell_\pi)}_{\text{可行分：值函数觉得当前状态下做得成吗}} \]

选分数最高的技能执行，循环直到完成（论文 Algorithm 1）。\(\ell_\pi\) 是技能的语言描述，\(i\) 是用户的高层指令，\(s\) 是当前观察。「可行分」也叫 affordance（可供性）：环境「允许」机器人做什么。在 101 条指令的评测里，PaLM-SayCan 在模拟厨房达到 84% 规划成功率、74% 执行成功率（真实厨房 81% / 60%）。

关键局限：LLM 全程只在「技能层」说话，从不产生底层电机动作；技能库要人工逐个预建（每个技能都要自己的演示数据和值函数）；语义理解和运动执行是两个互不相通的模块。SayCan 的底层技能后来被 RT-1 替换，效果立竿见影（RT-1 论文 Table 6：SayCan w/ RT-1 在两个真实厨房的长程任务执行成功率均为 67%，而 w/ Gato 为 33%/0%、w/ BC-Z 为 53%/13%）。

2.2 PaLM-E（2023.3）：把「眼睛」接进 LLM，但输出仍是语言

PaLM-E（arXiv:2303.03378）走了另一条路：不预建技能库，而是把图像、机器人状态等连续信号经过编码器（ViT，Vision Transformer）变成一串 embedding（连续向量），直接注入 LLM 的输入序列——文本里的特殊占位 token 被替换成这些向量，LLM 像「读」文字一样「读」图像。最大的 PaLM-E-562B = 540B 的 PaLM 语言模型 + 22B 的 ViT，是当时最大的多模态模型，在 OK-VQA（看图问答基准）上拿了 SOTA，还能做机器人任务规划——但输出的是语言计划（「先去抽屉→打开顶层抽屉→拿出薯片袋」），不是动作。

PaLM-E 最重要的实验发现是正迁移（positive transfer）：把具身数据（机器人图像、规划数据）混进多模态训练，不但没拖累语言能力，反而让视觉问答、图像描述等任务变好了。这直接启发了 RT-2 的反向操作：既然具身训练能帮到语言任务，那让 VLM 直接输出动作，互联网知识是不是也能帮到机器人？PaLM-E 还有一个更直接的贡献：它的 12B 版本（8B PaLM + 4B ViT）后来就是 RT-2 的两个主干之一（RT-2-PaLM-E）。

把 PaLM-E 称为「RT-2 的思想跳板」是我的叙事概括：两个事实支撑都在论文里（RT-2 用 PaLM-E 当主干之一、RT-2 引用其正迁移结论），但「跳板」这个因果定位是我加的。

3. RT-1 精读：数据喂出来的机器人 Transformer

RT-1（Robotics Transformer 1，arXiv:2212.06817）的野心写在摘要里：证明机器人领域也能复制「大数据 + 大模型 → 泛化」的公式。它的答案分两半：数据（第 1 节说的约 130k 轨迹、744 指令）和模型（一个为实时控制量身定做的 35M 参数 Transformer）。

3.1 架构：为 3 Hz 实时控制而设计

先解释一个硬约束：机器人是闭环控制（closed-loop control）的——模型每输出一步动作，机器人动一下，摄像头拍新画面，模型再根据新画面输出下一步，边看边做、错了能纠。人类演示动作的节奏约 2–4 秒一小步，论文据此推出模型至少要 3 Hz（每秒推理 3 次，即单次推理预算 <100 毫秒）才不拖后腿。这决定了 RT-1 不能像 GPT 那样堆参数，只能精打细算：

图 2-1｜RT-1 架构总览（依据论文 Figure 1a、Figure 3 与 Section 5.1 重绘）。三个组件各司其职：FiLM-EfficientNet 负责「带着指令去看图」，TokenLearner 负责「把看到的压缩成 8 个重点」，Transformer 负责「结合 6 帧历史决定动作」。

逐个组件拆开看（论文 Section 5.1）：

  • 指令编码：语言指令先经过 USE（Universal Sentence Encoder，谷歌的预训练句向量模型）变成一个 512 维句向量——注意 RT-1 不让 Transformer 自己读文字，而是借用一个现成句向量，省参数。
  • FiLM EfficientNet-B3：图像用 ImageNet 预训练的 EfficientNet-B3（一种轻量卷积网络）提特征，输出 9×9×512 的特征图，摊平成每帧 81 个视觉 token。关键设计是 FiLM 层（Feature-wise Linear Modulation，特征级线性调制）：把指令向量变成两组系数 \(\gamma, \beta\)，对图像特征做 \((1+\gamma)\cdot x + \beta\) 的逐通道缩放平移——相当于「带着问题看图」，任务相关区域被放大。FiLM 的两个 dense 层零初始化，训练开始时等于恒等映射，不破坏 EfficientNet 的预训练权重。图像 + 指令部分共 16M 参数。
  • TokenLearner：81 token × 6 帧 = 486 个 token，小 Transformer 也算不动（注意力开销随 token 数平方增长）。TokenLearner 是一个学出来的「软选择」模块，把每帧 81 个 token 压成 8 个信息量最大的 token，6 帧共 48 个——这是 3 Hz 实时的第一功臣（提速 2.4 倍）。
  • Transformer：decoder-only、8 层自注意力、19M 参数，对 48 个 token 做注意力后输出动作。全模型合计 35M 参数——不到 GPT-2 small 的 1/3。论文证明这个「小」是刻意的：受实时约束，模型大小不是越大越好（附录 D.4：砍到 21M 掉点，但推理时间从 129ms 的 Gato 级降到 15ms）。

3.2 动作 tokenization：本讲最重要的发明

现在到关键问题了：Transformer 天生只会做「从固定词表里选 token」的分类题，怎么让它输出连续的机械臂动作？RT-1 的答案简单粗暴：把连续动作离散化（discretize）。动作共 11 维（论文 Section 4 / 5.1）：

动作维度含义离散化方式
臂末端 x, y, z 位移（3 维）末端执行器（end-effector）——机械臂最前端装夹爪的那个点，第 1 讲讲过——在空间里平移多少米每个连续维在取值范围内均匀切 256 个 bin（格子），动作值落在哪个格子，就输出格子编号（0–255 的整数）
臂 roll, pitch, yaw 旋转（3 维）末端执行器绕三个轴各转多少（翻滚 / 俯仰 / 偏航）
夹爪开合（1 维）两指夹爪的张开程度
底座 x, y, yaw（3 维）移动底盘前进 / 平移 / 转向多少同上，256 bin
模式切换（1 维，本身离散）三选一：控制手臂 / 控制底座 / 终止任务（terminate）直接当分类维度

于是一个动作 = 11 个整数，每个 ∈ {0, …, 255}；模型输出 11 个 256 类的 softmax 分类，损失函数就是最普通的分类交叉熵（cross-entropy）（论文 Section 5.1 "Loss"）。用第 1 讲的行为克隆框架写出来，就是对演示轨迹最大化「专家动作 token」的对数似然：

\[ \mathcal{L}_{\text{BC}} \;=\; -\sum_{k=1}^{11} \log p_\theta\!\left(y_k \,\middle|\, i,\; \{x_j\}_{j=0}^{t}\right), \qquad y_k \in \{0,\dots,255\} \]

其中 \(y_k\) 是第 \(k\) 维动作的 bin 编号，\(i\) 是指令，\(\{x_j\}\) 是最近 6 帧图像。训练时带因果掩码；最终版推理时 11 维一次并行输出、不做自回归（论文 Table 13 消融：加自回归慢 2 倍以上且效果略降，所以砍掉了）。

图 2-2｜动作 tokenization 机制（依据论文 Section 5.1 "Action tokenization" 与开源代码 tokenizers/action_tokenizer.py 绘制）。数字例子按开源代码公式 int((a−min)/(max−min)×(vocab−1)) 实算。

为什么要多此一举地离散化，而不是让网络直接回归输出 11 个小数（MSE 损失）？论文用消融实验（Table 13）回答了：换成连续高斯输出后，seen tasks 从 97% 暴跌到 68%，抗干扰从 83% 跌到 37%。原因是人类演示是多峰的：绕开同一个障碍物，可以从左边绕也可以从右边绕，两种动作都对。高斯回归会把两个峰「平均」成中间的错误动作；而 256 类分类分布天生能表达「172 号和 30 号格子概率都高」这种多峰形状。离散化不只是工程妥协，它是表达能力的选择。这一点在第 4 讲会再次出现——扩散 / 流匹配路线用另一种方式（直接建模连续多峰分布）解决同一个问题。

3.3 代码对照：开源 RT-1 里的动作 tokenizer

RT-1 开源了推理代码（github.com/google-research/robotics_transformer，本节代码均出自 commit 4569641）。核心的动作 tokenizer 只有一百多行。先看文件头注释——它给出的动作规格恰好是 8 个 token（终止 1 + 平移 3 + 旋转 3 + 夹爪 1），比论文正文的 11 维少了底座 3 维和模式维，与 RT-2 论文里的 8 槽格式一致（开源版针对已发布 checkpoint 的纯操作任务）：

# tokenizers/action_tokenizer.py:16-22
# As an example, if an action is:
# terminate = [0, 1]
# world_vector = [0.9, 0.8, -0.3]
# rotation_delta = [-0.1, 0.2, .6]
# gripper_closedness = 0.9
# Then we build a sequence of tokens of length 8 [one for each dimension].

tokenize 的核心几行就是图 2-2 的「②③步」写成代码——先裁剪到合法范围，再归一化到 [0,1]，乘 (vocab−1) 截断取整：

# tokenizers/action_tokenizer.py:103-127（节选，省略若干断言）
def tokenize(self, action: tensorspec_utils.TensorSpecStruct) -> tf.Tensor:
    """Tokenizes an action."""
    action_tokens = []
    for k in self._action_order:
      a = action[k]  # a is [batch, actions_size]
      spec = self._action_spec[k]
      if spec.dtype == tf.int32:
        # Int32 actions are already assumed to be tokens ...
        token = tf.argmax(a, axis=-1, output_type=tf.int32)
        token = tf.expand_dims(token, axis=-1)
      else:
        a = tf.clip_by_value(a, spec.minimum, spec.maximum)
        # Normalize the action [batch, actions_size]
        token = (a - spec.minimum) / (spec.maximum - spec.minimum)
        # Bucket and discretize the action to vocab_size, [batch, actions_size]
        token = tf.cast(token * (self._vocab_size - 1), tf.int32)
      action_tokens.append(token)
    # Append all actions, [batch, all_actions_size]
    action_tokens = tf.concat(action_tokens, axis=-1)
    return action_tokens

反解（detokenize）是它的镜像运算——把 bin 编号还原成物理量，机器人拿到的就是这个浮点指令：

# tokenizers/action_tokenizer.py:147-156（节选，float 维度的还原分支）
else:
    actions = []
    for _ in range(action_dim):
      a = action_tokens[..., token_index:token_index + 1]
      a = tf.cast(a, tf.float32)
      a = a / (self._vocab_size - 1)
      a = (a * (spec.maximum - spec.minimum)) + spec.minimum
      actions.append(a)
      token_index += 1
    action[k] = tf.concat(actions, axis=-1)

损失函数在 transformer_network.py:117-119：就是普通的稀疏分类交叉熵，没有任何机器人专属的魔法——

# transformer_network.py:117-119
# define loss function
self._loss_object = tf.keras.losses.SparseCategoricalCrossentropy(
    from_logits=True, reduction=tf.keras.losses.Reduction.NONE)
划重点「动作 = token」在 RT-1 这里还只完成了一半：动作确实变成了离散 token、用交叉熵训练，但这些 token 活在一个机器人专属的小词表（每维 256 个 bin）里，和语言世界的词表毫无关系——模型不认识 "apple" 这个词的含义，只把它当第 42 号任务开关。RT-2 的革命是把另一半补上：让动作 token 直接住进 VLM 的词表。

3.4 训练数据与结果

数据侧的两个细节（论文 Section 5.2 与附录 C.2 / D.1）：

  • 不均衡靠采集端解决：有一个软件模块专门给操作员派发「下一条演示什么指令、场景怎么随机化」，从源头保证各指令的数据量均衡；评测指标也按技能加权平均，避免数据多的大技能淹没小技能。
  • 异构数据 co-training：混入仿真数据后，只在仿真里出现过的物体在真实世界的成功率从 23% 涨到 87%（+64 个百分点），原任务几乎不掉（−2）；混入另一种机器人（Kuka 机械臂，QT-Opt 强化学习采的 209k 抓取数据）后，跨本体评测从 22% 涨到 39%（Table 4 / Table 5）。这是「数据金字塔」（第 1 讲）思想最早的实证之一。

主结果（论文 Table 2，全部真机评测，共 3000+ 次试验）：

模型见过的任务没见过的指令组合抗干扰物抗新背景

表 2-1｜RT-1 vs 基线（论文 Table 2）。所有模型用同一份 130k 数据训练，只比架构。「没见过的指令」指 held-out 的 53 条新组合——比如训练里有「拿苹果」「放到台面上」，但没见过把两者连起来的说法。

另一个影响深远的消融（论文 Table 7）：把数据量砍掉 49%（但保留全部 744 种任务）对泛化的伤害，与把任务种类砍掉 25%（保留 97% 数据量）大致相当——数据多样性比数据量更重要。这句话后来成了机器人数据工程的口头禅。

3.5 RT-1 的局限：它不认识「恐龙」

  • 纯视觉运动模型，没有语言/常识。USE 句编码器只把指令压成一个向量当「任务开关」，模型并不真正理解词义——指令超出训练分布的词汇（比如「把灭绝动物拿给我」）就完全无能为力。论文自己承认：对新指令的泛化仅限于「见过概念的新组合」。
  • 专用架构，吃不到大模型红利。EfficientNet + TokenLearner + 小 Transformer 是为 3 Hz 定制的；NLP/CV 社区把模型越做越大，RT-1 无法直接受益。
  • 模仿学习天花板 + 闭源数据。行为克隆学不过演示者（第 1 讲的老问题）；代码开源了，13 万条真机数据不开源，外界无法复现。

这三条局限里，前两条正是 RT-2 的靶子。

4. RT-2 精读：把动作「写成」VLM 会说的一句话

4.1 核心思想：不再造机器人模型，而是「续训」一个 VLM

RT-2（arXiv:2307.15818）的出发点，用论文自己的话说：与其从零设计视觉-语言-动作架构（Gato 路线），或给 VLM 外挂一个动作头（CLIPort / MOO 路线），不如直接拿现成的、已经在互联网数据上烧过海量算力的 VLM 继续训练，不加任何新参数，让它学会把动作当文本说出来。论文选了两个主干：

  • RT-2-PaLI-X：PaLI-X 5B / 55B（ViT-22B 视觉编码器 + UL2 风格 encoder-decoder 文本骨干）；
  • RT-2-PaLM-E：PaLM-E 12B（ViT-4B + PaLM 8B，decoder-only，即上一节那位「跳板」的缩小版）。

机器人数据就是 RT-1 那批约 130k 演示。训练目标没有任何新东西——next token prediction（下一个 token 预测），论文附录 E 明说：这在机器人学习里就等于行为克隆损失。也就是说：训一个 VLA = 第 1 讲的行为克隆 + LLM 界最普通的自回归微调，唯一的发明在「动作怎么表示」。

4.2 动作如何变成文本 token：三步走

第一步：沿用 RT-1 的离散化。RT-2 的动作空间是末端执行器 6-DoF 位移（Δx, Δy, Δz, Δroll, Δpitch, Δyaw）+ 夹爪开合，共 7 个连续维，每维均匀切 256 个 bin；再加 1 个离散的终止命令。一个动作 = 8 个整数，按固定槽位排成一行「句子」（论文 Section 3.2）：

"terminate Δpos_x Δpos_y Δpos_z Δrot_x Δrot_y Δrot_z gripper_extension"
真实输出样例："1 128 124 136 121 158 111 255"（论文 Section 4.4）

（细心读原文会发现：Section 3.2 给的示例 "1 128 91 241 5 101 127" 只写了 7 个数，与它自己定义的 8 槽格式差一个；而 Figure 7 与 Section 4.4 的所有样例都是 8 个数。以 8 槽为准，前者当排版疏漏看待即可。）

第二步：给 256 个 bin 在 VLM 词表里找「座位」。这是 RT-2 最巧的一步，两个主干用了两种办法（论文 Section 3.2）：

图 2-3｜动作 token 与 VLM 词表的映射（依据论文 Section 3.2 绘制）。两种做法殊途同归：给 256 个 bin 在既有词表里找到 256 个「座位」，一个参数都不用加。

选「最少使用的 token」的动机——尽量不与高频语言 token 抢座位、把对原有语言能力的破坏降到最低——论文只陈述了做法并引用 symbol tuning 先例，没有展开论证动机；这个因果解释是我基于上下文的推断。

第三步：把机器人数据改写成 VQA 问答格式。每条轨迹的每一步都变成一个「问答对」：输入是相机图像 + 文本 "Q: What action should the robot take to {指令}? A:"（VQA = Visual Question Answering，视觉问答，VLM 最常见的训练格式），输出就是那行数字「句子」。对模型来说，它和普通的图文问答数据没有任何区别。

推理时加一道保险：约束解码。机器人可不能让模型回答「今天天气不错」——RT-2 在动作任务下把采样范围限制在合法动作 token 内（论文 Section 3.2 "Output Constraint"），保证吐出的每个 token 都能反解成电机指令；在普通 VQA 任务下仍允许输出全部词表。反解（de-tokenize）之后就是第 1 讲说的 delta EE 指令，机器人闭环执行。整条流水线：

4.3 co-fine-tuning：为什么必须「掺着」网络数据一起训

如果只拿 130k 机器人数据去微调 55B 的 VLM，会发生 LLM 界的老毛病——灾难性遗忘（catastrophic forgetting）：新数据分布太窄，模型把预训练学到的语义知识「冲掉」，退化成一个昂贵的 RT-1。RT-2 的对策是 co-fine-tuning（共同微调）：每个训练 batch 里同时掺入原始的网络图文/VQA 数据和机器人动作数据（论文 Section 3.2；配比见附录 B：PaLI-X 版机器人数据约 50%，PaLM-E 版约 66%，通过调高机器人数据的采样权重来实现批内平衡）。

消融实验（论文 Table 6，指标是未见物体/背景/环境三类泛化场景的平均成功率）直接量化了每一味药的效果：

模型训练方式unseen 泛化平均
RT-2-PaLI-X 5B从零训练（不用 VLM 预训练权重）9%
RT-2-PaLI-X 5B只用机器人数据微调42%

把 co-fine-tuning 类比成 LLM 持续预训练里的 replay（回放旧数据防遗忘）是我的教学类比——论文给出的机制解释就是「保留原数据让模型不忘记 VLM 阶段学到的概念」，与 replay 思想同源，但论文没有使用这个术语。

4.4 结果与涌现能力：机器人第一次「懂」了词义

常规泛化（论文 Table 4，约 6000 次真机评测）：seen tasks 上 RT-2（PaLI-X-55B 91% / PaLM-E-12B 93%）与 RT-1（92%）打平——说明换成 VLM 主干没牺牲基本功；但在未见物体/背景/环境三类泛化场景上，RT-2 两个版本平均都是 62%，约为 RT-1（32%）和 MOO（35%）的 2 倍，约为 VC-1 / R3M 等预训练视觉表征基线（10% / 12%）的 6 倍。

涌现能力（emergent capabilities）才是 RT-2 的真正卖点：下面这些指令在机器人数据里一次都没出现过，能力完全来自互联网图文预训练的迁移。论文把它们分成三类做定量评测（Table 3、Table 5）：

值得注意的对照：RT-1 面对这些指令不是「差一点」，而是根本听不懂——它的 USE 编码器把 "Taylor Swift" 压成一个向量，但 35M 的视觉运动模型里不存在「Taylor Swift 长什么样」的知识。RT-2 能行，是因为这份知识本来就躺在 55B 权重里，动作 tokenization 只是给它开了一条「表达出口」。这也回答了为什么 RT-2 是「VLA 的诞生」：V-L-A 三个字母第一次真正共享同一套权重。

4.5 chain-of-thought 变体：先打草稿，再动手

LLM 的思维链（chain-of-thought：先输出中间推理再给答案）也被搬了过来。RT-2 把 PaLM-E 版本额外微调几百步，让它在动作 token 之前先输出一段自然语言「Plan」。论文 Section 4.4 与 Figure 7 / Figure 10 的真实样例：

Instruction: I'm hungry.
Plan: pick rxbar chocolate.  Action: 1 128 124 136 121 158 111 255   （论文 Section 4.4）

Prompt: I need to hammer a nail, what object from the scene might be useful?
Prediction: Rocks.  Action: 1 129 138 122 132 135 106 127            （论文 Figure 7）

Instruction: I am sleepy, bring me a drink to help.
Plan: Pick redbull can.                                              （论文 Figure 10）

「饿了 → 拿巧克力棒」「要钉钉子 → 选石头当锤子」「困了 → 拿红牛」——中间那步语言推理把 VQA 数据和操作数据在同一个输出序列里桥接了起来。这是后来所有「VLA + 推理」工作（第 5 讲会再见到）的雏形。论文的态度也很克制：这是「有希望的初步证据」，不是成熟能力。

4.6 代价与局限

  • 推理太慢、太贵。55B 模型机器人本体装不下，只能部署在云端 TPU 集群、机器人走网络查询，控制频率 1–3 Hz（5B 版约 5 Hz）——比 RT-1 的 3 Hz 本地推理更脆弱（网络一断机器人就停），也远低于灵巧操作所需的几十 Hz。论文自称这是当时「用于闭环控制的最大模型」（比此前记录大一个数量级以上）。
  • 语义泛化 ≠ 动作泛化。互联网知识只教会模型「对什么做、何时做」，不会教「怎么动」：论文 Section 5 明确说 RT-2 学不会任何新动作，技能仍限于机器人数据的分布（附录 G 的失败案例：按特定部位抓取、用毛巾擦、叠衣服、工具使用，全部不行）。
  • 离散 bin 精度有限。256 格意味着每维动作分辨率固定，精细操作（论文原话 "dexterous or precise motions"）做不了；自回归逐 token 输出 8 个数字也拖慢频率。
  • 闭源、单本体。模型、数据、训练代码都不开放，外界无法复现；训练数据几乎全部来自同一种 Everyday Robots 机器人。论文自己都在 Limitations 里呼吁「希望更多开源 VLM 出现」——这句话直接预告了第 3 讲的 OpenVLA。
「离散自回归 token 的精度与频率局限，是后来扩散 / 流匹配连续动作头（第 4 讲 π0 路线）取而代之的直接动因」——这是我基于后续文献的因果归纳；RT-2 论文只把量化、蒸馏、更高频控制列为未来方向，没有点名扩散模型。

5. RT-X / Open X-Embodiment：把「数据引擎」开放给全世界

RT-2 的闭源单本体局限，由 2023 年 10 月的 Open X-Embodiment（OXE，arXiv:2310.08864）部分补上——第 1 讲介绍过这份「数据金字塔」底座，这里只讲它与 RT 配方结合后的实验结论。全球几十家机构（论文摘要口径：21 家机构；正文口径：34 个实验室贡献的 60 个数据集）把各自的机器人数据统一成 RLDS 格式，汇成 100 万+ 真机轨迹、22 种机器人本体、527 种技能、160,266 个任务。

在这份混合数据上重训 RT-1 和 RT-2 的配方，得到 RT-1-X 与 RT-2-X，回答一个关键问题：别的机器人的数据对我有用吗？答案是有用，而且不小（论文 Figure 4、Table I 与结论节）：

  • RT-1-X 在评测机器人上的平均成功率，比各机构原本为自己机器人调的最优方法高 50%——纯靠 co-training 别人本体的数据；
  • RT-2-X（55B）相比只用评测本体自己数据训练的模型，泛化性能约 3 倍提升；在 Stanford Bridge 数据评测上 RT-2-X 达 50%，而原方法 LCBC 只有 13%、单数据 RT-1 为 40%（论文 Table I）。

这就是「跨本体正迁移（positive transfer）」的第一份大规模证据，也宣告了 RT-1 消融里「多样性 > 数据量」的规律在更大尺度上成立。这份开放数据后来直接成为 OpenVLA（第 3 讲）和 π0（第 4 讲）的预训练底座——RT 系列闭源，但数据开源了，火种就这样传了下去。

6. 插曲：RT-H——在任务和动作之间再插一层「语言」

Google 系 2024 年的 RT-H（arXiv:2403.01823）继续琢磨「语言 ↔ 动作」的接口：在高层任务（"close the pistachio jar"）和低层动作 token 之间，插入一层语言动作（language motions）——细粒度运动短语，如 "move arm forward"、"rotate arm right"、"close gripper"。模型先预测语言动作，再以它为条件预测动作 token。好处有两个：① 语义迥异的任务（"pick coke can" 和 "pour cup"）在语言动作层共享结构，多任务数据更好复用（论文用约 100K 演示验证：RT-1/RT-2 同款厨房数据 70K + 更多样任务 30K）；② 人类可以在执行中途用语言动作纠正机器人（喊一句 "move arm backward"），模型还能从这些语言纠正中继续学习——论文报告比遥操作纠正类的交互式模仿学习基线（IWR）高 50%。RT-H 说明「把更多东西写成语言」这条路 Google 一直在深耕，也预示了第 5 讲会看到的分层 VLA 思路。

7. 影响与线索：RT 系列之后发生了什么

  • 「VLA」一词由此确立。RT-2 论文正式提出 "vision-language-action models (VLA)" 这个类别名（Section 1 原话 "We refer to such category of models as vision-language-action models"），此后所有「VLM 主干 + 动作输出」的模型都归入此类——本系列的名字就是这么来的（见第 0 讲全景地图）。
  • 范式被开源化。RT-2 闭源，2024 年 6 月的 OpenVLA 用全开源件复刻了同一配方：7B 参数（Llama-2 主干 + 融合视觉编码器）、OXE 97 万条轨迹训练、动作离散 token 输出——第 3 讲的主角，也是你第一个能亲手跑起来的 VLA。
  • 离散 token 的局限被新路线接管。1–3 Hz、bin 精度、自回归慢——这些痛点催生了扩散 / 流匹配的连续动作头路线，代表作 π0（可达 50 Hz 控制）——第 4 讲展开数学。
  • 人马出走，创立 Physical Intelligence。RT 系列的核心作者（Sergey Levine、Chelsea Finn、Karol Hausman、Brian Ichter 等）2024 年创立机器人基础模型公司 Physical Intelligence（π 公司），π0 即出自该团队——第 5 讲的前沿全景会从这条线讲起。

9. 本讲要点与自查

三个钥匙概念读懂后面所有 VLA 论文，只需要记住本讲这三个词的一句话定义：
① 动作 tokenization：把连续动作的每一维均匀切成 256 个 bin，动作变成整数序列，机器人控制从此变成「从词表选 token」的分类题，用交叉熵训练（RT-1 发明，RT-2 沿用并写进 VLM 词表）。
② co-fine-tuning：微调 VLM 输出动作时，把机器人数据和原始互联网图文数据混在同一批 batch 里训练，防止灾难性遗忘、保住语义能力（RT-2 的关键配方）。
③ 涌现泛化：机器人数据里从未出现的语义能力（认符号、做算术、认名人）因互联网知识迁移而「凭空出现」——VLA 区别于普通机器人策略的本质卖点。

下面 8 个问题都能答上来，本讲就过关了：

  1. RT-1 的训练数据规模和采集方式？（答：13 台 Everyday Robots 机器人车队、17 个月遥操作采集、约 130k episodes、744 条指令）
  2. 动作 tokenization 具体怎么做？为什么离散化反而比连续回归好？（答：每维均匀 256 bin → 编号当分类标签 → 交叉熵；分类分布能表达多峰动作，高斯回归会把多峰平均成错误动作——消融显示 seen 97%→68%）
  3. RT-1 靠什么做到 3 Hz 实时？（答：35M 小模型 + TokenLearner 把每帧 81 token 压到 8 + 图像 token 跨步缓存；单次推理 <100 ms）
  4. RT-2 与 RT-1 的本质区别一句话？（答：RT-1 的动作 token 住在机器人专属小词表里；RT-2 把动作写成 VLM 既有词表里的文本 token，零新增参数继承互联网知识）
  5. PaLI-X 和 PaLM-E 各怎么给动作 token 找座位？（答：PaLI-X 直接用词表里现成的数字 token；PaLM-E 覆写 256 个最少使用的 token，即 symbol tuning）
  6. co-fine-tuning 是什么、解决什么问题？（答：机器人数据与原始网络图文数据混合训练同一套权重，防灾难性遗忘；消融显示 55B 上比纯机器人数据微调高 11 个百分点）
  7. 举两个 RT-2 的涌现能力例子。（答：如 "move coke can near 3" 认数字卡片、"move banana near the sum of two plus one" 先算 2+1 再找「3」、"move coke can to Taylor Swift" 认名人——都不在机器人数据里）
  8. RT-2 为什么控制频率只有 1–3 Hz？这暴露了离散自回归路线的什么问题？（答：55B 模型只能云端 TPU 推理 + 网络往返 + 逐 token 自回归输出；精度受 bin 数限制、频率受解码步数限制——第 4 讲的扩散 / 流匹配路线由此接棒）
下一篇第 3 讲：OpenVLA——把 RT-2 配方开源给你。RT-2 证明了「VLM 主干 + 动作 token」的威力，但一切都锁在 Google 的 TPU 集群里。OpenVLA（2024.6，arXiv:2406.09246）用 Llama-2 + 开源视觉编码器 + OXE 97 万条轨迹复刻了这个配方，7B 参数、权重全公开、一张消费级显卡就能微调。第 3 讲我们会把它的动作 token 设计（256 bin 塞进 Llama 词表的最低频 token——和 RT-2-PaLM-E 如出一辙）逐行拆开，并教你怎么跑起来。
