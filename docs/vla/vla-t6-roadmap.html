不需要买机器人也能入门具身智能。Hugging Face 的 LeRobot 加上 LIBERO 等仿真基准，让你在一块消费级 GPU（甚至 Colab/按秒租卡）上跑通「采数据 → 训策略 → 评测成功率」的完整闭环：训一个 ACT 策略最快只要半小时，微调 π0.5 级别的 VLA 用 LoRA 一张 RTX 4090 也放得下。本讲给出：三档投入的实践路线、一张 2026 年软件栈地图、四个由浅入深的动手项目（零硬件可做前三个）、一份微调工程排查清单、核实过链接的学习资源，以及从「跑 demo」到「做研究」的四阶段成长路线图。

2.1 为什么第一个工具是 LeRobot

LeRobot 值得单独展开，因为它同时解决新手最头疼的三件事：

  • 数据格式碎片化：机器人数据有 RLDS、HDF5、rosbag 等一堆格式。LeRobotDataset（现行为 v3.0）统一为「同步的 MP4 视频 + Parquet 状态/动作 + 元信息」，托管在 HF Hub 上可搜索、可流式加载、可在线可视化；Hub 上已有数千个社区数据集，lerobot/pusht（2D 推方块）就是给新手的第一份教材数据。
  • 训练脚本碎片化：一条 lerobot-train 命令切换任意策略（--policy.type=act / diffusion / smolvla / pi0 / pi05 / groot ...），配置自动适配你数据里的相机数与动作维度；一条 lerobot-eval 在 LIBERO / MetaWorld 等标准环境评测；lerobot-record / replay / rollout 覆盖真机采集、回放与部署。没有 GPU 也能玩：--job.target=a10g-small 直接把训练提交到 HF 的按秒计费 GPU。
  • 硬件遥不可及：SO-100/SO-101 是官方设计的 3D 打印总线舵机臂，从买件、打印、装机、设电机 ID、标定到遥操作，文档一步步带做（SO-101 指南）；中文用户还有同济子豪兄的 SO-ARM101 中文教程（LeRobot 官方 README 推荐）。另有浏览器操作界面 LeLab 与免费的 Robot Learning Tutorial 交互课程。

2025–2026 的关键更新（官方 README / 文档核实）：数据集格式升到 v3.0；策略库大幅扩容——除 ACT/Diffusion 外，新增 π0/π0-FAST/π0.5、SmolVLA（450M 小 VLA，arXiv:2506.01844）、GR00T N1.7、HIL-SERL（人在环强化学习）乃至世界模型类策略（VLA-JEPA、FastWAM 等）；评测侧原生接入 LIBERO 与 MetaWorld；训练可一键提交 HF Jobs；发布 ICLR 2026 库论文。可以说它已经从「小玩具库」长成了开源具身智能的事实标准入口。

2.2 其余工具一句话定位

  • openpi：想微调 π0/π0.5 本体（而不是 LeRobot 里的移植版）就用它——JAX 血统、官方 checkpoint 全、LIBERO 示例最完整；π0.5-LIBERO 微调 checkpoint 官方称达到该基准 SOTA。
  • OpenVLA(-OFT)：学术界最常引用的 7B 开源 VLA 基线，LoRA 微调脚本是理解「VLM → VLA 微调」的最佳教材（第 3 讲详解）。
  • Isaac GR00T：做人形/跨本体、要 TensorRT 部署、要用 Isaac Lab 仿真与 GR00T-Mimic/GR00T-Dreams 数据生成管线时的主栈。
  • AgiBot GO-1、RDT：双臂与百万级数据方向的参考实现，读论文价值大于上手价值（个人算力难全量复现）。
  • ManiSkill3 / Genesis World：要 GPU 并行采样（RL 后训练、大规模数据生成）选 ManiSkill3；要多物理场与跨平台渲染选 Genesis。

3.2 评测基准

基准论文内容与地位（核实 2026-10）
LIBERO arXiv:2306.03310（NeurIPS 2023 D&B） VLA 圈事实标准：130 个语言条件桌面任务，分 5 个套件——LIBERO-Spatial / Object / Goal / Long（各 10 任务）+ LIBERO-90；VLA 论文惯用前 4 个十任务套件报数（共 40 任务、400 episode 协议）。OpenVLA（均值 76.5%）、π0.5（openpi 报 96.85%、LeRobot 复现 97.5%）、GR00T N1.7 都在其上评测；MuJoCo/robosuite 底座，LeRobot 与 openpi 均原生支持
SimplerEnv arXiv:2405.05941 real2sim 评测：把 Google Robot 与 WidowX（Bridge）的真实场景重建进仿真，验证了仿真成功率与真机成功率的排序相关性，可低成本评 RT-1/RT-1-X/Octo/OpenVLA 等真机策略；基于 ManiSkill3 的 GPU 并行分支比 CPU 版快 10–15×；GR00T N1.7 也报 SimplerEnv 结果
CALVIN arXiv:2112.03227 语言条件长时程基准：34 个任务，指标是「一条指令链连续完成几个子任务」（ABC→D 划分测跨环境泛化）；语言跟随与长程组合能力的经典考场
Meta-World arXiv:1910.10897 50 个桌面操作任务的多任务/元强化学习基准（MT10/MT50 等划分）；状态输入为主、轻量快速，LeRobot 评测已支持 MetaWorld
警示：基准成功率 ≠ 真机能力读 VLA 论文的排行榜数字时，记住四件事。① 协议差异巨大：同样叫「LIBERO 成功率」，有人 3 seeds × 500 rollouts（OpenVLA 论文口径），有人单 seed × 每任务 10 次；初始状态用不用固定文件、软重置还是硬重置，都能差出几个点（LeRobot 官方文档明确提醒软/硬重置结果不比特）。② cherry-pick 空间大：只报最强的套件、只报最好 seed、场景与光照挑过——都常见。③ 仿真-真机鸿沟：LIBERO 分数再高也不保证真机能用，SimplerEnv 这类 real2sim 基准存在的意义就是量化这条鸿沟。④ 基准会饱和：π0.5 一代已把 LIBERO 四个套件推到 96%+，区分度快速消失，前沿工作正转向 RoboCasa365、真机评测等更难的口径。
实用辨别法：看论文附录的评测协议——每任务 rollout 数 ≥10、seed ≥3、报 mean±std、写明初始状态来源与重置方式，才算严谨；若只报单一大数字且比 SOTA 恰好高 1–2 个点，先怀疑协议再怀疑模型。

4. 四个动手项目（由浅入深）

四个项目共享同一条主线：数据 → 策略 → 评测。项目 1–3 零硬件可做，项目 4 需要档 1 硬件。每个项目给出目标、前置、步骤、预期结果与常见坑。

项目 1：LeRobot 跑通 ACT / Diffusion Policy（零硬件，第一晚）

难度 ★时间 半天–2 天显存 2–14GB

  • 目标：用官方示例数据集在单卡上完成「下载数据 → 训练 → 看成功率」，建立对模仿学习全流程的手感。
  • 前置：Python 3.10+；任一 NVIDIA GPU（ACT 峰值约 2–6GB @BS8，Diffusion 约 8–14GB，官方硬件指南数字）；没有 GPU 用 Colab 的 ACT notebook 或 --job.target=t4-small 提交 HF Jobs；Mac（Apple Silicon MPS）也能训 ACT，只是慢（官方估计 ~6–14h）。
# 1) 安装并自检
pip install lerobot
lerobot-info

# 2) 训练 ACT：PushT 是 2D「推方块到目标区」示例任务
lerobot-train \
  --policy.type=act \
  --dataset.repo_id=lerobot/pusht \
  --policy.device=cuda \
  --output_dir=outputs/train/act_pusht \
  --job_name=act_pusht \
  --wandb.enable=true          # 可选：wandb login 后看训练曲线

# 3) 评测：在 PushT 仿真环境里跑 N 个 episode 统计成功率
lerobot-eval \
  --policy.path=outputs/train/act_pusht/checkpoints/last/pretrained_model \
  --env.type=pusht \
  --eval.n_episodes=50
  • 预期结果：4090 上 ACT 训练几十分钟量级收敛（官方指南：50 episode 数据集约 30–60 分钟）；评测成功率应明显高于随机策略且随训练步数上升。想加码就换 --policy.type=diffusion（第 4 讲原理）或用社区 SO-101 数据集（如 lerobot/svla_so101_pickplace）训 SmolVLA（~10–16GB）。
  • 常见坑：① 视频解码后端缺失——LeRobotDataset v3 用 MP4 存图像，需 torchcodec 或 pyav；② 成功率长期为 0——先确认 --policy.device 与数据 fps 没配错，再缩短 LR decay（官方指南：短训要同步缩短 scheduler_decay_steps，否则学习率一直停在峰值）；③ Windows 原生支持有限，建议 WSL2/Linux。

步骤概要（两条路线，二选一或都跑）：

# 路线 A：LeRobot 原生（新手推荐，环境最省事）
pip install -e ".[libero]"            # 在 lerobot 仓库内安装 LIBERO 额外依赖
export MUJOCO_GL=egl

# A1) 先评官方复现的 π0.5 baseline（需 ~24-40GB；显存不够跳到 A2）
lerobot-eval \
  --policy.path=lerobot/pi05_libero_finetuned \
  --env.type=libero \
  --env.task=libero_spatial,libero_object,libero_goal,libero_10 \
  --eval.n_episodes=10 --eval.batch_size=1

# A2) 24GB 卡方案：自己训 SmolVLA（数据仅 1.9GB，lerobot/libero）
lerobot-train --policy.type=smolvla --policy.load_vlm_weights=true \
  --dataset.repo_id=lerobot/libero --dataset.video_backend=torchcodec \
  --output_dir=./outputs/libero_smolvla --steps=100000 --batch_size=64   # 卡小就减 batch/steps

# 路线 B：OpenVLA-OFT 官方 repo
git clone https://github.com/moojink/openvla-oft && cd openvla-oft
# 按其 LIBERO.md：下载 openvla/modified_libero_rlds（~10GB）→
# 评测预训练 checkpoint moojink/openvla-7b-oft-finetuned-libero-spatial
#   （unnorm_key=libero_spatial_no_noops，~16GB）→ LoRA 微调单套件 → 对比成功率
  • 预期结果：路线 B 应能对上论文口径——OpenVLA 微调后 LIBERO 四套件均值 76.5%（3 seeds × 500 rollouts），OFT 更高且推理快 25–50×；路线 A 的 π0.5 复现均值 97.5%（LeRobot 文档数字，与 openpi 官方 96.85% 一致量级）。个人单卡请缩水协议（每任务 10 episode、1–3 seed），只看相对提升。
  • 常见坑：① robosuite/mujoco 版本地狱——严格按 repo 的 conda/pip 步骤，别混装；② unnorm_key 或 --env.control_mode（relative/absolute）与 checkpoint 不匹配 → 动作尺度错乱、机械臂乱飞；③ LIBERO-Long 成功率天然最低（长时程），别慌；④ 报结果时 pin 数据版本（--dataset.revision），Hub 数据集可能被重传；⑤ 复现榜单数字必须用硬重置（官方文档明示软重置结果会漂移）。

项目 3：openpi 复现 π0.5 微调（零硬件，一到两周）

难度 ★★★★时间 1–2 周显存 LoRA >22.5GB / 全量 >70GB

  • 目标：用 Physical Intelligence 官方栈微调 π0.5，走一遍工业级 VLA 微调的完整管线：数据转换 → 归一化统计 → 训练 → policy server → 仿真评测。呼应第 4 讲的 π0 原理。
  • 前置：Ubuntu 22.04（官方只测了这个）、uv、一张 4090（LoRA）或 A100/H100（全量）；磁盘余量充足（base checkpoint 数十 GB）。
# 1) 安装（注意子模块与 GIT_LFS_SKIP_SMUDGE）
git clone --recurse-submodules https://github.com/Physical-Intelligence/openpi.git
cd openpi && GIT_LFS_SKIP_SMUDGE=1 uv sync && GIT_LFS_SKIP_SMUDGE=1 uv pip install -e .

# 2) 归一化统计量——训练前必须算（LIBERO 配置指向预转换好的数据集，跳过数据转换）
uv run scripts/compute_norm_stats.py --config-name pi05_libero

# 3) 微调（JAX；LoRA 或全量由 config 决定；多卡用 --fsdp-devices）
XLA_PYTHON_CLIENT_MEM_FRACTION=0.9 \
  uv run scripts/train.py pi05_libero --exp-name=my_experiment --overwrite

# 4) 起 policy server，再按 examples/libero/README 的 Docker 工作流跑评测
uv run scripts/serve_policy.py policy:checkpoint \
  --policy.config=pi05_libero \
  --policy.dir=checkpoints/pi05_libero/my_experiment/20000

# 无机器人/无仿真时验证推理链路：examples/simple_client（随机观测打通 server）

换成自己的数据：以 examples/libero/convert_libero_data_to_lerobot.py 为模板把数据转成 LeRobotDataset；在 src/openpi/policies/ 定义你的输入/输出变换（观测键名、动作维度映射），在 training/config.py 添加 DataConfig 与 TrainConfig；重算 norm stats。若你的机器人本体在 π0 预训练混合里，可按 docs/norm_stats.md 复用预训练的归一化统计。

  • 预期结果：跑通后即可对比官方 π0.5-LIBERO 数字（openpi README 称 SOTA，LeRobot 侧复现均值 97.5%）；用自己数据微调时，成功判据回到项目 4 的数据质量清单。
  • 常见坑（多数来自官方 troubleshooting 表）：① 忘跑 compute_norm_stats → 直接报 missing norm stats；② loss 发散 → 检查 norm_stats.json 的 q01/q99/std：很少用到的维度区间过窄，归一化后数值爆炸，可手工修正；③ OOM → 设 XLA_PYTHON_CLIENT_MEM_FRACTION=0.9、加 --fsdp-devices、关 EMA；④ PyTorch 路线（train_pytorch.py）暂不支持 LoRA/混合精度/FSDP，想用 LoRA 请走 JAX；⑤ checkpoint 从 gs://openpi-assets 自动下载，缓存位置可用 OPENPI_DATA_HOME 改。

项目 4（可选，需硬件）：自采数据训练自己的 VLA

难度 ★★★★★时间 2–4 周预算 数百美元

  • 目标：完成真正的具身智能闭环——自己采 50–100 条演示，训练/微调策略，在你的桌面上让机器人自主完成任务。
  • 前置：SO-101 从臂 + 主臂（或整套零售套件）、2 个 USB 相机（一个看场景、一个装腕部）、能跑项目 1 的电脑；替代方案：无臂用 UMI 式手持夹爪 + GoPro 在野外采数据（arXiv:2402.10329）。

步骤概要（全部命令来自 LeRobot 官方文档）：

# 1) 组装 + 电机配置 + 标定（按 SO-101 文档：找端口→设电机ID→标定）
pip install "lerobot[feetech]"
lerobot-find-port
lerobot-setup-motors --robot.type=so101_follower --robot.port=/dev/ttyACM0
lerobot-calibrate   --robot.type=so101_follower --robot.port=/dev/ttyACM0 \
                    --robot.id=my_arm        # 主臂同理；id 之后必须全程一致

# 2) 遥操作练手（先不录数据，练到动作平滑）
lerobot-teleoperate --robot.type=so101_follower --robot.port=/dev/ttyACM0 \
  --robot.id=my_arm --teleop.type=so101_leader --teleop.port=/dev/ttyACM1 \
  --teleop.id=my_leader --display_data=true

# 3) 采集 50 条演示并上传 Hub（键盘 r 键可当场重录坏 episode）
lerobot-record \
  --robot.type=so101_follower --robot.port=/dev/ttyACM0 --robot.id=my_arm \
  --robot.cameras='{front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}}' \
  --teleop.type=so101_leader --teleop.port=/dev/ttyACM1 --teleop.id=my_leader \
  --dataset.repo_id=${HF_USER}/my_pick_place --dataset.num_episodes=50 \
  --dataset.single_task="Put the cube into the box"

# 4) 训练（ACT 起步；数据够多、卡够大可上 smolvla / pi0）
lerobot-train --policy.type=act --dataset.repo_id=${HF_USER}/my_pick_place \
  --output_dir=outputs/train/act_my_task --policy.device=cuda

# 5) 部署回真机评测（慢速 VLA 加 --inference.type=rtc 平滑执行）
lerobot-rollout --strategy.type=base --policy.path=${HF_USER}/my_policy \
  --robot.type=so101_follower --robot.port=/dev/ttyACM0 --robot.id=my_arm \
  --task="Put the cube into the box" --duration=60

数据质量清单（官方「Tips for gathering data」+ 通行实践）：

  • ☐ 相机固定死：位置、角度、曝光全程不动；「只看相机画面你自己能完成任务」是官方给的合格线；
  • ☐ 帧率一致：采集、训练、部署用同一 fps（SO-101 惯用 30fps）；
  • ☐ 动作平滑：先遥操作练熟再开录，抖动/犹豫的 episode 当场按 r 重录；
  • ☐ 数量与覆盖：≥50 条起步；官方建议每类物体位置 10 条、位置铺满工作空间；变化逐步加（先位置→再光照→再物体→再背景），一次只加一种；
  • ☐ 指令标注多样：同一任务准备多种说法（训 VLA 时用英文指令并做同义改写，π0.5/OpenVLA-OFT 都用语言增广提升泛化）；
  • ☐ 成功判据明确：「方块进盒」这种可二值判定的任务最容易起步；模糊任务先拆短；
  • ☐ 失败数据取舍：纯模仿学习（ACT/DP/π0 微调）以成功演示为主，明显失败的 episode 建议删除或重录；失败轨迹另有价值——留给 RL 后训练（HIL-SERL 的 dagger 策略）或做恢复动作数据，但别混进 BC 数据集。
  • 预期结果：50–100 条高质量演示 + ACT，在「抓取-放置」级任务上真机成功率可观（社区大量 SO-101 案例；HF 官方的叠 T 恤实验证明该生态上限很高）；换成微调 SmolVLA/π0 可检验语言泛化。
  • 常见坑：① 标定文件的 id 在遥操作/录制/部署间不一致 → 动作错位；② Linux 串口权限（sudo chmod 666 /dev/ttyACM*）；③ Waveshare 控制板跳线要拨到 B（USB）通道；④ 换过任何电机必须重新 lerobot-setup-motors + 标定；⑤ 部署时训练用腕部相机而现场没装（或反之）——观测键必须与数据集完全一致。

5. 微调工程要点清单

四个项目跑下来，你会反复遇到同一批工程问题。这份清单把它们收拢——每一条都对应过某家官方文档的 troubleshooting。

  • 动作空间选择：delta EE（末端增量，OpenVLA/SimplerEnv 的 7 维 = 6D 位姿增量 + 夹爪）对相机-机器人标定误差更鲁棒、跨场景泛化好；关节绝对位置（ACT 在 SO-101 上的默认）简单直接、适合固定平台。铁律：采集、训练、部署三处定义必须一致。趋势参考：GR00T N1.7 全面转向「相对 EEF」动作空间，正是为了跨本体（人类视频与不同机器人）共享同一动作定义。
  • 归一化统计量：均值/方差或分位数（openpi 用 q01/q99）二选一后训练与推理必须用同一份；换数据集要重算（compute_norm_stats）；小心几乎不动的维度导致区间过窄、归一化爆炸（openpi 官方 troubleshooting 原话级坑）。
  • 图像预处理一致性：分辨率、resize/crop 方式、RGB 通道序、多相机的键名与顺序，训练与推理逐项对齐；LIBERO 在 LeRobot 中强制 observation.images.* 命名约定，键名编码在归一化层里，改名即错位。
  • 指令增广：同一演示配多种语言说法（同义改写），显著提升语言泛化——OpenVLA-OFT 与 π0.5 的训练配方都包含语言增广；自采数据时用模板批量生成改写。
  • 动作分块与执行长度：预测 chunk 长度（一次预测多少步）与执行长度（实际执行多少步再重新推理）是两个旋钮；执行太长 → 反应迟钝，太短 → 推理频率跟不上控制频率。慢 VLA 用异步推理补偿（LeRobot 的 --inference.type=rtc；GR00T N1.7 甚至把该参数更名为 --execution-horizon 以强调这一区分）。
  • 评测协议：固定 N 次 rollout（LIBERO 通行 10 episode/任务）、≥3 个随机种子、报 mean±std、写明初始状态来源与软/硬重置；对比两个策略用同一 --seed 与同一数据 revision。
  • 控制频率核对：数据集 fps、仿真控制频率（SimplerEnv：Google Robot 3Hz / WidowX 5Hz）、真机控制环频率三者对齐，否则策略「手感」全变。

常见失败模式速查表：

症状最可能原因排查方向
机械臂高频抖动 / 震荡归一化不一致；控制频率与数据 fps 不匹配；action chunk 切换处不连续对比训练/部署的 norm stats 与 fps；开启 temporal ensembling 或 RTC 异步推理；检查 chunk 执行边界
轨迹漂移、总是差一点到不了covariate shift：测试初始分布超出训练覆盖；delta/absolute 动作模式配错；相机被动过补采对应区域数据；核对 control_mode/unnorm_key；重新标定与固定相机
夹爪开合时机错（抓到空气 / 放不下）执行长度与预测 chunk 不匹配；夹爪维度被当连续量归一化（实为 0/1 离散）调 n_action_steps / execution horizon；单独检查夹爪通道的归一化与阈值化
完全不跟语言指令LoRA 没训到 VLM 相关层；指令多样性不足；图像预处理不一致导致视觉输入失效扩大 LoRA target modules / 提高 rank；指令同义改写增广；逐项核对图像管线
微调后反而崩了（不如预训练）学习率过高灾难性遗忘；norm stats 没重算；多本体数据混合未加权降 lr / 改 LoRA；重跑 compute_norm_stats；按数据集设混合权重（GR00T 的 ds_weights_alpha 即为此设）
loss 发散 / NaN某些动作维度 q01≈q99 或 std≈0，归一化后数值爆炸手工修正 norm_stats.json（openpi 官方建议）；剔除全零维度
仿真很快、真机很卡推理延迟与网络往返；相机掉帧OFT/TensorRT 加速（GR00T N1.7：RTX PRO 6000 上 ~40Hz、Jetson Thor ~28Hz）；policy server 走本地网；检查相机实际 fps

7.1 阶段四的选题地图：八个开放问题

到了阶段四，你需要一个「值得深挖的问题」。下面八个是当前（2026）社区公认没解决的方向，每个附「为什么难 + 目前思路」：

  1. 数据 scaling law：机器人数据贵、脏、异构，「多少数据换多少能力」至今没有 LLM 那样清晰的曲线。目前思路：人类视频预训练（GR00T N1.7 用 20K 小时 EgoScale 视频）、世界模型合成数据（GR00T-Dreams/DreamGen）、百万级真机数据集（AgiBot World）三线并进，但配比规律仍是黑箱。
  2. 长时程任务与记忆：VLA 单次推理只看得到几帧，多步任务（做一杯咖啡）误差逐步累积、超出上下文就「失忆」。目前思路：分层架构（GO-1 的 latent planner、Helix 的 System1/System2、π0.5 的高层子任务预测）、语言作为中间记忆、外部场景记忆模块。
  3. 泛化 vs 专用：通才模型在单任务上常不如专才，专用微调又会灾难性遗忘。目前思路：base + 轻量微调的双层体系、Knowledge Insulation（π0.5：隔离知识通道防遗忘）、LoRA 式按任务挂载。
  4. 评测方法学：LIBERO 已饱和（96%+），真机评测贵且不可比，仿真评测有 sim2real 偏差。目前思路：real2sim（SimplerEnv）、更大更难的新基准（RoboCasa365 的 365 任务）、标准化报告协议（种子数/rollout 数/方差）——这也是普通研究者最容易做出贡献的方向。
  5. 安全与可靠性：与人和易碎物接触的策略没有行为保证，失败模式不可预测。目前思路：人在环 RL（HIL-SERL）、力/速度硬限制、不确定度估计与拒动、RECAP 式从失败经验中改进。
  6. 世界模型与 VLA 融合：世界模型会「想象」但推理慢，VLA 反应快但缺乏预见。目前思路：世界模型当数据引擎（DreamGen 生成训练轨迹）、当规划器（想象多步再选动作）、或直接统一架构（LeRobot 已收录 VLA-JEPA 等世界模型策略）。
  7. loco-manipulation（全身控制）：行走平衡与手臂操作耦合，人形「边走边干活」远比定基座难。目前思路：Unitree G1 等廉价人形 + GR00T 类跨本体基础模型、上下层分频控制（第 5 讲 Helix 的分层即此思路）。
  8. 跨本体统一动作空间：不同机器人自由度、标定、频率全不同，动作定义无法直接共享。目前思路：相对 EEF 动作（GR00T N1.7，人类视频与机器人共用）、归一化关节空间（RDT 的统一 tokenizer）、FAST 频域动作 token、embodiment tag 分头路由。

8. 结语：地图在手，路在脚下

七讲走完，可以把整个系列收束成一句话：VLA = VLM 的大脑（第 2、3 讲）+ 连续动作头的手（第 4 讲）+ 数据引擎的粮食（第 1、5 讲）。而本讲补上了最后一块：这些组件今天全部有开源实现、开放权重、免费数据与标准考场——这个领域的入门门槛，已经降到了「一块 GPU + 一个周末」。

今晚就能做的一件事装好 LeRobot，把 PushT 上的 ACT 训起来： 
pip install lerobot
lerobot-train --policy.type=act --dataset.repo_id=lerobot/pusht --policy.device=cuda
没有 GPU？用 Colab 的 ACT notebook，或者加 --job.target=t4-small 提交到 HF Jobs 按秒计费。半小时后你会看到第一条属于自己的成功率曲线——具身智能之路，就从那条曲线开始。全系列完，祝动手愉快。
