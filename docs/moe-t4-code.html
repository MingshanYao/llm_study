2. Gate.__init__：路由器长什么样

# inference/model.py:556-562（Gate.__init__，节选）
self.hash = layer_id < args.n_hash_layers          # 层号 < 3 → Hash 层
self.weight = nn.Parameter(torch.empty(args.n_routed_experts, args.dim))
                                                    # 门控矩阵 Wg: [384, 7168]
if self.hash:
    # token ID → 6 个专家号的预计算映射；随 checkpoint 分发，不学习
    self.tid2eid = nn.Parameter(torch.empty(args.vocab_size, args.n_activated_experts,
                                            dtype=torch.int32), requires_grad=False)
    self.bias = None                                # Hash 层没有 bias
else:
    self.bias = nn.Parameter(torch.empty(args.n_routed_experts, dtype=torch.float32))

四个值得停一停的地方：

  • 门控矩阵只有 [384, 7168]：约 275 万参数。整个 1.6T 模型里，「决定谁上场」的部分只占百万分之一——路由器是个小公务员，不是大老板。
  • Hash 层也保留 self.weight：看似矛盾，实则精妙——第 3 讲说过，Hash 层「去哪儿」不学习，但「用多少」仍按学习出的分数加权，所以门控矩阵照留（第 3 讲图 3-4 的绿路径）。
  • tid2eid 是 requires_grad=False 的整型表：它根本不是「参数」，只是搭 checkpoint 顺风车的一张静态查找表。哈希函数本身不在开源推理代码里（inference/ 中 grep tid2eid 仅 4 处命中，均为定义与加载）。
  • bias 是 float32 标量向量 [384]：每个专家一个数。它是全模型最便宜的「均衡机构」。

3. Gate.forward：路由的完整流水线

图 4-1｜Gate.forward 的三色路径图。与第 2 讲图 2-2、第 3 讲图 3-4 对齐着看。

# inference/model.py:564-584（Gate.forward，逐行注解）
def forward(self, x, input_ids=None):
    # ① 打分：[T, 7168] × [7168, 384] → [T, 384] 原始 logits
    scores = linear(x.float(), self.weight.float())
    if self.score_func == "softmax":
        scores = scores.softmax(dim=-1)          # 兼容旧代（V1/V2 权重）
    elif self.score_func == "sigmoid":
        scores = scores.sigmoid()                # 兼容 V3
    else:
        scores = F.softplus(scores).sqrt()       # ② V4：√Softplus 亲和度
    original_scores = scores                     # ③ 备份！加权要用原始分
    # Bias shifts scores for expert selection (topk) but does not affect routing weights.
    if self.bias is not None:
        scores = scores + self.bias              # ④ bias 只污染这份副本
    if self.hash:
        indices = self.tid2eid[input_ids]        # ⑤ Hash 层：查表得 indices
    else:
        indices = scores.topk(self.topk, dim=-1)[1]   # ⑥ 普通层：带 bias 的 top-6
    weights = original_scores.gather(1, indices) # ⑦ 加权用原始分（bias 不在场！）
    if self.score_func != "softmax":
        weights /= weights.sum(dim=-1, keepdim=True)  # ⑧ 选中 6 个内归一化
    weights *= self.route_scale                  # ⑨ ×2.5 校准量级
    return weights, indices

逐段解释（编号对应注释）：

  • ① 一行普通矩阵乘。注意 .float()：门控永远用高精度算（路由是稳定性敏感区，第 3 讲 §9），专家权重才是 FP4。
  • ② V4 新增的分支，就是 \(\sqrt{\mathrm{Softplus}}\)，一行完事。同一段代码还保留着 softmax / sigmoid 分支——一份代码兼容五代权重。
  • ③ + ⑦ 是「辅助损失免费」的代码化身：original_scores 先备份，等 top-k 选完人，再回头用原始分数 gather。bias 加在 ④ 的副本上，只决定「谁进名单」；名单里的人按 ③ 的原始分领权重。两份数据，井水不犯河水。
  • ⑤ vs ⑥：Hash 层直接查表拿 indices（无 bias——self.bias is None，④ 自动跳过）；普通层走带 bias 的 topk。
  • ⑧ softmax 天然归一所以跳过；sigmoid / √Softplus 都需要选中后局部归一（第 2 讲 §6）。
  • ⑨ route_scale=2.5：归一化把权重平均压到 1/6 ≈ 0.167，×2.5 后平均 ≈ 0.417，把残差流的量级校准回 SwiGLU 舒服的区间。
对应公式⑦ + ⑧ 合起来就是第 2 讲 §5.1 的 \(g_{i,t} = \dfrac{s_{i,t}}{\sum_{j\in\mathrm{Topk}} s_{j,t}}\)（选中者按原始分归一化），④ 就是 \(s_{i,t}+b_i \in \mathrm{Topk}\) 的比较键。公式与代码逐字符对应。

4. Expert.forward：一个专家的 SwiGLU

# inference/model.py:596-606（Expert.forward，逐行注解）
def forward(self, x, weights=None):
    gate = self.w1(x).float()                        # ① 升维：[B, 3072]
    up = self.w3(x).float()                          # ② 升维：[B, 3072]
    if self.swiglu_limit > 0:
        up = torch.clamp(up, min=-self.swiglu_limit, max=self.swiglu_limit)   # ③ 夹到 [-10, 10]
        gate = torch.clamp(gate, max=self.swiglu_limit)                       # ④ gate 只夹上界
    x = F.silu(gate) * up                            # ⑤ 开关 × 特征
    if weights is not None:
        x = weights * x                              # ⑥ 路由权重乘在这里（down 之前！）
    return self.w2(x.to(dtype))                      # ⑦ 降维：[B, 7168]
  • ①②⑤ 是标准 SwiGLU（第 0 讲 §3.2 的 \( \mathrm{SiLU}(xW_1) \odot (xW_3) \cdot W_2 \)）。一个专家 = 三个矩阵 \(w_1, w_3, w_2\)，各 [7168, 3072] 方向。
  • ③④ SwiGLU Clamping（第 3 讲 §9）：up 分量对称夹 \([-10,10]\)，gate 分量只夹上界 10（SiLU 对强负值输出接近 0，本就自灭，无需下界）。
  • ⑥ 是容易看漏的关键：路由权重 \(g_{i,t}\) 在降维投影之前乘进专家输出——即论文口径 \(g_{i,t} \cdot \mathrm{FFN}_{r,i}(x)\)。先混合再投影 vs 先投影再混合，数学上因线性可交换，但代码选择在 down 投影前乘，可以让降维矩阵共享处理已缩放的值。

5. MoE.forward：把专家们组装起来

# inference/model.py:629-644（MoE.forward，节选 + 逐行注解）
weights, indices = self.gate(x, input_ids.flatten())   # ① 路由：[T,6] 权重 + [T,6] 专家号
y = torch.zeros_like(x, dtype=torch.float32)           # ② 输出累加器
counts = torch.bincount(indices.flatten(),
                        minlength=self.n_routed_experts).tolist()  # ③ 每个专家分到几个 token
for i in range(self.experts_start_idx, self.experts_end_idx):
    if counts[i] == 0:
        continue                                       # ④ 无人问津的专家：跳过（零计算）
    idx, top = torch.where(indices == i)               # ⑤ 谁分到了专家 i？（token 行号, 槽位）
    y[idx] += expert(x[idx], weights[idx, top, None])  # ⑥ 聚 batch 过 FFN，加权累加
if world_size > 1:
    dist.all_reduce(y)                                 # ⑦ 教学版用 all_reduce 模拟 EP 合并
y += self.shared_experts(x)                            # ⑧ 共享专家恒激活，最后相加
  • ③ bincount：统计每个专家的接待量——第 1 讲图 1-2 负载分布的原始数据就是它。
  • ④ counts[i]==0 跳过：冷专家零成本；同时这也是「batch 聚合」的最小样本——⑤⑥ 把散落在各 token 的同一专家请求聚成一批再算，凑大 batch 才能吃满 GPU。
  • ⑦ 参考实现跑在单机多卡模拟下，用 all_reduce 合并各 rank 的部分和；生产实现是 Dispatch all-to-all → 分组 GEMM → Combine all-to-all 的融合流水（第 3 讲 §6 的 MegaMoE）。
  • ⑧ 共享专家最后无条件相加——第 2 讲图 2-2 的结构在这行收口。

8. 自查清单（全系列收官）

  1. Gate.forward 里 bias 污染的是哪份数据、绕过了哪份数据？（污染 scores 副本只做 topk；绕过 original_scores——gather 加权用它）
  2. Hash 层为什么也要保留门控矩阵？（「去哪儿」查表，但「用多少」仍按学习出的分数加权）
  3. 路由权重乘在专家的哪一步？（down 投影 w2 之前）
  4. counts[i]==0 的专家遭遇什么？（continue 零计算——但参数仍占显存，这正是负载不均的浪费）
  5. 手动模拟里 t3 的路由为什么变了？（E2 略过载 bias −0.02、E7 欠载 +0.02，比较键 0.28 vs 0.32 边际翻转；加权仍用原始分，输出不受 bias 污染）
  6. 教学版与生产版的本质差异属于哪一类？（通信与调度的工程实现；路由与加权的语义完全一致）
