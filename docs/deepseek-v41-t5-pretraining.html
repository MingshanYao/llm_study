1. 一分钟铺路：预训练是什么

一个 LLM 最早期的训练叫预训练（pre-training）：给模型看海量文本，每个位置都让它猜"下一个 token（词元）是什么"，猜错了就微调参数。token 可以理解为"字/词的碎片"，是模型处理文本的最小单位。这个目标在数学上叫下一 token 预测（next-token prediction）：

\[ \mathcal{L}_{\text{PT}} \;=\; -\sum_{t=1}^{n} \log P_\theta\!\left(x_t \mid x_{<t}\right) \]

预训练目标（通识形式，论文 §4 采用的即此目标）：把整段文本 \(x_1 x_2 \cdots x_n\) 逐位置求"猜对下一个 token"的负对数概率并求和。

逐符号解释：\(x_t\) 是第 \(t\) 个 token；\(x_{<t}\) 是它前面已经出现的所有 token；\(P_\theta(x_t \mid x_{<t})\) 是参数为 \(\theta\) 的模型在看完前缀后给"正确答案 \(x_t\)"打的概率——这个概率越接近 1，\(\log\) 越接近 0，损失越小；\(\sum_{t=1}^{n}\) 表示把这段文本里每个位置的损失加起来。训练就是不断调 \(\theta\) 让这个数变小。

为什么说"数据决定上限"？因为预训练的命题本质是压缩：模型在参数里压缩的是训练语料中的知识、语言规律和推理模式。语料里没有的东西，模型很难"无中生有"；语料里有大量重复、低质的内容，压缩空间就被浪费了。这就是为什么本讲花最大篇幅讲数据。后训练（SFT/RL，见第 6 讲）是在这个底子上"激发"能力，而底子有多厚，是预训练决定的。

DeepSeek-V4.1-Flash 这次预训练的一个特殊之处：它是原生多模态的——文本、图像（以及与图像交错的文字）从预训练阶段就一起喂进同一个主干模型，而不是先训一个纯文本模型、再"外挂"一个视觉模块（论文 §4.3.2 明确称之为 native multimodal training）。多模态语料怎么来、怎么清洗、怎么配比，是下一节的主角。

2. 数据构建（§4.1）：45T token 从哪来

2.1 文本数据：从"单条好不好"到"整体配比好不好"

论文在文本数据上的第一句话就很有信息量：为了追求更高智能，他们超越了小规模数据实验所反映的"单样本质量"，转而关注不同语料之间的整体交互——每种语料能提供什么独特的信息增益。打个比方：不是问"这颗食材新鲜吗"，而是问"这一桌菜搭配起来营养全不全"。

围绕这个理念，论文列出了四件具体的事：

  • 设计"缩放阶梯"（scaling ladder）：在"模型参数量 × 训练数据量"上设计一套由小到大的阶梯式实验，用更全面的评测来指导真正的大规模训练。论文只说"carefully designed to guide large-scale training runs"，未展开阶梯的具体档位；这是业界常见的"先训小模型扫参、再放大"的做法，但具体如何实施属于论文未披露细节。
  • 过滤"模型生成内容"（model-generated content）：把低能力模型产生的输出、低质量机器翻译文本筛掉。论文给了一个有意思的说法：这类内容是"隐式重复"（implicit duplication）——它们本质上是在换着花样复述已有信息，训练久了反而有害。
  • model-in-the-loop 数据迭代：让模型参与数据构建的闭环迭代，作为未来大规模合成数据的基础。注意论文的措辞是"探索"（explore）且定位为"为未来打基础"——本代预训练的多模态部分明确没有做大规模合成（见 2.2 节）。
  • 引入更多领域专家：让专家参与构建更细粒度的数据质量评估维度。
  • 代码语料更新：相比上一代，新语料纳入了更多新近发布的开源仓库、commit、库和新兴框架，覆盖更多编程语言，更贴近当代真实软件工程场景。

2.2 多模态数据：三类数据 + 一条"递增成本"的漏斗

多模态预训练语料由三类构成（论文 §4.1 Multimodal Data Curation）：

  1. 图文对（image-text pairs）：一张图配一段描述它的文字；
  2. 图文交错数据（interleaved image-text data）：像图文并茂的网页/教材那样，图片和文字穿插出现；
  3. 领域专用数据（domain-specific data）：补齐网络抓取数据的短板的专项数据。

一个大方向值得先说：论文明确表示"放弃了大规模数据合成"——前提判断是"原始网络数据天然富含多模态知识"，所以优先清洗并原样利用（native form），追求"最直接、最可扩展的视觉知识压缩"。这与第 6 讲的后训练形成鲜明对照：后训练几乎全靠合成数据与环境构建，而预训练多模态主打"清洗原生数据"。两处的取舍逻辑不同：预训练要的是互联网级规模的天然知识分布，后训练要的是可验证的任务。

数据来源上还有一个小插曲：他们最初发现爬虫系统过度偏向以文本为中心的网页，于是从 Common Crawl 重新引导（re-bootstrap）了爬虫，以覆盖更多含图、含视频的多模态网页。（注：本报告未在 §4.1 正文检索到对视频/音频模态数据管线的具体描述，论文本节实际展开的是图文类数据，读者如关心视频/音频请以论文原文披露为准。）

三类数据各自的清洗方式：

  • 图文对：从网页提取图片及其 alt text（网页里给图片配的文字说明，图片挂了时显示的那段话），用图文相关性阈值过滤，再按图像语义去重（即"两张图看起来内容一样"就算重复，而不是 URL 一样才算）。
  • 图文交错数据：主要来自网页和 PDF。论文特别指出：大规模多模态语料处理的 CPU 与磁盘成本远高于纯文本，所以把构建流程组织成"成本递增的多级阶段"——先用便宜的手段砍掉绝大部分，再对幸存者上昂贵的手段。具体是：图像检索前先做启发式与统计过滤、去重、质量模型筛选高价值文档 → 幸存文档拼装成图文交错序列 → 再做一轮图像感知（image-aware）的过滤与去重 → 最后用 SmolVLM（一个轻量开源视觉语言模型）对图文内容做严格质量打分，抽出高质量交错数据。
  • 领域专用数据：为弥补网络数据固有缺陷，加入提升细粒度视觉感知（如视觉定位 visual grounding 与指向 pointing）、OCR（光学字符识别，即把图片里的文字读出来）、长尾知识（冷门但有用的知识）的数据；另外还收集了大量图文代码对（image-code pairs）和计算机使用轨迹（computer-use trajectories）来增强多模态智能体（agentic）理解。

图 2：多模态交错数据的"成本递增漏斗"（依据论文 §4.1 Multimodal Data Curation 段落绘制）。漏斗主体层层收窄，越靠后的环节越昂贵（SmolVLM 打分最贵），因此放在最后只处理幸存者；黄色虚线是"废料回收"：被淘汰的文档经筛选重组后部分变成图文对数据，不浪费。

2.3 合并与去重：7 : 1 的最终配比

文本与多模态数据走的是两条独立管线，最终训练语料取两者的并集。对重叠样本：用多模态版本替换纯文本版本（一张带 alt text 的网页当然比纯文字版信息多），并采用两条管线中较大的 epoch 数（epoch = 数据被完整过一遍的次数）。替换之后，最终语料的 token 配比为：

\[ \underbrace{7}_{\text{纯文本}} : \underbrace{1}_{\text{多模态}} \qquad \text{（按 token 数计，论文 §4.1 Data Integration and Deduplication）} \]

其余三个工程细节：① 预训练与上下文扩展阶段之间联合预取并分配样本，把两个阶段的样本重叠降到最低（同一篇文档尽量不在两个阶段重复出现）；② 超长文档在混合前做确定性预切分，保证训练 token 在数据分片和训练步之间均匀分布；③ 持续优化 packing（把多条样本拼进定长训练序列的装箱算法），把填充率（padding rate）压到不超过 \(10^{-4}\)——一万个 token 的预算里浪费的填充位不到 1 个，几乎零浪费。

3. 模型设置（§4.2.1）：552B MoE 主干长什么样

先解释两个词。MoE（Mixture-of-Experts，混合专家）：把模型里的前馈层换成很多个"专家"小网络，每个 token 只请少数几位专家干活，从而"总参数很大、每次计算很小"（详见 MoE 基础篇与 DeepSeek MoE 演进）。激活参数：每个 token 实际参与计算的那部分参数量。V4.1-Flash 的总参数（backbone）是 552B，但每个 token 激活的只有 8B（prefill，读入阶段）或 16B（decode，生成阶段）——这就是"Flash"名字的由来。

3.2 8B / 16B 激活是怎么"训"出来的

论文 §1 引言交代了机制：V4.1-Flash 采用 CED（Causal Encoder-Decoder，因果编码器-解码器）架构——解码器的全局 KV 直接从编码器最终隐藏状态投影得到。直觉上：读入一篇长文档时（prefill），绝大部分 token 只需要过编码器（激活 8B 就够）；真正逐 token 生成答案时（decode），才动用更重的解码器（16B）。这种"输入便宜、输出略贵"的形状对读多写少的智能体场景特别划算（机制细节见 第 1 讲）。

要强调的是：8B/16B 不是训练后再"裁剪"出来的，而是架构在预训练时就定死的——40 层怎么分、每层多少专家、激活几个专家（6 个），共同决定了每 token 的激活量。预训练从头到尾都在这个稀疏激活的形态下进行，包括 sparse attention 也是从零开始（from scratch）在 64K 序列长度上直接训练、没有先 dense 后稀疏的过渡阶段（论文 §1、§4.2.2）。

4. 训练设置（§4.2.2）：怎么把这 45T token 喂进去

4.1 三套优化器分工

4.2 token 预算、批大小与学习率时间表

  • 总量：45T token 多模态数据，全程零不稳定（no instability）——对 552B 的模型来说，这意味着没有损失 spikes（损失突然飙升）之类的训练事故需要回滚。
  • 批大小：全程固定 100.6M token/步（不随训练阶段放大）。
  • 学习率：前 2000 步线性升温（warmup）到 \(2.6\times10^{-4}\)；保持到 28T token；28T→40T 按余弦（cosine）schedule 衰减到 \(2.6\times10^{-5}\)；40T→45T 保持不变直到结束。
  • 上下文长度：从零（from scratch）以 64K 序列长度训练，在 34T token 处扩展到 1M。注意论文 §1 特别强调：没有 dense attention 预热阶段，稀疏注意力一开始就是稀疏的。

论文没有给出余弦衰减的公式，只给了起止值。常规的余弦衰减形式如下（公式形式为通识写法，属本报告补充；起止数值 \(2.6\times10^{-4} \to 2.6\times10^{-5}\) 与区间 28T–40T 为论文事实）：

\[ \eta(t) \;=\; \eta_{\min} + \frac{1}{2}\left(\eta_{\max}-\eta_{\min}\right)\left(1+\cos\!\frac{t-t_1}{t_2-t_1}\,\pi\right),\quad t\in[t_1,t_2] \]

符号：\(\eta(t)\) 是第 \(t\) token 处的学习率；\(\eta_{\max}=2.6\times10^{-4}\)（28T 处），\(\eta_{\min}=2.6\times10^{-5}\)（40T 处）；\(t_1=28\text{T}\)，\(t_2=40\text{T}\)。直觉：学习率像退火一样先大后小——前期大步探索，后期小步精修。

4.3 多模态训练的特殊处理

图文混训会带来纯文本训练没有的麻烦，论文在 §4.2.2 和 §3.1（训练基础设施，第 4 讲详述）给出了四项针对性处理：

  • 按模态分开的负载均衡：图像 token 和文本 token 的分布不同，对专家路由的偏好也不同；如果把两者混在一起做总量均衡，会掩盖"某一模态内严重不均"的问题。于是论文把 auxiliary-loss-free 负载均衡（Wang et al., 2024a）扩展为文本、图像各持一套专家修正偏置（correction biases），各自独立更新。偏置更新速度设为 0.001（两种模态相同），另保留一个很小的序列级均衡损失（权重 0.0001）防止单条序列内极端失衡。
  • 视觉编码器解耦执行（disaggregated encoder，§3.1.1）：视觉编码器被复制到 LLM 参数树之外，每个训练步分三相——视觉编码器前向、LLM 前向/反向、视觉编码器反向——让视觉计算不干扰 LLM 的并行策略，LLM 相保持纯文本训练的并行方式。
  • 对比学习通信重叠（§3.1.1）：视觉编码器的对比预训练损失要在全批图文对上算，两种模态的特征需在数据并行（data-parallel）各副本间 all-gather（把所有副本的数据聚齐）；论文利用"文本特征梯度只依赖聚合后的视觉特征、反之亦然"的对称性，把两次 all-gather 完全藏进前向/反向计算里，不阻塞流水线。
  • 均衡图像分片（balanced image sharding，§3.1.1）：一条百万 token 的图像密集序列加载时能吃满一台主机的 I/O、CPU 和内存，所以把每条序列的图像按负载均衡切分到各 CP（context parallel，上下文并行）rank 上，每张图只读一次。论文还给出判据：只要每 token 原始字节 \(\rho\) 与每 token 计算量 \(C\) 满足 \(\rho < \tfrac{B_{\text{IO}}}{B_{\text{GPU}}}C\)（\(B_{\text{IO}}\)、\(B_{\text{GPU}}\) 为文件系统与 GPU 带宽），加载就能藏在计算后面；序列长度与集群规模在式中被约掉了。

CSA2 的跨层复用如何在大规模分布式训练中落地（§3.1.2）：共享注意力组件的层可能被切到不同的流水线并行（pipeline parallelism）阶段上（PP 把模型按层切开、各阶段分布在不同设备上），直接复用模块会与"各阶段只能看本地"的常规执行冲突。论文用影子索引器（shadow indexers）解决：每个参与阶段放一个轻量可执行副本，共享参数只有一个逻辑所有者（owner），由 owner 负责优化和 checkpoint，副本间做参数同步。另一个佐证是 Engram 模块被刻意放在第 1 层和第 14 层（零索引），理由正是"在训练流水线各阶段间均衡显存占用"——间接说明预训练确实使用了流水线并行。

关于硬件规模与并行配置的诚实说明：论文 §4.2.2 及全文没有披露预训练使用的 GPU 数量/集群规模，也没有给出 EP/PP/DP 各维的具体 rank 数。上文能确认的只有：使用了数据并行（对比学习 all-gather）、上下文并行（CP，图像分片）、流水线并行（影子索引器与 Engram 分层放置的表述间接证实）和跨阶段的共享状态管理。硬件规模属于论文未披露信息，请勿引用任何第三方猜测数字。

4.4 视觉编码器的两阶段训练（§4.2.2 Vision Encoder Training）

DeepSeek-ViT 在并入语言主干之前要单独过两关：

  1. 对比预训练（contrastive pre-training）：用 SigLIP 式的 sigmoid 对比损失，在约 47B（470 亿）图文对（来自 alt text 数据）上训练，输入分辨率压到最大 224×224（大图等比缩小）。直觉：对比学习就是"配对练习"——给模型看一张图和一段话，让它判断这段话是不是在描述这张图。为什么不用高分辨率？论文给了实验依据：高分辨率在该阶段的收益对最终模型贡献很小（后续自回归阶段专门负责高分辨率外推），在此阶段放大分辨率只会大幅增加计算开销。
  2. 自回归微调（autoregressive fine-tuning）：把视觉编码器接到一个 4B MoE LLM 上，在 236B token 的数据（图像描述、alt text、图表、OCR）上用下一 token 预测目标训练，分辨率限制在 544×544 到 1344×1344（超界等比缩放）。这一阶段练的是编码器对细粒度视觉特征的建模能力。训练完把 LLM 丢弃、只保留视觉编码器进入后续预训练管线，并沿用同样的分辨率策略。

这套"先对比后生成、最终丢掉脚手架 LLM"的流程意味着 4B LLM 只是一次性训练工具，不进入最终 552B 模型的参数；论文原文明确写了 discard the LLM，此点为论文事实而非推断。

  • 弱项二：部分知识/长上下文基准仍落后 Pro。MultiLoKo（45.5 vs 50.9）、SimpleQA-Verified（42.3 vs 55.2）、SuperGPQA（53.1 vs 53.9）、LongBench-V2（45.2 vs 51.5）有可见差距。SimpleQA 考的是"冷门事实知不知道"，与语料中长尾事实的覆盖密度强相关。
  • 多模态是"独有成绩单"：MMMU-Pro 56.5、CVBench 77.9、DocVQA 95.6、RefCOCO-avg 86.0。前两代基座没有对应成绩（表中为"-"），所以这四行无法横向比，只用于验证"原生多模态训练有效"这一主张。

论文还补了一个公开基准之外的测试：由于困惑度（perplexity，模型对文本"惊讶程度"的平均负对数概率，越低越好）没法通过模型 API 测，他们在内部留存评测集（内部文档、专有代码仓库、学术材料，面向复杂科研问题的推理/归因/解题）上测了 BPB（bits-per-byte，每字节比特数）：

\[ \text{BPB} \;=\; \frac{\text{全体测试文本的负对数似然（换算为比特）}}{\text{全体测试文本的字节数}} \]

BPB 的通识定义（本报告补充；论文只说报告 BPB、越低越好）：相当于"平均每存储一个字节的真实文本，模型要花多少比特的'惊讶量'"，越低说明模型把这类文本压缩得越好。

结论（论文 Figure 6）：V4.1-Flash-Base 在所有留存任务上 BPB 最低，论文据此认为它"更有潜力成为强基座模型"。这也呼应了引言中"留存集提升 5%–10%"的说法——公开基准看不全的进步，在更贴近真实研发场景的语料上显现了出来。

6. 训练中的关键观察

论文 §4 没有专门的"消融实验"章节（ablation，即控制变量拆解各设计贡献的实验），也未披露任何训练曲线。以下是散落在 §1、§4 文字中、论文明确给出的观察，以及本报告的整理：

  1. 45T token、零事故：论文原文 "We train DeepSeek-V4.1-Flash on 45T tokens of multimodal data with no instability"。对 552B 级 MoE，这本身就是优化方案（Muon + AdamW + Sinkhorn 平衡、按模态分偏置的负载均衡）稳定性的佐证。
  2. 稀疏注意力可以"从零训"：sparse attention 在 64K 序列长度上 from scratch 训练、没有 dense warmup 阶段，最终长上下文成绩（LongBench-V2 45.2）与语义评测没有出现塌方。这省掉了"先 dense 后 sparse"两阶段的开销（对 CSA2 机制本身的分析见第 2 讲）。
  3. 对比训练阶段低分辨率就够：论文明确做了取舍——224×224 的对比预训练虽然换更高分辨率有收益，但"这些收益对最终模型贡献很小"，因为高分辨率能力由后续自回归阶段专门补足。这是"在哪一阶段花算力最划算"的显式判断。
  4. 多模态语料"清洗优先、合成靠后"：判断依据是"原始网络数据天然富含多模态知识"；与后训练的"合成数据是主要增益来源"（第 6 讲）形成对照。两种哲学各有适用场景。
  5. 隐式重复有害：低能力模型的输出与低质量机翻在长训练视角下是负资产——这是数据过滤"隐式重复"标准的动机。

论文没给、读者常想问的：各模态数据的具体 token 数（只给了 7:1 总配比）、数据源的份额表、学习率/批大小为何取这些值、消融实验数字——均未披露。本讲不做任何数值补齐。另外，§4.1 开头的"多模态预训练数据"叙述以图文数据为主，视频/音频模态的数据管线在 §4 正文未见具体描述（引言只统称 45T token 为"多模态语料"），如需引用请以论文原文口径为准。

7. 本讲小结与自测

本讲小结

  • 预训练 = 用下一 token 预测把语料中的知识压进参数；数据的质量与配比决定模型上限。
  • 数据（§4.1）：文本侧重"整体配比"——scaling ladder 扫描、过滤隐式重复、更新代码语料；多模态侧"清洗优先于合成"——图文对（alt text + 相关性过滤 + 语义去重）、图文交错（成本递增漏斗 + SmolVLM 打分 + 废料回收）、领域专项（OCR、定位、图文代码对、computer-use 轨迹）；最终文本 : 多模态 = 7 : 1，packing 填充率 ≤ \(10^{-4}\)。
  • 模型（§4.2.1）：40 层（20+20 CED）、\(d=5120\)、1 共享 + 384 路由专家（激活 6）、552B 主干，prefill 激活 8B / decode 激活 16B；编码器 18 层 CSA2（m=2）、解码器 20 层 CSA2（m=1），多数层为 Reuse Mode。
  • 训练（§4.2.2）：Muon / AdamW / Sinkhorn 平衡三套优化器分工；45T token 零事故；批大小恒定 100.6M token；学习率 2000 步 warmup → \(2.6\times10^{-4}\)（至 28T）→ 余弦降到 \(2.6\times10^{-5}\)（40T）→ 保持；64K 起步、34T 处扩到 1M；多模态特殊处理包括按模态分离的专家负载均衡、视觉编码器解耦执行、对比学习通信重叠、均衡图像分片、影子索引器。GPU 规模未披露。
  • 评测（§4.3）：基座模型五维 19 项基准。以 1/3 总参数、1/4 激活参数对齐 1.6T 的 Pro：代码与英文知识反超（HumanEval 79.4、GSM8K 93.0、MMLU-Pro 74.1），多语言数学（MGSM 80.2）与部分知识/长上下文基准仍落后；留存集 BPB 全面最低（+5%–10%）；多模态四项首次有分（MMMU-Pro 56.5 等）。

自测清单（先自己答，再展开看参考答案）

Q1：最终训练语料里文本和多模态数据的比例是多少？重叠样本怎么处理？

答：文本-only : 多模态 = 7 : 1（按 token 数）。文本与多模态语料先各自独立构建，取并集；重叠样本用多模态版本替换文本版本，并采用两条管线中较大的 epoch 数（论文 §4.1 Data Integration and Deduplication）。

Q2：552B 主干，为什么每个 token 只激活 8B 或 16B？这两个数分别在什么阶段生效？

答：两个来源叠加。① MoE：每层 1 个共享专家 + 384 个路由专家，每 token 只激活 6 个路由专家；② CED 架构：解码器全局 KV 由编码器最终隐状态投影而来，读入阶段（prefill）绝大多数 token 只过编码器，激活 8B；逐 token 生成阶段（decode）使用解码器，激活 16B。这是架构在预训练时就定死的形态，不是事后裁剪（机制详见第 1 讲）。

Q3：学习率时间表的三个关键数字（初始值、衰减起点、终值）和上下文长度扩展发生在第几个 token？

答：warmup 2000 步到 \(2.6\times10^{-4}\)，保持到 28T token 后余弦衰减到 \(2.6\times10^{-5}\)（40T 处到位并保持至 45T）；上下文在 34T token 处从 64K 扩到 1M。批大小全程固定 100.6M token（论文 §4.2.2）。

Q4：为什么视觉编码器的对比预训练只用 224×224 分辨率？

答：论文给出两个理由：① 实验显示更高分辨率在该阶段的收益"对最终模型贡献很小"；② 高分辨率外推由后续的自回归微调阶段（544×544–1344×1344）专门负责，在对比阶段放大分辨率只会显著增加计算开销、总体收益不大（论文 §4.2.2 Vision Encoder Training）。

Q5：V4.1-Flash-Base 相比 V4-Pro-Base 的强项和弱项各举一个基准并给出数字。

答：强项（举其一）：HumanEval Pass@1 79.4 vs 76.8（或 MMLU-Pro 74.1 vs 73.5、GSM8K 93.0 vs 92.6、BigCodeBench 60.6 vs 59.2），且激活参数只有对方的约 1/6–1/3；弱项（举其一）：MGSM 80.2 vs 84.4（或 MultiLoKo 45.5 vs 50.9、SimpleQA-Verified 42.3 vs 55.2、LongBench-V2 45.2 vs 51.5）。按论文规则，分差 ≤0.3 视为同一水平。

Q6：论文披露了预训练用了多少张 GPU 吗？"影子索引器"是在解决什么问题？

答：GPU 数量与集群规模未披露，任何具体卡数都不是出自论文。影子索引器（shadow indexers，§3.1.2）解决的是：CSA2 的跨层 KV/索引共享在流水线并行下，共享组件的层可能被切到不同 PP 阶段、无法直接复用模块——做法是每个参与阶段放一个轻量可执行副本，共享参数只有一个逻辑 owner 负责优化与 checkpoint。
