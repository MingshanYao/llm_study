RL 训练工程师零基础七讲 · 第 1 讲：策略梯度从零讲

0 全景图 1 策略梯度 2 LLM×RL 3 PPO 4 RLHF·DPO 5 RLVR·GRPO 6 系统与实战 番外 SC

本讲定位：整个系列的数学地基。后面六讲的每个算法（PPO、DPO、GRPO）都是本讲那条公式 + 不同的修补。

读者假设：会加减乘除、知道 \(e^x\) 是指数函数就够了。不需要会微积分——「导数」会先解释成大白话，每个求导结论都配数值验证，你可以只用乘除跟着算。

场景收缩：本讲的问题是全系列最小的 RL 问题——只有一次动作、一个打分。第 2 讲再把它放大成「LLM 生成一整段回答」。

本讲目标：从「怎么让模型偏向高分动作」这个朴素愿望出发，推出 RL 的第一性公式 REINFORCE（策略梯度）：一次完整的手算更新；然后直面它最大的毛病——方差大到没法用——以及第一味药：baseline（减去平均分，把「绝对好坏」变成「比平均好多少」，即优势 advantage）。读完这讲，「好的加强、差的减弱」就不再是一句口号，而是一串你能亲手算出来的数字。

1. 场景：一个只会写标题的小模型

想象你有个电商产品：给商品起广告标题。你手头有三种风格可选：

  • \(A_1\)：疑问式——「还在为洗衣烦恼？」
  • \(A_2\)：数字式——「3 秒去污，10 人 9 夸」
  • \(A_3\)：感叹式——「太好用了吧！！」

每种风格有一个未知的真实点击率 \(r(A_1), r(A_2), r(A_3)\)。关键约束：事先不知道，只有把标题发出去、看用户点没点，才能拿到一次（带运气成分的）观测。没有「标准答案」可以照抄，只有「事后打分」——这正是第 0 讲说的 RL 和 SFT 的分界线。

这个问题在 RL 教材里叫多臂老虎机（bandit）：面对一台有三个拉杆的老虎机，哪个拉杆奖金多，只能拉了才知道。它砍掉了 RL 的全部复杂性（没有时序、没有延迟奖励），只留下最核心的一件事：在不知道各动作价值的前提下，如何调整「选择倾向」，让长期收益最大。策略梯度的一切都从这个最小场景长出来。

2. 朴素想法及其死胡同

最直觉的方案：每种风格都试一段时间，记住平均点击率，以后永远选最高的。这叫「贪心」。两个致命问题：

  1. 样本会骗人：A2 前三次恰好被点击，平均分虚高——它可能只是运气好。太早下结论会锁死在错误选择上（探索不足）；反过来，永远平均着试、不敢下注，又浪费流量（利用不足）。这就是经典的探索-利用两难，有一堆聪明解法（比如 ε-greedy：90% 选当前最优，10% 随机探索）。
  2. 对 LLM 场景直接失效：候选动作不是 3 种风格，而是所有可能的回答——天文数字，永远「试不完」。靠「每样试到再比较」的思路，在动作空间巨大时彻底破产。

需要换思路：不再「比较后硬选」，而是让「选择倾向」本身成为可学习的参数，用每次打分轻轻推它一把。这就是策略梯度。

3. 把选择变成概率：softmax 策略

给每个动作配一个可调的分数（术语叫 logit）：\(z_1, z_2, z_3\)。用第 0 讲提过的 softmax 把分数变成概率——「选择倾向」：

\[ \pi(a_i) = \frac{e^{z_i}}{e^{z_1} + e^{z_2} + e^{z_3}} \]

手算一遍。取 \(z = [1.0,\ 0.5,\ 0.0]\)：

动作分数 \(z_i\)\(e^{z_i}\)除以总和 5.367概率 \(\pi(a_i)\)
\(A_1\) 疑问式1.02.7182.718 / 5.3670.506
\(A_2\) 数字式0.51.6491.649 / 5.3670.307
\(A_3\) 感叹式0.01.0001.000 / 5.3670.186

参数 \(z\) 就是模型的可学习参数。所谓「训练」，就是根据每次的打分去微调这三个数。现在的核心问题是：一次观测（选了某个动作、得了某个分）之后，这三个数该往哪边调、调多少？

先说清「导数」后文反复出现梯度（记号 \(\nabla\)）。你只需要知道：梯度是一组数，每个参数一个，正号表示「这个参数调大对目标有利」，负号表示「调大不利」，数的绝对值表示「影响多大」。所以「算梯度」= 问每个参数「该往哪边拧」。

4. 推导 REINFORCE：三步走完

4.1 目标函数：期望奖励

我们想最大化的是期望奖励（按选择概率加权的平均得分）：

\[ J(\theta) = \sum_{i} \pi(a_i)\, r(a_i) \]

\(z\) 概率大、\(r\) 高的动作占的权重就大，\(J\) 就高。麻烦在于：\(r(a_i)\) 未知（只能试出来），所以没法直接对 \(J\) 求导。得绕一步。

4.2 关键变形：log-derivative 技巧

链式法则说 \(\nabla \log \pi = \frac{\nabla \pi}{\pi}\)，移项得到一个恒等式：

\[ \nabla \pi(a_i) = \pi(a_i) \cdot \nabla \log \pi(a_i) \]

代入目标函数的梯度：

\[ \nabla J = \sum_i \pi(a_i)\, r(a_i)\, \nabla \log \pi(a_i) \]

这个变形看着只是换个写法，实则点石成金：右边是「按概率 \(\pi\) 抽一个动作，用它的得分乘它的 \(\nabla\log\pi\)」这种随机量的平均值（数学行话：期望）。期望不用知道全貌，抽样就能估——而「按 \(\pi\) 抽动作、观测得分」，恰好就是我们手上唯一能做的事。于是得到可操作的更新规则，这就是 REINFORCE 算法（1992 年提出，所有策略梯度方法的老祖宗）：

\[ \boxed{\; z \leftarrow z + \mathrm{lr} \cdot r \cdot \nabla \log \pi(a) \;} \]

大白话：按当前倾向抽一个动作 → 看打分 → 分数越高，越用力把「选中它」的概率往上推；分数为负就反着推。推多狠，既正比于得分 \(r\)，也正比于 lr（学习率，步长旋钮）。

为什么非要绕 log\(\nabla\pi\) 和 \(\pi\nabla\log\pi\) 数学上完全等价，但 log 形式把「梯度 = 可采样的期望」这个结构显式化了：它天然对接「抽一次样就估一次梯度」的工作方式，并且能原封不动推广到「一条回答由几百个 token 连续采样组成」的场景（第 2 讲）。log-derivative 技巧是全部策略梯度方法的阀门。

4.3 softmax 的梯度长什么样（数值验证）

更新规则里还剩一个零件没算出：\(\nabla\log\pi(a)\)。对 softmax 策略，有个极好记的结论：

\[ \nabla_{z_j} \log \pi(a) = \mathbf{1}\{j{=}a\} - \pi(j) \]

读法：对第 \(j\) 个分数求导——\(j\) 恰好是被选中的动作时结果是 \(1-\pi(j)\)，否则是 \(-\pi(j)\)。向量形式记作 \(\,e_a - \pi\)（onehot 减概率）。直觉：把被选中者的概率往上顶、其余按各自的体量往下匀，「总和为 1」的守恒。

不用背，我们用乘除验证它。取初始 \(z = [0, 0, 0]\)，则 \(\pi = [1/3, 1/3, 1/3]\)。给 \(z_1\) 加一个很小的 0.1：

步骤算式结果
新概率\(e^{0.1} = 1.10517\)，总和 \(= 1.10517 + 1 + 1 = 3.10517\)\(\pi_1' = 1.10517/3.10517 = 0.35594\)
\(\log\pi_1\) 的变化\(\ln(0.35594) - \ln(0.33333) = \ln(1.06782)\)\(+0.06564\)
数值斜率\(0.06564 / 0.1\)0.656
公式预测\(1 - \pi_1 = 1 - 1/3\)0.667 ✓（小差值来自 0.1 不够小）

交叉项也验一下：\(z_1\) 上涨时 \(\log\pi_2\) 怎么变？新 \(\pi_2 = 1/3.10517 = 0.32204\)，\(\ln(0.32204/0.33333) = -0.03447\)，斜率 \(-0.345\)，公式预测 \(-\pi_2 = -1/3 = -0.333\) ✓。两个方向都吻合，\(\,e_a - \pi\) 这个结论可以放心用。

5. 完整手算一次 REINFORCE 更新

万事俱备，把第 3、4 节的数字串成一次真实更新。设定：当前分数 \(z = [1.0,\ 0.5,\ 0.0]\)，概率 \(\pi = [0.506,\ 0.307,\ 0.186]\)（第 3 节手算的）。这一步抽中了 \(A_2\)（数字式），市场反应好，得分 \(r = +3\)。学习率 \(\mathrm{lr} = 0.1\)。

步骤算式结果
① 梯度向量\(e_{A_2} - \pi = [0,1,0] - [0.506, 0.307, 0.186]\)\([-0.506,\ 0.693,\ -0.186]\)
② 乘上得分\(r \times ① = 3 \times [-0.506,\ 0.693,\ -0.186]\)\([-1.519,\ 2.079,\ -0.559]\)
③ 更新分数\(z + 0.1 \times ② = [1.0 - 0.152,\ 0.5 + 0.208,\ 0 - 0.056]\)\([0.848,\ 0.708,\ -0.056]\)
④ 新概率对新 \(z\) 重算 softmax（\(e^{0.848}=2.335\)，\(e^{0.708}=2.030\)，\(e^{-0.056}=0.946\)，总和 5.310）\([0.440,\ 0.382,\ 0.178]\)

看变化：\(A_2\) 的概率 0.307 → 0.382（上升）；两个落选者都下降，且按原有体量分摊——\(A_1\)（原来概率最大）降得最多（0.506 → 0.440），\(A_3\) 只微降 0.008。这正是 \(e_a - \pi\) 的守恒直觉：加分是定向的（只加给 \(A_2\)），但概率总和必须为 1，多出来的份额按比例从别人那里匀。

用代码验证（数字与手算完全一致，你可以现在就跑）：

import numpy as np

z = np.array([1.0, 0.5, 0.0])
pi = np.exp(z) / np.exp(z).sum()      # [0.506, 0.307, 0.186]
a, r, lr = 1, 3.0, 0.1                # 采样到动作 1（A2），奖励 +3
onehot = np.eye(3)[a]

z = z + lr * r * (onehot - pi)        # REINFORCE 一步更新
print(np.exp(z) / np.exp(z).sum())    # [0.440, 0.382, 0.178]

图 1-1｜REINFORCE 闭环。与第 0 讲图 0-2 逐环对应——只是把「模型」具体化成了「softmax 概率」、把「更新」具体化成了一条能手算的公式。

6. 最大的敌人：方差

公式是有了，但直接用它训练会立刻撞墙。两个来源的抖动：

  1. 打分本身带运气：\(A_2\) 真实点击率 0.5，但单次投放的结果是「点了 / 没点」二值——同样是发 \(A_2\)，这次更新推 \(+10\)，下次拉 \(-10\)（假设 10 分制），参数被来回猛拽。
  2. 推的方向和力度全靠单次采样：本讲为了简单，一次只抽一个动作；抽到谁，梯度就长什么样。多次采样之间的差异，全部变成了更新的噪声。

「梯度估得很准，但每次估出来的值都在大幅跳动」——这个性质叫高方差。后果是训练曲线剧烈震荡、对学习率极端敏感：步子大了荡秋千，步子小了挪不动。策略梯度研究的一半历史，就是在跟方差作斗争。本讲讲第一味药。

7. 第一味药：baseline 与优势（advantage）

7.1 数学上白送的性质

把更新公式里的得分 \(r\) 换成 \(r - b\)（\(b\) 是任意一个不依赖于本次抽到哪个动作的数，称为 baseline），梯度期望一模一样。一行证明：添加的那项是 \(-b \sum_i \pi(a_i)(e_{a_i} - \pi)\)，而 \(\sum_i \pi(a_i)\, e_{a_i} = \pi\)（概率自己加权自己），所以整个中括号 \(= \pi - \pi = 0\)。

期望不变，那图什么？图方差变小。数学上可以严格证明（本讲不推），选合适的 \(b\) 能把单次估计的抖动压下来；最常用的选择就是平均分 \(b = \mathbb{E}[r]\)。感受一下效果——沿用 3 动作的设定（\(\pi = [0.5, 0.3, 0.2]\)，三种动作的真实平均分分别是 1、3、5，总体平均 \(\mathbb{E}[r] = 2.4\)），看连续四次采样（抽到 \(A_1, A_3, A_1, A_3\)）各自给出的「更新幅度」：

采样序列得分 r不减免新幅度 \(\|r \cdot (e_a-\pi)\|\)减免新幅度 \(\|(r-2.4)\cdot(e_a-\pi)\|\)
抽中 \(A_1\)10.620.86
抽中 \(A_3\)54.952.57
抽中 \(A_1\)10.620.86
抽中 \(A_3\)54.952.57

不减免新的幅度在 0.62 和 4.95 之间跳（8 倍悬殊）；减免新在 0.86 和 2.57 之间（3 倍）。悬殊小了，参数就不会被单次「大分」甩来甩去。 averaged 之后两者殊途同归（期望相同），但抖动小的那条路走得稳。

7.2 更重要的是：信号从「全是正」变成「有正有负」

很多真实场景里打分没有负数（点击 1~10 分、验证通过 1 分、失败 0 分）。不减 baseline 时，每个被抽中的动作都在被「加强」，只是力度不同——所有加强互相抵消，净信号小、噪声大。减掉平均分后，信号立刻有了方向：

图 1-2｜baseline 的真正价值：把「绝对得分」变成「相对平均的优势」。右图橙条方向向下——差于平均的动作不再被温和加强，而是被明确削弱。「减掉平均后的得分」就叫优势（advantage，\(A = r - b\)）：它回答的不是「这次得分多少」，而是「这次比平均水平好多少」。

术语诞生 \(A = r - b\) 叫优势（advantage）。这个名字后面处处出现：第 3 讲里 PPO 用一套精细方法（GAE）估计每个时间步的优势；第 5 讲里 GRPO 的做法朴素直接——同一个问题采样一组回答，用「组内平均分」当 baseline。万变不离本讲。

8. 回望与预告：本讲在这张地图上

把本讲得到的零件登记一下，后面每一讲都从这里取件：

本讲得到的一句话后面哪里用到

log-derivative 技巧把梯度改写成「可采样估计的期望」第 2 讲：整条回答的 \(\sum_t \log\pi\) 直接可用

同时登记两笔「欠账」：① 打分只在结尾给一次，而一条回答有几百个 token——功劳怎么分摊到每个 token（第 2 讲引出、第 3 讲 GAE 解决）；② 单次打分带运气、采样带噪声——除了 baseline，还能用「重要性采样」回收旧数据降低成本（第 3 讲 PPO 的出发点）。

9. 自查清单

下面 8 个问题都能不假思索地回答，就可以进入第 2 讲：

  1. 为什么「试到平均分最高再固定选它」对 LLM 场景失效？（答：动作空间是所有可能回答，天文数字，试不完）
  2. softmax 策略里「参数」是什么？（答：每个动作的分数 \(z\)，softmax 把分数变成选择概率）
  3. 策略梯度为什么要绕道 \(\log\pi\)？（答：log-derivative 恒等式把梯度变成「按 \(\pi\) 采样可估计的期望」，对接「抽一次样更新一次」）
  4. REINFORCE 的更新公式？（答：\(z \leftarrow z + \mathrm{lr}\cdot r\cdot(e_a - \pi)\)，softmax 下 \(\nabla_{z}\log\pi(a) = e_a - \pi\)）
  5. \(e_a - \pi\) 的直觉？（答：顶高被选中者，按体量匀低其余，总和守恒）
  6. 策略梯度最大的毛病？（答：方差大——打分带运气、单次采样抖动，训练震荡）
  7. baseline 为什么不改变梯度期望、却值得用？（答：\(\sum_i \pi(e_{a_i}-\pi) = 0\)，期望不变；方差显著下降，信号从「全正」变「有正有负」）
  8. 优势 advantage 的定义和含义？（答：\(A = r - b\)，回答「比平均好多少」而非「绝对得分多少」）
下一篇第 2 讲：把 LLM 接上 RL——把本讲的「一次动作」放大成「生成一整段回答」：token 是动作、上下文是状态、整条回答共享末尾一个奖励。你会看到 LLM 的 RL 梯度雏形（对每个 token 的 log 概率求梯度、乘同一个奖励），认识两件新装备：当缰绳用的 KL 散度（含工程里真实使用的 k3 估计器）和控制探索的温度。读完它，「语言模型怎么就成了 RL 问题」不再是比喻。
