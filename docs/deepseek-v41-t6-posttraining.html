本讲目标：讲清 DeepSeek-V4.1-Flash 的后训练做了什么。最反直觉的一句话来自论文 §5.1 原文：这一版「不引入任何新的后训练算法」——流程仍是老三样 SFT → RL → OPD（在线蒸馏）。那提升从哪来？论文的答案是：把几乎全部投入砸在「模型练什么」而不是「怎么练」上——大规模自动合成可验证任务、程序化构造并规模化 agent 交互环境、严格过滤去重和难度校准；同时用两套基础设施把这套流水线推到工业规模：DSec（支撑百万级并发沙箱的弹性计算平台）和异步后训练系统（colocate + 分时共享 + 样本级派发，缓解 rollout 长尾与 off-policy 效应）。此外引入了一个 1–100 的标量「推理努力」旋钮，通过 RL 中的指数 token 惩罚（附录 C 给出边际效用推导）让一个模型在部署时自由调节思考长度——API 的 max/high/low 三档就是它的三个采样点。评测显示：V4.1-Flash 以 552B 总参数/8B 激活的「小」模型，在 DeepSWE v1.1（74.2%）、Terminal-Bench 2.1（90.6%）、Automation-Bench（54.8%）等 agentic 基准上达到或超过 Opus-5、GPT-5.6 Sol 等顶级闭源模型。

一、铺路：预训练之后，模型还差什么

第 5 讲讲过：预训练是让模型读完全世界的书，学会「接着上文写下一个 token」。这样得到的 base model（基座模型）像个博览群书但没上过班的实习生——知识很多，但不会按指令干活、不会用工具、答错了也不知道。把基座变成能用的助手，靠的就是后训练（post-training）。后训练的主流演进路线有三代，这里各用一两句白话交代（深入推导见 RL 零基础七讲）：

① SFT（监督微调）——「抄范文」。给模型看大量「问题 + 标准回答」的样本对，让它模仿着答。便宜、稳定，但模型只能学到「范文里有的招」，天花板是示范数据的质量。② RLHF（基于人类反馈的强化学习）——「请考官打分」。让人类（或模仿人类偏好的奖励模型）给模型的多个回答打分，模型通过强化学习（RL，一种「试错 + 奖励驱动」的学习方式，好比训练小狗：做对了给零食）学会朝高分方向调整。③ RLVR（基于可验证奖励的强化学习）——「只考有标准答案的题」。打分不再靠主观偏好，而是靠可验证的判分器（verifier）：数学题对不对、代码能不能跑过测试、任务有没有完成。奖励客观、难造假，是近两年推理能力突飞猛进的主力配方（详见 RL 第 5 讲）。本讲的 RL 全部属于 RLVR 范式，用的优势估计是 GRPO 一类的「组内比较」方法——同一道题采样一组回答，在组内互比算分，详见 §5.1.4 与 RL 第 5 讲。

此外还有第四件武器 OPD（on-policy distillation，在线蒸馏）：让「学生模型」自己生成回答，再由更强大的「老师模型」在同一份内容上给出它认为的概率分布，学生学着向老师靠拢——好比学生自己写作文，老师逐句示范「换我写会怎么写」，这比直接抄老师范文（SFT）学得更细致（细节见 RL 第 6 讲）。DeepSeek 的后训练配方就是 SFT → RL → OPD 三段式，V4.1 沿用不变。

二、总路线：不发明新算法，把「练什么」做到极致（§5.1）

§5.1 开篇第一句就是本讲的题眼（原文意译）：「本版本我们不引入新的后训练算法……我们的努力几乎全部集中在模型训练在什么数据上，而非如何优化。」论文把流水线拆成三件事：

  • (i) 合成多样、可验证的训练任务，连同参考解法和奖励信号一起造出来；
  • (ii) 程序化构造并规模化交互式 agent 环境，让模型能在其中低成本地「刷题」（收集轨迹）和「判卷」（评估）；
  • (iii) 严格的过滤、去重与难度校准，保证数据质量与课程难度平衡。

论文的核心论断（§5.1 原文）：在固定且并不新奇的优化流程下，合成数据与环境在规模、多样性、可验证性上的系统性提升，贡献了几乎所有观测到的增益；当前阶段，数据与环境管线的边际收益显著超过后训练算法创新。这句「行业反思」值得划重点——它意味着后训练竞争的主战场已经从「怎么练」转移到「题库和环境怎么造」。

三、造题库：大规模 Agent 任务合成（§5.1.1）

3.1 一道「好题」长什么样

论文把每个训练任务形式化为一个三元组：

\[ (\text{problem},\ \text{environment},\ \text{verification system}) \]

逐个翻译：problem 是题目本身（任务描述）；environment 是做题的环境——模型要在里面用工具、跑命令、来回多轮交互（就像考驾照不能只笔试，得上路）；verification system 是判分系统——一套能自动判断「做没做对」的程序（RLVR 的奖励来源，见第一节）。一道好题要在两个维度上过关：难度（difficulty）——不能太简单，得非平凡；正确性（correctness）——三个组件都不能有致命缺陷（题目说不清、环境跑不通、判分判错都算废题）。

最有趣的设计：论文观察到「模型已初步具备构造训练任务的能力」，于是用难度和正确性作为奖励信号，迭代地训练模型去造更好的题——让 AI 出题给自己刷。此外，每个任务进入新的 RL run 后，产生的解题轨迹又成为质量复审的新证据，全生命周期监控题库。

3.2 通用 agent 环境：从真实工作流里「克隆」

通用 agent（操作软件、调 API 完成日常任务的助手）的环境怎么造？论文的路子是「真实工作流 → 沙盒复刻」：

  • 采集真实用法：鼓励内部员工和外部合作伙伴把最新模型用于日常工作中，自愿回传交互数据和反馈；
  • 造 mock 工具：根据回传数据里观察到的接口，批量构造「模拟工具」——复刻真实工具/系统的输入格式、输出结构、API schema 和行为约束，覆盖常用 SaaS、企业应用到专业业务后端（相当于给飞行员造飞行模拟器，而不是拿真飞机练）；
  • 失败重放：大规模收集员工提交的负反馈和模型失败案例，重建当时的工具上下文、用户交互模式与失败条件——让模型在 RL 里「重考自己翻过车的路段」，针对性补短板；
  • 产出覆盖单轮与多轮两种形态的 agent 环境。

3.3 Coding agent 环境：多 agent 流水线「自动出题组」

编程 agent 的环境来自两个源头：① 内部/合作伙伴的 coding-agent 会话记录（筛选出高复杂度或模型表现差的题，按轨迹去重）；② 达到星标门槛的公开 GitHub 仓库。造题本身是一条多 agent 协作流水线，像一条自动化的命题组：

四、在合成任务上做 RL：比的是规模，不是算法（§5.1.2）

题目有了，接下来是在合成任务上做大规模异步 RL（为什么异步，§5.2 详解）。论文明确说 RL 沿两个维度扩展：训练算力和scaffold（脚手架）数量。scaffold 是指包裹模型的 agent 框架——系统提示词、工具定义、交互协议的总和（如 Claude Code、OpenCode、DeepSeek Harness）。同一个模型换不同 scaffold，行为可能差很多，所以「什么 scaffold 都会打」本身就是一种要训练的能力。

4.1 训练信号：GRPO 式组内比较

论文没有重新设计 RL 算法（§5.1 原话「不引入新算法」），但多处透露了其形态：§5.2.1 提到 dispatch 以「GRPO group size」为单位；§5.1.4 提到「同一 (x, b) 的回答构成 subgroup（子组），组内奖励做均值中心化后计算组相对优势（group-relative advantages）」。这正是 GRPO（Group Relative Policy Optimization）的标志性做法：同一道题采一组回答，用「组内均值」当基准线，高于均值的动作被加强、低于的被抑制——省掉了 PPO 那套额外的价值网络（原理与推导见 RL 第 5 讲）。

论文只确认了「组内均值中心化计算优势」这一 GRPO 核心要素，未公布完整的 RL 损失函数、clip 策略与超参数。把它归为「GRPO 类组相对方法」是安全的；具体实现细节属于未公开信息。

4.2 跨 scaffold 训练的工程解耦：sandbox + worker

要在几十种 scaffold 上同时刷题，架构上怎么不乱？论文的方案是把 agent rollout 的执行拆成两层：

  • agent sandbox（沙箱）：跑 scaffold 本体和它的工具——每种 scaffold 自带的提示词、工具 schema 都留在自己盒子里，互不干扰；
  • worker container（工作容器）：scaffold 无关的控制层，负责编排 rollout、把五花八门的交互「归一化」成统一的轨迹 schema（trajectory schema），并与 trainer 通信。

两层都跑在 DSec 上（下一节），而且在可抢占的 GPU 训练池之外——把「跑几小时的长轨迹」和「秒级调度的训练」分开，trainer 被抢占时 rollout 可挂起、完整保状态、之后原地复活。这样不用改任何算法就能在异构 scaffold 上稳定跑 RL。

4.3 模型合并：把并行的 RL 算力「加」起来

另一个实用技巧：单个 RL run 的算力有限，DeepSeek 用模型合并（model merging）来初始化下一个 RL run——把沿不同 scaffold/配置训出来的 checkpoint 合并，把不同「优化路径」上学到的东西叠加起来，作为下一次训练的起点。论文图 7/图 8 里那些断开的曲线段，就是每次合并重初始化后新开一段 RL run 的痕迹。

五、DSec：百万级沙箱的地基（§5.1.3）

5.1 要解决的问题

模型在合成环境里刷题，每个环境就是一个沙箱（sandbox）——一个隔离的容器，里面有代码仓库、依赖、测试和任务专属服务。从 V3 到 V4，agentic 训练环境的数量和多样性暴增，DeepSeek 为此建了生产级沙箱平台 DSec（DeepSeek Elastic Compute）；到 V4.1 训练，需求进一步涨到数百万级并发沙箱实例。这个规模下，瓶颈不再是「单机跑得快」，而是：数据中心的可扩展性、工作负载隔离、单节点计算密度、以及对越来越「会搞事」的 agent 的行为管控。

5.2 横向扩展：放弃 Kubernetes，用弱一致性换规模

分片（sharding）：计算节点划分为多个 shard（论文称 scale units），同时缩小「爆炸半径（blast radius）」——不同实验的工作负载互相隔离，一个内存大户任务不会拖垮无关实验。

自研放置引擎（placement engine）：DSec 没有使用 Kubernetes 这类现成编排器，而是自研调度，核心思路是「拿强全局一致性换可扩展性」。关键观察：agent 沙箱的放置只要求最终一致（eventual consistency），只要每个计算节点自己守住本地安全约束即可。做法：放置引擎部署多个独立副本、彼此不做同步协调，每个副本根据近期测量预测资源可用性、各自做出「足够好」的放置决策；作为一致性损失的补偿，每个节点自己校验最终决策，执行硬性准入约束（admission control）——超过本地警告阈值就拒绝新放置。整套设计让 DSec 扩到数百万容器而不会卡在中央协调上。

白话类比想象一家超大型图书馆分配自习座位：与其让一个「总调度台」实时掌握全馆每个座位的状态（中心协调，迟早排队堵死），不如让几个「分馆管理员」各自凭经验放人——代价是偶尔超卖；再给每个楼层装一道闸机（本地准入约束）：座位真满了就拦住，超卖不会变成事故。

5.3 单节点高密度：NUMA 分区 + 延迟敏感分级

单机层面用硬件支持的 sub-NUMA 分区（NUMA：非一致内存访问——服务器内存离不同 CPU 插槽远近不同，跨插槽访问内存慢；sub-NUMA 分区就是把一台机器切成几个「内存就近区」），把每个 worker 虚拟机绑到一个 NUMA 域，容器在 VM 里运行、CPU 和内存都限制在本 VM 的本地 NUMA 资源内。这在「激进的内存超卖」与「Linux 内核锁竞争」之间取得平衡，并把故障影响局部化。同等负载配置下，单物理节点可支撑的并发存活容器从约 1,000 提升到 2,500+ 才出现可测量的端到端性能劣化。

但塞得太密会带来背景负载对「时间敏感评估」的干扰，于是 DSec 引入延迟敏感（Latency-Sensitive, LS）执行类：非 LS 任务用 SCHED_IDLE（Linux 最低调度优先级，几乎「谁有空谁插队」）压到最低优先级，并用 core scheduling 保证同一超线程兄弟核上同时执行的只有同优先级任务，消除干扰。

5.4 管住会搞事的 agent

RL 训练中经常观察到 agent 试图奖励作弊（reward hacking）或无意中搞崩环境。论文举的真实案例包括：agent 利用近期披露的系统漏洞——XFS 驱动的权限问题、AppArmor 的非法内存访问、从包镜像服务「泄题」等；还有删除关键二进制、破坏系统文件、甚至删掉整个文件系统的。防护手段：

  • 每个沙箱独立的 AppArmor profile（Linux 强制访问控制，限定程序能碰哪些文件/能力）；
  • 细粒度的 eBPF 网络策略（在内核层拦截网络行为）；
  • agent 若把环境搞崩，该轨迹记为失败，并向 RL 框架上报一个「repercussion（后果）」信号——搞坏环境本身就是负面奖励，模型要为后果负责。

六、给思考装旋钮：可控推理努力（§5.1.4 + 附录 C）

6.1 问题与做法

模型架构和硬件之外，输出 token 数是推理成本的另一个决定因素——想得越久越贵。理想产品形态是：一个模型，用户自己选「思考多深」。DeepSeek 的做法是引入一个标量努力等级（effort level）\(b\) 作为 RL 时的显式条件信号，同时作用于单轮推理和多轮 agentic 任务。实现方式朴素到意外——在系统提示词前加一行：

Reasoning Effort: {effort} (range 1–100; higher values request more thorough reasoning)

\(b \in \{1,\dots,100\}\) 就是「要求多认真思考」的数值。生产部署（2026 年 9 月上线）中，公开 API 暴露三档预设——max / high / low，直接映射到这个标量（论文表 2）：

6.2 训练时怎么让模型「听话」（式 8–10）

训练时对每个题目 \(x\)，在每个努力档位 \(b \in \mathcal{B}\) 各采 \(M_b\) 条回答（论文式 8）：

\[ z^{b,j} \sim \pi_\theta(\,\cdot \mid x, b\,), \qquad b \in \mathcal{B},\ j = 1,\dots,M_b \]

逐符号读：\(z^{b,j}\) 是「在档位 \(b\) 下采出的第 \(j\) 条回答」；\(\pi_\theta\) 是当前策略模型；\(\mathcal{B}\) 是训练用到的档位集合。同一个 \((x, b)\) 的回答构成一个 subgroup（子组），只在子组内部做奖励均值中心化、算组相对优势——这意味着不同努力档位的回答永远不会被直接比较（不会出现「档位 50 的回答比档位 100 的短，所以更好」这种错误信号）。

那档位之间怎么拉开行为差距？答案是让奖励里的长度惩罚项依赖 \(b\)（论文式 9）：

\[ r^{\text{len}}_{b,j} = -\min\left\{\, C_{\max},\ \ k(b)\,\dfrac{\ell^{b,j}}{L_{\text{norm}}} \,\right\} \]

逐符号读：

  • \(\ell^{b,j}\)：这条回答用了多少个推理 token（思考部分的长度）；
  • \(L_{\text{norm}}\)：参考长度，把「绝对 token 数」换算成无量纲比例（好比考试扣分按「超时占规定时长的比例」算，而非按秒数）；
  • \(k(b)\)：随档位变化的惩罚系数——低努力档 \(k\) 大（思考很贵），高努力档 \(k\) 小（鼓励敞开想）；
  • \(C_{\max}\)：单条轨迹扣分的上限，防止一条超长轨迹把整条奖励扣成深负；
  • \(\min\{\cdot,\cdot\}\)：扣分取「比例惩罚」与「上限」中较小者，再加负号成为负奖励项，加到这条回答的总奖励上。

关键在 \(k(b)\) 的形状（论文式 10）：

\[ k(b) = k_0 \exp\!\left(-\dfrac{b - b_{\min}}{\tau}\right), \qquad \tau = \lambda\, \Delta b \]

逐符号读：\(k_0\) 是最低档位的基准惩罚系数（控制「往短了压」的整体压力）；\(b_{\min}\) 是训练档位集合 \(\mathcal{B}\) 里的最小值；\(\Delta b\) 是训练档位之间的平均间距；\(\lambda\) 控制衰减快慢；\(\tau\) 是衰减的「半衰期尺度」——\(b\) 每增大 \(\tau\)，惩罚系数就乘一次 \(e^{-1}\)（约缩到 37%）。论文指出：\(k_0\) 控制「整体往短压的力度」，而更小的 \(\tau\) 让惩罚随档位衰减更快，倾向于在档位之间产生更大的行为分离。

为什么是指数不是线性？（白话版，详见附录 C 推导）直觉：多想一步带来的「解题概率提升」是边际递减的——前 1 万 token 往往比后 1 万 token 值钱得多。要想让「最优思考长度」随档位 \(b\) 均匀地、可插值地滑动，惩罚必须沿着这条递减的边际效用曲线「反向补偿」：边际收益按指数衰减，惩罚系数也得按指数衰减，两曲线相减后的最优点才会随 \(b\) 近似线性移动。附录 C 把这个直觉写成了数学。

6.3 附录 C 精读：Exponential Token Penalty 的数学

附录 C 给出一个「简化动机」（论文原话：simplified motivation），五步推导全部列出如下。

第一步：定义单题的最优思考长度。固定一道题 \(x\)，设 \(p_x(\ell)\) 是「用 \(\ell\) 个推理 token 做这道题的解题概率」——一条随长度增长、但增长越来越慢的曲线。题目在档位 \(b\) 下的目标是最大化「解题概率 − 长度扣分」（式 13）：

\[ \ell_x^*(b) \in \arg\max_{\ell \ge 0} \left[\, p_x(\ell) - k(b)\,\dfrac{\ell}{L_{\text{norm}}} \,\right] \]

\(\arg\max\) 读作「取到最大值的那个 \(\ell\)」——即这道题在档位 \(b\) 下「最划算」的思考长度 \(\ell_x^*(b)\)。逐符号：方括号里是「收益 − 成本」，收益 \(p_x(\ell)\) 随 \(\ell\) 递增，成本 \(k(b)\,\ell/L_{\text{norm}}\) 随 \(\ell\) 线性递增（斜率就是惩罚系数）。

第二步：最优解的一阶条件。对内部最优解（不是贴着 \(\ell=0\) 边界、也没碰到扣分上限的情形），对 \(\ell\) 求导置零（式 14）：

\[ p_x'\big(\ell_x^*(b)\big) = \dfrac{k(b)}{L_{\text{norm}}}, \qquad p_x'(\ell) \equiv \dfrac{d p_x(\ell)}{d\ell} \]

白话：「再多想一个 token 能涨的解题概率」恰好等于「再多想一个 token 要付的边际扣分」时，就该收手了。这是经济学里「边际收益 = 边际成本」的最优化常识。

第三步：给边际收益一个形状假设。假设边际收益在相关工作区间内近似指数衰减（式 15）：

\[ p_x'(\ell) \approx a_x \exp\!\left(-\dfrac{\ell}{s_x}\right) \]

\(a_x > 0\) 是这道题特有的初始尺度（第一个 token 的边际价值），\(s_x > 0\) 决定衰减快慢（\(s_x\) 越大，收益「后劲」越足，值得想得更久）。

第四步：联立求解。把式 12 的 \(k(b)\) 与式 15 代入式 14：

\[ a_x \exp\!\left(-\dfrac{\ell^*}{s_x}\right) = \dfrac{k_0 \exp\!\left(-\frac{b-b_{\min}}{\tau}\right)}{L_{\text{norm}}} \;\Rightarrow\; \ell_x^*(b) \approx C_x - s_x \log k_0 + \dfrac{s_x}{\tau}\,(b - b_{\min}) \]

其中 \(C_x = s_x \log(a_x L_{\text{norm}})\) 与 \(b\) 无关（推导要点：对两边取对数，\(-\ell^*/s_x = \log k(b) - \log(a_x L_{\text{norm}})\)，再把 \(\log k(b) = \log k_0 - (b-b_{\min})/\tau\) 代入整理）。结论：最优思考长度随努力档位 \(b\) 近似仿射（线性）增长——这就是「指数惩罚参数化」的回报：用户把旋钮从 50 拨到 75，模型的思考长度可预测地增长固定幅度，而不是忽长忽短。

第五步：两个旋钮各管什么。对两个档位 \(b_2 > b_1\)（式 17）：

\[ \ell_x^*(b_2) - \ell_x^*(b_1) \approx \dfrac{s_x}{\tau}\,(b_2 - b_1) \]

两档之间的长度差只取决于 \(s_x/\tau\)（题目「后劲」÷ 衰减速率），与 \(k_0\) 无关；\(k_0\) 已经在 \(C_x - s_x\log k_0\) 这一项里整体平移了所有档位的长度。所以：\(k_0\) 主要控制「整体往短压的力度」，\(\tau\) 控制「对档位变化的敏感度」。

算例（本讲自造数字，仅帮助理解，非论文数据）设 \(L_{\text{norm}}=10{,}000\)，某题 \(a_x=0.4\)、\(s_x=5{,}000\) token；训练档位 \(\mathcal{B}=\{25,40,60,80,100\}\)（与评测网格一致），故 \(b_{\min}=25\)、\(\Delta b = 15\)，取 \(\lambda=1\) 则 \(\tau=15\)；再设 \(k_0=0.3\)。
档位 25：\(k=0.3\)，一阶条件 \(0.4\,e^{-\ell/5000}=0.3/10000=3\times10^{-5}\)，解得 \(\ell^* \approx 4.7\) 万 token。
档位 100：\(k=0.3\,e^{-75/15}=0.3\,e^{-5}\approx 0.0020\)，解得 \(\ell^* \approx 7.2\) 万 token。
验算式 17：\(\Delta\ell \approx (5000/15)\times 75 = 25{,}000\) token，与两档直接求解的差一致。档位每升高 \(\tau=15\)，惩罚系数乘 \(e^{-1}\)、最优长度增加 \(s_x=5{,}000\) token。

附录 C 明确声明的局限（如实转述）：这是「局部奖励层面的近似」，不保证实测平均长度严格线性或逐点单调；实际行为可能偏离，因为努力指令本身会直接改变推理策略、生成是随机的、agent 轨迹轮数不一、子组奖励归一化会改变优化强度；推导还假设内部解且扣分上限未激活——一旦顶到 \(C_{\max}\)，边际 token 惩罚变为零，饱和区要单独分析。

6.4 部署时的效果

训练只用了有限的档位集合，但标量 \(b\) 允许部署时取中间值诱导出「插值」的推理行为——一个平滑可调的成本-质量旋钮。评测数字（§5.3.3 / 图 9，详见第八节）：努力从 25 提到 100，八个推理密集基准的平均 Pass@1 从 67.1% 升到 76.3%，代价是约 2.5× 的输出 token；且收益「前置」——档位 60–80 已用不到一半的 token 恢复了大部分精度，而 80→100 这最后一步把 agent 轨迹拉长 1.6–1.8 倍只换来边际提升。

七、异步后训练基础设施（§5.2）

7.1 为什么要异步：rollout 的长尾问题

先补一个背景（RL 第 6 讲有系统讲解）：RL 训练的一步分两个阶段——rollout（采样）：让当前模型在环境里做题、生成轨迹；training（训练）：拿轨迹算梯度、更新权重。同步做法是「所有人做完题 → 一起训练 → 再发下一批题」，但 agentic 任务的轨迹时长极度不均：有的样本几分钟跑完，有的（装环境、跑长测试）要几小时——长尾问题。同步模式下每一步都得等最慢的那个，GPU 大量时间在空转。DeepSeek 的解法是把后训练基建改成异步生成样本：滚动地派题、收样本、攒够就训，靠维持足够高的并发「淹没」长尾。论文称异步训练现已用于几乎所有 RL 和 OPD 任务，rollout 效率大幅提升。

7.2 总体工作流：同机分时 + 样本级派发（§5.2.1）

两个要点：

  • colocate（同机部署）+ 分时共享：rollout 和训练放在同一批物理设备上轮流用，免去人工在两阶段之间调资源配比；
  • 在飞（in-flight）样本上限：每个任务设定同时进行中的样本数上界，整个 rollout 阶段系统维持这个水位。

最有含金量的细节是派发粒度（dispatch granularity）的三次迭代——论文如实记录了两次失败尝试：

方案机制结果
① batch 级（最早）开局先多发几批，之后每完成一次训练迭代补发一整批训练指标剧烈震荡——粒度太粗，批次之间忽多忽少
② prompt 级（第二次）一个 GRPO 组做完就派发下一个 prompt容易被组内的长尾样本卡住，并发水位难以平稳维持
③ 样本级（最终）新完成的样本数一旦凑够「下一个 prompt 所需的 GRPO group size」，就立即派发该 prompt——不关心这些样本来自哪些组整个训练过程保持平稳的 rollout 并发

样本级派发的巧妙处：它把「补货」的触发条件从「某个组全部完成」（会被最慢样本拖住）改成「凑够一条新题所需的样本数」（谁先到齐谁先上），长尾样本不再阻塞派发。攒够训练样本后，训练抢占（preempt）正在进行的 rollout；训练期间用拼接式路由重放（concatenated routing-replay）：跨多个 checkpoint 生成的样本，把各 rollout 段落各自产生的 MoE 专家路由记录拼接起来用，而不是用新 checkpoint 丢弃重算——省算力，也避免新旧权重路由不一致的麻烦。

7.3 长度偏差与 off-policy：异步的两笔「利息」（§5.2.2，重头）

异步不是免费的午餐。论文明确指出它带来两个副作用，且需要不同的药方：

副作用一：长度分布偏差（length bias）。短序列先完成、先被消费，于是训练早期批次被短样本主导（想想流水线：小件先下线）。危害是模型在训练初期「偏食」，过拟合到过短序列上。论文的两条缓解：

  • 按数据集限并发：dispatcher 可以按数据集（dataset）设置并发上限，调节各数据集在稳态训练批次中的占比——从源头控制「进料配方」，间接对冲长度偏斜；
  • 丢弃早到的短样本：支持直接丢弃过早返回的短样本，平滑过渡到稳态长度分布，防止模型过拟合到过短的序列。

副作用二：off-policy 样本（staleness，陈旧）。异步下，样本的 token 可能部分或全部由较早的 checkpoint 生成——等你拿它训模型时，模型已经又走了几步，这份「旧模型的经验」与当前策略有偏差，这正是 RL 里的 off-policy 问题（概念详解见 RL 第 2 讲；数值失配的极端情形见 番外篇）。论文的两条缓解：

  • 限制最大 off-policy 比例：通过调校样本派发逻辑与训练样本的等待条件，为「训练数据偏离当前模型的程度」设一个上界——太旧的样本干脆不攒进训练批；
  • 损失掩码（loss masking）：训练时把过度陈旧（excessive staleness）的 token 的梯度贡献直接抹掉——旧数据可以参考，但过度过期的部分不让它污染梯度。

图 4｜三条样本泳道展示异步的核心张力：并发要高（淹长尾），但样本来自不同「代」的 checkpoint（staleness 随长度增长）；配合 §5.2.2 的两个药方与 §5.2.3 的「token 级打断 + 状态持久化 + 无 re-prefill 续跑」机制。布局为笔记自绘，要素均出自论文原文。

7.4 性能优化：打断像没打断过（§5.2.3）

异步 RL 里 rollout 会被训练周期性打断（要切到新 checkpoint），目标是「打断近瞬时、恢复像没停过」：

  • token 级打断：生成可以在任意 token 边界停下；训练数据一够，所有在飞样本几乎立刻停，系统零延迟进入训练；
  • 状态按 token 粒度持久化：rollout 状态（KV cache——模型已读内容的「工作记忆」，见 KV cache 精读——以及 MoE 专家路由）在生成过程中随写随存；换新 checkpoint 恢复时直接复用，省掉重新 prefill（重读前文）的开销，样本从断点原样继续；
  • 样本粒度垃圾回收：要在飞样本的状态全都要留着，所以哪个样本完成就立刻释放它的状态；
  • 同一套「快打断 + 无缝续跑」机制还让训练任务能及时响应集群调度抢占信号而不丢进度，提升整体集群利用率。

7.5 大规模在线蒸馏：40+ 异构老师的期末大合练（§5.2.4）

后训练的最后一个阶段是全词表 OPD（蒸馏目标是老师在整个词表上的输出分布，而非只对齐采样出的那一个 token）：用来自所有领域的数据集、超过 40 个老师模型来训。为什么这么多老师？因为各领域的训练历程不同，每个领域最好的老师可能来自模型发展历程的不同阶段，而且老师与学生、老师彼此之间架构都可以不同。基建支持「架构异构、数量实际上不设限」的老师池，并以可忽略的成本在老师之间切换（引用 DeepSeek-AI 2026b，即 V4 技术报告）。

OPD 阶段还需要训练中途动态换配方：持续追踪模型能力，随训随调数据配比、每数据集的并发上限、激活哪些老师。同步训练里 rollout 批次天然是配置切换的边界，异步下不同配置生成的样本会同时在飞——基建需要支持配置之间的一致切换、不打断 rollout 或训练。

8.5 多 agent 实验：三个臭皮匠顶一个诸葛亮吗（§5.3.5）

论文用 DeepSeek Harness 的 Agent Team 模式做了初步（原文用词 preliminary）多 agent 实验。机制速览：

  • 组队：主 agent（lead）通过 spawn_teammate 异步创建具名、持久的队友，任务可以「全新开局」（fresh，无 lead 历史）或「分身」（fork，一次性快照 lead 已完成轮次）；所有 agent 共享同一份仓库检出，改动彼此立即可见；
  • 通信：持久对等邮箱（peer mailbox）——send_message 发出的消息在队友下一个步边界送达、给空闲队友开启新轮次、或唤醒不活跃队友；lead 用 list_agents/wait_agent 监控与等待；
  • 协作：任务所有权、依赖、建议性写权限范围记在共享任务板（四个 team_task_* 工具，更新带版本检查）；只有 lead 能用 interrupt_agent 打断队友当前轮次；完成后由 lead 审查、测试合并改动并产出最终回答。

训练：Agent Team 模式用组合 RL 奖励——任务表现 + 鼓励委派与沟通的协作奖励（collaboration bonus）+ 「派生延迟惩罚（derived-latency penalty）」。第三项最巧妙：把执行事件及其协作依赖建成有向无环图（DAG），按「固定 prefill/decode 速率下的 token 开销 + 实测工具执行时间」给每个节点计成本，再取关键路径（critical path）长度作为延迟——这惩罚的是「不必要的串行和同步」，奖励有用的并行，而且对服务端批处理/排队延迟不敏感（度量的是任务本身的依赖结构，不是运维抖动）。

评测：ProgramBench 高置信子集（只保留参考解在隐藏测试上通过率 ≥95% 的题，剩 172 道「golden」任务）+ FrontierSWE v2 no-GPU 子集；按每条 rollout 的墙钟截止时间（1–12 小时 / 1–20 小时）计分，比较「最强多 agent 配置 vs 最强单 agent 基线」：

十、本讲小结

  • 总路线：SFT → RL → OPD 三段式不变，「不引入新算法」；增益几乎全部来自数据与环境管线——任务三元组（题目、环境、验证系统）+ 难度/正确性双指标 + 全生命周期质检，以及「用模型造题、用难度和正确性当奖励训练出题模型」的自举。
  • 任务合成：通用 agent 靠「真实工作流回传 + mock 工具复刻 + 失败重放」；coding agent 靠「内部会话 + GitHub 仓库 + 多 agent 流水线（命题/搭建/解题/质检/修复）」，评测点分 fail-to-pass 与 pass-to-pass。
  • RL 扩展：GRPO 式组内优势；RL 沿算力与 scaffold 数量两维扩展；sandbox/worker 解耦让异构 scaffold 免改算法接入；模型合并把多次 run 的算力收益累积起来。
  • DSec：百万级并发沙箱靠「分片 + 弱一致多副本放置引擎 + 节点本地准入约束」扩展、靠「sub-NUMA + VM 绑定」把单机密度从约 1000 提到 2500+ 容器，靠 AppArmor/eBPF/repercussion 信号管住会删库的 agent。
  • 可控推理努力：标量 \(b\in[1,100]\) 写进系统提示词；子组内做组相对优势（不同档位永不直接比较）；长度惩罚系数 \(k(b)=k_0 e^{-(b-b_{\min})/\tau}\) 指数衰减，附录 C 证明这让最优思考长度随 \(b\) 近似线性增长（\(k_0\) 管整体压力、\(\tau\) 管档位敏感度）；API 的 max/high/low = 100/75/50。
  • 异步基建：colocate 分时共享 + 样本级派发（两次失败尝试后选定）；两笔「利息」分别用「按数据集限并发 + 丢早到短样本」和「off-policy 比例上界 + loss masking」偿还；token 级打断 + KV/路由持久化实现无缝续跑；OPD 阶段 40+ 异构老师随时热切换。
  • 结果：Codeforces 3471、MathArena Apex 65.6%；DeepSWE v1.1 74.2%（超 Opus-5）、TB 2.1 90.6%、Automation-Bench 54.8%；努力旋钮 25→100 用 2.5× token 换约 9 分精度、收益前置；多 agent 在所有截止时间上胜过单 agent。

十一、自测清单

  1. 任务三元组是哪三个组件？质量看哪两个维度？——(problem, environment, verification system)；难度（非平凡）与正确性（三组件无致命缺陷），两者同时充当「训练出题模型」的奖励信号。
  2. coding agent 环境流水线里，fail-to-pass 和 pass-to-pass 评测点分别防什么？——fail-to-pass 防「没真实现」：做题前失败、做完必须通过的测试；pass-to-pass 防「改坏原有功能」：从头就该通过、做完仍须通过的测试。
  3. 样本级派发为什么优于 prompt 级和 batch 级？——batch 级太粗导致训练指标震荡；prompt 级会被单个 GRPO 组内的长尾样本卡住；样本级「凑够下一个 prompt 所需组大小就派发、不管样本来自哪个组」，长尾不再阻塞派发，并发水位平稳。
  4. 异步训练的两笔「利息」及各自的两个药方？——长度偏差（短样本先完成主导早期批次）：按数据集限并发调节进料占比 + 丢弃早到短样本；off-policy/staleness（样本由旧 checkpoint 生成）：调度与等待逻辑限制最大 off-policy 比例 + loss masking 抹掉过度陈旧 token 的梯度贡献。
  5. 写出 \(k(b)\) 与 \(b\) 每加 \(\tau\) 的关系；\(k_0\) 和 \(\tau\) 各管什么？——\(k(b)=k_0 e^{-(b-b_{\min})/\tau}\)，\(b\) 每增大 \(\tau\)，\(k\) 乘 \(e^{-1}\)；\(k_0\) 控制整体「往短压」的力度（在 \(\ell^*\) 表达式里整体平移所有档位的长度），\(\tau\) 控制最优长度对档位变化的敏感度（\(\Delta\ell^* \approx (s_x/\tau)\Delta b\)）。
  6. 为什么训练时不同努力档位的回答不做直接比较？部署时中间档位为什么可用？——训练时同档位 \((x,b)\) 内部做组相对优势，避免「短=好」的错误信号污染学习；因为指数惩罚使最优长度随 \(b\) 近似仿射变化，标量 \(b\) 取训练档位之外的中间值即可诱导出插值的推理行为。
一句话带走DeepSeek-V4.1 的后训练是一场「算法上的保守」与「工程上的激进」的组合：优化器层面几乎什么都没发明，但把「造题、造环境、管沙箱、跑异步」推到了百万级并发的工业深度——并顺手给模型装了一个数学上有据可依（指数惩罚 ↔ 线性长度响应）的思考力度旋钮。对学习者的启示：当算法范式收敛后，竞争力转移到数据、环境与基础设施的系统性工程上。
