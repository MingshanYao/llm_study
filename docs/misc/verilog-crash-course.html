目标：半天内建立硬件思维，能独立写出组合逻辑、时序逻辑、三段式状态机，并用 Icarus Verilog 完成自检仿真

环境：任意编辑器 + iverilog（macOS: brew install icarus-verilog，Ubuntu: apt install iverilog gtkwave）+ GTKWave 看波形

TL;DR：Verilog 不是编程语言，而是用文字画电路图。抛弃「逐行执行」的软件直觉，记住三件事：① 你写的每行代码描述的是一块同时存在、永远在算的电路，与书写顺序无关；② 所有数字硬件只有两类积木——组合逻辑（assign 或 always @(*) + 阻塞赋值 =）和时序逻辑（always @(posedge clk) + 非阻塞赋值 <=）；③ 验证靠写 testbench 仿真自检，不是 printf 调试。按 §0→§9 顺序读完并跑通例程，半天可上手；再去 HDLBits 刷一周题即可熟练。

0. 先换脑子：你描述的是电路，不是流程

写 C 时，第 2 行要等第 1 行算完——语句是时间上的先后。写 Verilog 时，每一行代码都综合成一块真实存在的电路，上电后全部同时通电工作——代码是空间上的并列。下面这个对照是全篇最重要的图：

图 1｜心智模型对照。左边：三行代码在时间轴上排队执行；右边：同样的三块运算变成三块独立电路，一直并行地算，靠「连线」而非「调用」传递结果。由此推出 Verilog 与软件的四大差异：并发（所有块同时生效，书写顺序无意义）、没有变量只有连线与寄存器、时间由时钟驱动、for 循环是复制硬件（不是迭代）。

而这些电路里，只有两类积木——不带时钟的「纯逻辑」和带时钟的「寄存器」。它们分别对应 Verilog 的两种写法，这是第二张关键图：

图 2｜两类积木。左：组合逻辑像一坨门电路，输入变、输出立即变，没有记忆；右：时序逻辑像 D 触发器，平时输出不变，只在 clk 上升沿把输入 d「拍」进去——这就是「寄存器打一拍」。§2、§3 分别展开，§4 用一张表收拢。

1. 五分钟语法底子

1.1 第一个模块：module 与端口

Verilog 的基本单元是 module：一个带端口的「芯片」。端口就是引脚，分 input / output（还有双向 inout，新手先不碰）：

module top (
    input  wire [7:0] a,     // 8 位输入，[7:0] 表示 MSB 在前
    input  wire [7:0] b,
    output wire [8:0] sum    // 9 位输出：8 位 + 8 位最多 9 位
);
    assign sum = a + b;      // 连续赋值：描述一根"加法器电路"
endmodule

1.2 数值字面量与四种值

字面量格式固定为 <位宽>'<进制><数值>：8'd200、4'b1010、16'hDEAD、1'b1。不写位宽默认 32 位，这是截断/位宽不匹配问题的常见来源。

每个位有四种取值：0、1、x（未知，没复位/没驱动）、z（高阻，没人驱动）。仿真里看到 x 泛滥，通常是忘了复位。

1.3 wire 与 reg：一句话分清

wirereg
像什么一根导线，被动地被驱动always 块里赋值的「变量」
谁给它赋值assign、模块端口、实例化输出always / initial 块
综合成什么导线 / 组合逻辑组合逻辑（always @(*)）或触发器（posedge）

记忆法：reg 不等于寄存器——是否生成触发器取决于赋值语境（有没有时钟沿），不是类型名。always @(*) 里的 reg 综合出来是纯组合逻辑。

2. 组合逻辑：assign 与 always @(*)

assign 的含义是「电路上，左端的 wire 永远等于右端表达式的值」——它描述的是一坨常开着的门电路，不是一次性计算。常用运算符一张表带走：

简单组合用 assign 就够；带 if / case 的复杂组合用 always @(*)（4 选 1 多路选择器）：

module mux4 (
    input  wire [7:0] a, b, c, d,
    input  wire [1:0] sel,
    output reg  [7:0] y      // 注意：always 里赋值的目标要声明成 reg
);
    always @(*) begin        // @(*)：任何输入变了就重算 → 组合逻辑
        case (sel)
            2'b00:   y = a;
            2'b01:   y = b;
            2'b10:   y = c;
            default: y = d;  // 别漏 default，否则综合出锁存器
        endcase
    end
endmodule
组合逻辑三条铁律，违反第 ③ 条会综合出锁存器（latch）：组合输出必须「每时每刻都有定义」，漏了某个分支就意味着「保持上次的值」——这就是锁存器，FPGA/ASIC 流程里都是坏味道。① 敏感表一律写 @(*)，手写 always @(a or b) 极易漏信号；② 组合块内用阻塞赋值 =；③ if 要配 else、case 要配 default，让所有输出在所有分支都被赋值。

3. 时序逻辑：always @(posedge clk)

时序逻辑的心法一句话：每个时钟上升沿，所有寄存器同时采样一次，其余时间输出保持不变。看波形最直观：

图 3｜always @(posedge clk) q <= d; 的行为。d 在 t=340 从 5 变成 7，但 q 视而不见，直到 t=360 的上升沿才把 7 采进去——这就是「打一拍」：q 永远比 d 慢一个上升沿。数字系统的节奏全部由这一排排采样点定义。

3.1 为什么时序逻辑必须用非阻塞赋值 <=

<= 的语义：块内所有右值先同时算好，再统一更新——天然并行、与书写顺序无关，正好匹配「所有寄存器同时采样」的硬件行为。写成 =（阻塞）会引入对语句顺序的依赖，仿真和综合结果可能不一致，是 Verilog 第一大坑。口诀：时序用 <=，组合用 =，永不混用。

3.2 标准模板：带复位的计数器

module counter #(
    parameter WIDTH = 8           // 参数化：实例化时可改位宽
)(
    input  wire             clk,
    input  wire             rst_n,   // 低电平有效的异步复位
    output wire [WIDTH-1:0] cnt
);
    reg [WIDTH-1:0] cnt_r;

    always @(posedge clk or negedge rst_n) begin  // 时钟沿 或 复位下降沿都触发
        if (!rst_n)
            cnt_r <= {WIDTH{1'b0}};   // 复制算子：WIDTH 个 0，清零
        else
            cnt_r <= cnt_r + 1'b1;    // 每个上升沿 +1（写 1'b1 避免位宽陷阱）
    end

    assign cnt = cnt_r;
endmodule

两个工程习惯：① 复位信号命名 rst_n（_n 表示低有效），异步复位保证上电后寄存器有确定初值——仿真里的 x 靠它消灭；② FPGA 的寄存器上电配置本身有初值（可写 reg [7:0] cnt_r = 8'd0;），但复位仍是跨平台最稳的写法。

5. 状态机：三段式模板

任何「有过程、有阶段」的控制逻辑（握手、协议、缓存 Controller）都用有限状态机（FSM）表达。业界标准写法是三段式：状态寄存器、次态逻辑、输出逻辑各占一个 always 块，结构清晰、综合友好：

图 4｜三段式状态机。左：本例 FSM——start 到来进入 RUN，外部 busy 拉高表示完成进 DONE，输出 done 一拍后自动回 IDLE；右：三个 always 块与转移图一一对应（① 时序 ② 组合 ③ 组合）。

module fsm (
    input  wire clk,
    input  wire rst_n,
    input  wire start,
    input  wire busy,      // 假设来自下级模块的"忙"信号
    output reg  done
);
    localparam IDLE = 2'd0, RUN = 2'd1, DONE = 2'd2;
    reg [1:0] state, next_state;

    // 第一段：状态寄存器（时序）
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) state <= IDLE;
        else        state <= next_state;
    end

    // 第二段：次态逻辑（组合）
    always @(*) begin
        case (state)
            IDLE:    next_state = start ? RUN  : IDLE;
            RUN:     next_state = busy  ? DONE : RUN;
            default: next_state = IDLE;   // DONE → 自动回 IDLE，default 兜底
        endcase
    end

    // 第三段：输出逻辑（组合）
    always @(*) begin
        done = (state == DONE);
    end
endmodule

要点：状态用 localparam 编码；第二段 case 必须全覆盖（写 default）；输出也可以打一拍寄存后输出（时序更干净，代价是慢一拍）——这是进阶的 Moore/Mealy 取舍，先用组合输出练手即可。

6. 层次化：模块实例化

复杂设计 = 先画框图，每个框一个 module，再用实例化把框连起来。端口用命名关联 .端口名(信号名)，参数用 #() 传递：

module system (
    input  wire       clk,
    input  wire       rst_n,
    input  wire [7:0] a, b,
    output wire [8:0] sum
);
    wire [7:0] cnt;

    counter #(.WIDTH(8)) u_cnt (      // 实例化 counter，覆盖参数
        .clk   (clk),
        .rst_n (rst_n),
        .cnt   (cnt)
    );

    top u_add (                        // 实例化 §1 的加法器
        .a    (a),
        .b    (b),
        .sum  (sum)
    );
endmodule

不要用位置关联 top u_add (a, b, sum);——端口一改顺序就悄悄接错。仿真 testbench 里的 DUT 也是这么实例化的，见下一节。

7. 验证：testbench 与 iverilog

RTL 写完不是「跑一下看打印」，而是写一个没有端口的顶层模块（testbench）：生成激励灌进 DUT，再自动检查输出对不对。结构如下：

图 5｜testbench 结构。激励与时钟都写在 initial / always #延时 里（不可综合，只在仿真器里跑）；结果检查用 !== 四态比较 + 计数报错，实现「自检 tb」——跑完只看一行 ALL PASS / FAIL。

`timescale 1ns/1ps

module tb_top;
    reg  [7:0] a, b;
    wire [8:0] sum;
    integer errors = 0;

    top dut (.a(a), .b(b), .sum(sum));   // 实例化被测模块

    reg clk = 0;
    always #5 clk = ~clk;                // 每 5ns 翻转 → 周期 10ns

    initial begin
        $dumpfile("dump.vcd");           // 生成波形文件，gtkwave 可看
        $dumpvars(0, tb_top);

        a = 8'd3;   b = 8'd4;    #20;    // 施加激励，等 20ns
        if (sum !== 9'd7) begin
            $display("FAIL: 3+4 = %d", sum);
            errors = errors + 1;
        end
        a = 8'd200; b = 8'd100;  #20;
        if (sum !== 9'd300) begin        // 测进位：200+100=300 需要 9 位
            $display("FAIL: 200+100 = %d", sum);
            errors = errors + 1;
        end

        if (errors == 0) $display("ALL PASS");
        else             $display("%d FAILURES", errors);
        $finish;
    end
endmodule

编译运行只需三行命令：

iverilog -g2012 -o sim.vvp top.v tb_top.v   # 编译（-g2012 允许部分 SystemVerilog 语法）
vvp sim.vvp                                 # 运行仿真，打印 ALL PASS / FAIL
gtkwave dump.vcd                            # 可选：打开波形，观察图 3 那样的信号

图 6｜RTL 开发闭环。前两步用开源工具本地即可完成，能拦住 95% 的逻辑 bug；综合与上板属于后端流程，速成阶段先不碰。

10. 大作业实战（一）：数字电子钟

数电 / EDA 课程最经典的入门大作业：用 50MHz 板载时钟驱动 6 位七段数码管显示「时:分:秒」，并支持按键校时。它是 §3 计数器的极致运用——先把顶层框图画出来（先画图、后写码是 RTL 铁律）：

图 7｜数字钟顶层框图。蓝色实线是数据流：节拍 → 秒 → 分 → 时 → 译码显示；橙色虚线是控制流：按键经消抖后进校时状态机，覆盖计数的进位路径（调分 / 调时）。所有时序块共用同一个 50MHz 时钟——这是下一条关键技术点。

10.1 技术点①：用「节拍使能」，不要分频时钟

新手常犯的错误是把 50MHz 分频出一个 1Hz 时钟再拿去驱动计数器——分频出来的门控时钟时序难以收敛。正确姿势：所有逻辑都跑 50MHz，用 1 拍宽的使能脉冲 tick 当「节拍」：

// 50_000_000 / 100Hz = 500_000 分频，但输出不是低频时钟，而是 1 拍宽的脉冲
reg [18:0] div_cnt;
wire tick = (div_cnt == 19'd499_999);
always @(posedge clk) begin
    if (!rst_n)    div_cnt <= 19'd0;
    else if (tick) div_cnt <= 19'd0;
    else           div_cnt <= div_cnt + 1'b1;
end

10.2 技术点②：BCD 级联计数 + 校时复用同一条路径

秒 / 分 / 时是三级 60/60/24 进制回绕计数器。校时的诀窍：把「走时的进位」和「按键 +1」统一成同一个使能信号，计数器本体永远只有一套逻辑：

localparam RUN = 2'd0, ADJ_MIN = 2'd1, ADJ_HOUR = 2'd2;
reg [1:0]  mode;
reg [5:0]  sec, min;
reg [4:0]  hour;

// 模式状态机：按键切档 走时 → 调分 → 调时
always @(posedge clk) begin
    if (!rst_n)        mode <= RUN;
    else if (key_mode) mode <= (mode == ADJ_HOUR) ? RUN : mode + 2'd1;
end

// 使能信号 = 正常进位 OR 校时按键（秒在调分/调时时冻结）
wire run      = (mode == RUN);
wire sec_en   = run & tick;
wire min_en   = (run & tick & (sec == 6'd59)) | (mode == ADJ_MIN  & key_inc);
wire hour_en  = (run & tick & (sec == 6'd59) & (min == 6'd59))
              | (mode == ADJ_HOUR & key_inc);

// 三级计数器写法完全同构：使能时 +1，计满回绕
always @(posedge clk) begin
    if (!rst_n)      sec <= 6'd0;
    else if (sec_en) sec <= (sec == 6'd59) ? 6'd0 : sec + 1'b1;
end
// min（0–59）、hour（0–23）留作练习

10.3 技术点③：七段译码 + 动态扫描

译码是纯组合逻辑（§2 铁律：case 配 default）；动态扫描让 6 位数码管轮流点亮，用 1kHz 节拍每拍换一位，人眼看起来全亮：

// 七段译码器：独立成模块，到处复用（共阳极，0 点亮）
reg [6:0] seg_r;                      // {g,f,e,d,c,b,a}
always @(*) begin
    case (bcd)
        4'd0:    seg_r = 7'b1000000;
        4'd1:    seg_r = 7'b1111001;
        4'd2:    seg_r = 7'b0100100;
        // 3–9 留作练习
        default: seg_r = 7'b1111111;  // 全灭
    endcase
end
验收清单：上板走时准确（对照手机秒表）；校时三模式切换正常；按键必须消抖（复用 §3 计数器思路：按键稳定 20ms 才算一次按下）。踩坑点：24/60 进制回绕条件写错（== 59 还是 == 60？）、扫描频率过低导致肉眼可见闪烁（<60Hz 每位）。

11. 大作业实战（二）：交通灯控制器

状态机标准题：主干道（南北）与次干道（东西）红黄绿灯定时轮转，绿灯末段黄灯过渡。把 §5 三段式直接工程化——先画状态转移图：

图 8｜交通灯四状态循环。任一时刻只有一个状态有效，两方向灯由状态组合译码——「两边同绿」这类事故在结构上不可能发生。扩展紧急模式只需在第二段加一个高优先级条件：有急救车请求时 next_state 强制回到放行安全态。

实现要点：状态机 + 定时器（数据通路）共存于第一段时序块；时长全部参数化；倒计时用 §10 的节拍 tick（0.1s 一拍，30 秒 = 计 300）：

module traffic_light (
    input  wire clk, rst_n,
    input  wire tick,             // 0.1s 一拍（§10 的节拍发生器）
    output reg  [2:0] ns,         // {绿, 黄, 红}
    output reg  [2:0] ew
);
    parameter T_GREEN = 9'd300, T_YELLOW = 9'd30;
    localparam NSG = 2'd0, NSY = 2'd1, EWG = 2'd2, EWY = 2'd3;
    reg [1:0] state, next_state;
    reg [8:0] t;                       // 状态内倒计时

    // 第一段：状态寄存器 + 倒计时（时序）
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            state <= NSG;  t <= T_GREEN;
        end else if (t != 9'd0) begin
            t <= t - 1'b1;             // 还没计满，继续倒数
        end else begin
            state <= next_state;       // 计满，切换状态并重装时长
            case (next_state)
                NSY:     t <= T_YELLOW;
                EWG:     t <= T_GREEN;
                EWY:     t <= T_YELLOW;
                default: t <= T_GREEN;
            endcase
        end
    end

    // 第二段：次态逻辑（组合）
    always @(*) begin
        if (t == 9'd0)
            case (state)
                NSG:     next_state = NSY;
                NSY:     next_state = EWG;
                EWG:     next_state = EWY;
                default: next_state = NSG;
            endcase
        else
            next_state = state;        // 没计满就原地踏步
    end

    // 第三段：输出译码（组合）——默认全红兜底，再按状态改写
    always @(*) begin
        {ns, ew} = 6'b001_001;         // 安全兜底：全红
        case (state)
            NSG:     {ns, ew} = 6'b100_001;
            NSY:     {ns, ew} = 6'b010_001;
            EWG:     {ns, ew} = 6'b001_100;
            EWY:     {ns, ew} = 6'b001_010;
        endcase
    end
endmodule
验收清单：两方向灯严格互斥（任一时刻两红至少一组）；黄灯时长 ≠ 绿灯时长（参数化生效）；testbench 里把 T_GREEN 改小到几拍，用 §7 自检 tb 断言状态序列 S0→S1→S2→S3→S0。常见踩坑：倒计时在切状态那拍多减 1 导致时长差一拍（边界条件）；紧急模式插队后没有回到正确相位。

12. 大作业实战（三）：简化 CPU

计算机组成原理课程的大作业，也是 Verilog 的「毕业考」：实现一个 RV32I 子集（add / lw / sw / beq 等十几条指令）的处理器。标准打法分两步：先做单周期跑通功能，再切成五级流水线解决冒险。

12.1 第一步：单周期数据通路

图 9｜单周期 RV32I 子集数据通路（简化）。跟着 lw 走一遍：PC 取指 → 寄存器堆读出基地址 rs1 → ALU 把 rs1 加立即数算出访存地址 → DMEM 读出数据（绿色路径）→ 写回寄存器堆 rd。sw 走 rs2→wdata→DMEM 写入；beq 用 ALU 比较出 zero，配合「分支」路径改写 PC。橙色虚线是控制器发出的控制信号（图中画了 3 条，B 端 mux 与写回 mux 的选择信号同理，略）；「+4」「分支」两个加法器也略去。注意：寄存器堆、ALU、DMEM 都画在同一个周期里工作——单周期的代价是时钟必须慢到能容下最长路径。

译码用「默认值先行 + case 改写」的组合逻辑，正好复用 §2 的铁律：

reg [31:0] imem [0:1023];
initial $readmemh("prog.hex", imem);   // 上电装程序，tb 与 FPGA 初始化通用

// 单周期控制信号：默认值先行，case 改写（§2 铁律的实战形态）
always @(*) begin
    reg_wen = 1'b0;  alu_src = 1'b0;  mem_ren = 1'b0;  mem_wen = 1'b0;
    case (inst[6:2])                                            // opcode[6:2]
        5'b01100: reg_wen = 1'b1;                               // R 型运算
        5'b00100: begin reg_wen = 1'b1; alu_src = 1'b1; end     // I 型：B 端用立即数
        5'b00000: begin reg_wen = 1'b1; alu_src = 1'b1; mem_ren = 1'b1; end  // lw
        5'b01000: begin alu_src = 1'b1; mem_wen = 1'b1; end     // sw
        5'b11000: ;                                             // beq：ALU 比较出 zero
        default: ;
    endcase
end

12.2 第二步：五级流水线与三大冒险

单周期跑通后切成五级：取指 IF → 译码 ID → 执行 EX → 访存 MEM → 写回 WB，级间用流水寄存器隔开。图 10 是一张值得贴在工位上的流水线时空图：

图 10｜五级流水线时空图。add 要用 lw 刚读出的 t0——lw 的数据要到周期 4 才从 MEM 级出来，add 的 EX 却排在周期 4：这就是 load-use 数据冒险，只能停一拍（虚线框），把 EX 推迟到周期 5，再由「前递」把 lw 的 MEM 结果直接送到 add 的 EX 输入（橙色箭头）。停顿会顺延后级：第三条指令也跟着空泡一拍。三种冒险与对策：结构冒险（指令/数据存储器分开即回避）、数据冒险（前递 + load-use 停顿）、控制冒险（分支预测不跳转，跳了就冲刷 IF/ID）。

级间流水寄存器就是 §3「打一拍」的规模化应用——把每一级的「现场」原样搬一拍：

// 流水线骨架：级间寄存器 = 把上一级的"现场"打一拍
always @(posedge clk) begin
    if_id_inst  <= imem[pc[31:2]];    // IF→ID：取到的指令
    id_ex_rs1   <= reg_rdata1;        // ID→EX：两个源操作数
    id_ex_rs2   <= reg_rdata2;
    id_ex_imm   <= imm;               //         与立即数
    ex_mem_alu  <= alu_y;             // EX→MEM：ALU 结果
    ex_mem_wd   <= id_ex_rs2;         //         与待写存储器的数据
    mem_wb_rd   <= dmem_rdata;        // MEM→WB：读出的数据
    mem_wb_alu  <= ex_mem_alu;        //         （写回前二选一）
end

// 前递：操作数不等写回，从更晚的级"抄近路"（EX 的 A 操作数为例）
always @(*) begin
    if      (ex_mem_rd != 5'd0 && ex_mem_rd == id_ex_rs1) fwd_a = 2'b01;  // MEM→EX（最新）
    else if (mem_wb_rd != 5'd0 && mem_wb_rd == id_ex_rs1) fwd_a = 2'b10;  // WB→EX
    else                                                  fwd_a = 2'b00;  // 寄存器堆
end

// load-use 冒险检测：下一条 EX 就要用 lw 的结果 → 冻结一拍
wire load_use = id_ex_mem_read && (id_ex_rd != 5'd0) &&
                (id_ex_rd == if_id_rs1 || id_ex_rd == if_id_rs2);
// stall 时：pc 与 if_id 保持不变，id_ex 的控制信号全部清零（注入泡）

// 控制冒险：分支在 EX 才知道跳不跳 → 乐观地继续取指，跳了就冲刷
if (branch_taken) begin
    pc         <= branch_target;
    if_id_inst <= 32'd0;              // 把乐观取错的一条作废（注入泡）
end
建议路线：① 单周期先跑通 10 条指令，用 §7 的自检 tb 验证——程序用 $readmemh 装入，断言关键寄存器快照（比如跑一段斐波那契，比对 t0–t3）；② 切五级流水线，先不处理冒险，用「依赖后插入 nop」的程序验证骨架正确；③ 逐个实现前递 → load-use 停顿 → 分支冲刷，每步都用同一套 tb 回归。做完这套，§0 说的「并发 + 打一拍」世界观就完整闭环了。
