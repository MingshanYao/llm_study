一句话：attention 在 GPU 上慢，不是因为 FLOPs 多，而是因为 \(N{\times}N\) 的 softmax 中间矩阵要在慢得多的 HBM 里反复读写。FlashAttention 用「分块 + online softmax」让 \(S\) 从不落盘（FA1），用「循环交换 + 减少非 matmul 指令」把利用率从 25–40% 抬到 50–73%（FA2），用「warp 专化 + GEMM/softmax 异步流水」追平 Hopper 异步硬件（FA3），最后在 Blackwell 上直面「tensor core 翻倍、SRAM 带宽与指数单元原地踏步」的非对称扩展，用 TMEM、2-CTA MMA、软件模拟指数和条件重缩放把非 matmul 瓶颈再压下去（FA4）。

四代的主线逻辑：FA1 解决「能不能不存 \(N^2\)」（数学上可行：running max/sum + 输出重缩放）；FA2 解决「怎么摆才能吃满硬件」（并行度、寄存器、warp 分工）；FA3 解决「怎么等」（把同步算法改写成异步流水线）；FA4 解决「等什么」（瓶颈已从 matmul 移到 softmax 的 exp 与共享内存，算法要为非对称硬件改形）。

算法上最值得带走的一件事：online softmax 的归纳不变式——处理完前 \(j\) 个 KV 块后，寄存器里的 \((m^{(j)}, \ell^{(j)}, \tilde O^{(j)})\) 恒等于「只看前 \(j\) 块时的全局 rowmax、rowsum 与未归一化输出 \(\mathrm{diag}(\ell)^{-1}\) 等价形式」。四个版本的工程演进，全部是在保持这个不变式的前提下重排计算与数据搬运。

一、背景：标准 attention 为什么是访存受限

1.1 单头 attention 与标准实现

给定 \(Q, K, V \in \mathbb{R}^{N \times d}\)（\(N\) 为序列长度、\(d\) 为 head_dim），单头 attention 计算三步（FA1 论文 §2.2）：

\[ S = QK^\top \in \mathbb{R}^{N\times N},\qquad P = \mathrm{softmax}(S) \in \mathbb{R}^{N\times N}\ \text{（按行）},\qquad O = PV \in \mathbb{R}^{N\times d}. \tag{式 1}\]

标准实现（FA1 论文 Algorithm 0）把它拆成三个 GPU kernel：

Algorithm 0  Standard Attention（FA1 论文 §2.2）
1: 按块从 HBM 读 Q、K，计算 S = QKᵀ，把 S 写回 HBM。
2: 从 HBM 读 S，计算 P = softmax(S)，把 P 写回 HBM。
3: 从 HBM 读 P、V，计算 O = PV，把 O 写回 HBM。

问题在于 \(S, P \in \mathbb{R}^{N\times N}\)：以 GPT-2 为例 \(N{=}1024,\ d{=}64\)，\(N \gg d\)，这两个 \(N^2\) 矩阵的读写量 \(\Theta(N^2)\) 远超输入输出本身的 \(\Theta(Nd)\)。而其中的 softmax、mask、dropout 都是逐元素/按行归约操作——算术强度极低，是典型的访存受限（memory-bound）算子（FA1 §2.1）。

1.2 HBM vs SRAM：一个数量级的带宽差、三个数量级的容量差

FA1 论文 §2.1 给出的 A100 账本：

层级容量带宽特点
HBM（显存）40–80 GB1.5–2.0 TB/s全局可见，容量大但慢
SRAM（每 SM 片上）192 KB × 108 SM≈ 19 TB/s（估计）快一个数量级，小三个数量级

GPU 计算速度的增长长期快于访存速度的增长，所以多数 Transformer 算子都卡在 HBM 访问上。kernel 融合是常规药方——把 softmax、mask、matmul 融进一个 kernel，中间量不出 HBM；但训练场景下，为 backward 服务的中间量（\(S, P\)）仍然必须写进 HBM 存下来，朴素融合救不了 attention（FA1 §2.1 结尾）。FlashAttention 的答案是：让 \(N^2\) 的中间量根本不存在，backward 需要的信息用 \(O(N)\) 的统计量 + 重计算来替代。

图 1：标准 attention 与 FlashAttention 的数据流对比（对应 FA1 论文 Fig. 1）。左：三个 kernel，\(N^2\) 的 \(S,P\) 在 HBM 中落盘两份、读回两次；右：单个 kernel，\(S\) 的分块只在 SRAM 里生存，HBM 只承担 \(\Theta(Nd)\) 级的输入输出与 \(\Theta(N^2d^2/M)\) 级的块搬运（FA1 Theorem 2）。

1.3 roofline 视角：为什么「恰好注意力」可以既精确又快

算术强度 \(\mathrm{AI} = \mathrm{FLOPs}/\text{字节}\) 对照硬件 ridge point 决定了算子是算力受限还是带宽受限。标准 attention 的两头的 GEMM 本身是算力受限的，但夹在中间的 softmax（读 \(N^2\) 写 \(N^2\)）把整个链条拖入访存受限区——pipeline 里的每个 kernel 都要为 \(N^2\) 的中间量付带宽账。

FlashAttention 的关键观察（FA1 §1、§3.1）：

  • softmax 虽然耦合了整行（每个输出位依赖整行分母），但耦合的只是「行内归一化常数」\(m\)（rowmax）与 \(\ell\)（rowsum）两个统计量——它们只有 \(O(N)\) 个数；
  • 只要增量地维护 \((m, \ell)\) 并按比例重缩放已算好的部分输出 \(\tilde O\)，就可以一个 KV 块一个 KV 块地算，最终结果与全局 softmax 逐位数学等价（不是近似）；
  • backward 需要的 \(P\) 可以从 \(Q,K\) 块 + 前向存的统计量在片上重算，用多花 1.25–2 倍 GEMM FLOPs 换掉 \(N^2\) 的读写——在访存受限区这笔交换稳赚。

这就是「exact attention with IO-awareness」：FLOPs 略增、HBM 访存量从 \(\Theta(Nd + N^2)\) 降到 \(\Theta(N^2d^2/M)\)（\(M\) 为 SRAM 容量）。代入典型值 \(d{=}64{\sim}128\)、\(M{\approx}100\text{KB}\)，\(d^2 \ll M\)，访存量降数倍到一个数量级（FA1 Fig. 2：GPT-2 medium 前向+反向 HBM 读写 40.3 GB → 4.4 GB，运行时间 41.7 ms → 7.3 ms）。FA1 还证明了反向的下界：对任意 SRAM 大小 \(M\)，不存在 HBM 访问为 \(o(N^2d^2/M^{-1})\) 的精确注意力算法（FA1 Proposition 3）——也就是说在「精确计算」这个约束下，tiling 路线的 IO 账已经做到头了，后续三代比拼的全是「片上怎么摆、怎么流水」。

二、FA1：tiling + online softmax（arXiv:2205.14135）

2.1 安全 softmax 与分块合并公式

softmax 直接算 \(e^{x_i}\) 会溢出，标准做法是先减行最大值。FA1 §3.1 定义向量 \(x \in \mathbb{R}^B\) 的三个量：

\[ m(x) := \max_i x_i,\qquad f(x) := \big[\,e^{x_1 - m(x)},\ \dots,\ e^{x_B - m(x)}\,\big],\qquad \ell(x) := \sum_i f(x)_i,\qquad \mathrm{softmax}(x) = \frac{f(x)}{\ell(x)}. \tag{式 2}\]

核心引理：把行向量拼成 \(x = [x^{(1)}; x^{(2)}]\)，有（FA1 §3.1）

\[ m(x) = \max\big(m(x^{(1)}),\, m(x^{(2)})\big),\qquad \ell(x) = e^{m(x^{(1)}) - m(x)}\,\ell(x^{(1)}) + e^{m(x^{(2)}) - m(x)}\,\ell(x^{(2)}). \tag{式 3}\]

也就是：只要随身带着 \((m, \ell)\)，softmax 可以一块一块地合并。对输出再加一条：已算出的部分输出 \(\tilde O\)（未除以 \(\ell\)）在最大值更新时整体乘一个 \(e^{m_{\text{old}} - m_{\text{new}}}\) 即可。这两条合起来就是 online softmax（该技巧源自 Milakov & Gimelshein 2018 的 online softmax 与 Rabe & Staats 2021 的 streaming attention，FA1 脚注 2 与 §B.5 讨论了与后者的区别：FA1 增量更新输出、只保留一份副本，而后者存下每块的临时输出最后合并）。

2.2 Forward Algorithm 1 逐行讲解

FA1 论文 Algorithm 1（§3.1，带 mask/dropout 的完整版是附录 B.3 的 Algorithm 2）。为可读性，下面用论文原符号复述（\(\tilde m_{ij}, \tilde P_{ij}, \tilde\ell_{ij}\) 表示「当前块局部」的统计量，\(m_i, \ell_i\) 表示 HBM 中的 running 统计量）：

Algorithm 1  FlashAttention（FA1 论文 §3.1，输入 Q,K,V ∈ R^{N×d} 于 HBM，SRAM 容量 M）
 1: Bc = ⌈M/(4d)⌉          # KV 块大小：K_j,V_j,S_ij 都要塞进 SRAM
 2: Br = min(⌈M/(4d)⌉, d)  # Q 块大小
 3: 初始化 O = 0_{N×d}, ℓ = 0_N, m = -∞_N（都在 HBM）
 4: 把 Q 切成 T_r 块（每块 B_r×d），K,V 切成 T_c 块（每块 B_c×d）
 5: for j = 1 .. T_c do                    # ← 外层循环走 KV 块
 6:   把 K_j, V_j 从 HBM 载入 SRAM
 7:   for i = 1 .. T_r do                  # ← 内层循环走 Q 块
 8:     把 Q_i, O_i, ℓ_i, m_i 从 HBM 载入 SRAM
 9:     片上计算 S_ij = Q_i K_jᵀ ∈ R^{B_r×B_c}
10:     片上计算 m̃_ij = rowmax(S_ij)，P̃_ij = exp(S_ij − m̃_ij)，ℓ̃_ij = rowsum(P̃_ij)
11:     片上计算 m_new = max(m_i, m̃_ij)，
          ℓ_new = e^{m_i − m_new} ℓ_i + e^{m̃_ij − m_new} ℓ̃_ij
12:     写回 HBM：
          O_i ← diag(ℓ_new)^{-1} ( diag(ℓ_i) · e^{m_i − m_new} · O_i
                                   + e^{m̃_ij − m_new} · P̃_ij V_j )
13:     写回 HBM：ℓ_i ← ℓ_new, m_i ← m_new
14:   end for
15: end for
16: 返回 O

几处关键点的展开：

  • 块大小怎么定（第 1–2 行）：SRAM 里要同时容纳 \(K_j\)（\(B_c d\)）、\(V_j\)（\(B_c d\)）、\(S_{ij}\)（\(B_r B_c\)）以及 \(Q_i, O_i\)，所以 \(B_c = \lceil M/4d \rceil\)。块越大，HBM 重扫 \(Q/O\) 的遍数 \(T_c = \lceil N/B_c\rceil\) 越少——FA1 Fig. 2 中间图验证了块大小 64→256 时前向时间单调下降，之后被别的因素（算术本身）卡住。
  • 第 12 行是整个算法的心脏：旧输出 \(\mathrm{diag}(\ell_i) e^{m_i - m_{\text{new}}} O_i\) 表示「把旧输出从旧的 \((m_i,\ell_i)\) 归一化基准搬到新基准」，第二项 \(e^{\tilde m_{ij} - m_{\text{new}}} \tilde P_{ij} V_j\) 表示「新块从它的局部基准搬到新基准」，除以 \(\ell_{\text{new}}\) 后两者在同一基准下相加，正是式 3 的逐块合并。
  • 注意 FA1 把 \(\ell\) 除在每一步里（第 12 行的 \(\mathrm{diag}(\ell_{\text{new}})^{-1}\)）——每步都对 \(O\) 做两次逐元素向量乘 + 一次除法。FA2 的第一个改进就是砍这里的非 matmul FLOPs（§四）。
  • 外层循环为什么走 KV（第 5 行）：这样每块 \(K_j, V_j\) 只从 HBM 读一次，代价是 \(Q_i, O_i, \ell_i, m_i\) 每个外层迭代都要重读重写一遍（\(T_c\) 次）。FA1 选择的这个循环次序在 FA2 里被反转，原因见 §四.1。

正确性：归纳不变式

FA1 附录 C（Theorem 1 证明）对外层迭代次数 \(j\) 归纳：第 \(j\) 轮结束后，HBM 里的状态满足

\[ m^{(j)} = \mathrm{rowmax}\big(S_{:,1:jB_c}\big),\quad \ell^{(j)} = \mathrm{rowsum}\big(e^{S_{:,1:jB_c} - m^{(j)}}\big),\quad O^{(j)} = \mathrm{softmax}\big(S_{:,1:jB_c}\big)\, V_{1:jB_c}. \tag{式 4}\]

即：任何时刻，\((m, \ell, O)\) 都精确等于「只看前 \(j\) 个 KV 块」时的全局 softmax 结果。式 4 的第三条正是第 12 行更新公式的展开（论文附录 C 完整推导了 \(\mathrm{diag}(\ell^{(j+1)})^{-1}[\,e^{-m^{(j+1)}} e^{S_{:,1:j}} V + e^{-m^{(j+1)}} e^{S_{:,j+1}} V_{j+1}\,] = \mathrm{softmax}(S_{:,1:j+1})V_{:,1:j+1}\)）。所以算法跑完 \(j = T_c\) 时输出逐位等于 \(\mathrm{softmax}(QK^\top)V\)——online softmax 是重排而非近似。数值上唯一的差别是浮点舍入顺序，FA3 §4.3 的实测表明在 FP16 下它甚至比标准实现更准（中间 softmax 统计量全程留在 FP32）。

2.3 Backward Algorithm 4：不存 \(N^2\) 矩阵，用 \(O\) 和统计量重算

标准 backward（FA1 Algorithm 3）按链式法则需要 \(P \in \mathbb{R}^{N\times N}\) 全程在手：

\[ \mathrm{d}V = P^\top \mathrm{d}O,\quad \mathrm{d}P = \mathrm{d}O V^\top,\quad \mathrm{d}S = P \circ (\mathrm{d}P - D_i),\quad \mathrm{d}Q = \mathrm{d}S K,\quad \mathrm{d}K = \mathrm{d}S^\top Q, \tag{式 5}\]

其中行内 softmax 的梯度是 \(\mathrm{d}s = (\mathrm{diag}(p) - pp^\top)\,\mathrm{d}p\)，展开后出现 \(\mathrm{d}S_{ij} = P_{ij}(\mathrm{d}P_{ij} - D_i)\)，而那行内归约项

\[ D_i = \sum_j P_{ij}\, \mathrm{d}P_{ij} = \sum_j \frac{e^{q_i^\top k_j}}{L_i}\, \mathrm{d}o_i^\top v_j = \mathrm{d}o_i^\top \underbrace{\sum_j P_{ij} v_j}_{o_i} = \mathrm{d}o_i^\top o_i. \tag{式 6}\]

式 6 是 FA1 backward 能省掉 \(N^2\) 存储的全部秘密（附录 B.2 式 (4)）：行内对 \(N\) 个元素的大归约 \(P_{i:}^\top \mathrm{d}P_{i:}\)，恰好等于前向输出与输出梯度的一个 \(d\) 维点积 \(\mathrm{d}o_i^\top o_i\)——前向把 \(O\)（\(O(N)\) 大小）和 logsumexp 统计量存下来，backward 就能逐块重算 \(S, P\)、现场算梯度，全程不需要 \(P\) 离开 SRAM。FA1 论文称之为「selective gradient checkpointing 的一种形式」（§3.1），并明确对比了 Rabe & Staats：后者靠梯度检查点重算所有临时输出，FA1 只重算注意力矩阵本身，解析地消掉了其余重算（§B.5）。

完整的 backward（FA1 附录 B.3/B.4，Algorithm 2 前向完整版 / Algorithm 4 反向）结构和前向同款双层循环：外层走 KV 块 \(j\)，内层走 Q 块 \(i\)；每块片上重算 \(S_{ij}, P_{ij}\)（用前向存的 \(\ell_i, m_i\) 恢复 \(P = \mathrm{diag}(\ell_i)^{-1} e^{S - m_i}\)）、dropout mask（重放伪随机数生成器状态，连 \(O(N^2)\) 的 dropout mask 也不用存）、再按式 5 累加 \(\mathrm{d}V_j, \mathrm{d}K_j\) 到 SRAM 累加器（外层块结束时写回一次），\(\mathrm{d}Q_i\) 逐块读写 HBM：

Algorithm 4  FlashAttention Backward（FA1 论文附录 B.4，节选）
 6: for j = 1 .. T_c do
 7:   载入 K_j, V_j 到 SRAM
 8:   片上初始化 dK_j = 0, dV_j = 0（B_c×d，SRAM 累加器）
 9:   for i = 1 .. T_r do
10:     载入 Q_i, O_i, dO_i, dQ_i, ℓ_i, m_i
11-13:  片上重算 S_ij = τ Q_i K_jᵀ；P_ij = diag(ℓ_i)^{-1} exp(S_ij − m_i)
14-15:  片上重放 dropout 掩码 Z_ij（由前向保存的 RNG 状态生成）
16:     dV_j ← dV_j + (P_dropped_ij)ᵀ dO_i
17-18:  dP_ij = dO_i V_jᵀ（再乘回 Z_ij）
19:     D_i = rowsum(dO_i ∘ O_i)        ← 式 6：d 维点积，替代 N 维归约
20:     dS_ij = P_ij ∘ (dP_ij − D_i)
21:     dQ_i ← dQ_i + τ dS_ij K_j（写回 HBM）
22:     dK_j ← dK_j + τ dS_ijᵀ Q_i
23:   end for
24:   写回 dK_j, dV_j
25: end for

四、FA2：循环交换、减非 matmul FLOPs、warp 划分（arXiv:2307.08691）

FA1 的算法是「IO 最优」了，但离硬件上限还远：FA2 论文开篇给出的诊断是前向只跑到 A100 理论峰值的 25–40%（后向 25–35%），而优化过的 GEMM 能到 80–90%（FA2 §1）。FA2 把原因归结为线程块与 warp 之间的工作划分不当，从算法层面做了三处改动（FA2 §1 三点总结）：

4.1 改动一：循环交换——Q 做外层，K/V 做内层

FA1 的循环次序是「外层 KV 块 \(j\)、内层 Q 块 \(i\)」，每个线程块负责一列 \(S\) 的 tile。这带来两个问题：

  • 并行度太低：FA1 的线程块网格是 \(\text{batch} \times \text{heads}\)（FA2 §3.2），一块 GPU 上通常只有几十上百个块。当序列很长时 batch 往往很小，A100 有 108 个 SM，\(B \times H < 108\) 时大量 SM 闲置。长序列恰恰是 FlashAttention 最想赢的场景。
  • softmax 统计量被踢出片上：外层走 KV 意味着「每换一个 KV 块，就要扫一遍所有 Q 行」——某一行 \(i\) 的 running 统计量 \((m_i, \ell_i)\) 在内层迭代之间无法保留，FA1 只好每步把它们连同 \(O_i\) 一起写回 HBM（Algorithm 1 第 8、12、13 行），下一轮再读回来。

FA2 反转循环：外层走 Q 块 \(i\)、内层走 KV 块 \(j\)（FA2 Algorithm 1），一个线程块固定负责一个 \(B_r \times d\) 的 Q 行块，从头扫到尾扫完所有 KV。收益（FA2 §3.2）：

  • 并行维度多了一个：网格变成 \((\lceil N/B_r\rceil,\ \text{batch},\ \text{heads})\)，即使 \(B{=}1, H{=}1\)，长序列也能铺满 SM（「外层循环天然 embarrassingly parallel，线程块之间无需通信」）。官方代码里的网格就是这三个维度：
// csrc/flash_attn/src/flash_fwd_launch_template.h:63-64（commit e7a6402）
const int num_m_block = (params.seqlen_q + Kernel_traits::kBlockM - 1) / Kernel_traits::kBlockM;
dim3 grid(num_m_block, params.b, params.h);

FA2 前向的线程块网格：第一维就是序列维的 Q 块数——FA2 §3.2 所说的「even for a single head, parallelize across different thread blocks」在代码里就是这一个 grid.x。（这一循环交换的思路最早由 Phil Tillet 在 Triton 教程的 fused attention 中实现，FA2 §3.2 脚注 3 给出了出处。）

  • softmax 统计量全程留在寄存器：\(m_i, \ell_i\)（以及未归一化输出 \(\tilde O_i\)）跟着 Q 行块驻留，内层循环里只有 \(K_j, V_j\) 流进 SRAM、流出去，HBM 上的中间读写只剩最终的 \(O_i\) 与 \(L_i\)。

图 3：FA1 → FA2 的循环交换（对应 FA2 论文 §3.2 与 Fig. 2）。左：FA1 一个线程块沿 KV 列扫，softmax 统计量每步绕道 HBM；右：FA2 一个线程块固定一行 Q 块、让 KV 从面前流过，running 统计量（\(m,\ell,\tilde O\)）驻留寄存器，序列维加入网格并行。causal 场景下 FA2 还能按行块直接跳过对角线以上的整列 KV 块（§3.1.1 因果掩码第 1 条），比无掩码快约 1.7–1.8×。

4.2 改动二：减少非 matmul FLOPs

FA2 §3.1 算了一笔单价账：A100 的 FP16 matmul 峰值 312 TFLOPs/s，非 matmul FP32 只有 19.5 TFLOPs/s——一个非 matmul FLOP 的“价格”是 matmul FLOP 的 16 倍。GPU 有专用的 tensor core 做 GEMM，而 softmax 的逐元素操作占着通用 FP32 单元，所以哪怕非 matmul FLOPs 只占总数的零头，也值得抠。两处改动：

（1）输出重缩放改成「攒到最后除一次」。FA1 Algorithm 1 第 12 行每步都做 \(\mathrm{diag}(\ell_{\text{new}})^{-1}(\cdots)\)，两项各乘一次行向量再除一次。FA2 §3.1.1 指出：没必要每步除，维护「未归一化」的 \(\tilde O\)、只乘 \(e^{m^{(j-1)}-m^{(j)}}\) 这一个因子，循环全部结束后再 \(\mathrm{diag}(\ell^{(T_c)})^{-1}\) 一次到位：

\[ \text{FA2 内层：}\quad \tilde O^{(j)} = \mathrm{diag}\big(e^{m^{(j-1)} - m^{(j)}}\big)^{-1}\, \tilde O^{(j-1)} + e^{S^{(j)} - m^{(j)}} V^{(j)},\qquad O = \mathrm{diag}\big(\ell^{(T_c)}\big)^{-1} \tilde O^{(T_c)}. \tag{式 7}\]

（2）backward 与落盘只存一个 logsumexp。backward 恢复 \(P\) 需要 \(e^{S - m}\) 和 \(1/\ell\) 两个量，但它们可以合成一个：\(P = e^{S - L}\)，其中 \(L = m + \log \ell\)（logsumexp）。FA2 存 \(L \in \mathbb{R}^N\) 代替 FA1 的 \(\ell, m\) 两个向量，backward 里 `P = exp(S − L)` 一步完成（FA2 Algorithm 2 第 11 行）。

（3）exp 换成 exp2：GPU 上 \(e^x\) 实际编译为 \(\mathrm{ex2.approx}(x\cdot\log_2 e)\)。FA2 把 \(\log_2 e\) 因子预乘进 softmax scale（`scale_softmax_log2`），让「乘 scale、减 max」合并成一次 FMA。官方实现注释写得很直白：

// csrc/flash_attn/src/softmax.h:81-90（commit e7a6402）
// Instead of computing exp(x - max), we compute exp2(x * log_2(e) -
// max * log_2(e)) This allows the compiler to use the ffma
// instruction instead of fadd and fmul separately.
tensor(mi, ni) = exp2f(tensor(mi, ni) * scale - max_scaled);

4.3 改动三：warp 级工作划分——从「split-K」到「split-Q」

再往下钻一层是 warp（32 线程）之间的分工（FA2 §3.3）。一个线程块通常 4 个 warp，一起算一个 \(B_r \times B_c\) 的 S tile：

  • FA1（split-K）：把 \(K, V\) 按 4 个 warp 切开、\(Q\) 全体共享。每个 warp 得到 \(S\) 的一个列切片——但 softmax 要整行的 max 和 sum！于是每个 warp 算完自己的局部结果后，必须把中间结果写进 shared memory、同步、再横向相加才能拼出完整行。这些 smem 读写就是 FA1 前向慢的元凶之一。
  • FA2（split-Q）：把 \(Q\) 切给 4 个 warp、\(K, V\) 全体共享。每个 warp 独占若干完整的行：自己算自己的 \(QK^\top\) 切片、自己做行归约、自己乘 \(V\) 得到自己那块输出——行内归约完全在一个 warp 内闭合，warp 间零通信（不需要 smem 中转，行 max 用 warp 内 shuffle 4 线程一组归约即可）。
  • backward 同理避开 split-K；块大小在 {64,128}×{64,128} 里按 head_dim 与 smem 容量手工调（FA2 §3.3）。

五、FA3：为 Hopper 的异步硬件重写流水线（arXiv:2407.08608）

FA2 在 H100 上只跑到 35% 利用率（FA3 §1），除了没吃上 Hopper 新指令，更根本的是：FA2 的算法结构是同步的——它默认「发出一条指令、等它做完、再发下一条」，而 Hopper 的硬件把两件最重的事变成了异步单元：TMA（Tensor Memory Accelerator，专管 GMEM↔SMEM 拷贝）和 WGMMA（warpgroup 级异步 tensor core 指令，可直接从 shared memory 取操作数，FA3 §2.2）。FA3 的三个技术（§1）：producer-consumer 异步、把 softmax 藏进异步 GEMM 的阴影里、FP8 低精度。逐一细看。

5.1 warp specialization：producer 与 consumer 分家

思想（FA3 §3.1）：与其让所有 warp 都「又搬数据又算数」，不如把一个 CTA 的 warpgroup 分成两种角色，各干各的、靠多级流水线同步：

  • producer warpgroup：只发 TMA 搬运（Q、\(K_j\)、\(V_j\) 从 HBM 到 SMEM 的环形缓冲），发出即可走人，不等完成；
  • consumer warpgroup(s)：只做计算——WGMMA GEMM + softmax + 更新 \(\tilde O\)。
  • 配套 setmaxnreg：producer 只需要发指令，把它的寄存器份额动态让渡给 consumer（Hopper 特性，FA3 §2.2）。
  • SMEM 开成 \(s\) 段环形缓冲（pipeline），producer 填第 \((j \bmod s)\) 段的同时 consumer 吃第 \((j-s+1 \bmod s)\) 段。

5.2 pingpong 调度与两阶段 GEMM-softmax 流水

warp specialization 只把「搬数」藏起来了，「softmax」本身还是串在两个 GEMM 之间。FA3 §3.1 的引子账：H100 FP16 matmul 989 TFLOPS、指数类特殊函数只有约 3.9 TFLOPS（132 SM × 16 ops/clk × 1.83 GHz）；head_dim 128 时 matmul FLOPs 是 exp 的 512 倍，但 exp 吞吐低 256 倍——softmax 的指数能吃掉多达一半的周期。指数跑在独立的 MUFU 单元上，所以理想调度是：WG1 算 softmax 时，让 WG2 的 tensor core 正忙着 GEMM。

pingpong 调度（FA3 §3.1，Fig. 1）：用 bar.sync 强制 WG1 的 GEMM（本迭代的 PV + 下一迭代的 QKᵀ）排在 WG2 的 GEMM 之前，于是 WG1 的 softmax 恰好落在 WG2 的 GEMM 窗口里；下一轮角色互换，乒乓往复。实测把 FP16 前向（\(d{=}128, N{=}8192\)）从 570 提到 620–640 TFLOPS。

两阶段（2-stage）GEMM-softmax 流水（FA3 §3.2，Algorithm 2）：即使在一个 warpgroup 内部，也能把「本块的 softmax」和「下块的 GEMM」跨迭代重叠。依赖链的死结是：softmax 依赖 GEMM0 的输出 \(S\)，而 GEMM1 又吃 softmax 的输出 \(\tilde P\)。解法是寄存器里多养一份 \(S_{\text{next}}\)，把串行链拆成交替推进：

Algorithm 2  FA3 consumer warpgroup 主循环（FA3 论文 §3.2）
 4: S_cur = Q_i K_0ᵀ（WGMMA，等完成）
 6: 由 S_cur 算出 m, P̃_cur, ℓ（第一次 softmax）
 7: for j = 1 .. Tc-1 do
 9:   S_next = Q_i K_jᵀ（WGMMA，只发不等）      ← 下块的 GEMM0

14:   等 P̃_cur V_{j-1} 完成，重缩放 O_i

19: 收尾：O_i += P̃_last V_last；epilogue 重缩放、归一、写 O 和 L

5.3 FP8：布局约束、block quantization 与 incoherent processing

FP8 让 tensor core 吞吐翻倍，但 FA3 §2.2/§3.3 指出两道坎：

  • 布局约束：FP8 WGMMA 的操作数只接受 k-major（沿 \(K\) 维连续），而 attention 的 \(V\) 天然沿 head_dim 连续，第二个 GEMM 要求 \(V\) tile 沿序列维连续。TMA 不能顺手转置，于是 FA3 在 kernel 内用 LDSM/STSM 指令做 tile 级转置，并安排它跑在 producer warpgroup 里、藏在前两次 WGMMA 的阴影中；FP32 累加器与 FP8 操作数 A 的寄存器布局不一致，再用 byte permute 把累加器重排成 FP8 A 布局（FA3 §3.3，Fig. 3/4）。
  • 精度：e4m3 只有 3 位尾数，LLM 激活又有 outlier。FA3 两招（§3.3）：
    • block quantization：per-tensor scaling（每个张量一个 scale）改为每个 \(B_r\times d\) / \(B_c \times d\) 块一个 scale；FA3 的算法天然按块算，把 \(S\) 的块级缩放融合进去零开销；
    • incoherent processing：给 \(Q, K\) 都右乘一个随机正交阵 \(M\) 再量化。因为 \(MM^\top = I\)，\((QM)(KM)^\top = QK^\top\)，输出数学上不变，但 outlier 被「摊匀」到整个矩阵。实操中 \(M\) 取「随机 ±1 对角阵 × Hadamard 阵」，乘法复杂度 \(O(d\log d)\)，还能融合进 rotary embedding 不花额外时间。

效果（FA3 §4.3 Table 3）：构造 \(N(0,1) + N(0,100)\cdot\mathrm{Bernoulli}(0.001)\) 的重尾激活，FP8 基线（per-tensor）RMSE \(2.4\times10^{-2}\)，FA3 FP8（两招全开）\(9.1\times10^{-3}\)——2.6× 更准；消融显示去掉 incoherent processing 就退化到基线水平。另注意 FP16 的 FA2/FA3 RMSE 都是 \(1.9\times10^{-4}\)，比标准实现（\(3.2\times10^{-4}\)）还低 1.7×，因为中间 softmax 全程 FP32。

六、FA4：为 Blackwell 的非对称扩展改形（arXiv:2603.05451）

FA4 的正式论文发布于 2026-03-05（Zadouri, Hoehnerbach, Shah, Liu, Thakkar, Dao，《FlashAttention-4: Algorithm and Kernel Pipelining Co-Design for Asymmetric Hardware Scaling》），本章内容全部来自该论文（本地 paper/flash-attention-v4.pdf）、官方 CuTe-DSL 源码（flash_attn/cute/）与 Tri Dao 博客（tridao.me/blog/2026/flash4，2026-03-05），检索日期 2026-10-19。此前（2025-08）曾有过面向 Blackwell/cuDNN 的 FA4 预告材料，细节以 2026 年论文为准。

6.1 病灶变了：tensor core 翻倍，别的原地踏步

Blackwell B200 的 BF16 tensor core 吞吐是 H100 的两倍（2.25 vs 1.0 PFLOPS），但 SRAM 读带宽（128 B/clk/SM）与指数单元 MUFU（16 ops/clk/SM）没变（FA4 §2.2）。FA4 论文 §3.1.1 用「feeds and speeds」把每个 SM 每迭代的周期账算了一遍。设 tile 为 \(M{\times}N\)、head_dim 为 \(d\)：

\[ T_{\text{MMA}} = \frac{4MNd}{8192}\ \text{cycles}\quad(式 1),\qquad T_{\text{smem}} = \frac{3MNd}{8192}\ \text{cycles}\quad(式 2),\qquad T_{\text{exp}} = \frac{MN}{16}\ \text{cycles}\quad(式 3) \]

（其中 \(T_{\text{smem}}\) 算上了 \(QK^\top\) 是 shared-shared MMA、\(PV\) 是 tensor-shared MMA、操作数被多次读取的效应。）代入两种 tile 配置（FA4 Table 1）：

结论反直觉：在 Blackwell 上，attention 的瓶颈已经是「exp 指数 + smem 流量」，与 MMA 计算打平甚至超出 25–60%（FA4 §1）。FA3 那套「softmax 藏进 GEMM 阴影」的流水在 Hopper 上把 exp 完全藏住了；但在 Blackwell 上 exp 自己就是一堵与 MMA 等高的墙——藏不住，只能拆墙：要么让 exp 更快（软件仿真，§6.3），要么少做（条件重缩放，§6.4）。此外 Blackwell 的硬件也给流水线开了新空间：MMA 完全异步且把累加器直接写进新增的 256 KB tensor memory（TMEM）而不是寄存器，单条 MMA tile 从 Hopper 的 64×128 翻到 128×128，还有 2-CTA MMA 模式（CTA 对协同执行一条 MMA，B 操作数各存一半，FA4 §2.2）。

6.2 流水线：双 Q tile ping-pong + 独立 correction warpgroup

FA4 前向沿用 FA3 式的 ping-pong：每个 CTA 同时算两个 Q tile（high/low，各 128 行 query），一个 tile 跑 MMA 时另一个跑 softmax。三处 Blackwell 特有的结构变化（FA4 §3.1.2）：

  • 累加器住 TMEM，一个线程管一整行：Hopper WGMMA 的累加器在寄存器里、每行由 4 个线程交错持有，行 max 需要 warp 内 shuffle；Blackwell MMA 把 128×128 累加器写进 TMEM，于是两个 softmax warpgroup（各 128 线程）可以一个线程独占一行——行 max 不再需要 shuffle，统计量也不再是「每线程多份」。softmax 流程变成：整行读进寄存器 → 求行 max → 减 max/缩放/指数/转输入精度 → 行 sum。
  • correction 独立成 warpgroup：Hopper 上 \(\tilde O\) 的重缩放必须在 consumer 自己的寄存器里做，串在 GEMM 之后；Blackwell 的 \(P\) 经 TMEM 交给 MMA，重缩放可以交给专门的 correction WG 异步完成，「从关键路径上摘下来」。TMEM 分配上，\(S\) 与 \(P\) 重叠共享（两份 \(S\) / 四份 \(P\) 的容量），既省 256 KB 的紧张空间，又让流水线一上来就能同时算两个 \(S\) tile。
  • 寄存器极限运营：一个线程要整行持 128 个元素（BF16 输入 128 个寄存器起步），配置表按 (因果性, head_dim) 给出 exp 仿真频率与各 WG 的寄存器配额（源码 flash_fwd_sm100.py:104-113，如 causal+d128：`num_regs_softmax=184, num_regs_correction=80`）。

6.3 软件模拟指数：让 FMA 单元替 MUFU 打工

MUFU 的 exp2 只有 16 ops/clk/SM，而 FMA 单元宽得多。FA4 §3.1.3 用经典手法把 \(2^x\) 搬到 FMA 上算：

\[ 2^x = 2^{\lfloor x \rfloor} \cdot 2^{x - \lfloor x \rfloor},\qquad 2^{x_{\text{frac}}} \approx \sum_{i=0}^{n} p_i\, x_{\text{frac}}^i\quad (x_{\text{frac}} \in [0,1)) \tag{式 4（FA4 式 4–5）}\]

整数部分 \(2^{\lfloor x\rfloor}\) 用 IEEE 754 位操作（把 \(\lfloor x \rfloor\) 加进指数域）拼出；小数部分用 Sollya 求系数的多项式、Horner 法逐次 FMA 展开。精度账（FA4 Table 2）：3 次多项式在 FP32 下最大相对误差 \(8.8\times10^{-5}\)（比硬件 MUFU 差约 600×），但舍入到 BF16 后与硬件输出几乎不可区分（BF16 量化误差 \(3.9\times10^{-3}\) 主导，3 次多项式在 99% 输入上与硬件相差 <1 ULP）——反正 softmax 的下游就是 BF16 tensor core，这笔精度花得值。实际不全部替换：「partial emulation」只对每行 10–25% 的元素走仿真路径（其余仍走 MUFU.EX2），因为仿真要额外寄存器、会把寄存器压力推向 spill 的悬崖；比例按 MMA:exp 吞吐比逐配置调，源码里的配置键就叫 ex2_emu_freq：

键为 (causal, local, head_dim, …)，值里 ex2_emu_freq: 10 即「每 10 个 fragment 有 1 个走软件仿真」。数值内核按论文的 5 步算法逐条实现：

# flash_attn/cute/utils.py:803-817（ex2_emulation_2，commit e7a6402，一次处理两个 float）
def ex2_emulation_2(x, y, *, poly_degree=3, loc=None, ip=None):
    # We assume x <= 127.0 and y <= 127.0
    fp32_round_int = float(2**23 + 2**22)
    xy_clamped = (cute.arch.fmax(x, -127.0), cute.arch.fmax(y, -127.0))   # ① clamp 防 underflow
    # We want to round down here, so that the fractional part is in [0, 1)
    xy_rounded = cute.arch.add_packed_f32x2(xy_clamped, (fp32_round_int,)*2, rnd="rm")  # ② 魔数取整得 ⌊x⌋
    xy_rounded_back = cute.arch.sub_packed_f32x2(xy_rounded, (fp32_round_int,)*2)
    xy_frac = cute.arch.sub_packed_f32x2(xy_clamped, xy_rounded_back)     # ③ 小数部分
    xy_frac_ex2 = evaluate_polynomial_2(*xy_frac, POLY_EX2[poly_degree])  # ④ 多项式（Horner）
    x_out = combine_int_frac_ex2(xy_rounded[0], xy_frac_ex2[0])           # ⑤ 整数部分拼指数域
    y_out = combine_int_frac_ex2(xy_rounded[1], xy_frac_ex2[1])
    return x_out, y_out

6.4 条件重缩放（conditional rescaling）：把「每次都做」变成「攒够了再做」

online softmax 每步都要用 \(e^{m_{j-1}-m_j}\) 重缩放旧输出——一个行向量乘法，落在关键路径上。FA4 §3.1.4 的观察：重缩放只在出现「显著更大」的新 max 时才有必要。设阈值 \(\tau\)（取 \(\log_2 256 = 8.0\)，即允许累积 256 倍的「松弛」），更新规则改为：

\[ O_j = \begin{cases} e^{m_{j-1}-m_j}\, O_{j-1} + e^{S_j - m_j} V_j, & m_j - m_{j-1} > \tau\\[4pt] O_{j-1} + e^{S_j - m_{j-1}} V_j, & m_j - m_{j-1} \le \tau \quad(\text{跳过重缩放，且不更新 } m) \end{cases} \tag{式 8（FA4 式 6）}\]

正确性论证很朴素：只要最后用真实的 \(m_{\text{final}}\) 与最终归一化因子 \(\ell_{\text{final}}\) 收尾（\(\text{Output} = O_{\text{final}}/\ell_{\text{final}}\)），中间欠下的所有缩放一次性补齐——\(m\) 允许「落后」最多 \(\tau\) 个 log2 单位，指数值最多到 \(2^{\text{max\_offset} + \tau}\) 仍不溢出（源码注释：flash_fwd_sm100.py:91-92）。这正是 §三 手算示例第 1 行那种 \(e^{-1}\) 级别小重缩放的推广：与其每块都乘一遍，不如让 \(m\) 落后着，最后统一修正。工程细节：为避免 warp 分歧，只要 warp 内任一线程需要重缩放就整 warp 一起重缩放（FA4 §3.1.4）。代码里是 softmax.py 的三行分支：

# flash_attn/cute/softmax.py:381-388（SoftmaxSm100.update_row_max，commit e7a6402）
acc_scale_ = (row_max_old - row_max_safe) * self.scale_log2
acc_scale = cute.math.exp2(acc_scale_, fastmath=True)
if cutlass.const_expr(self.rescale_threshold > 0.0):
    if acc_scale_ >= -self.rescale_threshold:   # 新 max 领先不足 τ ⇒ 不值得缩放
        row_max_new = row_max_old
        row_max_safe = row_max_old
        acc_scale = 1.0                          # 因子恒 1，O 与 ℓ 原样保留

6.5 backward：TMEM 减 smem 流量、2-CTA + DSMEM 重构 dQ

backward 的账（FA4 §3.2.1，式 7–10）显示 smem 是头号瓶颈：5 个 GEMM 的 MMA 计算 \(T_{\text{MMA}} = 10MNd/8192 = 2560\) 周期，而 smem 总流量 3328 周期——超出 MMA 约 30%。FA4 三板斧：

  • TMEM 存中间量：FA3 的累加器在寄存器里，寄存器稀缺强加了 \(\text{S}, \mathrm{dP}, \mathrm{dV}, \mathrm{dQ}, \mathrm{dK}\) 近乎串行的排序；FA4 把 \(S/P\) 共享 TMEM offset 0、\(\mathrm{dP}/\mathrm{dS}/\mathrm{dQ}\) 共享另一块，流水线得以让「本迭代的 softmax」与「上一迭代的 dQ/dK MMA」并发（FA4 §3.2.2）。
  • 2-CTA MMA：MMA tile 变成 M=256，CTA 对各存一半 B 操作数，B 侧 smem 流量约减半（Table 3：总 smem 3328 → 2688 周期，超 MMA 幅度从 30% 降到 ~5%）。dQ 的归约轴恰好在 CTA 对之间被切开，FA4 用 DSMEM（分布式共享内存）在 CTA 对内交换一半 \(\mathrm{dS}\) tile，把 dQ MMA 变成 \((M/2, 2N)(2N, d)\) 的双归约形状（FA4 §3.2.3，Fig. 3）。
  • 原子加减半 + 确定性模式：dQ 靠全局 atomic 累加（每内层迭代一次），2-CTA 拆分后每个 CTA 只写自己那一半，全局原子归约次数减半。要可复现（RL 训练调试）时，用信号量锁串行化归约，并配合 CTA swizzle 与「最短作业优先」（SPT：causal 下 KV 块降序发射、Q 块从对角线升序、dQ 归约按 Q 块降序排队）调度，确定性 backward 达到非确定性版的 75% 速度（FA4 §3.2.4）。
  • LPT 调度：causal/varlen 天然负载不均，FA4 用经典 longest-processing-time-first 排布 tile（batch 最外层、head 分段 swizzle 保 L2 命中），H200 上 BF16 d128 实测 MHA +4–8%、MQA-8 +7–14% FLOPS（FA4 §3.3）。

6.6 实现语言：CuTe-DSL

FA4 全部用 NVIDIA CuTe-DSL（Python 内嵌 DSL）写成、零 CUDA C++，JIT 编译单 kernel 用时 2.5 s（前向）/1.4 s（反向），对比 FA3 的 C++ 模板 55 s/45 s，快 20–30×（FA4 Table 4）。FlexAttention 与 block-sparse 变体已被社区在此基础上不改核心框架地实现（FA4 §4）。代码入口：flash_attn/cute/。
