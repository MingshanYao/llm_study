MHA 的 Prefill 与 Decode 账本：并行维度、计算量、访存量——以及 MHA→GQA→MLA 的改善主线

分析对象：单层 MHA attention 的两种执行形态（prefill 的 FlashAttention、decode 的 FlashDecoding / PagedAttention），以及 MQA / GQA / MLA 对它的改造
口径：示例模型取 Llama-2-7B 形状的 MHA（32 层、H=32 头、\(d_h{=}128\)、bf16）；硬件参照 H800 SXM（3.35 TB/s、BF16 989 TFLOPS，ridge ≈ 295 FLOP/Byte），与站内 V4-Pro roofline 账本同口径，数字可相互对账
关联报告：vLLM 第 3 讲：PagedAttention、DSpark、KV Cache 量化、V4 注意力（CSA/HCA）、V4.1 CSA2、LLM 架构演进
生成日期：2026-10-16

一句话：prefill 的 query 维有 \(L\) 个 token，天然并行度充足，FlashAttention 用 tile 复用把算术强度从 1 抬到 \(B_r{\approx}128\)（理想单遍上界 \(4S/3b{\approx}2731\)，式 4），贴近 ridge；decode 的 query 维塌缩为 1，MHA 下每字节 KV 只服务 1 个 query head，AI=1，离 ridge 差约 300 倍——kernel 层的 batch×head×split-KV 并行只能把带宽用满，一个字节也省不下来。

主线公式：\(\mathrm{AI}_{\text{dec}} = m_q \times h_{sh}\)——每字节 KV 服务的 (query 数 × head 数)。GQA 把 \(h_{sh}\) 抬到 g、MQA 抬到 H、MLA 抬到 ≈2H 且字节本身更小；稀疏注意力直接少读、量化把字节变小、投机解码把 \(m_q\) 抬到 >1。整条 MHA→GQA→MLA→… 的演进，就是在这两个旋钮上做文章。

两个世界的推论：prefill 全线算力受限、decode 全线带宽受限，两者连 kernel 结构都不同（单 kernel online softmax vs 两阶段 split+combine）——PD 分离部署不是工程偏好，是算术必然。

一、口径：一条主线公式与基准配置

attention 的一切性能问题都能归结为一个比值——算术强度（AI = FLOPs / HBM 字节）对照硬件 ridge point。为让后文所有数字可复算，先固定符号：

符号含义示例取值
\(B\)batch 内请求数1（decode 单请求）/ 任意
\(H\) / \(H_{kv}\)query 头数 / KV 头数；\(h_{sh}=H/H_{kv}\) 为共享比32 / 32（MHA）
\(g\)GQA 组大小：一个 KV 头服务的 query 头数4（GQA-8 时）
\(L\) / \(S\)query 长度（prefill）/ KV 长度（上下文）4096 / 4096
\(d\)头维 head_dim128
\(B_r\), \(B_c\)FlashAttention 的 query / KV 块大小（tile）128 / 128
\(m_q\)一份 KV 字节被加载后服务的 query token 数decode=1；spec decode>1
\(b\)KV 每元素字节数2（bf16）

decode 的 AI 有闭式解。每个 KV 位置、每个 KV 头的 K 行与 V 行共 \(2d\) 个元素、\(2db\) 字节；每来一个 query（每头、每 token），对它做一次 \(QK^\top\)（\(2d\) FLOPs）和一次加权求和 \(AV\)（\(2d\) FLOPs）。若一份 KV 字节被 \(m_q\) 个 token、\(h_{sh}\) 个头共享，则：

\[ \mathrm{AI}_{\text{dec}}=\frac{4\,d\,(m_q\,h_{sh})}{2\,d\,b}=\frac{2\,m_q\,h_{sh}}{b} \ \xrightarrow{\ \text{bf16 }(b=2)\ }\ \boldsymbol{m_q\cdot h_{sh}} \tag{式 1}\]

MHA 逐 token decode：\(m_q{=}1\)、\(h_{sh}{=}1\) → AI = 1 FLOP/Byte。这个数与 S、d、H 全都无关——分子分母同步消掉，正是 decode attention「怎么算都省不了字节」的代数表述。

\[ \mathrm{AI}_{\text{dec}}(S)=\frac{4\,S}{(2S+1)\,b} \ \xrightarrow{\ S\to\infty\ }\ \frac{2}{b} \tag{式 1b}\]

精确版（把 Q 也计入）：分子 4S = QKᵀ 与 AV 各 2S；分母 (2S+1)·b = K、V 整条读一遍（2S 个元素）+ Q 读一遍（1 个 d 切片）。O 的写回若也计入则为 (2S+2)·b，S=4096 时与上式只差 0.02%，习惯上忽略。代回 bf16、S=4096：4×4096 / (8193×2) = 0.9999——式 1 的「AI=1」在 4K 上下文已精确到万分之二；极限 2/b 同时解释了 KV 量化的收益（bpe 减半 → AI 物理值翻倍）。

prefill 的 AI 由 tile 大小决定。KV 从 HBM 读进 SRAM 后，tile 内 \(B_r\) 行 query 复用同一份，等效于 \(m_q = B_r\)：

\[ \mathrm{AI}_{\text{pre}}\approx \boldsymbol{B_r\cdot h_{sh}}\quad(B_r{=}128 \Rightarrow \mathrm{AI}{\approx}128) \tag{式 2}\]

KV cache 占用（它决定能并发多少请求、多长上下文）：

\[ C_{kv} = 2\,H_{kv}\,d\,b\ \ \text{Byte / token / 层} \tag{式 3}\]

三个数放在一起，硬件判据只有一行：H800 BF16 的 ridge = 989 TFLOPS ÷ 3.35 TB/s ≈ 295 FLOP/Byte。AI 高于它是计算受限，低于它是带宽受限。

二、Prefill：FlashAttention 的账本

prefill 一次处理整段输入：\(Q\,[L{\times}d]\) 对 \(K,V\,[S{\times}d]\) 做标准 attention。因果 mask 下可见长度平均为 \(S/2\)，单层计算量：

\[ F_{\text{pre}} = 2\underbrace{\left(2\,H\,L\,\tfrac{S}{2}\,d\right)}_{QK^\top}+2\underbrace{\left(2\,H\,L\,\tfrac{S}{2}\,d\right)}_{AV}\;=\;4\,H\,L\,S\,d\;/\,2\cdot 2 \;\xrightarrow{\ L=S=4096\ }\;137.4\ \text{GFLOP/层} \]

精确式：\(F_{pre} = 2 \cdot H \cdot L \cdot S_{avg} \cdot d \cdot 2 = 4 H L (S/2) d\)；代入 H=32、L=S=4096、d=128 得 137.4 GFLOP。

并行维度：grid = \((B,\ H,\ \lceil L/B_r\rceil)\)。三个维度全部「老天赏饭」——batch 之间独立、head 之间独立、Q 维切出 \(\lceil L/B_r\rceil=32\) 个 tile。L=S=4096、单请求时就有 1×32×32 = 1024 个 CTA，远超 132 个 SM，不需要任何补占用的技巧。每个 CTA 内部，\(B_r{=}128\) 行 query 对 KV 块顺序扫描，用 online softmax（滚动维护 \(m, l\) 两个统计量）把 softmax 归并进循环，无需物化 \(L\times S\) 的分数矩阵：

图 1｜prefill 的 FlashAttention。A：并行网格是对角的「阶梯」——(head, q-tile) 每个 CTA 只看自己可见的 KV 前缀；B：CTA 内部把 KV 块搬进 SRAM，\(B_r\) 行 query 全额复用。K、V 在循环里反复进出 SRAM，但 Q tile 与 O 累加器全程驻留。

# FlashAttention forward（简化）—— grid: (B, H, ceil(L/B_r))，并行度天然充足
m, l, acc = -inf, 0, 0                    # online softmax 统计量，CTA 内驻留
for kv_block in range(ceil(S/B_c)):
    K_i, V_i = load(K[kv_block], V[kv_block])      # HBM → SRAM，全 CTA 复用
    s     = Q_tile @ K_i.T / sqrt(d)                # [B_r, B_c]
    m_new = max(m, s.max(-1))
    p     = exp(s - m_new)                          # 旧统计量按 exp(m-m_new) 重缩放
    l     = exp(m - m_new) * l + p.sum(-1)
    acc   = exp(m - m_new) * acc + p @ V_i          # [B_r, d]
    m     = m_new
O = acc / l

数字账本（单层，L=S=4096，causal，\(B_r{=}128\)）：FLOPs = 137.4 G；KV 的 DRAM 读取（一阶，每 tile 重读可见前缀）≈ 1.07 GB；AI = 137.4G / 1.07G = 128。时间 = max(137.4G ÷ 989T, 1.07G ÷ 3.35T) = max(139, 320 µs) = 320 µs。一阶口径下它仍偏带宽侧（128 < 295）——实际 FA2/FA3 靠两件事把它往上推：更大的有效 tile（对 GQA 把同组 \(g\) 个头堆进 query 维，等效 \(B_r \times g\)），以及 L2 跨 tile 复用（相邻 q-tile 调度上共享同一份 KV，DRAM 实读远小于一阶账）。那真实 AI 的天花板在哪？把 KV 的重读完全去掉、Q/K/V 各从 DRAM 恰好读一遍，就得到理想上界：

\[ \mathrm{AI}_{\text{pre}}=\frac{4\,L\,S}{(L+2S)\,b} \ \xrightarrow{\ L=S\ }\ \frac{4S}{3\,b} \ \xrightarrow{\ \text{bf16},\ S=4096\ }\ \mathbf{2731} \tag{式 4}\]

理想上界：分子 4LS = QKᵀ 与 AV 各 2LS（非因果口径；causal 分子减半 → \(2S/3b\) ≈ 1365，且随 S 增长不封顶）；分母 \((L+2S)\cdot b\) = Q 读一遍 + K、V 各读一遍，与维度 \(d\) 无关（分子分母同含 \(d\)）。它假设 KV 零重读（L2 完美），故为上界——与式 2 的 128（每 tile 必重读一遍 KV 的下界）夹出真实值的活动区间：FA2 实测 60~75% MFU，反推有效 AI \(=\mu\cdot\text{ridge}/\beta \ge (0.6{\sim}0.75)\times 295\) ≈ 180~220，正落其间、逼近 ridge。prefill attention 的优化空间就一句话：把真实 AI 从 128 往 2731 推——让每份 KV 服务更多行 query。

三、Decode：FlashDecoding / PagedAttention 的账本

decode 每步每请求只有 1 个新 token：\(Q\,[1{\times}d]\) 对整个 KV cache 做「GEMV」。单层计算量 \(F = 4\,H\,S\,d\)（无 causal 折扣，全部位置可见）= 67.1 MFLOP——只有 prefill 的 1/2048。KV 必须整份读一遍：\(C = 2\,H_{kv}\,S\,d\,b\) = 67.1 MB。两数相除，AI = 1（式 1 的实例）。时间 ≈ 67.1 MB ÷ 3.35 TB/s = 20 µs/层，全模型 32 层 ≈ 640 µs——而这 20 µs 里 GPU 算力的利用率是 67.1 MFLOP ÷ 20 µs ≈ 3.4 TFLOPS，只占峰值的 0.3%。

并行维度：Q 维塌缩为 1，只剩 batch × head × KV 分块。前两个在 MHA 下是纯数据并行（各请求、各头的 KV 互不复用，切多少份总字节不变）；第三个——split-KV——是 decode 特有的补充：把 KV 序列切成 n 段，每段一个 CTA 算出局部 attention 结果 \((o_i, m_i, l_i)\)，再用一次 combine kernel 按 online-softmax 规则跨 CTA 归并。它不减少任何字节，唯一目的是凑够 CTA 数把带宽打满：

图 2｜decode 的 split-KV 与 combine。四个 CTA 各算 1/4 序列的局部 \((o_i, m_i, l_i)\)，combine 用 \(w_i \propto e^{m_i - m}\cdot l_i\) 加权归并——数学上与 online softmax 的块间归并完全同构。batch 与 head 两个维度在 MHA 下零数据复用，切分只改变「谁来读」，不改变「读多少」。

# 阶段 1 —— grid: (B, H, n_split)，split-KV 补占用率
for s in my_split_range:               # 本 CTA 只负责一段 KV
    score = q @ K[s].T                 # [1, len_i] —— 这就是 GEMV
    m_i, l_i = local_softmax_stats(score)
    o_i = softmax(score) @ V[s]        # 局部输出 + 局部统计量
    emit(o_i, m_i, l_i)

# 阶段 2 —— combine kernel：跨 CTA 归并（decode 特有的额外一步）
m = max(m_i for all splits)
w_i = exp(m_i - m) * l_i
O  = sum(w_i * o_i) / sum(w_i)

batch 的作用要说准：B 个请求的 KV 互不相同，字节与 FLOPs 同乘 B，AI 纹丝不动还是 1。batch 带来的是吞吐——带宽饱和之前，单条延迟几乎不变、系统吞吐随 B 线性涨，这是 continuous batching 的全部秘密。batch 解决「带宽用没用满」，永远解决不了「读了多少」。

权重与 KV 抢带宽：7B 模型 bf16 权重 14 GB，每步都要整份流过（4.2 ms）；KV cache @4K 全模型 2.15 GB（0.64 ms）。短上下文时 decode 的带宽大头其实是权重；上下文拉到 32K（KV 17.2 GB）KV 才反超，64K（34.3 GB）占七成。「decode 被 KV cache 卡死」是长上下文/大模型的命题——上下文越长、batch 越大，KV 字节层优化越值钱。

五、演进 I：在 head 间共享 KV——MQA 与 GQA

式 1 指明了唯一的出路：\(m_q\) 被 decode 钉死为 1，那就动 \(h_{sh}\)——让多个 query 头共用同一份 KV。KV cache 字节数（式 3）与 AI（式 1）同时改善，一头省显存、一头省带宽：

  • MQA（Shazeer, 2019，arXiv:1911.02131）：全部 \(H\) 个 query 头共享 1 个 KV 头。cache ÷H、AI ×H（=32），走到了共享的极端；代价是所有头看同一份 K/V，表达力受损，质量退化明显（PaLM、Falcon 采用过）。
  • GQA（Ainslie et al., 2023，arXiv:2305.13245）：折中——\(H_{kv}=8\) 个 KV 头，每组 \(g=H/H_{kv}=4\) 个 query 头共享一份。cache ÷4、AI ×4，质量用 uptraining（约 5% 原训练量，把 MHA 权重转换成 GQA 再续训）拉回 ≈MHA。Llama-2-70B、Llama-3、Mistral、Qwen 全线标配，是当代稠密模型的默认选择。

图 3｜decode 注意力在 roofline ramp 上的爬坡：MHA 1 → GQA-8 4（×4）→ MQA 32（×8）→ MLA ≈242（×7.6），步进倍数就是「共享 head 数」的增幅。MQA 虽然在 AI 上追平 MLA 量级，但质量代价大；MLA 的坐标来自 DeepSeek-V2 配置（H=128，\(d_c{=}512\)、\(d_r{=}64\)）。对照的 prefill 两点：一阶 tile 口径 128，实测凭 L2 摊销贴住天花板——prefill 从来不是这条 ramp 的受害者。

图 4｜KV cache 的坍缩。每 token 每层从 MHA 的 16 KB 压到 MLA 的 1.15 KB（且 MLA 是 128 头的大模型口径）；GQA-8 537 MB 的含义是「同样显存能并发 4× 请求或 4× 上下文」。cache 容量与 decode AI 是同一枚硬币的两面：两者都由 \(H_{kv}\)（共享比）决定。

六、演进 II：MLA——低秩压缩、K/V 同源与「吸收」

GQA 仍在「砍头数」，MLA（DeepSeek-V2，2024，arXiv:2405.04434）换了思路：把每个 token 的 K/V 压成一个低秩潜向量 \(c_{kv}\in\mathbb{R}^{512}\)（所有头共享），另配一个 64 维的解耦 RoPE 键 \(k_r\)（RoPE 的位置变换与低秩吸收不相容，必须单独存）。cache 里每 token 每层只有 \([c_{kv} \mid k_r]\) = 576 个元素 = 1152 B——比 MQA（512 B）略大，却保留了全部 \(H{=}128\) 个头的表达力。

为什么 decode AI 能到 ≈2H：吸收（absorbed）形式把 \(W_{UK}\) 折进 query 侧——\(\mathrm{score} = (W_{UK}^\top q_h)\cdot c_{kv} + q_r\cdot k_r\)。于是每条 1152 B 的 cache 条目同时充当 K（打分）与 V（加权和）两个角色、服务 128 个头：

\[ F = 2\,H\,(d_c{+}d_r) + 2\,H\,d_c = 278{,}528\ \text{FLOPs/位置/层},\quad B = (d_c{+}d_r)\times 2 = 1152\ \text{B} \;\Rightarrow\; \mathrm{AI}\approx \mathbf{242} \]

即式 1 的 \(h_{sh}\approx 2H\)：一份潜向量被「K 用一次、V 用一次、128 个头共用」。代价是 score 维度从 128 涨到 576，每 token 注意力 FLOPs ×4.5——但 decode 带宽受限，多余的 FLOPs 是免费的。

图 5｜MLA 的两种执行形式。不吸收：把 \(W_{UK}\) 作用在 KV 侧、每 token 物化 128 维的 \(k_h/v_h\)，attention 回到标准 MHA 形状——score 维 128，FLOPs 省 4.5×，适合算力受限的 prefill。吸收：把 \(W_{UK}^\top\) 折进 query、cache 只留 1152 B 的潜向量——字节最小，适合带宽受限的 decode（FlashMLA 即此形式）。同一份压缩，按 roofline 选执行形式——这是 MLA 对 prefill/decode 不对称性最直接的回答，也是本文 §2/§3 两套账本的合流点。

七、演进 III：之后的四条路

MLA 把「head 间共享」走到了尽头，但主线公式 \(AI = m_q \times h_{sh}\) 与字节数还有别的旋钮可拧：

路线代表动的旋钮效果与账本口径

跨请求复用prefix caching（vLLM APC）batch 间共享前缀batch 维上唯一真实的数据复用：公共前缀的 KV 块只读一次

站内账本的衔接：V4-Pro roofline 报告中注意力核 AI = 4·n_h·c ÷ 576 B = 455，正是本文框架在 MLA+FP8 条目上的实例——「每字节服务的 (query × head × K/V 双用) 数」再除以条目字节。MLA（242，bf16 1152 B）与 V4（455，FP8 576 B）是同一公式在不同字节口径下的两次取值。

八、总结：两个旋钮，两层优化

把全文收进一张表：

层手段改变什么不改变什么
kernel 层
（FA tiling、split-KV、PagedAttention）		prefill：Q 维切 tile，\(B_r\) 行复用AI：1 → \(B_r\)（×128）KV 总字节数一个不减；decode 的 AI 仍钉在 \(m_q \times h_{sh}\)
decode：batch × head × split-KV 凑占用率带宽利用率（32 CTA → 128 CTA）
字节层
（GQA / MLA / 稀疏 / 量化 / spec / prefix）		提高 \(h_{sh}\)（head 共享、低秩压缩）AI 与 cache 同步改善——这才是 decode 提速的来源；kernel 层写得再好也只是在带宽上限上打转
提高 \(m_q\)（投机解码）或直接减字节（稀疏、量化、prefix 共享）AI ×\(m_q\) 或 bytes ÷k

表 4｜两层优化框架。主线公式 \(\mathrm{AI} = m_q \times h_{sh}\)：prefill 靠 tile 把 \(m_q\) 做到 128 所以先天健康；decode 的 \(m_q{=}1\)，于是 MHA→GQA→MLA 的每一步都是在 \(h_{sh}\)（1 → g → ≈2H）上做乘法，之后的稀疏、量化、投机解码则分别在「字节」「字节」「\(m_q\)」上继续做文章。

最后回到最初的问题——「decode 是不是只有 head 上的并行度」：batch、head、KV-split 三者都是纯数据并行，切多少份就读多少字节；它们负责把 3.35 TB/s 用满，而 GQA→MLA→稀疏这条演进线负责让流过带宽的字节变少。前者是 kernel 工程师的手艺，后者是模型架构师的手艺——decode 提速的历史，是后者不断给前者减负的历史。
