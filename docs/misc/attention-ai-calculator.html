Attention AI 计算器：一条统一公式算尽 MHA→GQA→MQA→MLA→稀疏→量化→投机解码

这是什么：注意力核算术强度（AI = FLOPs / HBM Bytes）的交互式账本——把所有注意力变种的 AI 归结为一条统一公式、四个旋钮，任意调参即时出数
口径：KV 单遍读取（每条 KV entry 从 HBM 恰好读一遍）；Q / O 流量可选计入；硬件档位含自定义
姊妹篇：MHA 的 Prefill 与 Decode 账本（本页公式的推导与 preset 数字与它逐项对齐：式 1b / 式 4 / B_r=128）、V4-Pro roofline 账本
生成日期：2026-10-19

一句话：所有注意力变种的算术强度都归结为一条乘法公式

\[ \mathrm{AI}_{\text{KV}} \;=\; \underbrace{\frac{2\,r}{b}}_{\text{元素经济性}}\;\times\;\underbrace{h_{sh}}_{\text{head 共享}}\;\times\;\underbrace{m_q}_{\text{query/步}} \qquad\Big(r=\tfrac{d_k+d_v}{n_{kv}}\Big)\]

四个旋钮各归一个技术家族管：m_q（decode 1 → spec τ → prefill L，投机解码与 PD 形态）、h_sh（MHA 1 → GQA g → MQA H → MLA H，head 共享）、r（标准 1 → MLA ≈1.9，K/V 同源低秩压缩）、b（BF16 2 → FP8 1 → FP4 0.5，KV 量化）。而上下文 S、batch B、稀疏读取量 \(s_{\text{read}}\) 不在公式里——它们在分子分母同时出现、恰好消掉。下面 §2 可以随便拧。

一、统一公式：符号、推导与化简

1.1 符号表

先立符号，再推导。分两组：结构组由模型架构决定（换架构才变），执行组由这一步怎么跑决定（同一个模型每步可不同）：

1.2 推导：把 FLOPs 与 Bytes 分别数出来

口径先行：\(\mathrm{AI}=\text{FLOPs}/\text{Bytes}\)，两边都按「一次注意力核调用、每请求每步」计——batch 与层数只是把两边同乘常数，先不放进来（§4 会看到它们恰好消掉）。

第 1 步｜FLOPs。注意力核只有两次矩阵乘：QKᵀ 打分、AV 加权求和。先数一个 query 头里的一条 query 向量——它要对 \(s\) 条 entry 各打分一次、加权一次：

\[ \underbrace{2\,d_k\,s}_{\text{QK}^\top\text{ 打分}}+\underbrace{2\,d_v\,s}_{\text{AV 加权}}=2\,(d_k+d_v)\,s \;\;\xrightarrow{\;\times\,H\ \text{个头}\;\times\,m_q\ \text{条 query}\;}\;\; \text{FLOPs}=2\,m_q\,H\,s\,(d_k+d_v) \tag{式 A1}\]

乘加各计一次 FLOP；softmax、\(1/\sqrt{d}\) 缩放等 O(s) 低阶项不计（对 AI 影响 <1%）。\(d_k\ne d_v\) 的来历：MLA 吸收态的打分走潜向量 + rope（\(d_c{+}d_r\) 维）、加权只走潜向量（\(d_c\) 维）；标准模式两者同为 \(d_h\)。

第 2 步｜Bytes。单遍口径：每条 KV entry 从 HBM 恰好读一次——decode 的 PagedAttention / FlashDecoding 本来就按页读一遍；prefill 则是 L2 完美的理想假设（真实有 tile 重读，见 §1.3 口径注）。entry 共 \(s\times H_{kv}\) 条，每条 \(e_{kv}\) 字节；Q 读取与 O 写回按勾选计入：

\[ \text{Bytes}=\underbrace{s\,H_{kv}\,e_{kv}}_{\text{KV：}s\times H_{kv}\ \text{条}\times e_{kv}\ \text{B}} +\mathbb{1}_Q\,\underbrace{m_q\,H\,d_k\,b_a}_{\text{Q 读一遍}} +\mathbb{1}_O\,\underbrace{m_q\,H\,d_v\,b_a}_{\text{O 写回}} \tag{式 A2}\]

第 3 步｜相除，得精确式：

\[ \mathrm{AI}=\frac{2\,m_q\,H\,s\,(d_k+d_v)} {s\,H_{kv}\,e_{kv}\;+\;\mathbb{1}_Q\,m_q\,H\,d_k\,b_a\;+\;\mathbb{1}_O\,m_q\,H\,d_v\,b_a} \tag{式 A}\]

Q/O 不勾时分母只剩 KV 项——这是 §2 计算器的默认口径。\(s\)（含稀疏的 \(s_{\text{read}}\)）只在 KV 项里线性出现：KV 主导时它约掉；只有勾了 Q/O 且 \(m_q\) 很大时，才通过 Q/KV 比例回到 AI（§4 的「不消」情形）。

第 4 步｜化简成乘法形式。Q/O 不计时，分子分母的 \(s\) 约掉、\(H/H_{kv}\) 收拢为 \(h_{sh}\)：

\[ \mathrm{AI}_{KV}=\frac{2\,m_q\,H\,s\,(d_k+d_v)}{s\,H_{kv}\,e_{kv}} =\frac{2\,(d_k+d_v)}{e_{kv}}\times\underbrace{\frac{H}{H_{kv}}}_{h_{sh}}\times\,m_q \;\xrightarrow{\ e_{kv}=n_{kv}\,b\ }\;\frac{2\,r}{b}\times h_{sh}\times m_q \tag{式 B}\]

最后一步要求 entry 内精度均匀（\(e_{kv}=n_{kv}b\)）：标准模式恒成立，MLA-V2 bf16 也成立；V3 混合精度（FP8 潜向量 + BF16 rope）时保留 \(\frac{2(d_k+d_v)}{e_{kv}}\) 整体作「元素经济性」因子，不拆成 \(2r/b\)。倒过来读：一条 entry 挣回 \(2(d_k{+}d_v)\,h_{sh}\,m_q\) FLOPs、花掉 \(e_{kv}\) 字节——AI 就是单条 entry 的收支比，所以它对整个核成立、与 \(s\) 和 \(B\) 无关。

两类模式的符号取值（只有 \(r\) 与 \(e_{kv}\) 两处不同）：

  • 标准变种（MHA / GQA / MQA / NSA / 滑窗）：\(d_k=d_v=d_h\)、entry = K+V 共 \(n_{kv}=2d_h\) 个元素 → \(r=1\)、\(e_{kv}=2d_h\,b\)，统一公式塌缩成 \(\mathrm{AI}=2\,m_q\,h_{sh}/b\)。
  • MLA 吸收态（DeepSeek-V2/V3）：entry = 单个潜向量 \([c_{kv}\mid k_r]\)，\(n_{kv}=d_c+d_r\)；打分走 \(d_k=d_c+d_r\)（吸收后的 \(q^\top c_{kv}\) + rope 点积）、加权走 \(d_v=d_c\) → \(r=\frac{2d_c+d_r}{d_c+d_r}\approx 1.9\)（K/V 同源双用），\(e_{kv}=d_c b_c+d_r b_r\)。

图 1｜统一公式的四个旋钮与各自的技术家族。GQA-8 与 FP4-KV 的 decode AI 同为 4 不是巧合——共享 4 个头与减半字节，在公式里是同一个乘法位置；但前者省 4× cache、后者省 2× cache，AI 相同、cache 收益不同，这正是要把四个旋钮分开看的原因。

1.3 口径注：单遍读取与既有账本的对齐

本页 KV 单遍读取的口径下，decode 的 PagedAttention / FlashDecoding 本来就是每页恰读一遍 → 数值精确（勾选 Q 后即姊妹篇式 1b 的 \(4S/((2S{+}1)b)\)）；prefill 的单遍是 L2 完美的理想上界（勾选 Q、不勾 O 即式 4），一阶 tile 口径的下界 \(B_r{\approx}128\)（式 2）不在本页公式里——真实 FA2 落在两者之间。MLA 的 242 与 V4-Pro 的 455 都是 KV 单遍口径的实例。

四、三个「消掉」与一个「不消」

统一公式最反直觉的地方，是几个看起来很重要的量根本不在里面：

  • 上下文 S 从不出现：它只进 cache 容量账（§2 的「KV cache」行）。decode 每步的 AI 与聊了多长无关——变长的是每步时间（∝ s），不是每字节的效率。
  • s_read 在 KV 主导时消掉：分子分母同乘 s → AI 不变。稀疏注意力（NSA/DSA）、滑窗、top-k 全部在此列：它们买时间，不买 AI——从 64K 里只读 1K，注意力时间 ÷64，但每字节效率纹丝不动。
  • B 恒消掉：batch 是纯数据并行，各请求的 KV 独立。加 batch 只提高占用率、把带宽用满——这正是姊妹篇的结论「batch × head × split-KV 三维并行都是纯数据并行」的计算根源。
  • 什么时候不消：勾选 Q/O 且 \(m_q\) 相对 \(s\) 很大时（prefill × 稀疏的组合），Q 项在式 A 分母里占主导，AI 掉向 \(\approx 2\,s_{\text{read}}\)（与 \(m_q\) 无关）——比如 L=4096 的 prefill 只 top-k 读 1024 条，AI 从 4096 跌到 ≈1365。在计算器里勾上「计入 Q」就能看到这个塌陷。

所以整条演进史在公式里的位置是：kernel 工程（FA/FlashDecoding/PagedAttention）决定「单遍读取」这个口径能否成立、把带宽用满；模型架构（GQA/MQA/MLA/稀疏/量化）拧四个旋钮把 AI 抬过 ridge；投机解码与 PD 分离拧 \(m_q\)。三层各管一段，互不越界。
