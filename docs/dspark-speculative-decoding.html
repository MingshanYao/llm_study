一句话：DSpark 面向高并发生产级 LLM 推理，用「半自回归 drafter」（并行主干 + 轻量串行头）解决并行草案的后缀接受率衰减问题，用「置信度调度的硬件感知前缀调度器」解决盲目验证长草案浪费批容量的问题；离线上把每轮接受长度相对 Eagle3 / DFlash 提升 16%–31%，在 DeepSeek-V4 生产环境中把同等吞吐下的单用户生成速度提高 57%–85%，并外推了服务系统的吞吐–交互性 Pareto 前沿。

三个杠杆：投机解码每 token 延迟 \(L=(T_{\text{draft}}+T_{\text{verify}})/\tau\)，DSpark 同时优化了 draft 更快（并行主干，\(T_{\text{draft}}\) 与块长无关）、draft 更好（串行头注入块内依赖，提高 \(\tau\)）、verify 更聪明（按置信度与引擎负载动态截断验证长度）。

一、为什么需要 DSpark：投机解码的两个新瓶颈

1.1 基础回顾：三个杠杆

自回归 LLM 每生成一个 token 都要做一次完整前向。投机解码（Ge et al. 2022; Leviathan et al. 2023; Chen et al. 2023）用轻量 draft 模型一次性提议 \(\gamma\) 个候选 token，大 target 模型在一次前向中通过拒绝采样并行验证，接受与自身分布一致的最长前缀并附加一个 bonus token——接受规则保证输出分布与 target 完全一致（无损）。论文第 2 节把每 token 平均延迟写成：

\[ L=\frac{T_{\text{draft}}+T_{\text{verify}}}{\tau} \tag{式 1}\]

其中 \(\tau\) 是每轮接受的 token 数（含 bonus token），\(T_{\text{draft}}\)、\(T_{\text{verify}}\) 是起草与验证的墙钟时间（论文 §2.1，式 1）。

加速归结为三个杠杆：draft 更快（降 \(T_{\text{draft}}\)）、draft 更好（升 \(\tau\)）、verify 更聪明（降有效 \(T_{\text{verify}}\)）。不同的 drafter 架构就是在这些杠杆之间做取舍。

1.2 自回归 drafter 与并行 drafter 的两难

架构代表方法\(T_{\text{draft}}\)建模能力痛点
自回归 drafterEAGLE、Eagle3、DeepSeek MTP\(\propto \gamma\)，随块长线性增长强：每个位置条件于已采样前缀被迫用小 \(\gamma\) 和浅网络；树验证（如 EAGLE-2 的 tree attention）会进一步消耗批容量
并行 drafterMedusa、DFlash 等一次前向，与 \(\gamma\) 近似无关弱：各位置互相独立后缀接受率快速衰减；长块盲目验证浪费算力

并行 drafter 可以享受很深的网络（DFlash 用 5 层，而 Eagle3 因 \(O(\gamma)\) 延迟只能用 1 层），这带来首个位置的条件接受率优势（论文实测 Math 域 0.88 vs 0.81、Chat 域 0.72 vs 0.53）；但由于每个位置都边际化所有可能的前驱而非条件于实际采样的那个，会出现「多模态碰撞」——上下文既可以是 "of course" 也可以是 "no problem" 时，并行 drafter 可能采样出 "of problem" 这种跨模式拼接（论文 §3.1，援引 NAT 的经典分析 Gu et al. 2018）。

1.3 高并发服务下的系统级瓶颈

即便草案质量够好，不加区分地验证整个长块在高并发场景也会损害总吞吐：轻负载时多验证几个被拒绝的 token 几乎免费；重负载时每个低置信 token 都占用 target 模型的批容量——本可以服务其他活跃请求（论文 §1、§3.2）。而理想的验证长度同时随数据域（代码接受率高、开放聊天低）和系统负载变化，静态阈值无法两全。DSpark 的两个组件正对应这两个瓶颈：

  • 半自回归生成（§3.1）：计算昂贵的并行主干保持 \(T_{\text{draft}}\) 与 \(\gamma\) 解耦，只追加一个轻量串行输出头注入块内依赖，缓解后缀衰减、提高 \(\tau\)。
  • 置信度调度验证（§3.2）：置信头估计每个位置的前缀存活概率，硬件感知调度器结合实时引擎吞吐画像，只为期望收益为正的 token 分配 target 验证预算。

三、设计原理：半自回归 + 置信度调度

3.1 半自回归生成（Semi-Autoregressive Generation）

图 2：三类 drafter 架构对比（对应论文 §2.2 与 §3.1 的论证）。DSpark 的核心观察：并行 drafter 输在「块内独立性」而不在「单点能力」，自回归 drafter 输在「单点能力受限于延迟预算」——那就各取所长。

并行阶段：对 DFlash 的两处沿用与一处修改

DSpark 的并行主干直接采用 DFlash（Chen et al. 2026）：draft 模型与 target 共享并冻结 embedding 层与 LM head；prefill 时从 target 的若干层 \(\{l_1,\dots,l_m\}\) 抽取隐藏态，拼接投影为上下文特征（论文式 2）：

\[ H_{\text{ctx}}=\mathrm{RMSNorm}\bigl(W_{c}\,[H^{(l_{1})};\,\dots;\,H^{(l_{m})}]\bigr), \tag{式 2}\]

再把它作为前缀拼进每层 draft 的 K/V（KV 注入，论文式 3），块内所有位置双向互相注意并注意 target 上下文：

\[ K_{i}=[W_{i}^{K}H_{\text{ctx}};\;W_{i}^{K}H_{d}],\quad V_{i}=[W_{i}^{V}H_{\text{ctx}};\;W_{i}^{V}H_{d}] \tag{式 3}\]

DSpark 对 DFlash 的修改很小：原版输入是 anchor token + \(\gamma\) 个 mask token、只预测 mask 位置；DSpark 把 anchor 本身当作第一个预测位，即 \(\gamma\) 个输入（anchor + \(\gamma-1\) 个 mask）产出 \(\gamma\) 个草案 logits——省一点计算，质量相当（论文 §3.1）。

串行阶段：用「转移偏置」做块内条件化

并行主干一次前向产出基础 logits \(U_1,\dots,U_\gamma\) 与隐藏态 \(h_1,\dots,h_\gamma\)。串行阶段不定义全局归一化的能量模型，而是用自回归因子化引入一个前缀依赖的转移偏置 \(B_k(x_0,x_{<k},\cdot)\)（论文式 4）：

\[ P(X\mid x_{0})=\prod_{k=1}^{\gamma}p_{k}(x_{k}\mid x_{0},x_{<k}),\qquad p_{k}(v\mid x_{0},x_{<k})=\frac{\exp\!\left(U_{k}(v)+B_{k}(x_{0},x_{<k},v)\right)}{\sum_{u\in\mathcal{V}}\exp\!\left(U_{k}(u)+B_{k}(x_{0},x_{<k},u)\right)} \tag{式 4}\]

其中 \(x_0\) 是上一轮 target 生成的 anchor token（论文中 anchor 与 bonus token 同义）。这个设计有一个关键性质（论文 §6 Related Work）：串行修正保持局部，每个位置的 \(p_k\) 仍是精确的 softmax——因而拒绝采样所需的每 token 概率严格成立；而同为「并行隐藏态上叠串行模块」的 CRF-NAT（全局归一化配分函数）和 CTC-drafter（对齐路径的隐变量边际化）都无法给出精确的 per-token 概率。

两种实例化：

  • Markov 头（默认）：\(B_k\) 只依赖紧邻前一个 token，退化为 \(V\times V\) 的一阶转移矩阵 \(B\)，用低秩分解 \(B=W_1W_2\)（\(r=256\)）近似（论文式 5）：
    \[B(x_{k-1},\,\cdot\,)=W_{1}[x_{k-1}]\,W_{2}\in\mathbb{R}^{V}\tag{式 5}\]
    \(W_1\) 是 embedding 查找表、\(W_2\) 是 logit 投影。回到 "of course / no problem" 的例子：位置 1 采出 "of" 后，Markov 头会在位置 2 抬高 "course"、压低 "problem"，直接缓解跨模式碰撞。
  • RNN 头：维护递归状态 \(s_k\) 累积整块前缀历史。每步把 \([s_{k-1};\,W_1[x_{k-1}];\,h_k]\in\mathbb{R}^{2r+d}\) 作为输入 \(z_k\)，做一次门控更新（论文式 6）：
    \[ s_{k}=\sigma(W_{g}\,z_{k})\odot s_{k-1}+\bigl(1-\sigma(W_{g}\,z_{k})\bigr)\odot\tanh(W_{c}\,z_{k}),\qquad B_{k}(x_{<k},\,\cdot\,)=W_{2}^{\top}\tanh(W_{o}\,z_{k}) \tag{式 6}\]
    \(W_g,W_c,W_o\in\mathbb{R}^{r\times(2r+d)}\) 由单个线性投影切分共享，\(s_0=0\)。实验显示 RNN 头只比 Markov 头带来边际收益且部署更复杂，故默认用 Markov 头（论文 §4.3.2）。

因为采样天然串行，串行块必须足够轻（\(T_{\text{sequential}}\ll T_{\text{parallel}}\)），让总 draft 延迟仍由并行阶段主导。

3.2 置信度调度验证（Confidence-Scheduled Verification）

置信头：预测「前缀存活概率」

置信头对每个草案位置 \(k\) 输出标量 \(c_k\in(0,1)\)，语义是：在块内前缀全部被接受的前提下，位置 \(k\) 的草案 token 能通过 target 验证的条件概率（论文 §3.2.1）。结构是线性投影 + sigmoid（论文式 7）：

\[ c_{k}=\sigma\bigl(w^{\top}[h_{k};\,W_{1}[x_{k-1}]]\bigr) \tag{式 7}\]

注意特征里拼了前一个草案 token 的 Markov embedding \(W_1[x_{k-1}]\)——置信预测本身也依赖块内已采样的前缀。监督标签是解析的逐步接受率（论文式 8，源自 Leviathan et al. 2023）：

\[ c_{k}^{*}=1-\tfrac{1}{2}\|p_{k}^{d}-p_{k}^{t}\|_{1} \tag{式 8}\]
式 (7) 中 \(w^\top[h_k;W_1[x_{k-1}]]\) 与开源代码的对应关系为：AcceptRatePredictor 的 input_dim = hidden_size + markov_rank（配置项 confidence_head_with_markov=True），即隐藏态 \(h_k\) 与 Markov embedding 拼接后过一个单层线性投影（见 §4.4）。

Sequential Temperature Scaling（STS）：校准到「绝对量级」

阈值类启发式只需置信分排序正确即可；而 DSpark 的调度器要用累计乘积 \(\prod_{i\le k}c_i\) 去算期望接受长度 \(\tau\)，需要绝对概率准确。神经置信估计普遍过自信（论文引 Guo et al. 2017），因此引入 STS：利用链式法则，在留出验证集上从左到右逐位置校准联合概率——每个位置 \(k\) 做 1 维网格搜索，找最小化累计乘积期望校准误差（ECE）的温度标量，并固定前面位置已校准的分数。温度缩放是保序变换，只修正概率量级、不破坏 drafter 学到的排序（论文 §3.2.1）。实测原始置信头 ROC-AUC 0.81–0.90 但 ECE 3%–8%，STS 后平均 ECE 降到约 1%。

硬件感知前缀调度器：把验证长度选择建模为全局吞吐最大化

设一批有 \(R\) 个活跃请求，请求 \(r\) 的逐位置置信分为 \(c_{r,1},\dots,c_{r,\gamma}\)，调度长度 \(\ell_r\in\{0,\dots,\gamma\}\)。投机解码只按连续前缀接受，故位置 \(j\) 的存活概率是累计乘积 \(a_{r,j}=\prod_{i\le j}c_{r,i}\)。单次验证的批规模（按 token 计）与期望接受数为：

\[ B=\sum_{r=1}^{R}(1+\ell_{r}),\qquad \tau=\sum_{r=1}^{R}\Bigl(1+\sum_{j=1}^{\ell_{r}}a_{r,j}\Bigr) \]

引擎吞吐 \(\mathrm{SPS}(B)\)（steps per second，每秒前向步数）在引擎初始化时对 batch size 画像一次、存成轻量成本表。调度器最大化期望系统吞吐 \(\Theta=\tau\cdot\mathrm{SPS}(B)\)（论文 Algorithm 1）：

图 3：硬件感知前缀调度器（对应论文 §3.2.2 与附录 A）。左侧是贪心准入流程；右侧解释 early-stopping 为何是无损性的必要条件。

生产环境的工程改造（论文 §5.2）

直接部署 Algorithm 1 会与真实基础设施冲突：真实 \(\mathrm{SPS}(B)\) 是离散锯齿状阶梯而非平滑单峰曲线；Zero-Overhead Scheduling（ZOS）要求下一步批规模在当前步结束前确定，同步调度会卡住 GPU 流水线。DeepSeek 的落地做法是异步化：当前步候选仍按最新的累计置信分严格排序，但截断长度（批容量上限 \(K\)）用两步前的置信头预测近似——本质上变成动态 top-\(K\) 选择。由于截断只依赖两步前的历史信息，异步设计天然构成因果屏障：既可以在锯齿 SPS 曲线上做不设 break 的全局搜索（找穿越硬件阶梯的最大吞吐），又不会把当前 token \(x_{r,k}\) 泄漏进准入决策，无损性保持成立。

3.3 训练目标

训练时从每条 target 序列随机采样多个 anchor 位置构成 \(\gamma\)-token 块；target 模型全程冻结，draft 共享并冻结 embedding 与 LM head，只更新主干、串行块与置信头。三项损失均按位置权重 \(w_k=\exp(-(k-1)/\gamma)\) 加权（早期位置对前缀式验证的期望接受长度贡献更大）：

\[ \mathcal{L}_{\text{ce}}=-\sum_{k=1}^{\gamma}w_{k}\log p^{d}_{k}(x_{k}^{*}) \quad(9),\qquad \mathcal{L}_{\text{tv}}=\sum_{k=1}^{\gamma}w_{k}\|p_{k}^{d}-p_{k}^{t}\|_{1} \quad(10),\qquad \mathcal{L}_{\text{conf}}=-\sum_{k=1}^{\gamma}w_{k}\bigl[c_{k}^{*}\log c_{k}+(1-c_{k}^{*})\log(1-c_{k})\bigr] \quad(11) \]
\[ \mathcal{L}=\alpha_{\text{ce}}\,\mathcal{L}_{\text{ce}}+\alpha_{\text{tv}}\,\mathcal{L}_{\text{tv}}+\alpha_{\text{conf}}\,\mathcal{L}_{\text{conf}}, \qquad \alpha_{\text{ce}}=0.1,\ \alpha_{\text{tv}}=0.9,\ \alpha_{\text{conf}}=1.0 \tag{式 12}\]

\(\mathcal{L}_{\text{tv}}\) 直接以总变差距离为损失——而逐步接受率恰为 \(1-\tfrac12\|p^d-p^t\|_1\)，所以最小化 \(\mathcal{L}_{\text{tv}}\) 就是在最大化期望接受率（论文 §3.3）。

4.1 串行头：式 (5) 的低秩 Markov 转移

deepspec/modeling/dspark/markov_head.py:17-32 把 \(W_1\) 实现为 embedding 查找表、\(W_2\) 实现为无偏置线性层，逐 token 加转移偏置：

class VanillaMarkov(nn.Module):
    def __init__(self, *, vocab_size: int, markov_rank: int):
        super().__init__()
        ...
        self.markov_w1 = nn.Embedding(self.vocab_size, self.markov_rank)
        self.markov_w2 = nn.Linear(self.markov_rank, self.vocab_size, bias=False)

    def get_prev_embeddings(self, token_ids: torch.Tensor) -> torch.Tensor:
        return self.markov_w1(token_ids.long())          # W1[x_{k-1}]

    def project_bias(self, latent_states: torch.Tensor) -> torch.Tensor:
        return self.markov_w2(latent_states)             # W2

    def compute_step_bias(self, token_ids, hidden_states):
        del hidden_states
        return self.project_bias(self.get_prev_embeddings(token_ids))
        # ↑ B(x_{k-1}, ·) = W1[x_{k-1}] W2 ∈ R^V，即式 (5)

markov_head.py:17-32。\(W_1[x_{k-1}]\) 是 rank-256 的低维 embedding，\(W_2\) 把它投回词表维度——对 10 万级词表，存储与每步计算都很小。

4.2 推理时的逐位采样循环：式 (4) 的执行体

草案采样从 anchor 出发自左向右进行：每步先给该位置的基础 logits 加上前一个 token 的转移偏置，再采样，把样本喂给下一步（markov_head.py:73-90）：

        sampled_tokens = []
        corrected_logits = []
        prev_token_ids = first_prev_token_ids.long()   # x_0 = anchor
        for step_idx in range(proposal_len):
            step_hidden = None if hidden_states is None else hidden_states[:, step_idx, ...]
            step_logits = self.apply_step_logits(
                base_logits[:, step_idx, :],            # U_k（并行主干基础 logits）
                token_ids=prev_token_ids,               # x_{k-1}
                hidden_states=step_hidden,
            )                                           # U_k + B(x_{k-1}, ·)
            corrected_logits.append(step_logits.unsqueeze(1))
            next_token_ids = sample_tokens(
                step_logits.unsqueeze(1), temperature=temperature,
            ).squeeze(1)                                # 按 p_k(·|x_0, x_{<k}) 采样
            sampled_tokens.append(next_token_ids)
            prev_token_ids = next_token_ids             # 条件于实际采样结果
        return torch.stack(sampled_tokens, dim=1), torch.cat(corrected_logits, dim=1)

markov_head.py:73-90（VanillaMarkov.sample_block_tokens）。这个循环逐位执行、无法并行，但它只包含 embedding 查找 + 一次 rank-256 矩阵乘 + 一次 softmax 采样，因此 \(T_{\text{sequential}}\ll T_{\text{parallel}}\)。返回的 corrected_logits（加偏置后的 \(p^d_k\)）正是后续拒绝采样所需的草案分布。

4.3 RNN 头：式 (6) 的门控递归

RNNHead 把 \(W_g, W_c, W_o\) 合并为单个 joint_proj 线性层再按三份切分（markov_head.py:142-173）：

        # Joint projection: [s_{k-1}; W1[x_{k-1}]; h_k] -> [gate; candidate; output]
        self.state_size = markov_rank
        self.joint_proj = nn.Linear(2 * markov_rank + hidden_size, 3 * markov_rank)

    def _rnn_step(self, state, prev_embeddings, hidden_states):
        z = torch.cat([state, prev_embeddings, hidden_states], dim=-1)  # z_k ∈ R^{2r+d}
        proj = self.joint_proj(z)
        gate_raw, candidate_raw, output_raw = proj.chunk(3, dim=-1)
        gate = torch.sigmoid(gate_raw)
        candidate = torch.tanh(candidate_raw)
        new_state = gate * state + (1.0 - gate) * candidate             # 式 (6) 上半
        bias = self.project_bias(torch.tanh(output_raw))                # B_k = W2^T tanh(W_o z_k)
        return new_state, bias

markov_head.py:142-173。训练时 apply_block_logits（teacher-forced，状态沿块展开）与推理时 sample_block_tokens（采样与状态更新交替）共用这一个 _rnn_step。

4.4 并行主干：KV 注入与 anchor+mask 输入

式 (2) 的上下文特征投影在 Qwen3DSparkModel._forward_backbone 中（qwen3/modeling.py:372-373）：

        target_hidden_states = self.hidden_norm(self.fc(target_hidden_states))

qwen3/modeling.py:372-373；target_layer_ids 指定从 target 哪些层抽特征（默认配置取 \([1,9,17,25,33]\) 五层，含 embedding 输出 -1 的约定，见 common.py:52-56 的 extract_context_feature）。

式 (3) 的 KV 注入在注意力层里体现为「上下文 K/V 与草案 K/V 沿序列维拼接」（qwen3/modeling.py:103-116）：

        k_ctx = self.k_proj(target_hidden_states)     # 对注入的 target 上下文特征做 K/V 投影
        k_noise = self.k_proj(hidden_states)          # 对本块（anchor+mask）表示做 K/V 投影
        v_ctx = self.v_proj(target_hidden_states)
        v_noise = self.v_proj(hidden_states)
        k = torch.cat([k_ctx, k_noise], dim=1).view(...)   # K_i = [W_i^K H_ctx ; W_i^K H_d]
        v = torch.cat([v_ctx, v_noise], dim=1).view(...)   # V_i = [W_i^V H_ctx ; W_i^V H_d]
        ...
        # is_causal=False：块内所有位置互相双向注意，并注意注入的 target 上下文

qwen3/modeling.py:103-116。训练时注意力掩码由 create_dspark_attention_mask 用 flex_attention 的 block mask 表达（common.py:86-96）：每个 draft 位置可以看 kv_idx < anchor_pos 的全部上下文、以及同一块内的其他 draft 位置——多条训练块在序列维上打包但互不可见，这与论文 §5.1 的「anchor-bounded sequence packing（token 级注意力索引）」一致。

anchor + mask 的输入构造在 create_noise_embed（common.py:276-293）：整块填 mask_token_id，仅把每块第一个位置替换为真实 anchor token 的 embedding。

4.5 置信头与三项损失

置信头的构建（qwen3/modeling.py:262-267）与式 (7) 的特征拼接一一对应：

qwen3/modeling.py:262-267。

式 (8) 的解析接受率标签直接由 draft/target 分布的 L1 距离算出（loss.py:67-70）：

def _compute_accept_rate_3d(*, outputs, aligned_target_logits):
    ...
    draft_probs = torch.softmax(outputs.draft_logits.float(), dim=-1)
    target_probs = torch.softmax(aligned_target_logits.float(), dim=-1)
    accept_rate_3d = 1.0 - 0.5 * (draft_probs - target_probs).abs().sum(dim=-1)
    return accept_rate_3d.clamp_(0.0, 1.0)          # c*_k = 1 - 1/2 ||p^d - p^t||_1

loss.py:67-70。式 (11) 的置信损失即以此（detach）为软标签做 BCE-with-logits（loss.py:156-163）；式 (9)(10) 分别对应 loss.py:112-114 的加权交叉熵与 loss.py:73-87 的加权 L1 距离；式 (12) 的权重合成在 loss.py:248-252。

位置权重 \(w_k\) 的实现为指数衰减掩码（loss.py:31-36）：

    if loss_decay_gamma is not None and loss_decay_gamma > 0:
        positions = torch.arange(block_size, device=device).view(1, 1, -1)
        decay_weights = torch.exp(-positions.float() / float(loss_decay_gamma))
        loss_weight_mask = loss_weight_mask * decay_weights

loss.py:31-36。默认配置 loss_decay_gamma=4.0，即 \(w_k=\exp(-k/4)\)（位置从 0 起算）。

论文写 \(w_k=\exp(-(k-1)/\gamma)\)、代码是 \(\exp(-k/\gamma_{\text{cfg}})\) 且 \(\gamma_{\text{cfg}}=4.0\) 固定而非随块长变化——两者同属「指数衰减、强调早期位置」一族，但常数与记号细节略有出入，属于论文表述与开源实现间的轻微偏差。

4.6 推理提案与置信截断：开源的是「诊断版」

评测时草案块的构建流程在 deepspec/eval/dspark/draft_ops.py:96-153（build_dspark_proposal）：并行主干前向 → sample_draft_tokens 串行采样 → 置信头预测 → 按阈值截断前缀 → 拼出 verify_input_ids（anchor + 被调度前缀）并给出 draft_probs 供拒绝采样。静态阈值截断的核心（draft_ops.py:88-93）：

def _confident_prefix_length(confidence_logits, *, block_size, threshold):
    if threshold <= 0.0:
        return int(block_size)                      # 阈值 0 = 标准定长验证
    below_threshold = confidence_logits.sigmoid() < threshold
    if not bool(below_threshold[0].any().item()):
        return int(block_size)
    return int(torch.nonzero(below_threshold[0], as_tuple=False)[0].item())
    # 返回第一个低置信位置之前的长度（连续前缀）

draft_ops.py:88-93。论文 §4.3.3 的阈值扫描实验用的正是这个机制（阈值 0 等价于固定长度验证）。

开源边界：论文 §3.2.2 的完整硬件感知前缀调度器（Algorithm 1 的全局吞吐最大化 + §5.2 的异步 top-\(K\) 改造）服务于 DeepSeek 内部 HAI-LLM/V4 生产引擎，不在 DeepSpec 开源仓库中；开源侧提供的是静态阈值诊断版与置信头校准评测（ECE/AUROC/Brier，eval/dspark/confidence_head.py 的 ConfidenceHeadRecorder 以累计乘积 \(\prod c_i\) 对照实际接受前缀做逐位置校准诊断）。调度算法本身论文以伪代码 + 充分参数给出，可复现但无官方引擎代码。

五、与相关方法的对比

方法drafter 形态块内依赖验证长度与 DSpark 的关键差异
经典投机解码（Leviathan/Chen 2023）独立小模型，串行起草有（自回归）固定 \(\gamma\)DSpark 继承其拒绝采样与无损性框架，但 drafter 换成半自回归、验证长度动态调度
EAGLE / Eagle3自回归特征外推 drafter（1 层，TTT horizon=7）有固定（可配树验证）位置 1 条件接受率受限于浅网络（0.81 vs DSpark 0.93，Math，Qwen3-4B）；\(T_{\text{draft}}\propto\gamma\)
Medusatarget 上挂多解码头，并行出多头无（靠树注意力缓解）固定并行草案的早期代表；无独立置信驱动的调度，块内独立性导致的后缀衰减同样存在
DFlash块扩散式并行 drafter（5 层，KV 注入）无固定DSpark 的直接基座：并行主干沿用 DFlash（含 KV 注入、共享 embedding/LM head），叠加串行头与置信调度
动态长度类（DISCO/SpecDec++/D-Cut 等）各类 drafter + 置信阈值/bandit—静态阈值只按置信排序截断，不看系统负载；DSpark 把调度建为 \(\Theta=\tau\cdot\mathrm{SPS}(B)\) 的全局吞吐最大化并按负载伸缩
DSpark并行主干 + 轻量串行头（Markov/RNN）+ 置信头有（局部、保持 per-token 概率精确）硬件感知动态调度同时动式 (1) 的三个杠杆；调度器满足非预期性（early-stop / 异步两步前近似），保持严格无损

与并行生成文献的关系（论文 §6）：NAT 一系针对「多模态碰撞」的解法要么引入隐变量/迭代精化，要么改训练目标，但大多无法给出精确的每 token 概率，不能直接套进拒绝采样；CRF-NAT 同样在并行隐藏态上叠串行模块，但全局归一化配分函数破坏了 per-token 概率；CTC-drafter 受对齐路径边际化限制只能做贪婪验证。DSpark 让串行修正保持局部（逐位置 softmax），这是它能与标准拒绝采样无缝衔接的关键设计。同期的 Domino（CausalEncoder，概念上类似 RNN 头）与 DFlare（逐层融合）是并行工作。

6.2 消融与分析

  • 为什么并行能赢自回归（§4.3.1，Qwen3-4B 逐位置条件接受率）：位置 1 上 DFlash 明显高于 Eagle3（Math 0.88 vs 0.81；Chat 0.72 vs 0.53）——这是深网络 vs 浅网络的容量差，而前缀存活过程使首个 token 杠杆最大；位置 2–7 上 Eagle3 稳中有升（Chat 0.53→0.74）而 DFlash 快速衰减（Code 0.87→0.78；Chat 0.72→0.63）。DSpark 兼得两端：起始 0.93（Math）且全程高而稳。
  • 一点点自回归就很值（§4.3.2）：块长固定 7 时，2 层 DSpark 就能在所有域上超过 5 层 DFlash——串行头带来的序列一致性比单纯堆深并行层更划算。块长从 4 扫到 16，DSpark 对 DFlash 的差距持续扩大：\(\gamma=7\) 时提升 16%（Math）/15%（Code）/18%（Chat），\(\gamma=15\) 时扩大到 30%/26%/22%。RNN 头只在长块上有边际增益，默认用 Markov 头。
  • 延迟开销：batch 128、上下文 {512,1024,2048,4096} 下，串行头使整轮（验证 + 并行 draft + 串行采样）延迟相对 DFlash 只增加 0.2%–1.3%，却带来最多 30% 的接受长度提升。
  • 置信头诊断（§4.3.3，静态阈值扫描）：Chat 域随阈值升高，整体接受率从 45.7% 升至 95.7%（被剪掉的「本会被拒」token 显著减少）；Math 76.9%→92.5%、Code 67.6%→92.0%。校准诊断：原始置信头 ROC-AUC 0.81–0.90 但 ECE 3%–8%（过自信），STS 校准后平均 ECE 约 1%。
