系列：大模型量化零基础七讲（本篇为第 2 讲）

前置：第 1 讲的量化公式、per-group 粒度、舍入/裁剪误差。本讲有一处用到「矩阵乘法」，会当场解释。

本讲地位：GPTQ 和 AWQ 是今天下载量最大的 4-bit 开源模型的两大主流格式（Hugging Face 上搜 GPTQ / AWQ 后缀的就是它们）。看懂这两篇，等于看懂了当前权重量化的「普通话方言」。

本讲目标：① 训练后量化（PTQ）的完整流程——不重新训练，拿训好的模型直接压；② 一个灵魂观点：量化的目标不是「权重本身偏差小」，而是「这一层的输出偏差小」；③ GPTQ 怎么用「逐列量化 + 误差分摊」实现这个目标；④ AWQ 怎么用「等效缩放」保护那 1% 最重要的权重；⑤ 两者怎么选、怎么亲手跑一遍。

1. PTQ 全景：不训练，只「翻译」

训练后量化（PTQ, Post-Training Quantization）的定义就藏在名字里：模型练完之后，再把它转成低比特。不碰训练数据、不跑反向传播、不动损失函数——整个过程更像「翻译」而不是「重修」。

输入输出清单：

  • 输入：训练好的 FP16 模型；几百到几千条有代表性的文本（校准集，不需要标签，维基百科/对话样例都行）。
  • 输出：低比特模型文件——INT4 权重矩阵 + 一组 scale/zero-point。
  • 过程：一层一层处理模型里的每个线性层（Linear）。对每一层：先用校准样本「过一遍」，拿到这一层的真实输入，再决定怎么量化这一层。

图 2-1｜PTQ 流程。校准集不是训练集：它只用来观察每层输入的分布，用来定 scale 和指导优化；模型权重在这个阶段从不被「学习」，只被「改写」。

2. 基线 RTN 与它的失败原因

最朴素的 PTQ 叫 RTN（Round To Nearest，就近取整）——就是第 1 讲手算的那个：每个权重直接就近入座，不搞任何优化。8-bit 下 RTN 表现不错（第 0 讲的底牌足够用）；但压到 4-bit，RTN 的模型开始明显变笨。为什么？

关键在于权重之间不是各过各的。回忆线性层在算什么：输出 \( y = w_1 x_1 + w_2 x_2 + \cdots + w_n x_n \)（一个「加权求和」——每个权重乘上对应输入再全加起来）。量化误差对输出的影响是 \(\Delta w_1 x_1 + \Delta w_2 x_2 + \cdots\)——是所有列的误差的加权和。这意味着：

灵魂观点既然输出只看「误差的总和」，那么某一列的误差大一点没关系——只要其他列的误差方向相反、把它抵消掉就行。单看每个权重都量化得不好，但加起来可以恰好没错。RTN 让每列独立就近入座，白白放弃了这个「互相打配合」的机会。

一个最小的数值演示：输入 \(x_1 = x_2 = 1\)，真实权重 \(w_1 = 0.9,\ w_2 = 0.1\)，真实输出 \(y = 1.0\)。用格子间距 0.125 的对称 4-bit（格子 \(\{\ldots, -0.125, 0, 0.125, \ldots\}\)）：

  • RTN：\(w_1 \to 0.875\)（差 −0.025），\(w_2 \to 0.125\)（差 +0.025）。输出 \(0.875 + 0.125 = 1.0\)——两列误差恰好抵消，输出分毫不差。
  • 反例：若 \(x_2 = -1\)，则 \(y = 0.8\)，量化后 \(0.875 - 0.125 = 0.75\)，误差 +0.05——同样的权重误差，因为输入变了，抵消关系就变了。

所以「误差能不能互相抵消」取决于校准输入的统计规律（哪些方向常出现、列与列是否相关）。要把「打配合」从碰运气变成系统方法，就需要知道：哪些误差组合代价大、往哪个方向补偿收益大。这就是 GPTQ 登场的地方。

3. GPTQ：逐列量化 + 误差分摊

GPTQ（Frantar 等，2022，ICLR 2023）把「让输出误差最小」写成一个明确的优化问题。对一层：

\[ \min_{W_q} \; \| WX - W_q X \|_2^2 \]

其中 \(W\) 是原始权重矩阵，\(W_q\) 是量化后的版本，\(X\) 是校准样本在这一层的输入（每一列是一条样本展开成的向量）。\(WX\) 是原始层的输出，\(W_qX\) 是量化层的输出——目标就是两种输出尽量一样，权重本身偏多少不直接管。

直接解这个「每个变量只能取 16 个格子值」的优化问题是天文数字级的组合爆炸。GPTQ 的策略是贪心逐列，来自剪枝领域的「最优脑损伤（OBS/OBD）」一脉，其量化版叫 OBQ。整层处理循环如下：

  1. 算统计量（Hessian）：\(H = 2XX^\top\)。名字唬人，直觉很简单：它记录「校准输入在哪些方向上分量重」——在这些方向上弄出误差，输出代价就大；冷门方向上出错则无所谓。\(H\) 一层只要算一次。
  2. 挑一列，就近量化：默认按 \(H\) 对角线从大到小的顺序处理（即先处理「代价最重」的列，术语 act-order / desc_act）。
  3. 把这一列的误差分摊出去：这一列量化后产生的偏差，不憋在自己身上，而是按一个由 \(H\) 决定的最优比例，加到所有尚未量化的列上——后面的列入座时会带着这份「修正量」就座，从而在整体上把输出误差吃回去。
  4. 重复，直到所有列处理完。

图 2-2｜GPTQ 的核心一步（列数仅为示意，真实的 \(W\) 每列有几千行）。橙色列刚量化完，误差顺着校准输入的相关性流向右侧未量化列。

3.1 两个工程细节（读模型卡时会遇到）

  • group_size（常为 128）：每 128 行共用一组 (s, z)。组越小精度越高、scale 存储越多——128 是公认甜点。
  • desc_act（act-order）：上面第 2 步的「按重要性排序列」。对均匀 4-bit 有可观增益，代价是 kernel 实现更绕。模型卡上看到 desc_act: true 就是开了这个开关。
# GPTQ 单层处理（极简示意，非真实实现）
X = collect_inputs(calib_data, layer)        # 校准输入
H = 2 * X @ X.T + lam * I                    # Hessian + 阻尼
order = argsort(diag(H), descending=True)    # act-order: 重的列先来
for i in order:
    s, z = group_params(W[:, i])             # per-group 128
    Wq[:, i] = round(W[:, i] / s) + z        # 本列就近入座
    err = (W[:, i] - dequant(Wq[:, i])) / H[i, i]
    W[:, order_after(i)] -= err * H[i, order_after(i)]
                                             # 误差分摊给未量化列
快不快GPTQ 不需要反向传播、不需要显卡训练，本质是「一层内的矩阵运算循环」——原论文量化 175B 模型只用约 4 个 GPU·小时。校准集几百条就够。这是 PTQ 能成为工业标配的根本原因：几乎免费。

4. AWQ：先把重要的权重保护起来

GPTQ 的思路是「量化后补救」（误差分摊）。AWQ（Lin 等，2023）换了个思路：量化前改造坐标，让重要的权重天生不容易被量化伤到。

4.1 前提观察：重要性极不均匀

一个权重「重要」，说的是它出错时输出受的影响大——由第 2 节的公式 \(\Delta w \cdot x\) 可见：误差乘上的是输入的大小。AWQ 团队实测：少数通道（约 0.1%~1%）对应的激活幅值远大于其他通道，这些通道上的权重误差会被放大很多倍——它们是「显著权重」。直接想到的办法是显著权重保留 FP16（混合精度），但那会让 GPU kernel 几乎没法高效写。

4.2 关键招式：等效缩放（不伤输出的「挪动」）

AWQ 对每个通道乘一个系数 \(s\)，同时把输入除回同一个 \(s\)：

\[ y = \sum_j w_j x_j \;=\; \sum_j (s_j w_j)\cdot\Big(\frac{x_j}{s_j}\Big) \]

输出数学上完全不变（就是乘法结合律），但量化的「难度分布」变了：

  • 显著通道的权重被放大：同样半格宽的量化偏差，相对放大的权重而言占比更小；
  • 对应的激活被缩小：即使剩点误差，乘上的 \(x/s\) 也变小了；
  • 不显著通道几乎不受影响。

图 2-3｜AWQ 等效变换一例。数字为示意；严格表述是：搜索每通道缩放系数，最小化 \(\|Q(W\cdot \mathrm{diag}(s))\,\mathrm{diag}(s)^{-1}X - WX\|^2\)。

「放大权重 → 相对误差变小」是简化说法；严格机制是缩放后显著权重在量化格子中的相对位置更优、且其输入被等比缩小，两者共同降低该通道对输出的误差贡献。工程结论不变：AWQ 对激活分布不友好的模型（outlier 多）通常比 RTN/GPTQ 更稳，且几乎不增加量化成本。

6. 亲手跑一遍

拿一个 7B 开源模型压成 4-bit（需要一块 ~20 GB 显存的卡，7B 模型量化时以 FP16 加载）：

# 方案 A：AutoAWQ
from awq import AutoAWQForCausalLM
from transformers import AutoTokenizer

model_path = "Qwen/Qwen3-8B-Base"
model = AutoAWQForCausalLM.from_pretrained(model_path)
tokenizer = AutoTokenizer.from_pretrained(model_path)

quant_config = {"w_bit": 4, "group_size": 128,
                "zero_point": True, "version": "GEMM"}
model.quantize(tokenizer, quant_config=quant_config)
model.save_quantized("./qwen3-8b-awq")
# 方案 B：GPTQModel（AutoGPTQ 的活跃后继）
from gptqmodel import GPTQModel, QuantizeConfig

model_path = "Qwen/Qwen3-8B-Base"
quant_config = QuantizeConfig(bits=4, group_size=128, desc_act=True)
model = GPTQModel.load(model_path, quant_config)
model.quantize(calib_dataset)          # 几百条文本即可
model.save("./qwen3-8b-gptq")
# 用 vLLM 起服务（自动识别 GPTQ/AWQ 格式）
# vllm serve ./qwen3-8b-awq
# 或 transformers 直接加载量化模型推理
验收量化完成后做三件事：① 比较量化前后模型文件大小（应约 1/4）；② 用同一批 prompt 对比生成质量（肉眼 + 困惑度）；③ 跑一个基准（如 MMLU 子集）看掉点是否在 1 个点以内。第 5 讲会讲怎么在 vLLM/llama.cpp 里把 4-bit 模型跑出真正的速度收益。

7. 自查清单

  1. PTQ 的输入输出各是什么？校准集的作用是什么？（答：输入=训好的模型+几百条校准文本；输出=低比特权重+scales；校准集只用来观察每层输入分布、指导 scale 和优化，从不训练权重）
  2. 为什么量化目标是「层输出误差」而不是「权重本身误差」？（答：输出是所有列误差的加权和，列间可以互相抵消；权重误差小≠输出误差小）
  3. GPTQ 的 Hessian \(H=2XX^\top\) 直觉上记录了什么？（答：校准输入在哪些方向分量重——这些方向上出错代价大，分摊补偿时按它走）
  4. GPTQ 处理一层的三步循环？（答：挑一列就近量化 → 计算该列误差 → 按 Hessian 最优比例分摊给未量化列；重要列先处理 = act-order）
  5. AWQ 的「显著权重」由什么定义？（答：对应激活幅值大的通道——误差乘 |x| 被放大；约占 0.1%~1%）
  6. AWQ 的等效缩放为什么不改变输出？（答：\(y=\sum (s_jw_j)(x_j/s_j)=\sum w_jx_j\)，纯乘法结合律）
  7. 两算法的共同点？（答：都基于校准集、都不需要反向传播、都优化层输出 MSE、量化都快）
  8. 拿到一个新模型，格式怎么选？（答：优先作者官方发布的格式；都自己压则按困惑度/下游分数定夺，4-bit 下通常伯仲之间）
