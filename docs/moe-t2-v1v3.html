本讲目标：把 DeepSeek MoE 地基的三次浇筑逐块讲透。① V1 双引擎：细粒度专家（同参数量下组合数从 120 → 约 44 亿）＋ 共享专家隔离（共性加工不再浪费路由竞争）；② V2 工程化：模型变大后专家分住不同 GPU，通信成为新瓶颈，用「设备限制路由」做交换；③ V2.5→V3 均衡革命：bias 门控把均衡信号藏进「梯度失明区」，辅助损失不再伤模型——配两轮完整手算；④ V3 的 sigmoid 亲和度与序列级保险丝；⑤ V3.2 的 Keep Routing（RL 场景的路由一致性）。

1. V1 的靶子：经典粗专家 MoE 的两个毛病

2024 年 1 月的 DeepSeekMoE 论文开篇先点名了 GShard / Switch 式经典 MoE 的两个结构性毛病：

  1. 组合灵活性差：专家少而粗（比如 16 个大 FFN 选 2 个）。每个大专家内部要同时处理「语法」「常识」「代码」……一堆混合职责，特化程度上不去。
  2. 共性知识摊派在路由专家里：像「基础语法处理」这种几乎所有 token 都需要的加工，本不该占用「按需分配」的路由名额，却不得不混在各个大专家里——每个专家都得自带一份「通用底料」，重复存储、挤占特化容量。

V1 的两个创新分别对着这两个毛病。

2. 创新一：细粒度专家分割（fine-grained expert segmentation）

2.1 机制：把大专家切小

论文的做法用一句话就能说完：把每个专家 FFN 切成 \(m\) 个小专家，同时把激活数从 \(K\) 提到 \(mK\)，激活参数量保持不变。\(m\) 叫分割比（16B 模型取 \(m=4\)）。专家变小 = 每个专家的中间维缩到原来的 \(1/m\)，职责可以更单一。

图 2-1｜细粒度分割的交换逻辑：专家数量 ×m、单个规模 ÷m、激活数 ×m → 激活参数与计算量不变，组合空间指数级放大。

2.2 V1-16B 的真实配置

项目数值备注

2.3 成绩单

  • DeepSeekMoE 2B 的效果匹敌 GShard 2.9B——后者专家参数与计算量都是它的 1.5 倍（V1 论文摘要原文）；
  • DeepSeekMoE 16B 以约 40% 的计算量达到与 LLaMA2 7B 相当的性能（V1 论文摘要原文）。
为什么切小有效大专家像一个「一人分饰八角」的演员，切小后每个小专家只需演好一个角色，路由器再把 8 个角色临时组队。同一个 token 拿到的不再是一个「什么都沾一点的加工」，而是 8 项精准服务叠加。

3. 创新二：共享专家隔离（shared expert isolation）

3.1 机制

再设 \(K_s\) 个「共享专家」：无论路由器怎么打分，每个 token 恒定经过它们（恒激活），并且它们不参与 top-k 竞争、不占路由名额。层的输出变成：

\[ \underbrace{\sum_{i=1}^{K_s} \mathrm{FFN}_{s,i}(x)}_{\text{共享专家：恒激活，处理共性}} \;+\; \underbrace{\sum_{i=1}^{K_r} g_i\, \mathrm{FFN}_{r,i}(x)}_{\text{路由专家：top-k 加权，处理个性}} \]

图 2-2｜共享 / 路由解耦结构。这个「恒激活支路 + 路由支路」的两段式结构从 V1 一直沿用到 V4，从未动摇。

3.2 为什么有效

课程比喻把专家想象成课程：「读写能力」是每个学生都要的必修课（共享专家，人人自动 enrolled）；「古埃及文字」「量子场论」是选修课（路由专家，按需选）。不隔离的话，每门选修课都得先讲一遍读写基础——重复、低效，选课名额还浪费。隔离之后，选修课容量全部用于真正的差异化内容。

回到负载均衡视角：共享专家把「人人都要」的巨大流量接走了，路由专家池里的流量竞争只剩「差异化部分」，热门/冷门的分布更接近真实需求差异，而不是被通用需求淹没。

3.3 V1 留下的债

细粒度专家把 \(N\) 从 16 量级抬到 64–384 量级，第 1 讲讲过的「赢者通吃」正反馈在小专家上更凶猛（单个专家的接待面更窄，更容易被冷落）。所以 V1 时代只能用老办法——辅助均衡损失——而且得加大剂量。均衡与特化的矛盾，从此从「隐忧」升级为「主线剧情」。

4. V2：模型放大 15 倍后，通信成了新老板

4.1 专家并行（EP）：专家分住不同 GPU

V2 总参数 236B、每 token 激活 21B，每层 160 个路由专家 + 2 个共享专家。这么多的专家显然放不进一张 GPU，解决办法是专家并行（Expert Parallelism）：把专家拆到不同卡上，每张卡只持有一部分专家。

图 2-3｜每次过 MoE 层，每个 token 都要跨网络两次（Dispatch / Combine），这在 V2 论文里被称为 all-to-all 通信——2000 亿参数模型的训练里，它贵得惊人。

4.2 设备限制路由（device-limited routing，M=3）

跨卡快递贵，那少寄几家就是了。V2 的做法：每个 token 的 top-6 专家，最多允许分布在 3 台设备上。具体做法是先按「设备累计分数」挑出最优的 3 台设备，再在这 3 台内选满 6 个专家。

  • 收益：每 token 的 Dispatch / Combine 对象从「最多 6 卡」缩到「最多 3 卡」，跨机流量大减；
  • 代价：路由自由度被硬性削减——每个 token 能看见的专家从全池缩到 3 卡的子集，特化被牺牲了一部分（第 1 讲矛盾的又一次现身：为工程让渡质量）；
  • 配套：辅助均衡损失升级为三重——专家级、设备级（每台设备接收的 token 数均衡）、通信级（每设备发出的 token 数均衡）。均衡这一侧的「管制」越来越多。
一句话记住 V2V2 把 V1 的架构原封不动放大到 236B，为了喂饱跨卡通信开始给路由「上枷锁」。枷锁能换效率，但每一道都在蚕食路由自由——后面 V3 加一道、V4 全拆掉。

5. V2.5 → V3：bias 门控——「辅助损失免费」的均衡革命

这是全系列最值得精读的一节。第 1 讲说过：辅助均衡损失的梯度直接改写门控分数，强迫 token 去次优专家，与特化打架。V2.5 起采用的 Wang et al. 2024 方案（V3 论文 §2.1.2）给出了漂亮的解法。

5.1 机制：一个「只在选择时生效」的偏置

每个专家维护一个标量偏置 \(b_i\)，参与 top-k 比较，但不参与加权：

\[ g'_{i,t} = \begin{cases} s_{i,t}, & \text{若 } s_{i,t} + b_i \in \mathrm{Topk}\big(\{s_{j,t} + b_j\}_{j=1}^{N_r},\ K_r\big) \\[4pt] 0, & \text{否则} \end{cases} \qquad g_{i,t} = \frac{g'_{i,t}}{\sum_j g'_{j,t}} \]

拆开读：

  • 选择时：比较的不是原始分数 \(s\)，而是 \(s + b\)——bias 是每个专家的「号牌加成」，让冷门专家的比较值被人为抬高；
  • 加权时：选中的专家按原始分数 \(s_{i,t}\) 归一化加权——bias 完全不出现在输出里；
  • 更新时：\(b_i\) 不是可学习参数、不参与反向传播，而是一个「滚动计数器」：训练中持续统计每个专家的实际负载，过载的每步 \(-\gamma\)，欠载的每步 \(+\gamma\)（V3 取 \(\gamma = 0.001\)）。

5.2 两轮手算：亲眼看 bias 如何「挪门槛」

设定：6 个路由专家，\(K_r = 2\)。为了看清机制，演示用的步长取 \(\gamma = 0.05\)（真实值 0.001，小步慢滚几万步）。某 token 的原始分数（sigmoid 后）：

\[ s = [0.62,\ 0.31,\ 0.47,\ 0.18,\ 0.55,\ 0.10]\quad(\text{E1..E6}) \]
轮次bias 向量 b比较键 s+btop-2 选中实际加权（用原始 s！）
第 1 轮 [0, 0, 0, 0, 0, 0] [0.62, 0.31, 0.47, 0.18, 0.55, 0.10] E1（0.62）、E5（0.55） g = [0.62, 0.55] / 1.17 = [0.530, 0.470]
负载更新 全局统计：E1、E5 过载 → 各 −0.05；E3 长期欠载 → +0.05。其余不变。
b 变为 [−0.05, 0, +0.05, 0, −0.05, 0]
第 2 轮 [−0.05, 0, +0.05, 0, −0.05, 0] [0.57, 0.31, 0.52, 0.18, 0.50, 0.10] E1（0.57）、E3（0.52），E5 被挤出 g = [0.62, 0.47] / 1.09 = [0.569, 0.431]

三个观察，每一个都是设计精髓：

  1. E1 连任：bias 只压了 0.05，而 E1 的真实分数 0.62 遥遥领先——bias 不会强行翻盘，只改变边际竞争。它惩罚的是「靠 bias 混进来的水分」，不是「真正的实力」。
  2. E5 让位给 E3：E5 与 E3 的真实分数只差 0.08，一点 bias 就足以翻转边际结果。挤出的名额流向欠载专家——均衡目的达成。
  3. 加权值与 bias 无关：两轮的加权都来自原始分数。语言建模的梯度只看得见「分数 → 输出 → 损失」这条链，bias 在链条之外。门控对「谁最好用」的学习完全干净。

5.3 为什么叫「辅助损失免费」（auxiliary-loss-free）

回忆第 1 讲结尾的伏笔：「top-k 选择对梯度失明」。现在这个「失明区」有了用武之地：

  • 老方案：均衡信号以损失形式混进主目标 → 梯度穿透门控分数 → 特化被污染；
  • 新方案：均衡信号以「+b 后再排序」的形式存在于离散选择环节——恰好是梯度失明的角落 → 主目标梯度毫无察觉；bias 自己由「负载统计」驱动，连反向传播都不需要。

均衡与特化第一次真正地「分居」：一个住在梯度看不见的房间里，一个住在梯度看得见的客厅里，互不干扰。V3 论文给出的训练全程 γ=0.001、每步滚动，全程稳定。

代价也要说这个机制是「开环控制」：γ 固定、没有收敛性证明，靠「小步长 + 长时间」慢慢滚。而且 bias 只在全局（batch）粒度上起效——它马上会遇到管不到的地方，见 §7。

6. V3：Sigmoid 替换 Softmax——从「全局耦合」到「独立打分」

6.1 改动

V3（671B / 37B，每层 256 路由 + 1 共享，激活 8）把亲和度从 softmax 换成 sigmoid，并对被选中的分数做行归一化：

\[ s_{i,t} = \mathrm{Sigmoid}(x_t^\top e_i), \qquad g_{i,t} = \frac{s_{i,t}}{\sum_{j \in \mathrm{Topk}} s_{j,t}}\ (\text{仅对选中者归一}) \]

6.2 手算对比：softmax 的「牵一发动全身」

取 3 个专家的 logits \(z = [3,\ 1,\ -1]\)，两种函数的输出：

专家zsoftmax（分母含所有分数）sigmoid（各自独立）
E13\(e^3/\Sigma = 20.09/23.17 = \mathbf{0.867}\)\(\sigma(3) = \mathbf{0.953}\)
E21\(2.718/23.17 = \mathbf{0.117}\)\(\sigma(1) = \mathbf{0.731}\)
E3-1\(0.368/23.17 = \mathbf{0.016}\)\(\sigma(-1) = \mathbf{0.269}\)

假如某个专家的 logit 异常飙升到 10（万亿模型训练里离群值是常态），softmax 的分母 \(e^{10} = 22026\) 会把其他所有专家的输出压扁到近零——一家爆雷，全行业加权被压。sigmoid 没有分母，E5 爆炸也不影响 E3 的 0.269。

另一个值得注意的数值对比（观察为推断，V3 论文未展开）：top-2 选中 E1、E2 时，softmax 版内部权重是 0.867 : 0.117 ≈ 7.4 : 1（赢家通吃，第二名近乎陪跑）；sigmoid 版归一化后是 0.953 : 0.731 ≈ 1.3 : 1（两位专家贡献接近对半）。后者让「多专家组队」真正有意义——对 V3 这种一次激活 8 个专家的模型，8 个合伙人每人都该出力，而不是一个独裁者加七个观众。

7. V3 的保险丝：序列级均衡损失（权重 0.0001）

7.1 bias 的盲区

bias 按全局负载滚动——它管的是「整个 batch 里每个专家的总量」。但设想一批训练数据里混了一段长代码：这 2000 个 token 全都天然需要「代码专家」。即使全局看每个专家都不算过载，这条序列内部的流量也是极端倾斜的：其他专家在这条序列上颗粒无收，「序列级」的均衡破产。

7.2 公式逐项拆

\[ \mathcal{L}_{Bal} = \alpha \sum_{i=1}^{N_r} f_i P_i, \qquad f_i = \frac{N_r}{K_r T}\sum_{t=1}^{T}\mathbb{1}\big(s_{i,t}+b_i \in \mathrm{Topk}\big), \qquad P_i = \frac{1}{T}\sum_{t=1}^{T} s'_{i,t} \]
  • \(T\)：这条序列的 token 数；\(\mathbb{1}(\cdot)\)：选中与否的指示（选中记 1）；
  • \(f_i\)：专家 \(i\) 在这条序列内的接待占比，均衡时恰好等于 1（分母 \(K_r T / N_r\) 正是「平均每人该接的量」）；
  • \(P_i\)：专家 \(i\) 在这条序列内的平均归一化亲和度（\(s'\) 是把分数在专家间归一化后的值，均衡时约为 \(1/N_r\)）。

小演算验证「均匀时最小」（\(N_r=4, K_r=2, T=4, \alpha=1\)）：

情形fPΣ fᵢPᵢ
均匀：每 token 选 2 个不同专家，轮流光顾[1, 1, 1, 1][0.25, 0.25, 0.25, 0.25]1.0（最小）
偏心：4 个 token 全挤 E1、E2[2, 2, 0, 0][0.45, 0.45, 0.05, 0.05]1.8

7.3 为什么权重压到 0.0001

这一项是真正的辅助损失（梯度会碰门控分数），所以 DeepSeek 给它的角色定位是保险丝而不是均衡主力：0.0001 的权重意味着它平时几乎不影响训练，只在「单序列内极端失衡」这种 bias 够不着的极端情形里施加一点温和的回拉。均衡的主力已经交棒给 bias 门控了。V4 论文原话：保留它「to avoid extreme imbalance within single sequences」（p.25）。

8. V3.2：Keep Routing——同一个矛盾在 RL 里的投影

V3.2 的 MoE 结构完全没动，但补了一块对 RL 训练至关重要的拼图。背景：DeepSeek 的 RL 流程是「推理框架生成 → 训练框架算梯度」，两边并行策略、浮点实现不同；再加上训练中策略参数本身在更新。三者叠加的后果：同一个输入，在推理框架里路由到 {E1, E3, E7…}，到训练框架里可能变成 {E2, E3, E9…}。

为什么致命？回忆第 1 讲：「top-k 选中谁」决定了 token 走哪一小撮参数。路由路径一变，token 激活的参数子空间瞬间切换——RL 需要精确衡量「同一策略下新旧输出的差异」，路径一漂移，这个衡量就失真了。

Keep Routing：采样时把推理框架算出的路由路径存下来，训练时强制走同一路径。论文说这一操作自 DeepSeek-V3-0324 起采用，「对 MoE 模型的 RL 训练稳定性至关重要」（V3.2 论文 p.8）。值得玩味的是：这套操作与 bias 门控是同一哲学的两次现身——路由路径（谁被选中）是一个需要被小心隔离、小心固定的敏感变量。

  2. 16 选 2 → 64 选 8，组合数各是多少？（120 → 约 44.3 亿）

  4. bias 门控的三条规则？（只在 top-k 比较时加 b；加权用原始分数；b 不参与反向传播、按负载 ±γ 滚动）
  5. 为什么说它「辅助损失免费」？（均衡信号藏在梯度失明的离散选择环节，主目标梯度无污染）
  6. softmax 门控的两个毛病？（分母全局耦合，离群值殃及全体；输出悬殊，多专家组队变独角戏）
  7. 序列级损失为什么是「保险丝」？（bias 只管全局总量，管不了单序列内极端倾斜；权重 0.0001 只防极端）
