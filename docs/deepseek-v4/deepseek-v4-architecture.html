TL;DR：DeepSeek-V4 系列包含 V4-Pro（1.6T 总参 / 49B 激活）与 V4-Flash（284B / 13B）两个 MoE 模型，原生支持 100 万 token 上下文。相对 V3，它保留 DeepSeekMoE 与 MTP，做了三件大事：(1) 混合注意力——CSA 把每 \(m{=}4\) 个 token 的 KV 压缩成 1 条目再做 top-k 稀疏注意力，HCA 把每 \(m'{=}128\) 个 token 压成 1 条目后做稠密注意力，两者 1:1 逐层交替；(2) mHC——把残差连接加宽为 \(n{=}4\) 条流，混合矩阵 \(B_l\) 投影到双随机矩阵流形，全层启用；(3) Muon 优化器负责绝大多数矩阵权重，AdamW 只管 embedding / 预测头 / RMSNorm / mHC 静态偏置。三招叠加，1M 上下文下单 token 推理 FLOPs 仅为 V3.2 的 27%（Pro）、KV cache 仅为 10%；Flash 更低至 10% / 7%，KV 约为 BF16 GQA8 基线的 2%。基础设施侧以 MegaMoE 单内核（通信-计算全重叠）、TileLang DSL、逐位确定性与批不变内核、张量级选择性重算支撑训练与推理。组件深读请见：注意力设计、CSA 压缩过程、KV cache 组织、mHC。

2. 层堆叠宏结构

图 1｜DeepSeek-V4 总体架构。左：层堆叠（对应论文 Figure 2 与 §4.2.1 的层配置；RoPE 细节见 §2.3.3 与 config.json 的 rope_scaling）。右：单层数据流（对应论文式 (1)，§2.2）：\(A_l\in\mathbb{R}^{1\times 4}\) 读出 4 条残差流作为层输入，\(F_l\)（注意力 + MoE）计算后由 \(C_l\in\mathbb{R}^{4\times1}\) 写回，\(B_l\in\mathbb{R}^{4\times4}\) 做流间混合——mHC 把 \(B_l\) 约束为双随机矩阵。

2.1 CSA 与 HCA 的交错策略

论文 §4.2.1（第 25 页）对 Pro 的描述是："前两层使用 HCA，后续各层以交错方式使用 CSA 与 HCA"。结合 config.json 的 compress_ratios 可以还原精确布局：层 1–2 为 HCA（\(m'{=}128\)），层 3–61 严格按 CSA → HCA → CSA → … 交替（30 层 CSA + 29 层 HCA，合计 31 层 HCA）。两种注意力的分工：

  • HCA（Heavily Compressed Attention）：以 \(m'{=}128\) 的激进压缩率把 KV 压成 \(\frac{1}{128}\) 长度的条目，然后做稠密注意力——每个查询都能看到全部历史（压缩形态的全局信息），无需索引器、无稀疏选择的开销与风险；
  • CSA（Compressed Sparse Attention）：以 \(m{=}4\) 的温和压缩率压缩 KV（保留更多细粒度信息），再由 lightning indexer 做 top-k=1024 的稀疏选择——低成本地"精读"被索引器挑出的少量压缩块。
论文只给出了摆放方式、未解释动机。从机制看合理的一种解释是：模型开头需要无差别地汇总全局信息（此时 token 尚无可供索引器学习的"查询焦点"，稀疏选择容易漏），HCA 的稠密-重压缩形态恰好提供廉价的全局视野；中后段 token 带有明确意图，CSA 的"轻压缩 + 精确索引"更能保住细粒度依赖。交替 1:1 则在全局粗粒度与局部细粒度之间逐层混织。此段为推断，论文未明说。

2.2 全 MoE、Hash 路由与 mHC 的摆放

三个宏结构事实（论文 §2.1，第 7 页）：

  • 没有稠密 FFN 层：61 层全部是 MoE。V3 只在前几层放稠密 FFN，V4 把它们也换成 MoE，但前 num_hash_layers=3 层改用 Hash 路由（Roller et al. 2021）——按 token ID 的预定义哈希函数确定专家，无需训练路由器、推理时零路由开销。官方推理代码里这是一行判断：
# inference/model.py:556（DeepSeek-V4-Pro 官方推理实现，commit b5968e9）
self.hash = layer_id < args.n_hash_layers   # 前 3 层 MoE 使用 Hash 路由（config: num_hash_layers=3）
  • mHC 全层启用：每层（含注意力层与 MoE 层）的残差连接都升级为 4 流 mHC，\(B_l\) 经 20 步 Sinkhorn-Knopp 迭代投影到双随机矩阵流形（详见 mHC 专篇）；
  • MTP 深度 1：与 V3 完全一致，主栈之外挂 1 个 MTP 模块（训练目标权重 0.3，LR 衰减期降为 0.1，§4.2.2）。

2.3 位置编码

V4 不再用 MLA 的解耦 RoPE，改为对 CSA/HCA 统一的部分旋转位置编码（论文 §2.3.3，第 12–13 页）：查询向量、压缩 KV 条目、以及核心注意力输出都只对最后 64 维施加 RoPE（config：qk_rope_head_dim=64）。由于压缩 KV 条目同时充当 key 和 value，注意力输出天然携带绝对位置；论文的做法是对输出再施加位置 \(-i\) 的 RoPE，使输出重新变为相对位置敏感。长上下文扩展用 YaRN（config：rope_scaling: factor=16, original_max_position_embeddings=65536，即 64K 原生 → 1M）；此外 config 还为压缩层单列了 compress_rope_theta=160000，推理代码中压缩层用它替代默认 theta 预计算频率（inference/model.py:476；论文未展开说明，其精确语义见 CSA 压缩专篇）。

3. 各组件概览

3.1 混合注意力：CSA / HCA

CSA 分三步：(1) token 级压缩器把每 \(m{=}4\) 个 token 的 KV 加权池化为 1 条目（双轨 \(C_a, C_b\) 重叠窗口设计，实际序列长度压缩到 \(\frac{1}{m}\)）；(2) lightning indexer 用 FP4 计算索引分数，为每个查询选出 top-\(k{=}1024\) 个压缩条目；(3) 共享 KV 的 MQA 在选中的稀疏集合上做核心注意力，输出经 \(g{=}16\) 组的分组投影降维回 \(d\)。HCA 同构但 \(m'{=}128\)、无索引器、稠密注意力。两者都带 \(n_{win}{=}128\) 的滑动窗口分支（弥补压缩块内的局部细粒度依赖）与 attention sink（可学习 logit 加到分母，允许总注意力权重偏离 1）。深读：注意力整体设计见 《DeepSeek-V4 Attention 设计解读》；压缩公式的逐项推导见 《CSA 压缩过程详解》。

从推理代码可以直接看清两种注意力的分派逻辑与 MQA/分组输出投影的落地：

# inference/model.py:453–479（节选，commit b5968e9）
self.compress_ratio = args.compress_ratios[layer_id]   # 逐层查表：4=CSA，128=HCA，0=纯 SWA
...
self.wkv = Linear(self.dim, self.head_dim)             # 单共享 KV 头（MQA），head_dim=512
self.wo_a = ColumnParallelLinear(self.n_heads * self.head_dim // self.n_groups,
                                 self.n_groups * args.o_lora_rank, ...)  # 分组输出投影 g=16, d_g=1024
...
if self.compress_ratio:
    self.compressor = Compressor(args, self.compress_ratio, self.head_dim)
    if self.compress_ratio == 4:
        self.indexer = Indexer(args, self.compress_ratio)  # 仅 CSA（m=4）配 lightning indexer
    else:
        self.indexer = None                                # HCA：无索引器，稠密注意力
...
if self.compress_ratio:
    original_seq_len, rope_theta = args.original_seq_len, args.compress_rope_theta

代码 1｜注意力层按 compress_ratios[layer_id] 分派：compress_ratio==4 时挂 indexer（CSA），==128 时只有压缩器（HCA）。wkv 把 hidden 投到单头 512 维，即论文的共享 KV MQA；wo_a/wo_b 两级投影对应论文的分组输出投影（\(n_h c / g \to g \cdot d_g \to d\)）。

3.2 mHC：流形约束超连接

把残差流从 \(\mathbb{R}^d\) 加宽到 \(\mathbb{R}^{4\times d}\)，层更新为 \(X_{l+1} = B_l X_l + C_l F_l(A_l X_l)\)（式 (1)）。\(A_l, C_l\) 用 Sigmoid 约束为非负有界，\(B_l\) 用 Sinkhorn-Knopp 投影到双随机矩阵流形——谱范数 ≤ 1（前向非扩张）、对乘法封闭（任意深度堆叠仍稳定）。三个映射由"动态（依赖输入）+ 静态偏置"两部分参数化，静态部分归 AdamW 管。深读：《DeepSeek mHC 解读》。

3.3 MoE：DeepSeekMoE 的微调

沿用细粒度路由专家 + 共享专家范式（§2.1），相对 V3 只改了四处：亲和度打分从 Sigmoid 换成 \(\sqrt{\mathrm{Softplus}(\cdot)}\)（config scoring_func: "sqrtsoftplus"）；负载均衡仍用辅助损失免费策略（bias 更新速度 0.001），另加权重 0.0001 的序列级均衡损失防止单序列极端失衡；去掉了路由目标节点数限制（靠重设并行策略保效率）；前 3 层用 Hash 路由替代稠密 FFN。SwiGLU 激活带 clamp（线性分量夹到 \([-10,10]\)，config swiglu_limit: 10.0）。

3.4 MTP 与推测解码谱系

MTP 模块与目标（深度 1）原封不动继承 V3。值得注意的是后续演进：V4.1 用 DSpark（3 层滑窗 drafter + 置信度调度验证）替代了 MTP 的推测解码角色，且 DSpark 在预训练后单独阶段训练、不向主干回传梯度（V4.1 论文 §2.4.3）。

4. 训练配方

4.1 Muon + AdamW 的参数分工

论文 §2.4（第 14 页）+ §4.2.2（第 25 页）的分工是精确的：Muon 管"绝大多数模块"（所有 2D 权重矩阵），AdamW 只管四类参数——embedding、预测头、mHC 的静态偏置与门控因子、所有 RMSNorm 权重。Muon 侧配置：momentum 0.95、weight decay 0.1、更新矩阵 RMS 重标定到 0.18（以复用 AdamW 学习率量级）、混合 Newton-Schulz 迭代——前 8 步用 \((a,b,c)=(3.4445,-4.7750,2.0315)\) 快速收敛，最后 2 步切 \((2,-1.5,0.5)\) 把奇异值精确钉在 1。由于 V4 直接对注意力 Q 与 KV 条目做 RMSNorm（§2.3.3），attention logits 不会爆炸，无需 QK-Clip。

论文未解释为何标量/近标量参数不参与正交化，但理由是结构性的：Newton-Schulz 正交化对向量（\(1\times n\)）会抹掉各分量的幅度差异（正交化后各方向等权），对 RMSNorm 的逐通道缩放因子、Sigmoid 门控这类"幅度即语义"的参数恰是破坏性的；把这些参数留给保幅值的 AdamW 是自然选择。V4.1（§2.5）沿用同一分类（"normalization-layer weights and other non-matrix parameters"）。此解释为推断，非论文原文。

4.3 低精度训练与存储

  • KV cache 混合精度：RoPE 维用 BF16、其余维用 FP8——相对纯 BF16 存储近乎减半（§2.3.4，第 13 页）；
  • lightning indexer FP4：索引分数计算在 FP4 下进行，加速超长上下文的索引（§2.3.4）；
  • 路由专家 FP4：V4 系列的路由专家参数用 FP4 精度（摘要，第 4 页）；现有硬件上 FP4×FP8 峰值算力与 FP8×FP8 相同，未来硬件理论可再省 1/3；
  • FP4 量化感知训练（post-training，§5.2.1）：对 MoE 专家权重与 indexer QK 路径做 MXFP4 QAT——前向模拟量化、反向直通估计（STE）回到 FP8 主权重；FP4→FP8 反量化无损（E4M3 比 E2M1 多 2 个指数位），可完全复用既有 FP8 训练框架；
  • 通信精度：EP Dispatch 用 FP8、Combine 用 BF16（§3.1）；Muon 的 MoE 梯度经随机舍入降到 BF16 同步，配 all-to-all + FP32 本地求和替代 reduce-scatter，通信量减半且数值稳健（§3.4.1）。

4.4 训练稳定性：两记实招

万亿参数 MoE 训练中遭遇与 MoE 层离群值相关的 loss spike，论文（§4.2.3，第 26 页）给出两个经验有效、机理未完全理解的手段：

  • Anticipatory Routing：步骤 \(t\) 用当前参数 \(\theta_t\) 算特征，但路由索引用历史参数 \(\theta_{t-\Delta t}\) 预先算好并缓存（提前取数，"预判式"路由），解除主干与路由网络的同步更新耦合。配合"仅 spike 时自动触发 + 短回滚"的动态开关，额外墙钟开销可忽略（激活时约 20%）；
  • SwiGLU Clamping：线性分量夹到 \([-10,10]\)、门分量上限 10，有效消除离群值（config swiglu_limit: 10.0）。

5. 训练与推理基础设施

5.1 MegaMoE：单内核通信-计算全重叠（§3.1）

MoE 层被拆成 Dispatch / Linear-1 / Activation / Linear-2 / Combine 五段，其中两段通信两段计算； profiling 显示单层内通信总时长小于计算，因此把专家切成波（wave）调度进单个融合内核后，计算可以完全盖住通信。实测对通用推理负载加速 1.50–1.73×，对 RL rollout 等长尾小批量场景最高 1.96×；CUDA 实现以 MegaMoE 名义开源在 DeepGEMM（PR #304）。论文还给出软硬件共设计的平衡点：对 V4-Pro，每个 token-专家对需 \(6hd\) FLOPs（SwiGLU 三投影）但仅 \(3h\) 字节通信，通信可全隐藏的条件为 \(C/B \le 2d = 6144\) FLOPs/Byte——带宽过了这个阈值就不再是瓶颈，堆带宽收益递减。

5.2 TileLang 与确定性内核（§3.2–3.3）

V4 的新架构若用普通算子拼装会产生数百个细碎 ATen 调用，官方用 TileLang DSL 开发融合内核覆盖绝大多数路径，配套两项工程：Host Codegen 把宿主侧校验移入生成代码（每次调用 CPU 开销从几十上百微秒降到 1 微秒以内）；集成 Z3 SMT 求解器做形式化整数分析（向量化、屏障插入等 pass）。更重要的是 §3.3 的批不变（batch-invariant）与逐位确定性内核库：注意力解码弃用 split-KV、改双内核策略（满波单 SM / 尾波多 SM 但累加顺序对齐）；GEMM 全线用 DeepGEMM 替代 cuBLAS 并弃用 split-k；注意力反向用每 SM 独立累加缓冲 + 全局确定性求和替代 atomicAdd；MoE 反向用 token 序预处理 + 跨 rank 缓冲隔离。这套性质使 pre-training / post-training / inference 三条管线逐位对齐，也是 §5.2.3 "WAL + KV 快照恢复 rollout"正确性的前提。

5.3 训练框架（§3.4）

  • Muon 的混合 ZeRO：稠密参数限制 ZeRO 并行上限并用背包算法装桶（padding < 10% 开销）；MoE 参数按专家独立优化——把所有专家的 down/up/gate 投影分别展平后均匀切分到各 rank，不设 ZeRO 上限；
  • mHC 的低成本实现：融合内核 + 选择性重算（重算大部分层间隐状态与归一化输入，避开计算密集算子）+ 调整 DualPipe 1F1B 重叠以容纳增大的流水线通信——mHC 墙钟开销仅 6.7%；
  • 两阶段上下文并行：压缩注意力要求 \(m\) 个连续 KV 条目、且压缩后各 rank 长度不齐。第一阶段各 rank 把末 \(m\) 个未压缩条目发给下一 rank 拼合压缩，产出定长 \(s/m+1\) 条目；第二阶段 all-gather + 融合 select-and-pad 算子整理成全长 \(cp\_size \cdot s/m\) 的压缩序列；
  • 张量级激活检查点：扩展 autograd，开发者只标注需要重算的张量，框架用 TorchFX 反向遍历找最小重算子图插入 backward，共享 storage 的张量自动去重。

5.4 推理框架与 KV cache（§3.5）

混合注意力产生三类尺寸与淘汰策略各异的 KV 条目（CSA/HCA 压缩条目、lightning indexer 条目、SWA 未压缩条目 + 待压缩尾部缓冲），PagedAttention 的"逐层同构 page"假设被打破。V4 的方案是把 SWA 与未压缩尾部当作序列状态（定长状态缓存池动态分配），把 CSA/HCA 压缩条目放进经典分块缓存（块大小取 \(\mathrm{lcm}(m,m')\) 的倍数以同时满足两种内核对齐），并为共享前缀复用设计了盘上存储（SWA 部分提供全存 / 周期检查点 / 零存三档权衡）。深读：《DeepSeek-V4 KV Cache 组织解读》。

8. 演进小结：V3.2 → V4 → V4.1

图 2｜三代架构增量（依据 V3.2 论文 §2 / 摘要、V4 论文 §2、V4.1 论文 §1–§2）。V4 的关键一步是把"省 FLOPs"（V3.2 的 DSA 稀疏化）扩展为"省 FLOPs + 省 KV"（序列维压缩）；V4.1 再进一步做跨层复用（Full/Reindex/Reuse 三模式）与 FP4 缓存：相对 V4-Flash，运行时 KV 约降至 1/4、持久化 KV 约降至 1/8（V4.1 论文 §1），且 4K→1M 的 decode FLOPs 仅增长 1/4（近乎平坦）。

三点结构性观察：

  • 残差连接的演进：V3.2 恒等残差 → V4 全层 mHC（\(n{=}4\)）→ V4.1 Single-Pass mHC（把 \(A_l\) 的使用错位一个 block，消除输入混合对当前块系数的依赖，部署内核 Mega-mHC 把激活读写降到理论下界 \((n{+}1)d\)，流量减半）；
  • 注意力主线：压缩与稀疏两件事在 V4 合流（CSA），V4.1 干脆去掉 HCA、用纯 CSA2 靠跨层 KV/索引复用继续压 KV——层级分组（如编码器 6 层一组：1 层 Full + 5 层 Reuse）；
  • 训练稳定性的延续：V4 靠 Anticipatory Routing + SwiGLU clamp 扑灭 spike；V4.1 45T token 训练报告"no instability"，稀疏注意力从 64K 起从头训练、不再需要稠密预热。
