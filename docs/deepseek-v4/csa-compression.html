依据：DeepSeek-V4: Towards Highly Efficient Million-Token Context Intelligence（本地 paper/deepseek_v4.pdf，arXiv:2606.19348）；官方参考实现 DeepSeek-V4-Pro inference/model.py

TL;DR：CSA 的压缩是一次可学习门控池化（learned gated pooling）：对每 m=4 个 token，用两条内容投影 \(C_a, C_b\) 和两条门控投影 \(Z_a, Z_b\)，按重叠双分支窗口取 2m=8 个候选 token，对候选做 softmax 得到「每个 token × 每个维度」的权重，再逐元素加权求和成一条 512 维的压缩 entry。压缩率 1/m=1/4，边界因重叠而平滑；entry 随后经 RMSNorm、部分 RoPE（只转最后 64 维）与 FP8/BF16 混合量化进入 KV cache，等待 Lightning Indexer 的 top-k 稀疏选择。每条 entry 约 576 B、摊到每 token 约 144 B（推断），只有 BF16 GQA8 基线（4096 B/token）的 3.5%。

1. 压缩处在整个注意力的什么位置

DeepSeek 的注意力优化有三个正交维度：MLA 压「entry 大小」（KV 头维度，576 元素/token）、GQA 压「KV 头数」、V4 的 CSA/HCA 首次压「序列长度」——把 n 个 token 的 KV 变成 n/m 条 entry。压缩器（Compressor）是 CSA 层所有后续动作的源头：Indexer 的打分对象、核心注意力的 K/V、KV cache 的主体，全部是压缩 entry。

图 1｜CSA 层数据流中的压缩器。三条支路共享输入 H：压缩器产出 KV cache 主体（压缩 entry，本页主题）；低秩 latent \(c^Q\) 一份两用（升维成查询头 + 喂给 Indexer 打分）；滑窗分支保留最近 128 个 token 的未压缩 KV，弥补压缩破坏的块内可见性。HCA 层没有 Indexer 分支，压缩率为 128 且全 entry 稠密参与（见 主文档 §2.3 数据流图）。

一个容易混淆的顺序问题：CSA 是先压缩、后稀疏。压缩发生在序列维（4 个 token → 1 条 entry），稀疏选择发生在压缩之后（top-k=1024 条 entry）——Indexer 的打分对象已经是压缩 entry 而非原始 token，这使得索引器本身也只需在 1/4 长度的序列上工作。

2. 记号、形状与总公式

设输入隐状态 \(H \in \mathbb{R}^{n \times d}\)（n 为序列长度），压缩率 m=4（V4-Pro 的 CSA 层），head 维度 c=512。压缩器的全部工作可以概括为两个公式（论文式 11–12）：

\[ [\,S_a^{mi:m(i+1)-1};\, S_b^{m(i-1):mi-1}\,] = \mathrm{Softmax}_{row}\!\left([\,Z_a^{mi:m(i+1)-1} + B_a;\, Z_b^{m(i-1):mi-1} + B_b\,]\right) \]
\[ C_i^{\mathrm{Comp}} = \sum_{j=mi}^{m(i+1)-1} S_j^a \odot C_j^a + \sum_{j=m(i-1)}^{mi-1} S_j^b \odot C_j^b \]

其中 \(\odot\) 为 Hadamard 积（逐元素乘）。各对象的形状与实现对应如下：

记号含义形状（V4-Pro）实现（model.py）
\(H\)输入隐状态\(n \times d\)x
\(W^{KV}_a, W^{KV}_b\)两条 KV 内容投影\(d \to c\)（c=512）wkv（折叠成 coff·c=1024 宽）
\(W^{Z}_a, W^{Z}_b\)两条门控分数投影\(d \to c\)wgate（同上折叠）
\(B_a, B_b\)窗口内可学习位置偏置\(m \times c\)（各）ape（形状 m × 2c，两支各半）
\(S^a, S^b\)门控权重（每 entry）\(m \times c\)（各）score.softmax(dim=2)
\(C_i^{\mathrm{Comp}}\)第 i 条压缩 entry\(c=512\)（每条）；\((n/m)\times 512\)（整体）池化输出，再经 norm / RoPE / 量化

表 1｜压缩器的记号与形状。压缩发生在「序列维」：输出 entry 数 = n/m，每条 entry 仍是 512 维——entry 的大小没有变，变的是多少个 token 共享一条 entry。

3. 压缩逐步拆解

3.1 第一步：两条投影轨（式 9）

对每个 token 的隐状态做两组独立投影，得到两套「内容」与两套「打分」：

\[ C_a = H \cdot W_a^{KV},\quad C_b = H \cdot W_b^{KV};\qquad Z_a = H \cdot W_a^{Z},\quad Z_b = H \cdot W_b^{Z} \]

\(C_a, C_b\) 是真正会被池化、缓存、参与注意力的内容向量；\(Z_a, Z_b\) 不进 cache，只在压缩时当门控分数用。为什么要两条轨而不是一条？这正是下一步「重叠双分支」的物料基础——两条独立学出来的投影，一条负责「本窗口视角」、一条负责「前一窗口视角」，等价于给边界两侧的 token 各配一套专属的表征通道。

图 2｜压缩器的四条输出轨。内容轨 \(C_a, C_b\) 与门控轨 \(Z_a, Z_b\) 两两配对；门控轨不进 KV cache，只在压缩瞬间使用。高亮列示意：token t2 在四条轨上各得到一个 512 维向量。

3.2 第二步：重叠双分支窗口（式 11 的取段）

第 i 条压缩 entry 不只取「本窗口」的 m 个 token，而是取 2m=8 个候选：

  • \(C_a\) 分支取第 \([mi,\ m(i+1)-1]\) 段——本窗口；
  • \(C_b\) 分支取第 \([m(i-1),\ mi-1]\) 段——前一窗口。

于是相邻两条 entry 共享一个窗口：窗口 i 的 token 既经 \(C_a\) 进入 entry i，又经 \(C_b\) 进入 entry i+1。除序列最后一个窗口外，每个 token 的信息都会进入两条相邻 entry——压缩边界处的语义不会在任一 entry 中被「拦腰截断」，等效压缩率仍为 1/m（论文 p.10）。

图 3｜重叠双分支的窗口划分（m=4，示意 20 个 token / 5 个窗口）。蓝轨（\(C_a\)）取本窗口，橙轨（\(C_b\)）错后一窗取前一窗口，两轨信息相加成一条 entry：每条 entry 由 2m=8 个候选 token 汇聚而成，entry 数仍是 n/m。

3.3 第三步：门控权重 Softmax(Z+B)（式 11）

对 2m 个候选，用门控分数加可学习位置偏置做归一化，得到权重：

\[ S = \mathrm{Softmax}_{row}\!\left([\,Z_a^{mi:m(i+1)-1} + B_a;\, Z_b^{m(i-1):mi-1} + B_b\,]\right) \]

三个关键性质：

  • 权重与内容同维：\(S_j \in \mathbb{R}^{c}\)（c=512），每个 token 在每个维度上都有一个权重，而非一个标量——模型可以表达「这个 token 的哪些维度值得保留、哪些抹掉」；
  • 位置偏置 \(B_a, B_b \in \mathbb{R}^{m \times c}\)：窗口内 4 个位置各有一套可学习偏置（逐维），让池化对「token 在窗口内的相对位置」敏感（比如句尾 token 常携带收束信息）；
  • Softmax 保证有界：权重经过归一化，池化结果的量纲稳定，不会因个别 token 的 \(Z\) 分数过大而爆炸。
关于归一化的轴：论文把 2m 个候选记作一次 \(\mathrm{Softmax}_{row}\)；参考实现中两支各自在自己的 m 个候选上做 softmax（score.softmax(dim=2) 作用在 token 维——每一维在 4 个候选 token 间形成一个分布），再把两支的加权和相加，与式 (12) 的「两支之和」一致（见 §5 代码）。图 4 按「每列（每个维度）在候选间归一化」的口径绘制。

图 4｜门控池化的矩阵视角（式 11–12）。左侧是 2m=8 个候选内容向量，中间是两支门控权重（深色格示意较大权重），逐元素相乘后沿候选维求和得到一条 entry。深浅不一的格子强调：权重是学出来的、逐 token 逐维度的，不是均匀平均。

3.4 第四步：Hadamard 加权求和成 entry（式 12）

\[ C_i^{\mathrm{Comp}} = \sum_{j=mi}^{m(i+1)-1} S_j^a \odot C_j^a \;+\; \sum_{j=m(i-1)}^{mi-1} S_j^b \odot C_j^b \]

两条分支各产出一个 512 维向量，相加即第 i 条 entry。整个池化只有逐元素乘与求和两种运算，没有矩阵乘、没有注意力——这是它能够便宜地对全序列每个 token 都执行一遍的原因；压缩器的开销相对于它省下的注意力算力可以忽略（推断）。至此，序列长度 n 的 KV 变成了 n/m 条 entry，等效压缩率 1/m。

3.5 边界细节：第一条 entry 的「前一窗口」不存在怎么办

entry 0 的 \(C_b\) 取段 \([m(i-1),\ mi-1]\) 在 i=0 时指向窗口 −1，并不存在。参考实现的处理是补值：错位后空出的候选槽位，内容侧补 0、分数侧补 −∞——−∞ 经 softmax 归一化后权重恰为 0，等价于「不存在的窗口不参与池化」。序列末尾对称地少一次复用（最后一个窗口不再进入下一条 entry）。

图 5｜序列起始处的边界处理（放大 entry 0 与 entry 1）。缺失窗口在内容侧补 0、分数侧补 −∞，softmax 自动将其权重归零——边界不需要任何特殊分支代码。

4. 压缩之后：归一化 → 部分 RoPE → 混合精度量化 → 缓存

池化输出并不会直接进 cache。参考实现在压缩器 forward 的末尾串了一条固定的后处理链，压缩与「存储格式」在同一步完成：

图 6｜压缩后的处理链。RMSNorm 稳定核心注意力的 logits（因此 V4 不再需要 Muon 的 QK-Clip）；部分 RoPE 只旋转最后 64 维、使用独立的 compress_rope_theta=16 万；主 KV 的非 RoPE 维以 FP8 存储、RoPE 64 维保持 BF16（位置精度）；Indexer 复用同一压缩器逻辑，但 KV 走 Hadamard 旋转 + FP4（对应论文「indexer FP4 计算」）。

  • RMSNorm：entry 既是 key 又是 value，不归一化的话 attention logits 容易爆炸（§2.3.3）；
  • 部分 RoPE（最后 64 维）：压缩 entry 同时充当 K 和 V，输出会带上 KV 的绝对位置旋转，所以主注意力侧还要对输出做位置 −i 的反旋转，让输出携带「query 与 entry 的相对距离」（§2.4）；
  • 混合精度：RoPE 维 BF16（位置敏感）+ 其余 FP8，相比纯 BF16 cache 近乎减半（§2.3.4）。

5. 参考实现对照（Compressor 类）

以下摘自官方 inference/model.py:279-372（有删节，均为连续行内摘录）。类注释原文就写明：When overlap=True (ratio==4), uses overlapping windows for smoother compression boundaries——重叠是专门给 m=4 的 CSA 准备的。

class Compressor(nn.Module):
    """Compresses KV cache via learned gated pooling over `compress_ratio` consecutive tokens.
    When overlap=True (ratio==4), uses overlapping windows for smoother compression boundaries."""

    def __init__(self, args: ModelArgs, compress_ratio: int = 4, head_dim: int = 512, rotate: bool = False):
        super().__init__()
        ...
        self.compress_ratio = compress_ratio
        self.overlap = compress_ratio == 4
        coff = 1 + self.overlap
        self.ape = nn.Parameter(torch.empty(compress_ratio, coff * self.head_dim, dtype=torch.float32))
        # wkv and wgate in the checkpoint is stored in bf16, ...
        # When overlap, the first half of dims is for overlapping compression, second half for normal.
        self.wkv = Linear(self.dim, coff * self.head_dim, dtype=torch.float32)
        self.wgate = Linear(self.dim, coff * self.head_dim, dtype=torch.float32)
        self.norm = RMSNorm(self.head_dim, args.norm_eps)
        ...
    def forward(self, x: torch.Tensor, start_pos: int):
        ...
        kv = self.wkv(x)
        score = self.wgate(x)
        ...
        kv = kv.unflatten(1, (-1, ratio))
        score = score.unflatten(1, (-1, ratio)) + self.ape
        if overlap:
            kv = self.overlap_transform(kv, 0)
            score = self.overlap_transform(score, float("-inf"))
        kv = (kv * score.softmax(dim=2)).sum(dim=2)
        ...
        kv = self.norm(kv.to(dtype))
        apply_rotary_emb(kv[..., -rd:], freqs_cis)   # 只旋转最后 64 维
        if self.rotate:
            kv = rotate_activation(kv)               # Hadamard 旋转，供 FP4 量化
            fp4_act_quant(kv, fp4_block_size, True)  # indexer 的 KV 走 FP4
        else:
            act_quant(kv[..., :-rd], 64, ...)        # 主 KV：非 RoPE 维 FP8 存储

6. 为什么这么设计（FAQ）

Q1：为什么用可学习的门控池化，而不是平均池化？

平均池化把窗口内所有 token 无差别混合：重要 token 的信息被稀释，无关 token 的噪声被保留。门控池化让网络自己学「哪个 token 的哪些维度进入 entry」，是一次有选择的压缩。注意压缩率只由窗口大小 m 决定，与权重无关——门控不改变 entry 数，改变的只是每条 entry 的内容质量。

Q2：为什么权重是 c 维向量（逐维）而非每个 token 一个标量？

标量权重只能整条向量缩放；逐维权重能表达「这个 token 的某些维度值得保留、其余抹掉」，表达力上限更高，而计算上仍只是逐元素乘加，与 Hadamard 积 \(\odot\) 天然配合。

Q3：为什么要重叠双分支？代价是什么？

非重叠压缩在窗口边界做「硬切分」：跨边界语义（一个跨在 t7–t9 上的短语）只能进其中一条 entry。重叠让每个 token 的信息进入两条相邻 entry，边界平滑；entry 0 的缺失窗口用 −∞ 优雅处理（图 5）。代价是候选数翻倍（2m）、两条投影轨宽度翻倍（coff=2），即压缩器的参数量与计算量近似翻倍。

这笔「翻倍」开销花得值：压缩器对每个 token 只跑一次、开销是 O(n) 级的线性投影；而它换来的是后续注意力在 1/4 长度的 entry 序列上做 top-k 选择。相比省下的注意力算力与 KV cache，压缩器开销可以忽略。

Q4：为什么 CSA 用 m=4、HCA 用 m′=128，而不是全用一种？

m 越大压缩越狠，但单条 entry 混合的 token 越多、粒度越粗。CSA 用轻压缩保住细粒度（4-token 粒度），再用 top-k 稀疏控制算力，放在中间层承担主要的信息存取；HCA 用重压缩把 cache 压到 CSA 层的 1/32，全部 entry 稠密参与、保证全局信息「一个不漏」，适合放在模型头尾做粗粒度全覆盖建模。两者共享同一套压缩骨架——HCA 可以看作「去掉重叠与 Indexer 的 CSA」（源码：overlap=False 且 indexer=None）。

Q5：压缩把块内 token 的因果可见性破坏了，怎么办？

一条 entry 是 4 个 token 的混合体：块内 token 彼此不可见，且对当前 query 而言最近处的 token 几乎总是最相关的。因此每层额外保留最近 \(n_{win}=128\) 个 token 的未压缩 KV，与被选中的压缩 entry 拼接后一起参与核心注意力（图 1 下路）。这也是为什么压缩质量（Q1–Q3）重要——滑窗只兜住「近处」，远处信息全靠 entry 本身的保真度。
