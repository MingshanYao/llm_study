本篇定位：毕业加餐。用一篇 2026 年 9 月的新论文，把第 1、2、3、5、6 讲的知识点拧成一个真实的工程问题：为什么「训练引擎」和「推理引擎」对不上账时，RL 会崩、SFT 却没事。

论文：Score Centering Stabilizes Off-policy Reinforcement Learning，Martin Marek & Max Ryabinin（Together AI），2026-09-17，arXiv:2609.20807；官方代码 github.com/martin-marek/score-centering。

前置要求：第 1 讲（score、REINFORCE 更新式）、第 2 讲（on/off-policy、KL）、第 3 讲（重要性采样、clip）、第 5 讲（GRPO 组内中心化）、第 6 讲（rollout/trainer 分离、权重同步）。全部数学手算，不跳步。

本篇目标：RL 训练时，生成样本的是推理引擎、算梯度的是训练引擎——明明「同一个模型」，两个引擎算出的概率却差之毫厘（浮点误差、算子实现、量化、异步旧权重），这叫训练-推理失配（TIM）。本文证明：TIM 之所以能让 RL 崩溃，是因为每步梯度里混进一个 drift（漂移）项——它不带任何学习信号，只负责把训练器一步一口地「蒸馏」向采样器；而采样器每步又被同步成「被拉过」的权重，偏差滚雪球，直到 reward 崩塌。修复出奇地简单：把每个 token 的 score 减去它在采样器分布下的期望（score centering），drift 被精确抵消，学习信号分毫不动。它是加法修正：无超参数、不放大方差，重度量化下比整个重要性采样家族都更能打，还能和 TIS/MIS 叠加组队。全文手算验证每一个关键数字。

一、两个引擎，同一个模型，答案差一点点

第 6 讲画过 GRPO 训练步的数据流：推理引擎（vLLM/SGLang，追求吞吐）负责生成 rollout，训练引擎负责对生成结果反向传播。两边加载的是同一份权重，理论上对同一个 token 给出的概率应该一模一样——第 3 讲的重要性采样 ratio \(\rho = p/q\) 在理想情况下恒等于 1。

实际上「差之毫厘」，而且没有 bug 也会差。论文列出的四个来源：

来源机制能否靠工程消除
浮点加法不满足结合律同一模型、同一权重，只是求和顺序不同，结果就不同（见下方盒子）要「批无关 kernel」，代价是 GPU 利用率下降
算子实现与输入形状推理自回归地逐 token 算，训练按序列并行算——同样的 kernel 吃不同形状，内部求和顺序不同难彻底消除；换 fp16 能大幅缩小但仍非零
量化采样器用 int8/fp4 权重、fp4 KV cache 换吞吐；训练器是 bf16量化本身就是目的，只能算法上补偿
异步陈旧（staleness）为打满 GPU，采样与训练异步跑：一条 rollout 生成时，训练器已经又走了几十步等同步会闲置硬件；agentic 长任务下不可接受
手算：为什么加法顺序能改结果论文脚注给了一个 fp4（4 位浮点）的例子，高中算术就能验证。fp4_e2m1 能表示的数只有 \(\dots, 0.5, 1, 1.5, 2, 3, 4, 6\)——注意它表示不出 2.5（四舍五入进位到最近的 2 或 3）。于是：
\((0.5+0.5)+2 = 1+2 = 3\)；但 \(0.5+(0.5+2) = 0.5+2.5\)，先算括号时 \(2.5\) 被舍成 \(2\)，得 \(0.5+2 = 2.5\)，又舍成 \(2\)。同样三个数，3 ≠ 2。GPU 里几十亿个这样的加法并行发生、顺序取决于 kernel 和张量形状——「同一个模型」在两个引擎里给出的概率自然有细微出入。

论文标题里的 off-policy 就是第 2、3 讲的语汇：采样分布 \(q\) ≠ 训练分布 \(p\)。TIM 是产生 off-policy 的一种特殊原因——不是策略自己学走了，而是同一个策略的两份实现不一致。它有多致命？先看一组对照事实：SFT 完全不怕——哪怕训练数据全是另一个模型离线生成的（蒸馏/拒绝采样微调），训练照样稳。RL 却会因为这点小差别崩溃甚至 reward 归零。为什么？

二、破案实验：SFT 不怕、RL 怕的分水岭在哪

作者的切入点很巧：构造一个「介于 SFT 和 RL 之间」的对照实验。用 Qwen3-1.7B 训 Countdown 游戏，人为给采样器权重加一点固定噪声，制造程度可控的 TIM，然后变动两个旋钮：采样器更不更新（离线 vs 在线）和奖励长什么样。

奖励形式离线训练（采样器冻结）在线训练（TIM 下）
全正奖励 +1/0✅ 唯一稳定的❌ 最不稳定的
全负奖励 0/−1❌ 崩：log 概率没有下界，负梯度把「没抽到的 token」的概率无限压向 0，loss 无界 → 模型塌缩介于两者之间
组内中心化（GRPO 式，正负混合）❌ 不稳✅ 最稳定的

两种坏法，两种病因：离线 + 负奖励崩在「压低别人」（logp 无下界）；在线 + 全正奖励崩在另一件事上——而这件事正是本篇主角。关键观察：在线 +1/0 奖励的 RL，本质上是蒸馏：只把成功的 rollout 喂给训练器做最大似然，老师就是采样器。离线蒸馏之所以稳，是因为老师是固定的，学生收敛到老师的拟合就停了。而在线蒸馏的老师不是别人，是学生自己的一个有偏拷贝，每一步都被学生反向更新——

图 A-1｜没有 TIM 时 s̄ = 0，回路里没有这股拉力，训练正常；有 TIM 时，每一步的更新都混进「朝采样器的蒸馏」，且采样器同步跟进、偏差代代放大。类比复印机：母本每代都被换成上一代的复印件，每代带一点色偏——越印越歪。

本篇主角登场「在线 + TIM」崩溃的元凶，论文给它起了名字：drift（漂移）——更新里一个恒定指向采样器的偏置项。下一节用两步高中数学把它从梯度里「拆」出来，再一行代码消掉它。

三、数学核心：把每步更新拆成 drift + signal

3.1 复习：score 是什么

第 1 讲定义过：score 就是 \(\log p\) 对参数的梯度，并且对 softmax 策略手算验证过（有限差分）：

\[ s_a = \nabla_\theta \log \pi(a) = e_a - \pi \]

\(e_a\) 是「选中动作 a」的 one-hot 向量，\(\pi\) 是当前策略的概率分布。REINFORCE 更新式 \(z \leftarrow z + \mathrm{lr}\cdot R\,(e_a - \pi)\) 就是「往实际抽中的方向推、从平均趋势里扣回来」。

3.2 恒等式一：score 的期望恒为零

softmax 版直接算：\(\mathbb{E}_p[s] = \sum_a \pi_a\,(e_a - \pi) = \pi - \pi\cdot 1 = 0\)。一般版也一行：\(\sum_v p_v \nabla_\theta \log p_v = \nabla_\theta \sum_v p_v = \nabla_\theta 1 = 0\)——概率总和永远是 1（常数），常数的变化率为零；而「概率总和的变化率」恰好就是 score 的加权平均。所以 on-policy 时，不管在哪个前缀处，期望更新都是零向量场：推高的和压低的恰好抵消。

3.3 TIM 下就不为零了，而且方向精确可算

TIM 时，token 从采样器 \(q\) 抽、score 却用训练器 \(p\) 算，期望变成 \(\bar{s} = \mathbb{E}_q[s]\neq 0\)。softmax 情形下它精确等于：

\[ \bar{s} = \sum_a q_a\,(e_a - \pi) = q - \pi \]

方向就是「从训练器指向采样器」。第 2 讲算过 KL：\(\mathrm{KL}(q\|p)\) 越小说明两个分布越像，而把它降下去的梯度正是 \(-\bar{s}\)——所以沿 \(+\bar{s}\) 走 = 把 \(p\) 拉向 \(q\) = 向采样器蒸馏（蒸馏损失「把概率挪到老师喜欢的 token 上」的下降方向，正是 \(-\bar{s}\)）。

3.4 恒等式二：把更新拆成 drift + signal

用到第二个高中级工具——协方差拆分。两个数列 \(A, B\) 的「乘积的平均」等于「平均的乘积」加「协方差」：\(\mathbb{E}[AB] = \mathbb{E}[A]\,\mathbb{E}[B] + \mathrm{Cov}(A,B)\)。先拿具体数字找感觉：\(A=[1,2,3]\)，\(B=[2,0,4]\)：\(\mathbb{E}[A]=2\)，\(\mathbb{E}[B]=2\)，\(\mathbb{E}[AB] = (1{\times}2 + 2{\times}0 + 3{\times}4)/3 = 14/3 \approx 4.67\)；而 \(\mathbb{E}[A]\mathbb{E}[B] = 4\)，差的 \(2/3 \approx 0.67\) 就是协方差——「两者是否一起变」的度量。套到策略梯度上（论文式 3）：

\[ \underbrace{\mathbb{E}_q[R\,s]}_{\text{每步的实际更新}} \;=\; \underbrace{\mathbb{E}_q[R]\cdot\bar{s}}_{\text{drift（漂移）}} \;+\; \underbrace{\mathrm{Cov}_q(R,\,s)}_{\text{signal（信号）}} \]

两块的性质完全不同：

drift：\(\mathbb{E}_q[R]\cdot\bar{s}\)signal：\(\mathrm{Cov}_q(R,s)\)
内容平均奖励 × 朝采样器的方向「哪个 token 的 score 与高奖励一起出现」
携带信息？无——它只看平均分，分不清哪条 rollout 成功有——这才是真正的学习信号
on-policy 时\(\bar{s}=0\)，自动消失保留（学习全靠它）
TIM 时\(\neq 0\)：每步都在向采样器蒸馏，幅度 ∝ 平均奖励仍在（但有偏）

这解释了第二节的现象：全正奖励在线训练最不稳——\(\mathbb{E}_q[R] > 0\) 处处成立，每个前缀处都在把训练器拉向采样器，反馈回路火力全开；组内中心化让平均奖励有正有负，拉力和推力部分相抵，所以最稳——但注意，只是「部分相抵」。

为什么 GRPO 的组内减均值救不了第 5 讲的组内中心化只保证「同一个 prompt 的 G 条 rollout，优势加和为 0」，可 drift 发生在每个前缀处：一个「开头写对了」的前缀，后续答对的期望优势为正 → 此处被拉向采样器；一个「开头就抄错数」的前缀，期望优势为负 → 此处被推离采样器。也就是说，drift 恰好在携带学习信号的前缀处非零，与 token 是否影响得分无关。组中心化能缩小 drift（与 +1/0 相比），但消不掉——这就是它的天花板。

四、一行修复：score centering

思路顺理成章：既然 drift 的祸根是「TIM 下 score 的期望不再为零」，那就手动把它归零——在每个前缀处，从 score 里减掉它在采样器分布下的期望（论文式 4）：

\[ \tilde{s} \;=\; s - \bar{s}, \qquad \bar{s} = \mathbb{E}_q[s]\ \text{（给定前缀，是常向量）} \]

代回协方差拆分（论文式 5），逐行看：

\[ \mathbb{E}_q[R\,\tilde{s}] = \cancel{\mathbb{E}_q[R]\cdot\mathbb{E}_q[\tilde{s}]} + \mathrm{Cov}_q(R,\tilde{s}) = \mathrm{Cov}_q(R,\tilde{s}) = \mathrm{Cov}_q(R, s) \]

第一项被划掉是因为 \(\mathbb{E}_q[\tilde{s}] = \bar{s} - \bar{s} = 0\)——drift 精确归零（不是缩小，是消失，且不依赖任何近似）。最后一步是因为 \(\tilde{s} = s - \text{常向量}\)：给每个数减同一个常数不改变「一起变动」的程度，signal 分毫不动。对比 on-policy 时的期望更新 \(\mathbb{E}_p[R\,s] = \mathrm{Cov}_p(R,s)\)：唯一剩下的区别只是协方差在哪个分布下测量。没有 TIM（\(p=q\)）时 \(\bar{s}=0\)，修正自动为零——不需要它时它是透明的，因此没有任何超参数。

五、和重要性采样的正面交锋

第 3 讲的重要性采样（IS）在期望意义上也能精确消 drift：\(\mathbb{E}_q[\frac{p}{q} R\,s] = \mathbb{E}_p[R\,s]\)。那为什么还需要 SC？对比两张「药方」的药性：

重要性采样（乘法修正）Score Centering（加法修正）
修正形式每个 score 乘上 ratio \(\rho = p/q\)——依赖抽到了哪个 token，逐样本随机每个 score 减去 \(\bar{s}\)——只依赖前缀，逐前缀确定
方差稀有 token 的 ratio 可任意大 → 梯度方差爆炸不放大方差（减的是确定量）
实现代价需要采样器记录 logprob（本来就有）需要采样器记录 top-k logprob（新增，但很便宜，见 §6）
超参数剪裁区间一堆（下表）零
阿喀琉斯之踵 ratio 太大必须剪/丢 → 被剪掉的地方 drift 漏回来协方差测在 \(q\) 下而非 \(p\) 下 → 重度 staleness 时吃亏（可组合 IS 弥补）

实践里的 IS 家族（论文表 1）全部在「剪多少、丢多少」上做文章，且各有各的剪法：

方法作用层级ratio 保留区间区间外处置
裸 IS（Williams 1992）token\([0, \infty)\)不剪 → 方差爆炸，没人敢用
TIStoken\(\min(r, 2.0)\)截断
MIS（IcePop）token\([0.5, 5.0]\)直接丢弃该 token

Score Centering加法、无区间、无超参——与上表所有方法的工作原理正交

关键洞察：它们还能组队。SC 可以叠在任何 IS 方法上——先用 IS 加权 score，再减去「加权 score 的期望」\(R\,(w\,s - \mathbb{E}_q[w\,s])\)。有个优雅的自检：取纯 IS（\(f(r)=r\)）时，加权 score 的期望本来就为零，SC 项自动消失（没什么可中心化的）；而 TIS/MIS 剪掉了一部分，SC 恰好把剪漏的 drift 补上。§7 的实验会看到：重度 staleness 下组队最强。

六、实现：存不下 15 万维，就存 top-128

精确的 SC 需要「采样器对每个已采样 token 的完整下一 token 分布」——算 \(\bar{s}\) 要对整个词表求和。但 Qwen3 词表 15.2 万：fp32 存一个 token 的全量 logprob 约 608KB；1024 条 rollout × 3.2 万长度 ≈ 20 TB，不可行。论文的解法分两步：

第一步：只记 top-\(k\) logprob（\(k=128\)）。vLLM/SGLang 原生支持，几乎零开销。头部覆盖不了的「尾部概率质量」用训练器自己的分布按比例缩放来补：记头部集合为 \(H\)，

\[ \hat{q}_v = \begin{cases} q_v & v \in H \\ \rho\, p_v & v \notin H \end{cases} \qquad \rho = \frac{1-\sum_{v\in H} q_v}{1-\sum_{v\in H} p_v}\ \text{（采样器尾部质量 ÷ 训练器尾部质量）} \]

第二步：尾部期望不用真算。利用恒等式一（\(\mathbb{E}_p[s] = 0\)，尾部期望 = 零 − 头部期望），求和缩到头部 \(k\) 个 token（论文式 10）：

\[ \mathbb{E}_{\hat{q}}[s] = \sum_{v\in H} (q_v - \rho\, p_v)\, s_v \]

再把它写成可自动微分的标量损失——中心化项里的系数全部加 stop_gradient（sg，当常数用、不参与求导——修正必须是「平移」，不能自己也被梯度推着走）：

\[ L = -R\,\Big(\log p_{y_t} - \sum_{v\in H} \mathrm{sg}\big[q_v - \rho\, p_v\big]\,\log p_v\Big) \qquad\Longrightarrow\qquad -\nabla_\theta L = R\,(s_{y_t} - \bar{s}) = R\,\tilde{s}_{y_t} \]

单个 token 的最小实现（论文原码，10 行 JAX）：

import jax.numpy as jnp
from jax.lax import stop_gradient

def score_centering_loss(train_logp, samp_logp, topk_ids, sampled_token, advantage):
    train_head_logp = train_logp[topk_ids]
    tail_mass_ratio = (1 - jnp.exp(samp_logp).sum()) / (1 - jnp.exp(train_head_logp).sum())
    head_prob_residual = jnp.exp(samp_logp) - tail_mass_ratio * jnp.exp(train_head_logp)
    logp_correction = (stop_gradient(head_prob_residual) * train_head_logp).sum()
    return -advantage * (train_logp[sampled_token] - logp_correction)

效果与代价：\(k=128\) 甚至 \(k=32\) 在所有实验里与全量 SC 打平（头部覆盖 >99.9% 概率质量）；整个修正的墙钟开销在 baseline 方法的 1% 以内。

七、实验：从 0.6B 到 30B，从加噪声到真量化

所有对比都钉在同一目标函数上（REINFORCE + 组内中心化奖励），每次只叠加一种修正，公平对照。模型：Qwen3-0.6B（Countdown 游戏）与 Qwen3-30B-A3B-Base（MoE，INTELLECT-2 数学数据）。

设置TIM 怎么造的结果
合成权重噪声（0.6B）采样器权重 + 固定高斯偏移 \(\Delta\theta\)，三档强度噪声越大崩得越早（DPPO 三档分别崩在 ≈160 / 80 / 20 步）；最重噪声下只有 SC 及 SC+MIS/TIS 存活
int8 量化采样器（0.6B）采样器权重/激活/KV 全 int8，训练器 bf16SC 单用与 SC+IS 并列最好
重度 staleness（0.6B）推理引擎每 64 步才同步一次SC+TIS/MIS 最佳，超过 SC 单用（原因见 §5：IS 先把分布拉近，SC 再消残余 drift）；PPO/DAPO 靠 clip 也能活
30B MoE · FP8 采样器轻失配连裸 PG 都稳（58% 训练准确率）——轻 TIM 下各方法短期拉不开差距
30B MoE · FP4 KV cacheKV cache 量化到 fp4裸 PG 200 步内崩，MIS 训练后期崩；SC 52%、TIS 51% 稳住
30B MoE · INT8 权重激活 + INT4 KV重度失配SC 30%，TIS 12%，其余全部 <5%——差距随失配加重而拉开

两个值得记住的旁证：① PPO/DAPO 在 staleness 下活着、在量化/噪声下崩——它们的 clip 区间是为「策略自己走远」产生的 ratio 设计的，数值误差造成的偏差不沿这个区间活动，clip 管不着；② 轻失配短期看不出差别——drift 是逐步累积的，轻 TIM 只是滚得慢。这也调和了此前文献的分歧（有人 fp8 稳、有人 bf16 都崩）：看的训练步数不一样。

什么时候该上 SC？——如果你的系统 bf16 对 bf16、每步同步、序列短，大概率感觉不到 TIM（FP8 采样器下连裸 PG 都稳）。但如果 rollout 引擎做了量化（int8/fp4 KV）、或异步更新（长 rollout、agentic 任务），SC 是便宜的保险：开销 <1%、零超参、on-policy 时自动失效；异步越重越该和 TIS/MIS 组队。MoE 还有一处论文没有重放的 TIM 源：两个引擎的路由不一致——实践中建议重放路由索引。

八、局限与边界

  • SC 只保证消 drift，不保证完全回到 on-policy 更新：剩下的更新在 \(q\) 下测协方差，而非 \(p\) 下。p 和 q 离得越远（重度 staleness）失真越大——实验里 SC+IS 组合正好补这块短板。
  • 头条数字来自故意加重的 TIM + 短序列，作为「轻 TIM × 长训练」的代理。结论方向可信，具体倍数别外推。
  • 负奖励那条病（离线崩）本文没治：SC 治的是「在线 + 漂移」，「离线 + 负奖励把 logp 压向 −∞」是另一个机制（另一条研究线）。

九、和系列各讲的连接

讲次本篇用到 / 扩展了什么
第 1 讲score = \(e_a - \pi\) 与 REINFORCE 更新式——加 SC 后更新规则回到同一形式（\(\pi\) 换成 \(q\)）；「减均值」从奖励侧换到 score 侧
第 2 讲on/off-policy 的精确定义（采样分布 ≠ 训练分布）；\(\mathrm{KL}(q\|p)\) 的下降方向 = 蒸馏方向 = drift 方向
第 3 讲IS ratio 与 clip：整个剪裁家族一览；PPO 的 clip 抗「策略走远」、不抗「数值误差」
第 4 讲蒸馏视角的呼应：SFT = 对固定老师做最大似然（稳）；drift = 对会动的老师蒸馏（崩）
第 5 讲GRPO 组内中心化的能力边界：降方差救不了偏差；训练病症清单新增一个病因「TIM drift」，药方就是 SC
第 6 讲rollout/trainer 分离、权重同步、异步 staleness、量化——TIM 的全部现实来源；「ratio 监控」之外的第三条稳定思路：加法修正

十、自查清单

  1. TIM 的四个来源？哪两个「没有 bug 也存在」？（浮点不结合律、算子与输入形状）
  2. 为什么 SFT 对数据来源不敏感、RL 敏感？（老师固定 vs 老师随学生移动：蒸馏收敛 vs 反馈回路）
  3. 写出拆分式 \(\mathbb{E}_q[R\,s] = \mathbb{E}_q[R]\,\bar{s} + \mathrm{Cov}_q(R,s)\)，指出哪块是学习信号、哪块是漂移。
  4. softmax 策略下 \(\bar{s}\) 精确等于什么？方向朝哪？（\(q - \pi\)，指向采样器）
  5. 为什么 GRPO 组内中心化消不掉 drift？（drift 按前缀产生；前缀处期望优势 ≠ 0）
  6. SC 的定义与两重保证？（\(\tilde{s} = s - \bar{s}\)：drift 精确归零；\(\tilde{s}=s-\)常向量 → 协方差不变）
  7. SC 与 IS 的本质区别？为什么能组队、纯 IS 时 SC 项为何自动消失？（乘法随机 vs 加法确定；\(f(r)=r\) 时加权 score 期望本来就是零）
  8. 为什么 top-128 logprob 就够？（尾部用 \(p\) 按质量比 \(\rho\) 缩放；\(\mathbb{E}_p[s]=0\) 让尾部期望 = −头部期望；头部覆盖 >99.9% 质量）
一句话带走RL 怕 TIM，不是因为两引擎差得多，而是因为差的方向永远一致、还会被同步回路代代放大。score centering 用一行加法（score 减去它在采样器下的期望）把这个方向精确抹平——零超参、零方差代价、on-policy 时自动隐身。第 6 讲调试清单里的「reward 不涨/训练崩」分支，从此多了一味药。
