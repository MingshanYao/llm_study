1. RL 训练为什么不是「普通训练」

普通训练（预训练、SFT）的系统图很简单：数据集固定，GPU 循环做「前向 → 反向 → 优化器」。RL 训练多出两样东西：

  1. 一条高频推理生产线：训练数据（回答）不是从磁盘读的，是模型现场生成的。LLM 生成慢（逐 token 自回归），这条生产线的耗时通常占整个训练步的 50%~80%。
  2. 一条反向的权重同步流：推理引擎用的权重必须跟训练引擎保持新鲜——每更新一步，新权重就要广播给所有推理卡。普通训练里「模型权重」只活在训练进程里；RL 训练里它要在两类引擎间来回搬运。

图 6-1｜GRPO 训练系统全景。RLVR 路线下没有 RM 服务（verifier 是纯 CPU 程序，常用容器沙箱执行代码测试）；RLHF 路线则多一台 RM 推理服务。

2. 组件明细与两个关键机制

组件职责要点
Prompt 池 / dataloader供给训练问题难度分层（pass rate 0.2~0.8 的题最值钱，第 5 讲病症三）；持续淘汰过易/过难题
Rollout 引擎批量生成回答vLLM：PagedAttention 把 KV cache 像虚拟内存一样分页管理，碎片小、吞吐高；SGLang：RadixAttention 前缀树缓存，同一 prompt 的 G 条回答共享前缀计算

监控曲线与告警W&B / TensorBoard；断点续训是刚需——长训练一定会挂

2.1 权重同步

每一步更新后，新权重要从 Trainer 流向 Rollout 引擎。三种常见做法：NCCL 集合通信直接广播（卡对卡，最快）、共享内存 / CPU 中转（跨机场景）、参数服务器中转。工程要点是别让同步成为新瓶颈：大模型权重几十 GB，同步一次的代价不低，于是有了下面的架构之争。

2.2 colocate（同位）vs 分离式

架构做法优点代价
colocate（veRL 默认）训练卡与推理卡是同一批卡，分时复用：生成时训练引擎让位，训练时推理引擎卸载省卡；权重同步几乎零成本（就在本卡）两类引擎互相等待；显存要在两者间腾挪（offload）
分离式独立推理集群专职 rollout，训练集群专职训练，异步接力两套集群各自满载，吞吐高；异步化空间大卡数翻倍；权重同步走网络；数据变陈旧（第 4 节）

3. 显存账本：为什么 7B 单卡都训不动

面试高频题，也是选配置的日常依据。混合精度 + Adam 训练时，每个参数实际占用的显存远不止权重本身：

项每参数字节7B 模型合计
bf16 权重（前向用）214 GB
fp32 主权重（优化器更新的真身）428 GB
Adam 一阶矩 m428 GB
Adam 二阶矩 v428 GB
梯度（bf16）214 GB
合计（不含激活值）16112 GB

112 GB 还没算激活值（序列越长越恐怖）——单卡 80 GB 无解。而推理只需要 bf16 权重（14 GB）加 KV cache。这就是「推理单卡能跑、训练必须多卡」的算术。对策阶梯从便宜到贵：

  1. LoRA：冻结原权重，只训插入的低秩小矩阵——优化器状态骤减，单卡变可行（RL 实验起步常用）；
  2. ZeRO / FSDP 分片：见下；
  3. offload：把优化器状态甚至参数挪到 CPU 内存 / NVMe（用通信换显存）；
  4. 更多卡 + 更细的并行。

3.1 四种并行方式（类比版）

方式怎么切类比（全班抄书做题）
数据并行 DP每卡完整模型，吃不同数据，梯度 all-reduce 平均每人抄整本书，各做各的题，最后对答案取平均
张量并行 TP单层的大矩阵按行/列切片分卡把一道题拆成几步，几个人同时算，中间频繁递纸条（通信最频繁）
流水线并行 PP按层切，卡间传激活工厂流水线：每人负责几道工序，产品依次传递
ZeRO / FSDP数据并行的省内存版：参数/梯度/优化器状态切片，用到时临时聚合书包轮流背：书平时分头保管，做题时互相借页

ZeRO 的三档（记法：1 切优化器状态、2 加切梯度、3 加切参数，切得越多越省显存、通信越多）。FSDP 是 PyTorch 原生的 ZeRO-3 式实现；Megatron 走 TP+PP 组合路线。真实训练通常是组合拳：TP + PP + DP(FSDP) 叠加，再叠加第 1 节的两条生产线。

4. 同步还是异步：on-policy 程度的取舍

理想很纯粹：用最新的策略采样、立刻更新（严格 on-policy，第 1 讲以来的默认设定）。但生成和训练互相等待，GPU 大量空转。工程折中——让 rollout 提前跑：

  • 训练端不等最新权重，用手头已有的回答凑批开算（数据是「几个版本之前」的模型生成的）；
  • 数据变陈旧 = off-policy 程度上升，而第 3 讲的重要性采样 ratio 正是为此准备的修正器——ratio 会自动偏离 1 来加权补偿；
  • 但 ratio 偏离 1 太远（陈旧度过高），修正失真、训练不稳——所以要监控 ratio 分布、限制陈旧步数（staleness）。
零件再上岗至此第 3 讲的 ratio 出现了第三个身份：PPO 里是更新保险丝的原料；GRPO 里是目标函数的一部分；异步系统里是「数据新鲜度」的度量衡。一个概念在系统不同层反复出场，是这套技术栈的典型美感。

5. 异常曲线的十分钟排查清单

把第 5 讲的病症门诊扩展成工程师的 checklist（症状 → 按序排查）：

症状按序排查（快 → 慢）
loss spike① 梯度范数是否爆炸（clip 没开？）② 数据批次有没有脏样本（回看 spike 时刻的 prompt）③ 学习率/预热配置 ④ bf16 数值溢出（换 fp32 层或调 loss scale）
reward 不涨① 无梯度组占比（全对全错太多？→ 难度过滤）② KL 是否锁死（β 过大或实现错 → 模型躺平）③ 抽 20 条人工核对 verifier 判分（判错的真答案比漏判的假答案更致命）④ 熵是否已经坍缩
KL 爆炸① β 与 k3 实现核对（符号错了 KL 会是负的）② π_ref 是否加载了正确 checkpoint ③ 学习率 ④ reward 是否有巨大分值（clip 奖励上限）
显存 OOM① 长尾超长回答（一条 32k token 的回答能单独爆卡 → 截断 + 长度监控）② batch 拆小 / 梯度累积 ③ 激活值重算（activation checkpointing）④ offload 优化器状态
生成退化（复读/乱码）① reward hacking 侦察：抽高分回答人工看（第 4 讲 4 节）② 熵曲线 ③ 采样参数是否被训练带偏 ④ 回滚到上一个正常 checkpoint
纪律：每次只改一个变量；每个实验必存 checkpoint 与完整配置；曲线异常先「复现到最小规模」再上大集群排查。这三条纪律的价值超过任何单点技巧。

9. 自查清单（本讲 + 全系列）

本讲的 6 个问题：

  1. RL 训练系统比普通训练多出哪两条流？（答：高频推理生产线 + 反向权重同步）
  2. colocate 和分离式架构各自的代价？（答：互相等待与显存腾挪 vs 卡数翻倍与数据陈旧）
  3. 7B 模型 Adam 训练的显存账本？（答：16 字节/参数 ≈ 112 GB + 激活值；推理仅 2 字节/参数 + KV cache）
  4. DP / TP / PP / FSDP 一句话各是什么？（答：不同数据 / 层内切矩阵 / 按层流水线 / 切片式数据并行）
  5. 数据陈旧为什么不是致命问题？（答：重要性采样 ratio 自动补偿，但要监控 ratio、限制 staleness）
  6. reward 不涨的排查顺序？（答：无梯度组占比 → KL 锁死 → 人工核对 verifier → 熵）
