本讲目标：V4 的 MoE 是「地基不变、六处翻新」：① 亲和度换 \(\sqrt{\mathrm{Softplus}}\)（手算对比）；② 拆掉 V2 以来的节点数限制——通信枷锁全部解除；③ 用 MegaMoE 波级流水把 all-to-all 通信藏进计算（1.50–1.73×，RL rollout 最高 1.96×）；④ 专家权重压到 FP4（配 QAT），显存与带宽骤降；⑤ 前 3 层改 Hash 路由，61 层全 MoE；⑥ 训练稳定性三件套（Anticipatory Routing / SwiGLU clamping / 既有 bias 保险丝）。V4.1 再补一刀：图文各一套 bias。每一处都回答「改了什么、为什么、代价是什么」。

2. 亲和度换成 √Softplus：三代函数的收官

2.1 定义与手算

\[ s_{i,t} = \sqrt{\mathrm{Softplus}(x_t^\top e_i)} = \sqrt{\log(1 + e^{z_i})} \]

两步走：先 softplus 光滑化（第 0 讲：ReLU 的光滑版，负半轴不断流），再开根号（把增长放缓）。拿 \(z = [-2, 0, 2, 4, 8]\) 与 sigmoid 并排手算：

一眼可见的分工：sigmoid 在 \(z=8\) 时挤死在 0.9997——再大的分数也只值 1，区分度没了；√Softplus 还在增长（2.83），分数之间永远有差距。

2.2 三条性质与动机

图 3-1｜三代亲和度。形状对比见第 0 讲图 0-2，耦合对比见第 2 讲图 2-4。

  • 独立：没有 softmax 式分母，逐专家打分互不干扰——V3 确立的优点全盘继承；
  • 无上界：不像 sigmoid 封顶在 1，大分数仍有区分度；开根号让增长比线性更慢（\(z\) 大时近似 \(\sqrt{z}\)），天然压住极端值——配合 V4 面对的「路由放大离群值」问题（§9）看，这个选择很合理；
  • 零点光滑：负半轴平滑趋 0 不为 0、处处可导，训练梯度不会像 ReLU 那样在某处断流。
√Softplus 的动机分析：V4 论文只写了「把 Sigmoid 换成 √Softplus」一句话（§2.1，p.7），未给原因。上述性质分析（尤其「配合离群值治理」的关联）为推断。

代码一瞥（V4-Pro 推理代码 model.py，详见第 4 讲）：config.json 里 "score_func": "sqrtsoftplus"，实现一行 scores = F.softplus(scores).sqrt()。归一化与 route_scale 见 §3。

3. 均衡机制：不动，但在 384 个专家上继续滚

V4 的均衡与 V3 完全同款：bias 门控（更新速度 0.001）主责 + 序列级损失（0.0001）保险丝（第 2 讲 §5、§7 已精讲，不再重复）。第 4 讲会看到代码里对应的 self.bias 与 weights /= weights.sum(...)，以及最后乘上的 route_scale = 2.5（把归一化后平均 1/6 的权重量级放大回 SwiGLU 习惯的幅度，校准残差流的尺度）。

4. 384 个专家的显存账：为什么必须谈 FP4

先算账。一个路由专家的参数：三个矩阵，\(3 \times d_{model} \times d_{expert} = 3 \times 7168 \times 3072 \approx 66.1M\)。

项计算结果
单个路由专家\(3 \times 7168 \times 3072\)≈ 66.1M 参数
全部路由专家\(66.1M \times 384 \times 61\) 层≈ 1.55T
对照官方总参1.6T路由专家占绝对大头（共享专家/注意力/embedding 补足余量）✓

这 1.55T 参数每个 token 只用其中 6/384，但推理时全部要驻留显存。FP8 存不下（1.55T × 1 字节 ≈ 1.55TB，任何单机都放不下，卡数与带宽都吃不消），V4 把路由专家压到 FP4——直接砍半。FP4 是什么、为什么敢压这么狠，见 §7。

5. 通信成本模型：一笔可以算清楚的账

拆掉节点限制（V2 的 M=3、V3 的 M=4）意味着每个 token 的 6 个专家可以分布在任何设备上——通信路径完全放开。敢这么做的前提，是把通信成本算到笔笔清楚。V4 论文 §3.1 把 MoE 层拆成五段：

\[ \underbrace{\text{Dispatch}}_{\text{送出}} \to \underbrace{\text{Linear-1}}_{\text{升维}} \to \underbrace{\text{Act}}_{\text{SwiGLU}} \to \underbrace{\text{Linear-2}}_{\text{降维}} \to \underbrace{\text{Combine}}_{\text{取回}} \]

对每个「token-专家对」（一个 token 被分给一个专家，就叫一对）：

  • 计算量：SwiGLU 三次矩阵乘 = \(6hd\) FLOPs（\(h=7168\) 模型维、\(d=3072\) 专家中间维；系数 6 = 三次投影 × 每次乘加 2 FLOPs）；
  • 通信量：Dispatch 送 \(h\) 字节（FP8 隐状态）+ Combine 回 \(2h\) 字节（BF16 结果）= \(3h\) 字节。

把「计算/通信」比上「带宽」得到判据：只要硬件的算力-带宽比满足

\[ C/B \le 2d = 6144\ \text{FLOPs/Byte} \]

（\(C\) = 每 token-专家对 6hd FLOPs 除以 \(h\)、\(B\) = 带宽；直觉版：传 1 字节的时间里，GPU 能算 6144 次乘加，而每个字节的活儿只值 \(2d=6144\) 次乘加——刚好收支平衡，带宽就不再是瓶颈），通信就可以被计算完全盖住。论文的结论：V4 的硬件配置过了这条线，「继续堆带宽收益递减」——这就是拆掉节点限制的底气：通信不用躲，盖住它就行。

一句话记住这个判据这是「算术强度」思想：通信延迟能不能藏进计算时间，取决于「每字节数据配套的计算量」是否 ≥ 硬件「每字传输时间内能完成的计算量」。V4 的配置刚好达标。

6. MegaMoE：波级流水，让通信彻底「隐身」

道理上「通信可以盖住」，工程上要靠调度。先看不做调度的惨状：

图 3-2｜波级流水示意（对应 V4 论文图 5 的思想）：把 384 个专家切成若干「波」，每波的 Dispatch 一完成就立刻开算，不等其他波。稳态下「计算、传输、回传」三条流水并发，整层耗时被压缩到接近纯计算时间。实测：通用推理加速 1.50–1.73×，RL rollout（生成量极大、通信占比高的场景）最高 1.96×。

生活比喻洗衣店接了三批订单。逐层同步 = 等 3 批衣服全部收齐 → 全部洗完 → 全部送回，三次等待三次闲聊。波级流水 = 第 1 批衣服进洗衣机的同时，店员出门收第 2 批；第 1 批烘上，第 2 批进洗，第 3 批在收——任何时刻「洗、收、送」三线并行。MegaMoE 就是这个流水线的 CUDA 实现名（开源在 DeepGEMM 中）。

7. FP4：把 1.55T 参数塞进 4 个比特

7.1 五分钟浮点数课

计算机存小数用「科学计数法的二进制版」：一个浮点数 = 符号位 × 尾数位 × 指数位。FP32 给 8 位指数 + 23 位尾数（约 7 位十进制精度）；FP16/BF16 各给 5/8 位指数；FP4（E2M1 格式）总共只有 4 个比特：1 符号 + 2 指数 + 1 尾数，能表示的值一共 15 个：

图 3-3｜E2M1 的表示能力。单个数糙成这样，怎么敢拿去存 1.55T 参数？两个答案：分组缩放（把值域先挪到合适的量级再取整）＋ 量化感知训练。

7.2 QAT：让模型「提前适应穷日子」

训练完成后再把 FP32/FP8 权重硬压到 FP4（训后量化，PTQ），误差会直接砸进前向计算——MoE 的矩阵乘是「分组 GEMM」，每组 batch 小，误差没法互相平均，掉点明显。V4 的做法是 QAT（量化感知训练），post-training 阶段：

  1. 前向：模拟量化——权重先「假装」被压到 FP4（乘 scale、四舍五入到 15 个值、再乘回 scale），模型看到的永远是「穷日子版的自己」，学习过程自动把重要参数挪到 FP4 表示得准的位置上；
  2. 反向：STE 直通——「四舍五入」没有梯度，反传时假装这一步是恒等映射（straight-through estimator），梯度照常流回 FP32 主权重；
  3. 部署：原生 FP4——训练定型后直接用 FP4 权重推理，显存与加载带宽兑现减半收益。

代码佐证：kernel.py 的 fp4_gemm_kernel 文档写明 B is stored as [N, K//2] in float4_e2m1fn_x2（两个 FP4 打包进 1 字节）、片上把 FP4 上转 FP8/FP32 做乘累加；量化核按 1×32 tile 求 amax 定 scale，fp4_max = 6.0——与上面的数轴完全对应。论文 §5.2.1（p.33–34）补了一个精巧结论：FP4 → FP8 的反量化可以做到无损，因为 FP8（E4M3）比 E2M1 多 2 个指数位，只要 128×128 块内子块 scale 的比值不超阈值，FP4 的舍入误差能被 FP8 完全吸收。

8. Hash 路由：前 3 层不学「去哪儿」，只学「用多少」

8.1 机制

V3 把前 3 层留成稠密 FFN；V4 改成「前 3 层也用 MoE，但路由不学习」——Hash 路由：按 token ID 查一张预计算好的固定映射表 tid2eid（形状 [词表 129280 × 6]），直接给出 6 个目标专家号。论文原话：「Hash routing determines the target experts of each token according to a predefined hash function with regard to the input token ID」（p.7）。

图 3-4｜两条路由流水线。查表是 requires_grad=False 的整型张量、随 checkpoint 分发，哈希函数本身不在开源推理代码里。

8.2 为什么前 3 层可以不学（推断链）

论文未解释动机。可拼出的理由链：

  • 浅层没有可学的分工：语言的专业分工是深层语义现象（「这段是化学」要到几层之后才明朗），浅层 token 该去哪个专家的信号本来就弱——自由路由在浅层要么学成接近均匀（白养 384 个专家的路由器），要么被早期噪声带偏；
  • 稳定性：V4 自己发现路由与主干同步更新是 loss spike 温床（§9）；前 3 层换成无参数选择，等于在最不稳的地方直接切断这条反馈回路；
  • 负载天然均匀：每个 token ID 恒定映射 6 个专家、表是预计算平衡表，热门 token 也分流量，浅层不需要均衡机制（没有 bias）；
  • 零路由开销：查表即可，与「批不变、逐位确定」的工程目标一致；
  • 不是全弃学习：加权仍走学习分数——「用多少」的表达力保留。
以上五条均为推断；可核实的事实只有：前 3 层 Hash、无 bias、表在 checkpoint 里（model.py:556–562）。「浅层不特化」与 V1 论文的专家可视化观察方向一致，但该引文未逐字核对。

9. 训练稳定性：路由是离群值的「帮凶」

V4 论文 §4.2.3 承认：万亿 MoE 训练的 loss spike 与 MoE 层激活离群值强相关，而且「the routing mechanism itself appears to exacerbate the emergence of these outliers」（论文原话）。恶性循环是：

\[ \text{某专家权重异常} \to \text{它的亲和度异常} \to \text{token 涌向它} \to \text{它的激活进一步异常} \to \cdots \]

注意这与 √Softplus 的选择（无上界、温和放大）以及第 2 讲 bias 门控（均衡信号隔离）其实是同一个主题的三次变奏：路由是全网络最敏感、最容易正反馈的部分，一切手段都在给它「减震」。V4 的两个实招（论文坦承机理未完全理解）：

  • Anticipatory Routing（预判路由）：路由索引用 \(\Delta t\) 步之前的旧参数 \(\theta_{t-\Delta t}\) 预计算——主干和路由的更新解耦，token 的流向在 spike 形成前就被「旧地图」定住；代价是约 20% 额外墙钟开销，由 spike 检测器动态启用（平时不开）；
  • SwiGLU Clamping：专家的 up 分量夹到 \([-10, 10]\)、gate 分量夹上界 10（代码 torch.clamp(up, -10, 10)）——训练期把 MoE 层的离群值物理按住。

10. V4.1：均衡的多模态化——图文各一套 bias

V4.1-Flash 保持 1 共享 + 384 路由（中间维 2304）的 DeepSeekMoE 结构，唯一的 MoE 级变更是多模态辅助损失免费均衡。问题：图像 token 与文本 token 的路由偏好天然不同（图像像素块需要的加工与「法律条文」毫无交集），如果混在一个 bias 体系里均衡，两模态各自的失衡会互相掩盖——图像侧挤爆的专家，可能恰好是文本侧冷清的，全局统计看起来岁月静好，模态内早已旱涝两重天。

图 3-5｜V4.1 双模态 bias。门控、专家池、加权规则全部共用，只有「选择时的加成」按模态分家——最小改动解决「混着均衡掩盖模态内失衡」的问题。

11. V4 小结：枷锁与解锁的完整清单

枷锁（V2/V3 时代为效率戴上的）V4 的解锁方式
节点数限制（M=3/4）压路由自由度取消限制 + §5 成本模型 + §6 MegaMoE 把通信藏进计算
浅层不敢用 MoE（V3 前 3 层稠密）Hash 路由：不学习的 MoE，负载天然均匀、零风险
1.55T 专家参数的显存/带宽压力FP4 + MXFP4 QAT（§7）
万亿训练的路由离群值√Softplus 温和放大 + Anticipatory Routing + SwiGLU clamp（§9）

而 V1 定下的地基——细粒度专家、共享隔离、bias 门控——一件没动，只是规模从 64 专家滚到 384。这就是「演进」的实感：范式 2024 年就定了，之后五年全是在给范式扫清工程障碍。

12. 自查清单

  1. √Softplus 相比 sigmoid 保住了什么、改进了什么？（保住独立打分；改进：无上界、大分数有区分度、负半轴光滑不断流）
  2. 「通信可以被计算盖住」的判据是什么？（\(C/B \le 2d = 6144\) FLOPs/Byte：每字节的活儿 ≥ 每字节传输时间内能算的量）
  3. 波级流水稳态下并发的三件事？（算当前波、传下一波、回传已完成波）
  4. 为什么 FP4 必须 QAT 而不是训后硬压？（分组 GEMM 组内 batch 小、误差无法平均；QAT 让权重提前适应低精度）
  5. Hash 路由层「学习」的是什么、「不学习」的是什么？（加权分数仍学习；选哪 6 个专家不学习——查固定表）
  6. 为什么图文要各一套 bias？（混着均衡会互相掩盖模态内的失衡）
