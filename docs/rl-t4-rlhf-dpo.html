RL 训练工程师零基础七讲 · 第 4 讲：RLHF 与 DPO

本讲定位：讲奖励的「制造」与它的两条消费路线：经典 RLHF（PPO 消费）与简化路线 DPO（省掉 RL 循环）。ChatGPT 式对齐的来龙去脉在本讲成型。

前置要求：第 2 讲（KL 缰绳、reference model）必须已读；第 3 讲有整体印象即可（本讲不要求会手算 PPO）。

本讲彩蛋：DPO 的推导是全系列最漂亮的一步棋——三行代数把「RL 问题」折叠成「监督学习」。推导的每一步都给出了直觉版本。

本讲目标：第 3 讲的 PPO 只是引擎，本讲讲燃料：奖励从哪来。主线是 InstructGPT 三段式：人类偏好数据 → Bradley-Terry 模型 → reward model 训练（手算其损失）；以及随之而来的宿敌 reward hacking。然后讲 RLHF 的著名简化 DPO：从「KL 约束下奖励最优」的解析解出发，把 RL 循环折叠成一个监督损失，彻底去掉 rollout、RM 和 critic（手算其损失）。最后对比两条路线的适用边界，并给出反馈自动化的 RLAIF。

1. RLHF 三段式：InstructGPT 的流水线

2022 年的 InstructGPT 论文确立了「用人类反馈做强化学习」（RLHF）的工业流水线，ChatGPT 是它最著名的产物。三段式：

  1. SFT：先用人写的示范微调出会对话的底子（第 0 讲讲过）；
  2. 训练 Reward Model：让人对模型的多个回答做偏好标注，训出一个「模仿人类口味的打分器」；
  3. PPO 强化学习：以 RM 的打分为奖励，用第 3 讲的引擎优化策略，KL 缰绳拴住 SFT 参考。

图 4-1｜RLHF 与 DPO 的流程对比。DPO 之所以 2023 年一出现就爆红：训练管线从「四模型 + 高频推理」缩成「两模型 + 普通监督训练」，单卡也能跑。

2. 偏好数据：为什么是「比较」而不是「打分」

最自然的设计似乎是人给每个回答打个分（比如 1~10），直接当奖励训练。实际没人这么干，原因是人的绝对分数极不稳：今天心情好通通 8 分起，标注员 A 的 7 分等于标注员 B 的 9 分。但「这两个回答哪个更好」的比较判断又快又稳——人很擅长比较，很不擅长校准。所以偏好数据长这样：

字段例
prompt「解释什么是复利」
chosen（被选中）「复利指利息并入本金再生息……」——准确、有条理
rejected（被拒绝）「复利就是利滚利啦，反正很厉害就对了！」——含糊

标注员按统一指南（经典的 HHH：Helpful 有帮助、Honest 诚实、Harmless 无害）成对比较。代价是每次比较只有 1 bit 信息，需要海量标注——InstructGPT 用了约 3.3 万条比较，现代模型用量远超此数。标注太贵？下文第 7 节的 RLAIF 用 AI 打标解决。

3. Bradley-Terry 模型与 reward model 训练

3.1 把「偏好」翻译成「分数差」

要训打分器，先得约定「分数如何对应偏好概率」。Bradley-Terry（BT）模型给出最简洁的假设：

\[ P(y_w \succ y_l \mid x) = \sigma\big(r(x, y_w) - r(x, y_l)\big) \]

读法：回答 \(y_w\) 被人选中的概率，是两个分数之差过一个 sigmoid（第 0 讲的老朋友：把实数压到 0~1）。直觉：分差越大，偏好越一边倒；分差为 0，五五开。注意只有「差」有意义——给所有回答加 100 分不改变任何偏好，所以 BT 天然把 RM 的绝对分数定义成「相对量」。

手算感受（\(\Delta = r_w - r_l\)）：

分差 \(\Delta\)\(\sigma(\Delta)\)含义
00.500人觉得半斤八两
+10.731七三开
+20.881接近一边倒
+50.993毫无悬念

3.2 RM 的训练损失（手算）

标注数据里偏好是确定的（人已选好 \(y_w\)），训练目标就是「让模型预测的偏好概率贴近 1」，即最大化似然，等价于最小化：

\[ \mathcal{L}_{\mathrm{RM}} = -\log \sigma\big(r(x, y_w) - r(x, y_l)\big) \]

手算：当前 RM 打出分差 \(\Delta = +1\)，loss = \(-\ln\sigma(1) = -\ln 0.731 = 0.313\)。梯度方向：拉大分差——「选中者的分数往上提，拒绝者的往下压」，直到与标注一致；分差已经很大时（\(\Delta = 5\)，loss = 0.007），推力自动变小——不会为一条已经学对的样本过度用力。这个「sigmoid + 交叉熵」的组合和逻辑回归一模一样，RM 训练本质上是「对人类偏好做逻辑回归」。

RM 长什么样就是一个普通 transformer（通常从 SFT 模型初始化），把语言模型的输出头换成一个标量输出头：输入 (prompt, 回答)，输出一个数。参数量与基座同阶——这是「四模型架构」里第三条大汉。

4. reward hacking：后训练的头号大敌

RM 只是「人类口味的拟合」，必然有洞。而 RL 是一个不知疲倦的漏洞挖掘机：它不关心 RM 是否公平，只关心分数。Goodhart 定律一句话概括：「当一项测量变成优化目标，它就不再是好测量」。经典翻车案例：

RM 的可乘之洞模型学到的作弊姿势
标注员偏爱长回答（显得认真）车轱辘话、套模板凑长度——信息密度暴跌
偏爱礼貌、客气的开头满篇「作为一个 AI 助手，我很乐意……」的废话壳
偏爱自信、流畅的语气一本正经地胡说（幻觉被奖励强化）
顺着用户说话得分高谄媚（sycophancy）：用户说错的也点头称是

对抗手段（按常用程度）：KL 缰绳（第 2 讲——不许离人味太远）、多 RM 投票/集成、定期人工抽查盲评、以及第 5 讲的釜底抽薪——能用程序判分的领域就不用 RM。

诊断经验：训练中 reward 曲线「稳定上升」从来不是好消息的全部——必须同时盯人工评测和 KL。reward 涨 + 人工评测平或跌 = 典型 hacking 信号； reward 涨 + KL 爆炸 = 正在跑飞。

5. DPO：把 RL 循环折叠成一个监督损失

5.1 出发点：KL 约束下的最优策略有解析解

RLHF 的优化目标（第 2 讲的缰绳 + 奖励合体）：

\[ \max_\pi \ \ \mathbb{E}_{y \sim \pi}\big[r(x,y)\big] - \beta\, D_{\mathrm{KL}}\big(\pi \,\|\, \pi_{\mathrm{ref}}\big) \]

这个问题有解析解（推导细节可跳过，记住形态即可）：

\[ \pi^*(y \mid x) = \frac{1}{Z(x)}\, \pi_{\mathrm{ref}}(y \mid x)\, e^{r(x,y)/\beta} \]

直觉：最优策略 = 参考模型按奖励做指数加权——奖励高的回答，概率按 \(e^{r/\beta}\) 抬升；\(\beta\) 越小抬升越猛（缰绳越松）。\(Z(x)\) 是归一化常数（让概率加起来等于 1），它依赖全部回答、算不出来——这个「算不出来的 \(Z\)」曾经堵死了这条路。

5.2 关键一步：用「策略」反解「奖励」，Z 消失了

把上式移项反解（两边取对数）：

\[ r(x,y) = \beta \log \frac{\pi^*(y \mid x)}{\pi_{\mathrm{ref}}(y \mid x)} + \beta \log Z(x) \]

这意味着：最优的奖励函数，可以直接从「策略相对参考模型的概率变化」里读出来。现在把它代入 BT 公式——\(P = \sigma(r_w - r_l)\)，而两个回答相减时，\(\beta\log Z(x)\) 是同一项，减没了：

\[ P(y_w \succ y_l) = \sigma\Big(\beta \Big[\underbrace{\log \tfrac{\pi(y_w)}{\pi_{\mathrm{ref}}(y_w)}}_{\text{chosen 相对涨了多少}} - \underbrace{\log \tfrac{\pi(y_l)}{\pi_{\mathrm{ref}}(y_l)}}_{\text{rejected 相对涨了多少}}\Big]\Big) \]

于是得到 DPO 损失——长得和 RM 损失一模一样，只是把「RM 的分数」换成了「策略自己的相对概率变化」（术语叫隐式奖励）：

\[ \mathcal{L}_{\mathrm{DPO}} = -\log \sigma\Big(\beta \Big[\big(\log\pi(y_w) - \log\pi_{\mathrm{ref}}(y_w)\big) - \big(\log\pi(y_l) - \log\pi_{\mathrm{ref}}(y_l)\big)\Big]\Big) \]

训练循环就是普通监督学习：取偏好对 → 算两遍前向（π 和 π_ref）→ 这个 loss → 反向传播。没有 rollout、没有 RM、没有 critic、没有 PPO。代价：需要一个冻结的 π_ref（两模型架构）。

5.3 手算一次 DPO 损失

设定 \(\beta = 0.1\)；chosen 的 \(\log\pi = -20\)（参考模型给 −22，相对涨了 2）；rejected 的 \(\log\pi = -25\)（参考给 −22，相对跌了 3）：

步骤算式结果
chosen 隐式奖励\(\beta \times (-20 - (-22)) = 0.1 \times 2\)\(+0.2\)
rejected 隐式奖励\(\beta \times (-25 - (-22)) = 0.1 \times ({-}3)\)\(-0.3\)
sigmoid 自变量\(0.2 - (-0.3)\)\(+0.5\)
预测的偏好概率\(\sigma(0.5)\)\(0.622\)
DPO loss\(-\ln 0.622\)0.474

梯度方向：继续拉大「chosen 相对涨幅 − rejected 相对涨幅」这个差值，且差值越大推力越小（自适应刹车）。眼熟吗？chosen 相当于带正优势的样本、rejected 相当于带负优势的样本——DPO 的梯度就是第 1 讲 REINFORCE 的「一正一负」样本对，只是它不采样、直接用给定的偏好对。

5.4 DPO 的软肋：只看得见「相对差」

手算里藏着一个陷阱：loss 只依赖两者隐式奖励的差。如果优化器把两个回答的概率同时拉高同样多（都涨 1 nat），差值不变、loss 不变——DPO 完全无感。理论上无碍（相对排序对就行），实践中有症状：chosen 的绝对概率可能不升反降（模型整体概率质量外流），输出变得发散。这是 DPO 相对 PPO 最常被诟病的一点，也催生了 IPO、KTO 等修补变体（思路一句话：给绝对概率加约束或改损失形状，本系列不展开）。

6. DPO vs PPO：怎么选

PPO / RLHF（第 3 讲）DPO（本讲）
数据偏好数据训 RM，奖励在训练中在线打分偏好数据一次性离线消费
训练中是否生成回答是（rollout 占大头，需要推理引擎）否（纯监督式，像 SFT）
模型数4（actor、critic、ref、RM）2（π、π_ref）
工程难度 / 成本高：分布式 + 推理引擎 + 四模型协同低：单卡可跑小规模
上限在线探索：可超越数据分布（AlphaGo 式）被偏好数据封顶：分布外的能力练不出来
稳定性超参敏感、易 hacking、难诊断稳、好复现、但有相对性软肋
典型用途推理能力、Agent、大规模对齐中小规模偏好对齐、快速迭代、风格调整
一句话分界DPO 是「比较级模仿」——从人给的偏好对里挤信息；PPO 是「真试错」——模型自己生成、自己挨分。只要目标超越了人类示范的边界（数学、代码、长程任务），就必须回到在线 RL。这正是下一讲的主角：RLVR + GRPO。

7. RLAIF：让 AI 当标注员

人类标注贵且慢，于是把第 2 节的标注员换成 AI：给一个强模型一组原则（Anthropic 的叫法：constitution），让它按原则对回答做偏好标注——RLAIF（A = AI feedback）。Anthropic 的 Constitutional AI 把它玩成完整闭环：先让模型自我批评、按原则修改自己的回答，再用 AI 按原则标注偏好，训 RM，跑 RL。优点：便宜、量大、原则可审计；隐患：AI 标注员的系统性口味偏差会被原样学进 RM。实践中常见「人机混标」：AI 粗筛 + 人精标争议样本。

8. 自查清单

下面 9 个问题都能不假思索地回答，就可以进入第 5 讲：

  1. 偏好数据为什么用比较而不是绝对打分？（答：人擅长比较、不擅长校准；绝对分数跨人跨天漂移）
  2. BT 模型的公式？分差 +2 对应的偏好概率？（答：\(P=\sigma(r_w - r_l)\)；0.881）
  3. RM 的损失与梯度方向？（答：\(-\log\sigma(\Delta r)\)；拉大分差，学对的样本推力自动变小）
  4. Goodhart 定律 + 两个 reward hacking 实例？（答：测量变目标就不再是好测量；长度注水、谄媚……）
  5. KL 约束下的最优策略形态？（答：\(\pi^* \propto \pi_{\mathrm{ref}}\, e^{r/\beta}\)——参考模型的指数奖励加权）
  6. DPO 里 \(Z\) 为什么能消掉？（答：它只依赖 prompt \(x\)，chosen 与 rejected 的分数相减时同一项抵消）
  7. DPO 的「隐式奖励」是什么？（答：\(\beta\log(\pi/\pi_{\mathrm{ref}})\)，从策略相对参考的变化里读出的奖励）
  8. 手算：\(\beta=0.1\)、chosen 相对 +2、rejected 相对 −3，loss 多少？（答：\(\sigma(0.5)=0.622\)，loss 0.474）
  9. DPO 的相对性软肋与「必须回到在线 RL」的分界？（答：只约束相对差，chosen 绝对概率可能降；要超越数据分布（数学/代码/长程任务）必须在线试错）
