系列：RL 训练工程师零基础七讲（本篇为第 0 讲，零数学，只搭全景、定地图）

读者假设：不需要任何机器学习背景；知道 ChatGPT 这类模型「输入文字、输出文字」就够了。所有行话第一次出现都会解释。

系列目标：读完七讲，你能看懂 RL 训练工程师的日常对话、跑通第一个 RL 训练 demo，并知道下一步该深入哪里。

本讲目标：在进入任何数学之前，先回答四个问题：① 一个 LLM 是怎么被「造」出来的——预训练、SFT、RL 三个阶段各干什么；② 为什么有了 SFT 还需要 RL——模仿学习和试错学习差在哪；③ RLHF、RLVR、reward model、rollout 这些天天出现的名词到底指什么；④ RL 训练工程师每天的工作长什么样、本系列怎么带你入门。这一讲没有任何公式，但每个概念都会在后面某一讲展开——把它当作系列的总目录。

1. 一个 LLM 的一生：三个阶段

市面上的对话模型（GPT、DeepSeek、Qwen……）都不是一次训练出来的，而是三棒接力。用「学做菜」来类比，三棒分别是：

  • 预训练（pretraining）：读遍全世界的菜谱、食材科普、食客点评——把语言和知识塞进模型。它学会了「接龙」：给半句话，预测下一个字大概率是什么。
  • SFT（supervised fine-tuning，监督微调）：看师傅做菜——喂给模型几万到几百万条人写的高质量问答示范，让它模仿「被提问时该怎么回应」。
  • RL（reinforcement learning，强化学习）：自己上手做菜、请试吃员打分——模型自己生成大量回答，每个回答被打一个分数，分数高的回答今后更可能出现，分数低的被压制。

图 0-1｜LLM 训练三阶段。注意第③格的数据来源变了：示范数据是人写的，RL 的回答是模型自己生成的——这个区别是后面一切故事的开端。

术语预训练之后的所有阶段（SFT + RL）合称后训练（post-training），也叫对齐（alignment）。招聘里说的「RL 训练工程师 / 后训练算法工程师」，主战场就是第三棒，兼管第二棒。

2. SFT 已经很好了，为什么还要 RL？

这是整个系列最重要的一问。SFT（模仿学习）有三个结构性的天花板，恰好是 RL 能补的：

2.1 SFT 只知道「答案长什么样」，不知道「答案好不好」

SFT 的训练信号是「照着这个答案说」。它见过一百万个标准答案，但没被告诉过：错答案错在哪、好答案好在哪、好和更好之间差多少。就像只看师傅的成品菜，从没被试吃员点评过——点评本身就是信息，而且是模仿给不了的信息。

2.2 SFT 的上限被示范数据封死，RL 可以超越示范

模仿的上限就是示范本身。最著名的例子：AlphaGo 的第 37 手——那步棋人类几千年围棋史里从没人下过，胜率评估一度接近 0，事后被证明是妙手。它下得出来，恰恰因为它不是学人类棋谱（模仿），而是自己下、自己赢、自己总结（试错）。LLM 的 RL 同理：数学题的新解法、代码的新写法，可以来自模型自己的探索，而不必先存在于任何人的示范里。

2.3 训练时照抄标准答案，考试时只能照抄自己——SFT 的「脱轨」问题

SFT 训练时，模型永远在「标准答案的上文」里预测下一个词——每一步都有人纠偏。可推理时，上文是它自己刚生成的：一旦某一步说岔了，它是在自己造成的岔路上继续预测，没人拉回来，而且训练时根本没见过这种岔路。RL 没有这个错位：训练时模型就在走自己生成的路，好的坏的都经历过、都被打过分——训练条件和考试条件一致。

直觉学开车：SFT 是看教学视频（看得到正确操作，摸不到方向盘）；RL 是真上车（开歪了自己知道、被扣分，下次调整）。视频看得再多，也要上路才能学会——尤其是「从歪的地方拉回来」这件事，视频里根本看不到。

3. RL 问题的三个零件：策略、奖励、更新

把第三阶段抽象到最简，只有三个零件在循环：

  1. 策略（policy）：就是模型本身。给它一个问题，它输出的是「每个候选回答的概率」——回答不是背出来的，是按概率采样出来的。同一个问题问两遍，答案可能不同，因为采样有随机性。
  2. 奖励（reward）：对一次生成的回答打一个分。打分的可以是程序（数学题对答案、代码跑测试）、可以是学出来的打分模型，也可以是人。它是 RL 唯一的目标信号。
  3. 更新：根据分数调整模型参数——高分的回答，下次遇到类似问题更可能出现；低分的被压制。仅此而已，所有 RL 算法（PPO、GRPO……）都是这句话的不同实现方式。

图 0-2｜RL 训练的最小闭环。蓝色的模型是唯一被更新的东西；绿色打分环节怎么实现（人 / 规则 / 打分模型），决定了是 RLHF 还是 RLVR——第 5 节展开。

换个脑子预训练和 SFT 的「训练数据」是人准备好的、固定的；RL 的训练数据（回答）是模型现场生成的，每一圈都在变。所以 RL 训练系统天生比普通训练多一条「高频推理」的生产线——这是第 6 讲系统工程的主线，也是这个岗位偏工程的根源。

5. RLHF vs RLVR：奖励从哪来，决定了练出什么

图 0-2 里唯一留白的环节是「打分」。当前工业界就两条路线，这也几乎是近三年 LLM 后训练的全部主线：

RLHF 路线（2022~）RLVR 路线（2024~）
奖励来源人类偏好数据 → 训练一个打分模型（RM），RM 模仿人的口味程序自动判分：数学对标准答案、代码跑测试、格式查正则
擅长什么没有标准答案的领域：有帮助度、语气、安全性、写作有标准答案的领域：数学、代码、Agent 任务、逻辑推理
主要风险RM 只是「人味的拟合」，会被钻空子（reward hacking）：学会写长话、学会谄媚verifier 本身写得糙也会被钻空子（格式分吃掉正确分）
代表工作InstructGPT、ChatGPT、Constitutional AIo1、DeepSeek-R1（GRPO）、各家推理模型

时间线帮你串一下：2022 年 InstructGPT 论文确立了 RLHF 三段式，ChatGPT 把它带火；2023-2024 年 DPO 等简化算法流行（嫌 PPO 难跑）；2024 年底 o1 展示「大规模 RL 练推理」的威力，2025 年初 DeepSeek-R1 开源复现，RLVR + GRPO 一跃成为开源社区标配。如今两条腿走路：RLVR 管数学/代码/Agent，RLHF（RM）管开放域体验——训练框架是同一套，只是打分函数不同。这也是为什么本系列从第 1 讲起先打底子（策略梯度、PPO），再分别进入两条路线（第 4、5 讲）。

6. RL 训练工程师的日常长什么样

把光环摘掉，这个岗位一周的时间大致这样分布（比例是量级感受，非精确统计）：

工作块具体在干什么时间占比
跑实验、看曲线改 reward 函数 / 超参 / 数据配比，起一个训练，盯 reward 均值、KL、熵、回答长度四条曲线，判断「在学、崩了、还是躺平」~40%
系统工程让训练跑得快（rollout 吞吐、权重同步、多机并行）且稳（断点续训、失败重跑、显存爆了怎么办）~40%
奖励与数据写 verifier（数学判分、代码测试沙箱）、构建 prompt 池、按难度分层、清洗脏数据~10%
读论文、复现新算法（DAPO 这类）出来，读明白、在自家框架里复现出论文曲线~10%

注意前两行：一半以上的时间在「让训练跑得快、跑得稳」，而不是发明算法。这就是为什么这个岗位叫「训练工程师」而不叫「RL 研究员」——对工程能力（Python/PyTorch/分布式）的要求，往往高于对数学天赋的要求。这既是坏消息（要补的工程课不少），也是好消息（工程是练出来的，不挑出身）。第 6 讲会给一条从零开始的具体路线。

看招聘 JD 时常见「熟悉 verl / OpenRLHF / TRL 之一」「了解 vLLM」「有 FSDP/Megatron 经验」——对应的就是上面表格里的工程行；「熟悉 PPO/GRPO 原理」对应的是本系列第 1~5 讲的内容。

8. 自查清单

下面 8 个问题都能答上来，第 0 讲就过关了：

  1. 三个训练阶段各自的学习信号是什么？（答：预测下一个词 / 模仿示范答案 / 奖励打分）
  2. SFT 和 RL 最本质的区别？（答：学习信号来自「标准答案」还是「对生成结果的打分」；回答是模型自己采样的）
  3. 为什么说 RL 能超越示范数据？（答：训练信号是「结果好坏」而非「照着谁说」，模型可以探索出示范里没有的解法——AlphaGo 第 37 手）
  4. rollout 指什么？（答：让当前模型实际生成一遍回答；也是 RL 训练数据的来源）
  5. RLHF 和 RLVR 的奖励分别从哪来？（答：从偏好数据学出的打分模型 / 程序判分如对答案、跑测试）
  6. reference model 是干什么的？（答：冻结的锚，用 KL 散度拴住训练中的模型，防止为刷分跑飞）
  7. reward model 和 verifier 的区别？（答：学出来的打分器 vs 写死的程序判分器；前者像人、后者像裁判）
  8. 这个岗位过半时间在干什么？（答：让训练跑得快、跑得稳的工程活，而不是发明算法）
