RL 训练工程师零基础七讲 · 第 2 讲：把 LLM 接上 RL

0 全景图 1 策略梯度 2 LLM×RL 3 PPO 4 RLHF·DPO 5 RLVR·GRPO 6 系统与实战 番外 SC

本讲定位：把第 1 讲的「一次动作」放大成「生成一整段回答」——语言模型正式接入 RL。第 3~5 讲的所有算法都建立在本讲的对应关系上。

前置要求：读完第 1 讲（REINFORCE、\(e_a - \pi\)、baseline）。本讲新增的数学只有两小块：对数概率求和、KL 散度，都从零手算。

本讲目标：回答「语言模型怎么就成了 RL 问题」。核心是三组对应：token 是动作（词表几万选一）、上文是状态、一整条回答共享末尾一个奖励。由此得到 LLM 版 REINFORCE：对每个 token 的 log 概率求梯度、全部乘同一个奖励。然后补三件 LLM 特有的装备：① 稀疏延迟奖励带来的「功劳记账」难题（第 3 讲解决）；② KL 散度——拴住模型防止为刷分跑飞的缰绳（含工程里真实使用的 k3 估计器）；③ 温度——控制探索的旋钮。

1. 三组对应关系：从老虎机到语言模型

第 1 讲的最小场景里，模型做一次选择、拿一个分。语言模型把这个动作串成长链。逐项对照：

RL 概念第 1 讲（标题生成器）LLM 的 RL
状态（此刻的处境）没有（一步定胜负）prompt + 已经生成出的那几个 token（前缀）
动作（一次选择）3 种标题风格从词表（几万~十几万）里挑下一个 token
策略softmax over 3 个分数softmax over 整个词表——就是模型最后一层输出
轨迹（完整一次尝试）单次选择从 prompt 出发，逐 token 采样，直到结束符（记作 <eos>）
奖励点击率回答全部生成完之后打一个分（verifier 判分 / RM 打分 / 人评）
没有新模型注意：LLM 的 RL 不需要任何新架构。模型还是那个 next-token 预测器，只是训练目标变了——第 1 讲是「这个 token 该不该出」（SFT 视角），现在是「出了这个 token，最后得分高不高」（RL 视角）。模型、前向、反向传播全部复用。

2. 一条回答的「总打分」：对数概率

RL 优化的是「回答被选中的概率」。一条回答是一串 token，它的总概率是每步概率的连乘（概率的链式法则）；连乘在计算上不好处理（几百个小于 1 的数乘起来直接下溢成 0），所以一律取对数——连乘变连加：

\[ \log \pi(\text{回答} \mid \text{prompt}) = \sum_t \log \pi(\text{token}_t \mid \text{前缀}_t) \]

手算一个完整例子。迷你词表只有 5 个词：{很, 不, 热, 好, <eos>}。prompt 是「今天天气」。模型采出两条回答，把每步概率和对数概率都列出来：

回答甲「很好」概率\(\log\pi\)回答乙「不热」概率\(\log\pi\)
出「很」0.6−0.511出「不」0.2−1.609
出「好」0.5−0.693出「热」0.3−1.204
出 <eos>0.5−0.693出 <eos>0.5−0.693
合计\(0.6{\times}0.5{\times}0.5 = 0.15\)−1.897合计\(0.2{\times}0.3{\times}0.5 = 0.03\)−3.506

两个读数：甲被采出的概率是乙的 5 倍（0.15 vs 0.03）；log 空间里这个差距就是三个 \(\log\pi\) 的逐项差之和。整份训练要做的就是挪动这两个数——RL 说的是：甲得分高就把 −1.897 往上推（概率变大），乙得分低就把 −3.506 往下压。

3. 轨迹版 REINFORCE：LLM 的 RL 梯度雏形

把第 1 讲的更新规则里的「一个动作」替换成「一整条回答」，直接得到：

\[ \nabla J = \mathbb{E}\Big[\, R \cdot \sum_t \nabla \log \pi(\text{token}_t \mid \text{前缀}_t) \,\Big] \]

大白话：一整条回答的所有 token 共享同一个奖励 \(R\)；奖励好，整条链上每个 token 的 log 概率一起推高；奖励差，整条链一起压低。第 1 讲的 \(e_a - \pi\) 在这里不要求你手写了——「对每个 token 的 log 概率求梯度」由深度学习框架的自动微分代劳，你只需要在 loss 里把它组合出来：

for step in range(num_steps):
    prompts = sample_batch_of_questions()          # 1. 取一批问题
    answers = model.generate(prompts)              # 2. rollout：模型自己采样回答
    rewards = [verify(q, a) for q, a in zip(prompts, answers)]  # 3. 打分
    # 4. REINFORCE 损失：整条回答的 log 概率 × 奖励（取负 = 梯度上升）
    logprob = sum_logprob(model, prompts, answers) # Σ_t log π(token_t)
    loss = -(rewards * logprob).mean()             # baseline/优势在第 3 讲加入
    loss.backward()
    optimizer.step()

和 SFT 的 loss 对比一眼见底：SFT 是「−log π(标准答案)」（照着抄），RL 是「−R × log π(自己的回答)」（自己写、按分记账）。训练数据从「人给的答案」换成了「模型采的答案」，监督信号从「答案本身」换成了「一个标量分」。

图 2-1｜LLM 的 RL 最小闭环。蓝色 token 盒是「动作」，绿色盒是「奖励」；每个 token 的 log 概率是求梯度的对象，奖励是它的权重。

4. 难题一：稀疏与延迟——功劳怎么记？

图 2-1 也暴露了 LLM RL 最深的一道难题：几百个 token，只有末尾一个奖励。术语叫稀疏（就一个数）与延迟（生成完才知道）。后果是「功劳记账」（credit assignment）失灵：

  • 数学题的回答推了十步公式、最后答案算错——整条链被同一个负奖励压低，包括那些完全正确的中间步骤。
  • 反过来，答案蒙对了但推理全靠跳步——整条链被加强，跳步的习惯也被一起加强。

也就是说，「\(R\) 乘到每个 token 头上」是个粗糙的一刀切：好链条里的坏 token、坏链条里的好 token，被一视同仁。怎么把功劳细分子到每个 token，是 RL 的核心难题，本系列遇到三次、每次用不同的工具糊上一格：

工具思路哪讲
价值网络 + GAE学一个「预测未来得分」的网络，用它把整条链的 R 拆成每步的优势第 3 讲（PPO）
组内对比同一个问题采多条回答，互相比较——整条回答之间比高下，不细究 token第 5 讲（GRPO）
过程奖励（PRM）对每个推理步骤单独打分（代价：又需要一个打分模型）第 5 讲末尾（点到为止）
要建立一个诚实的预期：当前工业界主流（GRPO 一族）在 per-token 记账上仍然粗糙——大多数实现就是「整条回答共享一个组内优势」。细粒度功劳分配是公认的开放问题，论文年年有，尚未出现公认的完胜方案。

5. 难题二：模型会跑飞——KL 散度当缰绳

5.1 为什么需要缰绳

只盯着奖励优化有一个必然结局：找到奖励函数的漏洞。真实案例（RLHF 时代反复出现）：奖励模型偏爱礼貌开头，模型就学会每句都以「作为一个 AI 助手，我很乐意……」开场；偏爱长回答，模型就学会车轱辘话来回说；甚至输出乱码——只要打分模型（而非人类）觉得好。这类「钻空子得分」的行为叫 reward hacking，是后训练的头号大敌（第 4、5 讲还会回来）。

通用的防跑飞手段：在「被冻结的出发模型」旁边拴一根绳。出发模型就是 SFT 之后的那个模型，术语叫参考模型（reference model，\(\pi_{\mathrm{ref}}\)）——它不训练、只做对比。绳的松紧用 KL 散度度量。

5.2 KL 散度从零讲

KL 散度衡量「两个概率分布差多远」：

\[ D_{\mathrm{KL}}(P \,\|\, Q) = \sum_x P(x) \log \frac{P(x)}{Q(x)} \]

读法：按 \(P\) 的权重，平均一下「\(P\) 认为的可能性 vs \(Q\) 认为的可能性」的对数比。若两个分布完全相同，比值处处为 1，log 为 0，KL = 0；分布越岔越远，KL 越大；KL 永远 ≥ 0。

手算。设 \(P = [0.6, 0.3, 0.1]\)，\(Q = [0.3, 0.3, 0.4]\)：

分量\(P(x)\log\frac{P(x)}{Q(x)}\)数值
\(x_1\)\(0.6 \times \ln(0.6/0.3) = 0.6 \times \ln 2\)\(+0.4159\)
\(x_2\)\(0.3 \times \ln(0.3/0.3) = 0.3 \times 0\)\(0\)
\(x_3\)\(0.1 \times \ln(0.1/0.4) = 0.1 \times \ln 0.25\)\(-0.1386\)
KL(P‖Q)求和0.2773

反着算一遍：KL(Q‖P) = \(0.3\ln 0.5 + 0 + 0.4\ln 4 = -0.2079 + 0.5545 = 0.3466\)。不对称——KL(P‖Q) ≠ KL(Q‖P)，这是它和「距离」最大的区别（所以叫「散度」）。哪个方向是「正着」？取决于你想让谁的权重做平均；本系列固定用 KL(π‖πref)：按当前模型的输出分布加权，衡量「相对参考模型，我把概率质量挪了多少」。

5.3 在训练里怎么用：目标函数与逐 token 惩罚

RLHF 的优化目标（InstructGPT 写法）就是「奖励 + 缰绳」：

\[ \max_\theta\ \ \mathbb{E}\big[R(x, y)\big] - \beta \cdot D_{\mathrm{KL}}\big(\pi_\theta \,\|\, \pi_{\mathrm{ref}}\big) \]

实现上通常把 KL 拆成每个 token 一小笔罚款加进奖励里（第 \(t\) 个 token 处 reward \(\mathrel{-}= \beta \cdot \mathrm{KL}_t\)），这样优势估计能逐 token 地感知「我离参考模型多远了」。\(\beta\) 是缰绳松紧：太小会跑飞，太大模型躺平不敢动。KL 曲线是训练监控的必看曲线——它突然飙升，几乎总是出事的第一个信号（第 6 讲调试清单里会再见到它）。

5.4 工程细节：k3 估计器

精确算每个 token 的 KL 要把整个词表的分布都拿出来比，太贵。实践（TRL、veRL 等框架的默认实现）用一个抽样估计——对 rollout 里实际采出的每个 token，记 \(\delta = \log\pi_{\mathrm{ref}} - \log\pi\)（两个模型对该 token 的对数概率之差，两者本来就要算，白拿），然后：

\[ \mathrm{KL}_t \approx \underbrace{r - \log r - 1}_{k_3}, \qquad r = \frac{\pi_{\mathrm{ref}}}{\pi} = e^{\delta} \]

两个好性质：① 无偏（按当前策略采样时，它的期望恰等于真实 KL——Schulman 2016 年的博客给出，也是它成为默认的原因）；② 永远 ≥ 0：令 \(f(t) = t - \ln t - 1\)，\(f(1) = 0\) 且它是凸函数，所以对一切 \(t > 0\) 有 \(f(t) \ge 0\)。手算一遍（\(\delta = -0.5\)，即当前模型比参考模型更看好这个 token）：

步骤算式结果
比值 r\(\delta = \log\pi_{\mathrm{ref}} - \log\pi = -0.5\)，\(r = e^{\delta} = e^{-0.5}\)\(r = 0.6065\)
k3\(r - \ln r - 1 = 0.6065 - (-0.5) - 1\)0.1065 ≥ 0 ✓

（对照：取 \(-\delta = \log\pi - \log\pi_{\mathrm{ref}}\) 也能无偏估计 KL（k1 形式），但单个样本上它可以为负——「罚款为负」等于倒贴奖励，很怪，所以工程上用恒非负的 k3。）

记住这张牌「KL(π‖πref) 缰绳」在后面出现两次：第 3 讲它作为 PPO 的第三个组成部分（连着 reference model 一起撑爆显存——这就是 GRPO 要改良的对象）；第 5 讲 GRPO 目标函数里它的 k3 形式直接出场。

6. 探索的旋钮：温度

第 1 讲说过，RL 的回答是采样出来的，采样要有随机性才有多样性、才有探索。控制随机性的旋钮是温度 \(T\)：把 softmax 改成 \(\pi \propto e^{z/T}\)。\(T\) 越小分布越尖（确定性强、探索少），越大越平（花样多、质量散）。手算感受一下，取 \(z = [2.0,\ 1.0,\ 0.5]\)：

温度有效分数 \(z/T\)softmax 结果手感
\(T = 0.5\)[4, 2, 1][0.844, 0.114, 0.042]近乎笃定：几乎总是选第一个（日常使用、输出稳定）
\(T = 1.0\)[2, 1, 0.5][0.628, 0.231, 0.140]模型的「本意」（RL 训练采样常用）
\(T = 2.0\)[1, 0.5, 0.25][0.481, 0.292, 0.227]刻意抹平：多探索（训练初期/多样性需求）

另外两个常用采样截断，一句话带过：top-k（只在分数最高的 k 个候选里采样）和 top-p（只在累计概率到 p 的小集合里采样）——它们是把长尾低质量候选剪掉的工程手段，不改变本讲的任何数学。

训练时温度为什么通常取 1（即「模型的原始分布」）？因为 RL 的比较逻辑建立在「按模型真实倾向采样」上：温度改变分布，就改变了优势的定义域；而且第 5 讲会看到，训练久了模型分布自发变尖（熵坍缩），多样性本身是需要守护的资产。推理（给用户用）时再按产品需要调低。

7. 拼起来：一个完整的 LLM-RL 训练步

把本讲全部零件组装，得到「第 0 讲图 0-2」的工程版说明书。一次训练步依次发生：

  1. 取 prompt：从任务池抽一批问题（第 5 讲会讲 prompt 难度分层）；
  2. rollout：当前模型按温度采样，每个问题生成回答（推理引擎，第 6 讲的主角）；
  3. 打分：verifier / RM 给每条回答一个 \(R\)（绿盒）；
  4. 算优势：给 \(R\) 减 baseline（第 1 讲），细化到 token（第 3 讲 GAE 或第 5 讲组内归一化）；
  5. 更新：loss = −优势 × log π（本讲第 3 节）+ KL 罚款（第 5 节），反向传播更新参数。

第 3 讲开始，我们给第 4、5 步装上精密仪表——那就是 PPO。

8. 自查清单

下面 8 个问题都能不假思索地回答，就可以进入第 3 讲：

  1. LLM 的 RL 里，状态、动作、奖励分别是什么？（答：前缀 / 下一个 token / 回答结束后的打分）
  2. 一条回答被选中的概率怎么算？（答：逐 token 概率连乘，log 空间为求和：\(\sum_t \log\pi\)）
  3. 轨迹版 REINFORCE 对什么求梯度、权重是什么？（答：每个 token 的 \(\nabla\log\pi\)，全部乘同一个 \(R\)）
  4. RL 的 loss 和 SFT 的 loss 本质区别？（答：SFT 是 −log π(标准答案)；RL 是 −R×log π(自己采的回答)，监督信号从「答案」变「分数」）
  5. 什么是 credit assignment 难题？（答：整条链共享一个末尾奖励，无法区分链上哪个 token 立功/闯祸）
  6. KL 散度的定义与两个关键性质？（答：\(\sum P\log(P/Q)\)；不对称、恒 ≥ 0、相同则为 0）
  7. 为什么需要 reference model？KL 缰绳太紧太松各什么症状？（答：防 reward hacking / 跑飞；太松跑飞、太紧躺平）
  8. k3 估计器的公式和它 ≥ 0 的原因？（答：\(r - \ln r - 1\)，\(r = \pi_{\mathrm{ref}}/\pi\)；\(t - \ln t - 1\) 在 \(t=1\) 取最小值 0）
下一篇第 3 讲：PPO 精讲——REINFORCE 有两大浪费：数据用一次就扔（更新完策略就变了），功劳记账全靠一个末尾奖励。PPO 用「重要性采样」回收旧数据、用「裁剪」防止更新过猛、用「GAE」把末尾奖励精细拆分到每个 token。手算逐分支验证 clip 的行为，手算一遍 GAE，最后看清那个撑爆显存的「四模型架构」——以及它如何孕育出第 5 讲的 GRPO。
