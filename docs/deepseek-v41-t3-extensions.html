TL;DR：DeepSeek-V4.1-Flash 的 KV cache 压缩由 CED + CSA2 + SWA Bounded Replay 三条主线完成（第 1、2 讲），而本讲的四个「架构扩展」是主线之外的加/改件：① Single-Pass mHC 把 mHC 残差流的「输入混合系数」推迟一个 block 使用，解开了 kernel 之间的串行依赖，配合 Mega-mHC 部署内核把激活访存流量从 \((4n+4)d\) 砍到 \((2n+2)d\)（正好减半、达到理论下界）；② Engram 挂上 196B 参数的「稀疏查表记忆模块」（2/3/4-gram 多头哈希查表，FP8 存储），把「死记硬背」从主干计算里解耦出去；③ DSpark 是预训练后单独训练的投机解码模块：一次前向并行产出 5 个草稿位置，用置信度调度验证长度；④ FP4 Main KV Cache 把主 KV cache 从 V4 的 FP8 压到 4-bit（E2M1 + 每 16 通道一个 E4M3 scale，去掉了 NVFP4 的二级全局 scale），靠对数值范围的严格论证保精度，主 KV 存储几乎减半。四者论文均只给「性能几乎无损」的定性结论，未附单独消融表。

0. 先搞清楚「架构扩展」是什么定位

读这一讲之前，先把四个组件在论文里的身份摆正。DeepSeek-V4.1-Flash 的头号目标是压 KV cache——先补一句小白解释：模型在生成文字时，每处理一个 token 都要留下中间计算结果（Key/Value 向量），供后面的 token「回看」上文，这堆留存的向量就是 KV cache；上下文越长它越大，是长文本推理最吃显存的部分。

论文 §1 把压缩主线归纳为三个层面：架构层是 CED（因果编码器-解码器，让解码器的全局 KV 从编码器末层投影出来）+ CSA2（跨层共享全局 KV 与 Top-K 索引）；精度层是 FP4 全局 KV cache；部署层是 SWA Bounded Replay（不再持久化滑窗 KV，用少量重算换存储）。这三条是「主角」。

而 §2.4 的四个组件，论文的定位原话是：「Complementing CED and CSA2, we further streamline the original DeepSeek-V4 architecture」——即在主线之外进一步精简/增强原架构：mHC 升级为 Single-Pass 版（省访存）、集成 Engram（增强能力）、引入 DSpark（加速解码）、主 KV 压到 FP4（省存储）。论文 §2.1 明确这四者都属于 V4.1-Flash 的正式组成部分（图 3 的总体架构图明确画出了 Single-Pass mHC、Engram、DSpark），并未描述任何「可选开关」；所谓「可能并非全开」的猜测，唯一依据是 DSpark 在预训练之后才单独训练、Mega-mHC 单内核只用于部署（训练侧仍保留多 kernel 实现），论文并未说它们可以关闭——这是论文的原文立场，本讲照实呈现。

1. Single-Pass mHC：两趟变一趟的「残差流水线」

1.1 背景一分钟：mHC 原版是什么

标准 Transformer 的残差连接（residual connection，即「每层的输出直接加回输入」这条主干道，像高速公路的主车道）只有一条 \(d\) 维的信息流。Hyper-Connections（HC）把它加宽成 \(n\) 条并行流（\(n \times d\)），用一个「读出」映射从 n 条流里调出本层的输入、一个「写回」映射把输出写回去、一个 \(n\times n\) 的「流间混合」矩阵管 n 条流互相串门。DeepSeek 的 mHC（流形约束超连接）在 HC 基础上把流间混合矩阵约束成「双随机矩阵」（行和 = 列和 = 1），解决 HC 复合增益失控导致的训练不稳定。背景详解见姊妹篇，此处只需记住：mHC 在 V4 里全面启用，本讲配置为 \(n=4\) 条流。

记号对应关系要先说清（两篇论文记号不同）：mHC 论文里的三个映射 \(H^{pre}\)（读出）、\(H^{post}\)（写回）、\(H^{res}\)（流间混合），在 V4.1 论文式 (2) 里分别写作 \(A\)（\(\mathbb{R}^{1\times n}\)，读出/输入混合）、\(C\)（\(\mathbb{R}^{n\times 1}\)，写回）、\(B\)（\(\mathbb{R}^{n\times n}\)，流间混合）。本讲统一用 V4.1 论文的 \(A/B/C\)。

1.2 动机：FLOPs 不贵，访存才贵

mHC 的问题不在计算量（n=4 的系数 FLOPs 可忽略），而在激活访存——训练/推理时把中间激活在显存（HBM）里搬进搬出的字节数。现代芯片算力增长远快于显存带宽，「搬数据」常常比「算数据」更耗时，所以激活的读写字节数是实打实的性能账。

V4.1 论文先立了一个理论标尺：mHC 下相邻两个 block 的流更新，理想情况是一次映射 \((X_{l-1}, Y_{l-1}) \to (X_l, \hat{X}_l)\)，需要读 \((n+1)d\)（n 条旧流 + 1 份层输出）、写 \((n+1)d\)，所以下界是 \((2n+2)d\)。\(\hat{X}_l = A_l X_l\) 是当前 block 的层输入，\(Y_{l-1} = F_{l-1}(\hat{X}_{l-1})\) 是上一 block 的输出（\(F_l\) 是 block 内的注意力/MoE 等层函数）。

但 V4 的实际实现是多趟（multi-pass）：由于公式里存在数据依赖，三个 kernel（kernel 即 GPU 上一次成批执行的融合计算单元，起 kernel 有启动与读写开销）必须串行执行：

\[ X_l = B_{l-1} X_{l-1} + C_{l-1} Y_{l-1} \quad\text{（残差更新，对 } n \text{ 收缩）} \tag{3} \]
\[ (A_l, B_l, C_l) = \mathsf{H}(X_l) \quad\text{（系数预测，对 } nd \text{ 收缩）} \tag{4} \]
\[ \hat{X}_l = A_l X_l \quad\text{（输入混合，对 } n \text{ 收缩）} \tag{5} \]

逐个符号解释：式 (3) 用上一 block 的流间混合矩阵 \(B_{l-1}\) 混合旧流 \(X_{l-1}\)，再加上写回项 \(C_{l-1}Y_{l-1}\)，得到新流 \(X_l\)；式 (4) 的 \(\mathsf{H}\) 是系数预测器（含归一化与投影，逐 token 动态生成三个系数）；式 (5) 用刚算出的 \(A_l\) 把 n 条流「读出」成一份 d 维层输入 \(\hat{X}_l\)，喂给 \(F_l\)。

麻烦出在式 (4) → 式 (5) 的依赖上：\(\mathsf{H}\) 里有一处对整个隐藏维 \(nd\) 的归约（reduction，即把 d 个维度加总求一个统计量，比如 RMS 归一化的均方根——必须看完全部 d 维才能算出）。所以 \(A_l\) 要等 \(X_l\) 全部读完才算得出来，式 (5) 只能再读一遍 \(X_l\)。三个 kernel 分别读 \((n+1)d\)、\(nd\)、\(nd\)，共写 \((n+1)d\)；把 \(F_l\) 里的 pre-norm（层函数前的归一化）也算上，总激活访存流量为 \((4n+4)d\)，正好是下界的 2 倍。

论文还提到一个中间方案：由于 \(\mathsf{H}\) 的归一化权重可以离线折叠进投影权重、RMS 除法放在投影之后，残差更新和系数预测可以共享一次对残差的遍历（每算出一小块 \(X_l\) 就立刻累计投影输出与平方和），只剩输入混合因为 \(A_l\) 未就绪而必须第二遍读 \(X_l\)——即两趟实现，\((3n+2)d\)。但两趟仍比下界多一次 \(X_l\) 的读。

图 1｜多趟 vs Single-Pass（依据论文 §2.4.1 式 (3)–(6) 及其访存分析）。关键差别只有一处：输入混合用的系数从「本 block 现算的 \(A_l\)」换成「上一 block 留下的 \(A_{l-1}\)」，串行依赖随之消失，三个 kernel 融成一个。

1.3 机制：把系数「错位一格」

Single-Pass mHC 的改动小到惊人——把输入混合系数整体推迟一个 block：

\[ X_{l+1} = B_l X_l + C_l\, F_l\big(A_{l-1} X_l\big), \qquad (A_l, B_l, C_l) = \mathsf{H}(X_l) \tag{6} \]

与式 (2) 逐项对比：唯一的差别是 \(F_l\) 的输入从 \(A_l X_l\) 换成 \(A_{l-1} X_l\)。也就是说，第 \(l\) 个 block 用第 \(l-1\) 个 block 算出的读出系数来调自己的输入——系数「晚到一步」，但永远在手边。这样一来，\(X_l\) 的每一小块（tile）算出来后可以立刻同时用于两件事：输入混合（用现成的 \(A_{l-1}\)）与系数预测（为下一个 block 累计归约量），不必等全维归约完成。论文的实验结论是「this shift incurs negligible performance degradation（该错位带来的性能退化可忽略）」。

训练与部署两侧的处理不同（这回答了「是否全开」的疑问）：

  • 预训练侧：保留现有多 kernel 实现——因为错位只改变「每个 block 应用哪一组混合系数」，数学结构不变，沿用旧实现即可；
  • 部署侧：把残差更新、输入混合、系数预测三步融合成一个 kernel，即 Mega-mHC。该 kernel 沿隐藏维分 tile 处理 \(X_l\)，同时完成输入混合与「下一 block 系数」的累计，并把输入 pre-norm 与 FP8 转换也吸收进来。残差流只读一次、写一次，达到理想映射的 \((n+1)d\) 读 + \((n+1)d\) 写。

收益/代价小结：收益是激活访存精确减半且达到理论下界（对以访存为瓶颈的推理/训练都有直接意义）；代价是把混合系数错位一格（论文称性能退化可忽略）+ 需要编写 Mega-mHC 部署内核（工程成本，论文未展开）。另外 Mega-mHC 与 §3.2 提到的 Mega-Gate、Mega-MoE 同属 DeepGEMM 的融合内核家族，使 Reuse Mode 层在 prefill 只需 15 个 kernel、decode 只需 11 个。

2. Engram：给模型外挂一个「查表式记忆体」

2.1 它是什么：把「死记硬背」从主干里解耦出去

先建立一个直觉：Transformer 处理「记住地球上有多少个国家、某个冷门 API 的参数名」这类事实记忆时，靠的是把知识压进几百亿参数的权重里，每次回忆都要动用大量计算。Engram（论文引用为 Cheng et al., 2026c，原论文标题 Conditional memory via scalable lookup: A new axis of sparsity for large language models，ACL 2026）的思路是：把这部分「记忆」拆出来，改用超大规模查找表（embedding table，可理解为一张巨型「外置笔记本」）存——查表本身几乎不花计算，而且表可以做得极大（本模型 196B 参数）而不增加多少激活计算。这就是论文所说的「decouple memorization from computation（把记忆从计算中解耦）」。

「Engram」这个名字论文未解释来源。英语中 engram（记忆痕）是神经科学术语，指记忆在脑中留下的物理痕迹，与该模块「外置记忆体」的定位吻合——此为命名动机的推断，非论文原文。

V4.1-Flash 对 Engram 的集成方式是「沿用原设计 + 两处修改」：保留分词器压缩（tokenizer compression）、多头哈希（multi-head hashing）、上下文感知门控（context-aware gating）、多分支整合（multi-branch integration）四大件；第一处修改是去掉短因果卷积（原文：其性能收益不值推理栈里的额外复杂度）；第二处是嵌入表改用「动量更新 + Sinkhorn 平衡」优化（见 §2.4，下文 2.3）。

图 2｜Engram 查表数据流（依据论文 §2.4.2 与 §3.1.3）。「多头哈希」可类比给每个 N-gram 发 8 张不同编号的门禁卡，各卡指向一张独立的表——8 张表同时命中同一记忆的概率远高于单表，降低哈希碰撞风险；门控则像「按需调亮度」，由上下文决定这段查到的记忆以多大比例混入主干。

2.3 训练侧怎么训（§3.1.3 + §2.5）

196B 的表用普通 Adam 优化器训不动——Adam 要为每个参数存两个动量状态，显存直接爆炸。论文 §2.5 给的解法是「动量更新 + Sinkhorn 平衡」：工作流与 Muon 优化器一致（只维护一份动量缓冲），但把 Muon 里的 Newton–Schulz 正交化换成 Sinkhorn 平衡——对动量更新矩阵交替做行归一化、列归一化，直到每行、每列的均方根（RMS）都约等于 1：

\[ \Delta_t = \sqrt{n}\, U^{(K)} = \sqrt{n}\, D_r\, \tilde{G}_t\, D_c, \qquad \frac{1}{n}\sum_{j=1}^{n}(\Delta_t)_{ij}^2 \approx 1, \quad \frac{1}{m}\sum_{i=1}^{m}(\Delta_t)_{ij}^2 \approx 1 \tag{7} \]

符号含义：\(\tilde{G}_t\) 是 Nesterov 动量修正后的梯度矩阵；\(D_r, D_c\) 是 Sinkhorn 平衡找出的行、列对角缩放矩阵；\(U^{(K)}\) 是交替归一化 \(K\) 轮后的矩阵；\(\sqrt{n}\) 把「单位行 \(\ell_2\) 范数」换算成「单位行 RMS」；\(m\) 是矩阵较大维（对嵌入表即词表/n-gram 身份数），\(n\) 是隐藏维。直观理解：一行对应一个 token/n-gram 身份、一列对应一个隐藏特征，行与列双向归一化正好利用了这种「身份 × 特征」结构，让每一行的更新量、每一列的更新量都均衡。为数值稳定，RMS 过小的行（\(\rho_i \le \tau\bar{\rho}\)）被掩蔽；有效学习率乘以 \(\gamma = 0.18\) 以对齐 Adam 的更新幅度（接近 Moonlight 的 0.2）。训练配置里 \(K=11\)，Engram 学习率按前作做法放大 5×。论文声称：与 Muon 一样只需一份动量缓冲，且经验上优于 Adam。

工程侧（§3.1.3）的关键设计：

  • 表按行切分到「engram 并行」专用进程组——组大小权衡单卡显存占用与查表通信范围；优化器状态再在表分片的各副本间分摊。
  • 预取前移：查表索引只依赖输入 token 序列，因此在流水线各 stage 开始处理当前步 microbatch 之前，就对整个本地 batch 发起 embedding 预取，尽量不干扰流水线执行。
  • 梯度异步回传：embedding 梯度在反向传播期间先缓冲，主干反向完成后才归还给所属 rank；预取与梯度传输特意安排与视觉编码器的前向/反向重叠（V4.1 是多模态训练，见第 4、5 讲）。
  • FP8 存取直通 GEMM：embedding 以 FP8 存储与读取，取出的值和缩放因子直接交给后续矩阵乘，省一次反量化。
  • 更新融合：Sinkhorn 归一化跨迭代维护行/列缩放向量，避免每次重写整个归一化矩阵；行归一化与部分列统计累加融合成单个 kernel，减少访存。
  • RL 阶段：滚动生成（rollout）期间 Engram 表常驻 GPU 显存，降低主机内存压力、避免主机内存碎片导致的 OOM。

2.4 带来什么能力

论文对 Engram 的收益表述集中在能力面：§1 说「integrate the Engram conditional memory module to strengthen model capabilities」，§2.1 说它「adds sparsely accessed conditional memory」。原论文标题把它称为「稀疏性的新轴」——即除了 MoE 的专家稀疏之外，再加一条「记忆稀疏」的容量扩展轴。需要如实说明：本报告（V4.1 技术报告）没有给出 Engram 的单独消融数字（如去掉 Engram 各基准掉多少分），其能力收益的证据在 Engram 原论文中，V4.1 报告仅引用其做法。

3. DSpark：会「看情况下注」的投机解码

3.1 投机解码是什么（小白版）

大模型解码时一个 token 要过一遍整个模型，很慢。投机解码（speculative decoding）的思路像「代写 + 批改」：先用一个便宜的小模型（drafter，草稿员）一口气猜出 k 个 token，再让昂贵的大模型（target）一次前向把这 k 个 token 全部批改——对的留下，错的从出错处截断重猜。因为大模型的批改是并行的，一次批改顶好几次生成，快。V3 的 MTP 模块就是 DeepSeek 上一代投机解码方案（随主干一起预训练）；V4.1 改用 DSpark（Cheng et al., 2026a，arXiv:2607.05147）。

3.2 机制：半自回归草稿 + 置信度调度验证

论文 §2.4.3 对 DSpark 的一句话定位是「semi-autoregressive drafting with confidence-scheduled verification（半自回归草稿生成 + 置信度调度验证）」，机制四件套：

  1. 草稿员很小：3 个 Transformer block，滑窗注意力窗口仅 128 token（对比主干 40 层、百万上下文，草稿员便宜到可以忽略）。
  2. 半自回归草稿：草稿员单次前向并行算出 5 个草稿位置的 base logits（即每个位置「下一个 token 是什么」的原始打分）——不是老老实实猜一个再猜下一个，所以叫「半」自回归；位置之间的依赖由一个轻量 Markov 头建模（Markov 头即「只看前一个状态」的小预测器，补上并行生成缺失的接续关系）。
  3. 置信度头：一个 confidence head 预测每个草稿位置的条件接受概率（这个位置如果被大模型批改，有多大把握被留下），并据此估计前缀存活概率（前 i 个草稿全被接受的概率）。
  4. 置信度调度验证：调度器把前缀存活概率与实测的引擎吞吐曲线结合，为每个请求动态选择验证长度——目标是「在当前系统负载下最大化系统级 token 吞吐」。直觉：模型有把握时多验证几个（赚得多），没把握或系统忙时少验证几个（不浪费批改算力），像下注时看牌面和牌桌拥挤程度决定押多少。
专门阶段单独训练——只训 DSpark，主干冻结； · 后训练（post-training）期间：DSpark 与主干一起继续训练，但 DSpark 目标的梯度不回传进主干； · 动机：让 DSpark 始终对齐持续进化的策略模型，从而同时加速在线服务与 RL/OPD 的 rollout 生成。

图 3｜DSpark 工作流与训练安排（依据论文 §2.4.3）。图中未标注任何加速倍数——V4.1 论文未给出 DSpark 的具体加速数字（原论文 arXiv:2607.05147 才有），本讲不编造。

3.3 收益与代价

收益：论文 §1 定性表述为「improve decoding efficiency through semi-autoregressive draft generation and confidence-scheduled verification」。两点结构性优点值得一提：其一，草稿与验证解耦，验证长度逐请求自适应，天然适合多租户、负载波动的在线服务；其二，DSpark「保持与进化中的策略对齐」，使其在后训练快速迭代时仍能服务 RL/OPD 的 rollout 生成（这部分属于部署与训练系统协同，第 4、6 讲会再遇到）。

代价：多出一个需单独训练、随策略持续更新的模块；主干预训练期间没有 MTP 陪伴（论文 §2.1：「We omit the MTP module during backbone pre-training」）。V4.1 论文未给出 DSpark 的接受率/加速倍数等量化数字。

4. FP4 Main KV Cache：主 KV 从 8-bit 再砍到 4-bit

4.1 背景：为什么主 KV「敢」用 4-bit

第 2 讲说过，V4.1 的全局 KV（CED + CSA2 之下，跨层共享的那份）常驻 HBM，是长上下文 KV 占用的大头；V4 已把主 KV 存成 FP8（8-bit 浮点）。现在要再砍到 FP4（4-bit）。这为什么可行？关键在 V4.1 的注意力结构：被量化的缓存值在进入注意力计算前会先反量化（dequantize）回高精度——也就是说 FP4 只用于「存」，不用于「算」，因此不需要硬件原生支持 FP4 矩阵乘，任何平台都能跑。论文原话：「Dequantizing cached values before attention allows us to use a more accurate format without requiring native matrix-multiplication support for that format, preserving compatibility across hardware platforms.」（FP4 格式背景见 量化七讲·第 4 讲；KV cache 量化系统落地见 第 5 讲。）

4.2 用什么格式：E2M1 + 每 16 通道一个 E4M3 scale（去全局 scale）

论文的表述分两层，需要掰开：

  • 论文首先说「采用 OCP 标准的 MXFP4 格式以支持尽可能多的硬件平台，尽管实验中其他格式精度更高」。MXFP4 与 NVFP4 的元素格式同为 E2M1（1 符号 + 2 指数 + 1 尾数，每数量级只有几个刻度、天生很粗），差别在 scale（缩放因子）：第 4 讲讲过，MXFP4 是每 32 个数共享一个 E8M0（纯 2 的幂）scale，NVFP4 是每 16 个数一个 E4M3 scale 外加一个张量级二级全局 scale。
  • 随后论文给出最终选择：「在评估的约 4-bit 格式中，选择 E2M1 + 每 16 通道一个 E4M3 scale，跟随 NVFP4，但省去其二级全局 scale，以平衡精度与简洁。」即 scale 布局取 NVFP4 的（组大小 16、E4M3），但只有一级 scale。
两句话并存的理解：元素格式 E2M1 属于 OCP FP4 标准（MXFP4/NVFP4 共用），保住了「硬件平台兼容」这一层；而由于缓存值在注意力前反量化、不走硬件原生 FP4 矩阵乘，scale 布局不必迁就硬件 tile，因此可以选实验中更准的 NVFP4 式「每 16 通道 E4M3」并再省掉全局 scale。这是对论文行文逻辑的解释性推断，论文未明说两句之间的衔接。

省掉全局 scale 为什么安全？论文给了一段干净的量级论证——全局 scale 本来的作用是防止数值超出格式上限，而这里上限富余得很：

  • 该格式可表示的最大幅值 = E4M3 scale 上限 × E2M1 元素上限 = \(448 \times 6 = 2688\)；
  • 训练出的最大 RMSNorm 权重幅值约 1，故经 RMS 归一化后，512 通道 KV latent 的 \(\ell_2\) 范数至多约 \(\sqrt{512}\)；
  • RoPE 不改变范数（RoPE 是旋转变换，只转方向不拉长度），所以旋转后各通道绝对值仍被 \(\sqrt{512} \approx 22.6\) 界住；
  • 训练中实际观测到的最大幅值约 10。

\(10 \ll 22.6 \ll 2688\)：观测峰值距格式上限还有两个数量级以上的余量，省掉全局 scale「未造成可测量的精度下降（no measurable decrease in accuracy）」，还简化了缓存布局。

4.3 怎么训、怎么量化

  • QAT（quantization-aware training，量化感知训练——训练时就模拟量化误差，让模型适应低精度）：V4 已对 FP4 indexer 的 Q/K 用 QAT（那是为加速索引计算、缩小索引缓存）；V4.1 把 QAT 扩展到主 KV cache——这里 FP4 的目的是省存储而非加速矩阵乘。论文 §1 概括为「训练期间使用 FP4 全局 KV cache，性能退化极小（only marginal performance degradation）」；§2.4.4 落到实处：QAT 在 post-training 阶段引入。
  • 量化时机：RoPE 之后。缓存值在 RoPE（旋转位置编码，给向量「盖上位置戳」的旋转操作）之后量化。先量化再 RoPE 在实验中只有边际的精度改善，却会在解码时引入额外开销，得不偿失。
  • 格式统一：非 RoPE 分量与 RoPE 分量用同一量化格式（V4 的 MLA 式缓存常见「部分 RoPE」设计，两段分别处理，此处格式保持一致）。
  • SWA KV 仍保留 FP8：滑窗 KV 对量化敏感（sensitivity to quantization），不跟风压到 FP4。注意滑窗 KV 本来就只在窗口内保留、体量小且不进持久缓存（第 1、2 讲），压它的收益小、风险大。

图 4｜FP4 主 KV cache 的量化流水线与量级论证（依据论文 §2.4.4）。QAT 在 post-training 引入，让模型在训练中就「习惯」量化误差。

4.4 与 V4 的 FP8 KV 对比：省了多少

V4 的主 KV cache 为 FP8；V4.1 改为 FP4 后，「存储占用几乎减半（nearly halves the storage footprint），HBM 与卸载到 SSD 时皆然」。这与第 2 讲的全局 KV 总账对上：CSA2 跨层共享（架构）× FP4（精度）两层相乘，V4.1-Flash 的全局 KV 占用降到 890 字节/token，约为 V4-Flash 的 1/4（论文 §6）。

6. 本讲小结

  • Single-Pass mHC：一行公式改动的典范——把输入混合系数从「本 block 现算」错位成「上一 block 留下」，解开 kernel 串行依赖，Mega-mHC 单内核把激活访存从 \((4n+4)d\) 压到 \((2n+2)d\)，精确减半且达到理论下界；训练侧公式照用，部署侧才启用融合内核。
  • Engram：196B 参数的稀疏查表记忆模块（2/3/4-gram × 8 头哈希 × 素数容量 FP8 表，挂在第 1、14 层），把记忆从主干计算中解耦；训练用动量 + Sinkhorn 平衡更新（省掉 Adam 的状态显存），查表可预取、可重叠，V4.1 的修改是去短因果卷积 + 换优化器。
  • DSpark：预训练后单独训练的投机解码模块——3 block 小草稿员单次前向并行出 5 个草稿位置，Markov 头补依赖、置信度头估存活概率，调度器按实测吞吐曲线逐请求定验证长度；后训练与主干同训但梯度不进主干，保持与进化策略对齐。
  • FP4 Main KV Cache：主 KV 从 FP8 压到 4-bit——E2M1 元素 + 每 16 通道 E4M3 scale（NVFP4 布局去掉二级全局 scale），靠「2688 上限 ≫ √512≈22.6 范数界 ≫ 实测 ~10」的量级余量保精度；RoPE 后量化、注意力前反量化，跨硬件兼容；SWA KV 因量化敏感仍留 FP8。主 KV 存储相对 V4 的 FP8 几乎减半。
  • 方法论上值得记住：这四个扩展都不动「模型学到什么」，只动「信息怎么搬运」（mHC）、 「知识存在哪」（Engram）、「下一步怎么猜」（DSpark）、「缓存存多省」（FP4）——这正是 V4.1「在压 KV 的主线之外，把系统每一层的浪费都拧一遍」的整体风格。

7. 常见疑问（FAQ）

Q：这四个扩展里，哪一个对「KV cache 变小」贡献最大？
A：只有 FP4 Main KV Cache 直接作用于 KV cache——把主 KV 的存储精度从 FP8 压到 FP4，相对减半；再与第 2 讲的 CSA2 跨层共享相乘，得到全局 KV 约 890 B/token（V4-Flash 的 1/4）。Single-Pass mHC 省的是激活（层间传递的中间量）的读写，不是 KV cache；Engram 反而增加参数（但查表几乎不加计算）；DSpark 优化的是解码速度。读论文时容易把这四件事混进「KV 压缩」一个大筐，实际它们的账本各记各的。

Q：mHC 的「激活访存减半」对最终速度影响多大？
A：论文没有给出端到端的墙钟时间数字。可以确定的是：mHC 的系数计算 FLOPs 可忽略，其开销本来就集中在访存，因此访存减半基本等价于该环节耗时趋近减半；但整个 Transformer 层还有注意力、MoE 等大头，端到端收益要打折。论文给出的一个系统级旁证是：配合 Mega-Gate、Mega-mHC、Mega-MoE 等融合内核，CSA2 Reuse Mode 层的 prefill 只要 15 个 kernel、decode 只要 11 个——kernel 数量少，意味着更少的启动开销与更高的流水线效率（推断：论文陈述了 kernel 数与访存数字，未直接给出「减半 → 快 x%」的映射）。

Q：为什么 FP4 只压「主 KV」，连 indexer K 也一起压吗？
A：论文 §2.4.4 标题与内容针对的是主 KV cache（全局注意力的主体缓存）；而 indexer 的 FP4（含 indexer 查询与键）是 V4 就已经用 QAT 做过的——那是为了加速索引计算、缩小索引缓存，本讲沿用这一事实。SWA KV（滑窗那份）因对量化敏感保留 FP8。也就是说 V4.1 的全局 KV 三种成分里：主 KV 在本讲升级到 FP4，indexer K 沿用 V4 的 FP4，滑窗 KV 维持 FP8。

8. 自测清单

Q1：Single-Pass mHC 改了公式里的哪一处？为什么这一处改动能让三个 kernel 融成一个？

答：把式 (2) 中 \(F_l\) 的输入 \(A_l X_l\) 改为 \(A_{l-1} X_l\)（式 (6)），即输入混合改用上一个 block 算出的系数。原实现里式 (5) 的输入混合必须等式 (4) 的系数预测完成（后者含对隐藏维的全归约），导致 \(X_l\) 被读两次、kernel 串行；错位后混合用的系数现成，每块 tile 算出即可同时用于混合与为下一 block 累计归约量，三 kernel 融成 Mega-mHC 单 kernel，访存从 \((4n+4)d\) 降到 \((2n+2)d\)（下界）。

Q2：Engram 为什么能用 196B 参数还几乎不增加计算？它在 V4.1 里相对原版改了哪两处？

答：因为它把知识放进查找表、按 N-gram 哈希地址稀疏访问——每个 token 只查少量条目，查表计算可忽略，参数量与计算量解耦（「记忆与计算解耦」）。两处修改：① 去掉短因果卷积（收益不值推理栈复杂度）；② embedding 改用动量更新 + Sinkhorn 平衡的优化器（省 Adam 的优化器状态显存，经验上还更优）。

Q3：DSpark 的「置信度调度验证」调度的是什么？依据是什么信号？

答：调度每个请求的验证长度（目标模型一次批改多少个草稿 token）。信号是置信度头估计的前缀存活概率（草稿前缀被接受的概率）与实测的引擎吞吐曲线，目标是在当前系统负载下最大化期望的系统级 token 吞吐。

Q4：FP4 主 KV cache 用什么格式？省掉 NVFP4 的二级全局 scale 为什么没有精度问题？

答：E2M1 元素格式 + 每 16 通道一个 E4M3 scale（无二级全局 scale）。安全余量来自量级论证：格式可表示上限 \(448\times 6=2688\)；而 RMSNorm 权重最大约 1，归一化后 512 通道 KV latent 的 \(\ell_2\) 范数至多 \(\sqrt{512}\approx 22.6\)，RoPE 保范数，训练实测最大幅值约 10——距上限两个数量级以上。

Q5：FP4 主 KV cache 为什么不需要硬件原生 FP4 矩阵乘支持？SWA KV 为什么不一起压？

答：因为缓存值在进入注意力计算之前先反量化，FP4 只用于存储不用于计算，所以不依赖硬件 FP4 矩阵乘、跨平台兼容。SWA KV 对量化敏感，保留 FP8（其本身仅保留窗口内条目、不进持久缓存，压缩收益也小）。

Q6：本讲四个扩展中，哪两个有明确的量化收益数字？哪两个在 V4.1 报告里只有定性结论？

答：Single-Pass mHC（激活访存 \((4n+4)d \to (2n+2)d\)，解析减半）与 FP4 主 KV（相对 FP8 存储几乎减半）有明确量化收益；Single-Pass 的性能影响与 FP4 的精度影响也只有定性表述（「可忽略/极小」）。Engram 与 DSpark 在 V4.1 报告中连收益数字都没有（分别在原论文中），仅有集成方式与训练安排的描述。
