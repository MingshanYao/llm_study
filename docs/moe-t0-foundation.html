系列：DeepSeek MoE 零基础五讲（本篇为第 0 讲，不含任何 DeepSeek 内容，只打地基）

读者假设：不需要深度学习背景；会一点 Python 更好，不会也能读。所有数学都从零手算。

浓缩版对照：读完本系列再看 DeepSeek MoE 进化史（浓缩版），它读起来就会顺畅很多。

本讲目标：MoE（Mixture of Experts，混合专家）是对 Transformer 里 FFN 层的改造。要把 MoE 的每个细节讲明白，得先搞懂 6 件事：① Transformer 的一层长什么样、FFN 在哪；② 矩阵乘法就是「一堆加权求和」；③ FFN（尤其是 SwiGLU 版本）在算什么；④ 参数量和计算量是两码事——这一条是整个 MoE 故事的起点；⑤ softmax、sigmoid、softplus 三个函数各自的手算与脾气（DeepSeek 三代模型正好各用了其中一个）；⑥ top-k 选择是怎么回事、为什么它「不可导」。这 6 件事任何一个含糊，后面讲「细粒度专家」「bias 门控」「√Softplus」都会变成听天书。

1. 一个 token 在 Transformer 里怎么流动

语言模型处理文字的第一步是分词（tokenize）：把文本切成一个个「token」。你可以先粗暴地把 token 理解为「一个词或词的一部分」。比如「我喜欢吃火锅」可能被切成「我 / 喜欢 / 吃 / 火锅」4 个 token。每个 token 会查一张大表（词表，embedding 表），变成一个固定长度的向量——DeepSeek-V4 里这个向量的长度是 7168 个数。也就是说，一个 token 进了模型，就是一个装着 7168 个数字的列表。

然后这个向量会依次穿过 61 层结构完全相同的模块（DeepSeek-V4 是 61 层），每过一层，向量被更新一次。每一层的内部结构是：

图 0-1｜一层的结构。本系列所有故事都发生在中间那个蓝色高亮盒子里：稠密模型在这里放一个 FFN，MoE 模型在这里放一群专家 + 一个路由器。

两个小记号约定，后面所有篇幅都会用到：

  • \(T\)（序列长度）：这段输入一共有多少个 token。一批输入就是一个 \([T, 7168]\) 的二维数组（表格）：\(T\) 行、每行 7168 个数，一行对应一个 token 的当前状态。
  • \(d\)（模型宽度）：这个 7168 叫模型维度，记作 \(d\)。它决定了「一个 token 的状态用多少个数来描述」。

2. 矩阵乘法：就是「一堆加权求和」同时算

神经网络里的参数，几乎全部存放在「权重矩阵」\(W\) 里，而矩阵乘法是它们的用法。先看一个 \(2\times 2\) 的手算例子，别怕，一步都不跳：

\[ \begin{bmatrix} 1 & 2 \\ 3 & 4 \end{bmatrix} \begin{bmatrix} 0 & 1 \\ 1 & 0 \end{bmatrix} = \begin{bmatrix} \,1{\times}0 + 2{\times}1 \, & \, 1{\times}1 + 2{\times}0 \, \\ \, 3{\times}0 + 4{\times}1 \, & \, 3{\times}1 + 4{\times}0 \, \end{bmatrix} = \begin{bmatrix} 2 & 1 \\ 4 & 3 \end{bmatrix} \]

规则：结果第 \(i\) 行第 \(j\) 列 = 左矩阵第 \(i\) 行 与 右矩阵第 \(j\) 列的对应相乘再求和（点积）。所以矩阵乘法本质上就是「一次性算很多个加权求和」：左边的每一行是「输入」，右边的每一列是「一组权重」。

直觉把 \(W\) 的一列看成一个「打分员」：它对输入的每个分量分配权重，加权求和得到一个输出数。\(W\) 有多少列，就有多少个打分员，就产出多少个输出分量。所谓「训练模型」，调的就是这亿万个权重。

把 7168 维的 token 向量乘上一个 \(7168 \times 7168\) 的矩阵，就完成一次「全连接变换」——输出的每个分量都是输入 7168 个数的加权组合。FFN 就是把两三个这样的变换串起来，中间夹一个「激活函数」。

3. FFN 深讲：token 的「深度加工车间」

3.1 最朴素的两层 FFN

\[ \mathrm{FFN}(x) = \mathrm{act}(x W_1)\, W_2 \]

流程：先把 \(x\)（\(d\) 维）用一个 \(d \times d_{ffn}\) 的矩阵 \(W_1\) 升维到 \(d_{ffn}\)（通常是 \(d\) 的好几倍，比如 4 倍），过一个激活函数（逐元素处理，比如把负数压掉），再用 \(d_{ffn} \times d\) 的矩阵 \(W_2\) 降维回 \(d\)。

为什么要「先升后降」？直觉：升维是把 token 的含义展开成很多并列的「特征槽位」（每个槽位一个打分员），每个槽位独立判断「这个 token 有没有某种特征、有多强」；激活函数负责把关（弱的置零/压小）；降维再把有用特征汇总回标准尺寸。模型学到的大部分「知识」就存在这两个大矩阵里——这也是为什么 FFN 占了稠密 Transformer 约 2/3 的参数（Attention 部分只占剩下约 1/3）。

3.2 现代标准答案：SwiGLU（DeepSeek 全系用的版本）

DeepSeek 用的 FFN 不是最朴素版，而是 SwiGLU。区别是把「一个升维矩阵」拆成「两个并列的升维矩阵 \(W_1\)（gate 分支）和 \(W_3\)（up 分支）」，让两条分支的信息互相调制：

\[ \mathrm{SwiGLU}(x) = \big(\underbrace{\mathrm{SiLU}(x W_1)}_{\text{gate：开关信号}} \odot \underbrace{(x W_3)}_{\text{up：原始特征}}\big)\, W_2 \]

其中 \(\odot\) 是逐元素相乘（两个等长向量，对应位置相乘），\(\mathrm{SiLU}(z) = z \cdot \mathrm{sigmoid}(z)\) 是个温和的「软开关」：输入很负时输出接近 0（关闭），输入为正时输出约等于输入（放行）。

完整手算一个小例子（维度小到能心算）。设 \(d=2\)、\(d_{ffn}=2\)，输入 \(x = [1, 2]\)：

步骤算式结果
gate 分支\(x W_1\)，取 \(W_1=\begin{bmatrix}1&0\\0&1\end{bmatrix}\)（恒等矩阵）\([1, 2]\)
up 分支\(x W_3\)，取 \(W_3=\begin{bmatrix}1&1\\1&-1\end{bmatrix}\)，即 \([1{\times}1{+}2{\times}1,\ 1{\times}1{+}2{\times}({-}1)]\)\([3, -1]\)
SiLU 开关\(\mathrm{SiLU}(1)=1{\times}\sigma(1)=0.731\)，\(\mathrm{SiLU}(2)=2{\times}\sigma(2)=1.762\)\([0.731, 1.762]\)
逐元素相乘\([0.731{\times}3,\ 1.762{\times}(-1)]\)\([2.193, -1.762]\)
降维\(\times W_2\)，取恒等矩阵\([2.193, -1.762]\)

真实模型里 \(d_{ffn}\) 远大于 2（V4 的稠密层中间维是 \(d\) 的数倍；MoE 专家则是 \(d_{ffn}=3072\)），但计算流程一模一样。一个 SwiGLU 专家的参数量是三个矩阵之和：

\[ \text{参数量} = 3 \times d \times d_{ffn}, \qquad \text{每 token 计算量} = 2 \times 3 \times d \times d_{ffn}\ \text{FLOPs（乘和加各算一次）} \]

拿真实数字验算一下（这两个数字后面反复出现）：V4 的一个路由专家 \(d=7168\)、\(d_{ffn}=3072\)，参数量 \(3 \times 7168 \times 3072 \approx 6600\) 万；每个 token 每次用它要 \(2 \times 6600\) 万 \(\approx 1.3\) 亿 FLOPs。

4. 参数量 ≠ 计算量 ≠ 激活参数：MoE 故事的起点

这是全系列最重要的一节。三个词天天出现，但说的不是一回事：

概念含义由什么决定比喻（一家餐厅）
参数量（总参数）模型里存了多少权重数字结构定义，训练完固定餐厅雇了多少厨师
计算量（FLOPs）处理一个 token 要做多少次乘加结构 × 每 token 实际走哪些路径做一桌菜实际要动用多少厨师工时
激活参数（activated params）处理一个 token 时真正参与计算的参数个数路由结果决定这一桌菜实际用到的厨师人数

稠密模型（dense model）里，这三个量是绑死的：7B 稠密模型每个 token 都要跑全部 70 亿参数，雇 100 个厨师就得每桌菜都让 100 个人上手。想要更多「知识容量」（更多参数），就必须付出同等规模的计算和电费——这就是 MoE 要打破的绑定。

DeepSeek-V4-Pro 的官方数字是：总参数 1.6T（1.6 万亿），每 token 只激活 49B（490 亿）。也就是说餐厅雇了 1.6 万个厨师，但每做一道菜只需要 49 个厨师 simultaneously 干活——其他人在休息室待命。参数量（知识容量）和计算量（推理成本）从此解耦。MoE 的全部魔法与全部麻烦，都从这个解耦开始。

为什么可行「每个 token 只用一小部分参数」成立的假设是：不同 token 需要的加工方式不同。「猫」需要生物学特征加工，「方程」需要符号推理加工——与其让一个大 FFN 兼顾所有模式，不如备多套小 FFN（专家），按需取用。

5. softmax 从零讲：把一堆分数变成「概率感」

MoE 的门控（路由器）会给每个专家打一个分，然后把分数变成「选择依据」。第一个登场的就是 softmax——它把任意一组实数变成一组非负、总和为 1 的数，从而有了「占比」的含义：

\[ \mathrm{softmax}(z_i) = \frac{e^{z_i}}{\sum_j e^{z_j}} \]

手算一遍（\(z = [2.0,\ 1.0,\ 0.1]\)，三个专家）：

专家分数 \(z_i\)\(e^{z_i}\)除以总和 11.21softmax 输出
E12.07.3897.389 / 11.210.659
E21.02.7182.718 / 11.210.242
E30.11.1051.105 / 11.210.099

softmax 的四个关键脾气（后面好几处设计都源于它们）：

  1. 总和恒为 1：输出是「占比」。想让某个专家占比变大，必然压小别人——它是全局耦合的。
  2. 指数放大差距：输入差 1 分，输出占比差 \(e \approx 2.7\) 倍。分数稍有优势，占比就大幅领先（赢者通吃倾向）。
  3. 对平移不变：所有 \(z_i\) 同时加 3，输出完全不变（分子分母同乘 \(e^3\)）。只关心相对差距。
  4. 数值上溢风险：\(z\) 很大时 \(e^z\) 爆炸（\(e^{100}\) 已超出浮点范围）。工程上要「先减最大值再算」，实现里处处是这个细节。
深入：为什么减最大值不影响结果？

\(\mathrm{softmax}(z_i) = e^{z_i - m} / \sum_j e^{z_j - m}\)（\(m = \max z\)），分子分母同乘 \(e^m\) 后与原式恒等。减去 \(m\) 后最大的指数值变成 \(e^0 = 1\)，其余都 \(\le 1\)，永远不会溢出。这是所有 softmax 实现的标准姿势。

6. sigmoid 从零讲：每个分数独立过门

DeepSeek-V3 起改用 sigmoid 计算亲和度。sigmoid 是单输入函数，把任意实数压到 \((0,1)\) 区间：

\[ \sigma(z) = \frac{1}{1 + e^{-z}} \]

手算几个点：\(\sigma(0) = 0.5\)（对称中心）；\(\sigma(2) = 1/(1+e^{-2}) = 1/(1+0.135) = 0.881\)；\(\sigma(-2) = 0.119\)。

和 softmax 比，sigmoid 的根本区别在于没有分母：每个专家的分数各自独立计算，互不影响。E1 的分数再爆炸，也压不到 E2 的输出。代价是输出总和不再为 1（比如三个都打到 0.9），所以 DeepSeek-V3 的做法是：先用 sigmoid 独立打分选专家，选完之后只在被选中的那一小撮内部做归一化，恢复「占比」含义。这个「先独立选择、后局部归一化」的两段式设计，从 V3 一直沿用到 V4（函数换成谁，两段式结构不变）。

另一个重要脾气：饱和。当 \(z\) 很大（比如 10），\(\sigma(z) \approx 0.9999\)，图像水平贴着 1 走——此时输入再怎么变，输出几乎不动，梯度接近 0。饱和既是优点（天然把分数限制住）也是缺点（大分数失去区分度、梯度消失）。

7. softplus 从零讲：ReLU 的光滑版

ReLU（\(\max(0, z)\)）是神经网络最常用的激活：负数归零，正数照抄。它简单好用，但有个「尖角」——在 \(z=0\) 处导数突然从 0 跳到 1，不可导。softplus 是它的光滑替身：

\[ \mathrm{softplus}(z) = \log(1 + e^{z}) \]

手算：\(\mathrm{softplus}(0) = \log 2 = 0.693\)；\(\mathrm{softplus}(2) = \log(1+7.389) = \log 8.389 = 2.127\)；\(\mathrm{softplus}(-2) = \log 1.135 = 0.127\)。行为特征：\(z\) 很大时 \(\approx z\)（和 ReLU 重合，无上界）；\(z\) 很负时 \(\approx 0\) 但永不为零、处处光滑。

8. top-k：从 N 个分数里挑前 k 个

MoE 门控的最后一道工序是 top-k：有 \(N\) 个专家的分数，只保留最大的 \(k\) 个，其余的一律视为没被选中（输出置 0）。例如 5 个专家的分数是：

图 0-3｜top-k 是一个「硬选择」：非中即零，没有中间态。

最后一步的「归一化」：被选中的分数 \(0.41, 0.30\) 除以它们的和 \(0.71\)，得到 \(0.58, 0.42\)，重新凑成一组占比，用作混合权重。

注意 top-k 的一个尴尬性质：它是离散选择——「选谁」这个决策没有连续的过渡（0.409 和 0.411 的分数可能选中不同的专家），所以「梯度」这个训练工具对「选谁」这件事是失明的：模型无法通过常规训练信号直接学会「该把 token 送给谁」，只能通过「分数本身」间接学。这个看似技术细节的性质，正是第 2 讲「bias 门控」整个发明的突破口——bias 之所以能做均衡而不伤模型，就是因为均衡信号恰好可以藏进这个「梯度失明」的角落里。

9. 自查清单

如果下面 8 个问题都能不假思索地回答，就可以进入第 1 讲了：

  1. Transformer 一层里，哪一块是 MoE 改造的对象？（答：FFN——单个 token 的深度加工模块，占约 2/3 参数）
  2. 矩阵乘法的物理含义是什么？（答：同时算很多组「加权求和」，每列权重 = 一个打分员）
  3. SwiGLU 的三个矩阵 \(W_1, W_3, W_2\) 各干什么？（答：gate 开关信号 / up 原始特征 / down 降维汇总）
  4. 参数量和计算量的区别？V4-Pro 的两个数是多少？（答：存了多少 vs 每 token 实际用多少；1.6T 总参 / 49B 激活）
  5. softmax 为什么是「全局耦合」的？（答：分母含所有分数，一个涨别人就得跌）
  6. sigmoid 和 softmax 最根本的区别？（答：无分母、逐专家独立；需要事后局部归一化）
  7. softplus 和 ReLU 的关系？（答：光滑版，负半轴不断流、零点不产生尖角）
  8. top-k 为什么对梯度「失明」？（答：非中即零的离散决策，没有连续过渡，训练信号进不去）
