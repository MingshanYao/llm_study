LLM 架构演进技术报告

FFN 与 Attention 的降算 / 降存主线

定位：中等深度技术综述。以「短板转移」为主线，梳理 Attention 与 FFN 两个子模块自 2022 年以来的架构演进，量化每一代技术究竟压掉了哪一种成本（FLOPs / 带宽 / 容量），并解释为什么演进方向会如此。

数据来源：各模型公开 Technical Report、开源 config.json、vLLM / SGLang 工程博客，以及本报告基于公开配置做的一阶解析推导（推导过程见第 4 章）。

日期：2026-09-20

摘要（TL;DR）

  1. 架构设计的本质是在给定「卡数 × 数据 × 时间」预算下追求更低 Loss 的 Trade-off。所有架构创新都不是"更聪明"，而是"把资源从已经过剩的短板挪到仍然稀缺的短板"。
  2. 两个子模块攻的是两种不同的成本，分工非常清晰：
    • FFN 是参数量的主战场（Dense 模型中占 82%，MoE 稀疏层中占 98.4%）→ 主攻路线是 MoE：把参数量与计算量解耦。
    • Attention 是访存量的主战场（KV Cache 随序列长度线性增长，且每步 decode 都要全量读一遍）→ 主攻路线是 压 KV Cache。
  3. 瓶颈已经完成两次转移：Compute bound（Dense 训练算力不够） → Bandwidth bound（Decode 读 KV / 读权重） → Capacity bound（Agent 时代 KV Cache 吃掉全部显存）。
  4. KV Cache 的四条压缩路径可以按"压掉什么"分类：
    路径代表压掉的东西量级
    Head 共享MQA / GQAKV 的份数8×~16×
    表示压缩MLA每份 KV 的维度3.56×（2048 → 576 元素）
    Token 稀疏NSA / DSA需要读取的 token 数DSA ≈ 5×，NSA ≈ 25~31×
    机制替换GDN / KDA / LightningKV Cache本身（换成 O(1) 状态）与 L 无关
    层间混合Hybrid 3:1 / 5:1 / 7:1需要存 KV 的层数3×~8×
  5. Agent 时代负载发生质变：实测中位输入 142K token、中位输出 444 token、prefix 命中率 >96%。99% 以上的 token 消耗在 Prefill，但其中绝大部分被 Prefix Cache 命中——成本大头不再是计算，而是 KV Cache 的存储与搬运。这直接催生了 Prefill / Decode 解耦，以及"Prefill 降激活、Decode 降 KV"的架构级解耦设计。
  6. 稀疏化与低精度是正交的：Sparse 消除"量级冗余"（只算 k/n），低精度消除"倍数冗余"（每元素字节数）。两者收益近似相乘，工程上必然叠加。
  7. 训推硬件诉求已经分野：推理走向异构专用化（指标从 $/GB·s⁻¹ 转向 $/FLOPS），训练必须坚持同构（Bitwise 一致性 > 一切）。
  8. 2026 年进展（详见 §9）：上述每条主线都又推进了一截——
    • Attention：DeepSeek-V4 用 CSA（压缩+稀疏）+ HCA（重压缩+稠密）把 1M 上下文 KV 压到 V3.2 的 10%（V4-Flash 7%），并用 mHC 把残差连接重构为"双随机约束的多并行流"，开辟"训练稳定性"第三战线。
    • 模型级 PD 解耦：DeepSeek-V4.1-Flash（2026.09）用非对称 Causal Encoder-Decoder 把"Prefill 降激活、Decode 降 KV"做进权重——prefill 激活 8B / decode 激活 16B，KV 对 HBM 压到 1/4、对 SSD 压到 1/8。PD 解耦从系统层调度下沉为模型结构（§5.3 / §9.1）。
    • Hybrid SSM 收敛：Nemotron 3 Nano / Qwen3.5 / Mamba-3 殊途同归到"SSM + 稀疏 MoE"，印证纯 Linear 不取代 Hybrid、但 Linear 占比持续上升。
    • 低精度：战线从"推理 FP8"推进到"训练 FP4"（NVFP4 预训练 12B/10T token 对标 FP8）；FP8 KV cache 成为长上下文默认起点（decode 延迟斜率降至 54%）。
    • Agent 负载：TraceLab 实测 prefix 命中 95.7%，但历史重读占 ~60% 成本——优化重点从"压字节"转向"让重读更便宜"（Mooncake SSD offload 把命中率从 36% 拉到 84%）。
    • 硬件：进入 HBM4 时代（Rubin 22 TB/s、MI455X 432 GB/23.3 TB/s、TPU v7 Ironwood 9216-chip pod）；NVIDIA Rubin CPX 专用 decode 卡被取消，说明"异构专用化"有上限。
    • 标配变化：1M 上下文 + 稀疏 MoE 已从"卖点"变成旗舰模型的"入场券"（GPT-5.4/5.5、Gemini 3.1、Claude 4.6、Kimi K2.6、DeepSeek-V4 同窗口对齐）。

1. 分析框架：短板转移（Bottleneck Migration）

1.1 为什么"演进"是有方向的

大模型架构不是自由探索，而是被三条硬约束框死的：

给定：卡数 N、数据量 D、时间 T、精度下限 L_max
求：  架构 A，使 Loss(A) 最小

在这个约束下，任何时刻系统中只有一块短板真正限制 Loss。把资源投入到非短板维度上是纯浪费。因此架构演进的轨迹 = 短板被逐个消除后，资源重新分配的轨迹。

1.2 三块短板

带宽（Bandwidth）GB/sDecode 阶段：每生成 1 个 token 要流式读完权重 + KVGQA / MLA / Sparse Attention / 低精度
容量（Capacity）GBAgent 长上下文 + 大 Batch：KV Cache 超过权重成为显存第一占用者Hybrid / Linear Attention / 多级存储 / PD 解耦

对任意算子，算术强度 AI = FLOPs / Bytes。当 \( \text{AI} < \text{ridge point} \) 时该算子 memory bound，增加算力无用；反之则 bandwidth bound 之外还有余量。

2. Attention 演进：从"算得起"到"存得起"

2.1 成本从哪里来

标准 Attention 在每个 token、每一层都要缓存 Key 和 Value：

KV_Cache_bytes = 2 × L_layers × n_kv × d_head × bpe × T_seq × B_batch
                 ↑    ↑          ↑       ↑       ↑      ↑        ↑
              K和V  层数     KV头数  头维度  每元素  序列长度  并发数

以 Llama-2-70B 为基线（80 层、8 个 KV head、head_dim=128、BF16）：

每 token 每层 = 2 × 8 × 128 = 2048 个元素 = 4096 字节
每 token 全模型 = 80 × 4096 = 320 KB
32K 上下文单请求 = 10.0 GB

这个 2048，就是后续所有优化的参照原点。

Attention 的成本有两个完全不同的形态，必须分开看：

阶段成本形态瓶颈
Prefill计算 O(L²)，KV 只需写一次Compute bound（长序列时）
Decode每生成 1 token，全量重读 L 个 token 的 KVMemory bandwidth bound

Decode 的残酷之处：生成 1 个 token 的 Attention FLOPs 只有 2·n_h·(d_qk+d_v)·L（Q·Kᵀ + softmax·V 各一次，2 倍 MAC 计入），但必须搬运 L × kv_bytes 字节。序列越长，计算量涨一倍、搬运量也涨一倍，而计算单元本来就没跑满。

2.2 第一刀 · Head 共享：MHA → MQA → GQA

思路：KV 的份数不必等于 Query 的份数。多个 Query head 共享一组 KV head。

MHA:  n_kv = n_q           → 2 × n_q × d  元素/token/层
MQA:  n_kv = 1             → 2 × d        元素/token/层
GQA:  n_kv = n_q / g       → 2 × (n_q/g) × d

收益：Llama-2-70B 从 MHA（64 KV heads）降到 GQA（8 KV heads），KV Cache 直接 ÷8。

代价：

  • MQA 过于激进，表达能力损失明显，且需要专门的 uptraining 才能从 MHA checkpoint 转换。
  • GQA（g=8）是工程甜点：几乎无损，但每个 KV head 存的东西一点没变。

关键局限：GQA 压的是"份数"，没压"每份的内容"。当 n_kv 已经降到 8 甚至 4 时，继续降的收益递减、损失陡增。这条路很快走到头了。

2.3 第二刀 · 表示压缩：MLA（Multi-head Latent Attention）

思路的根本转变：不再问"存几份"，而是问"存什么"。

MLA 观察到：K 和 V 都可以从一个低秩隐向量重建。于是缓存的不是 K ∈ R^(n×d) 和 V ∈ R^(n×d)，而是：

c_t = W_DKV · h_t                    ∈ R^512       (d_c = 512, 低秩联合隐向量)
k_t^R = W_Dk^R · h_t                 ∈ R^64        (d_r = 64, 解耦的 RoPE 部分)

缓存：[c_t ; k_t^R]  →  512 + 64 = 576 个元素 / token / 层

推理时按 head 上投影重建：
k_t,h = W_UK^h · c_t  (+ RoPE 部分)   ∈ R^192      (128 nope + 64 rope)
v_t,h = W_UV^h · c_t                  ∈ R^128

图 2 · MLA 机制示意：缓存低秩联合隐向量 c_t（512 维）与解耦的 RoPE key k_tᴿ（64 维），推理时按头上投影重建 k/v。RoPE 部分不压缩——位置相关的旋转会破坏低秩子空间，这是 MLA 能成立的关键工程细节。下方两行对比 decode 算术强度。

为什么 RoPE 要解耦？因为 RoPE 是位置相关的旋转，如果对 c_t 施加 RoPE，低秩压缩就会被破坏（旋转后的向量不再落在同一个低秩子空间里）。DeepSeek-V2 把 RoPE 部分单独拎出来不压缩，是 MLA 能成立的关键工程细节。

量化收益（以 DeepSeek-V3 config 为准：61 层、kv_lora_rank=512、qk_rope_head_dim=64）：

Llama-2/3 GQA 基线DeepSeek-V3 MLA压缩比

MLA 的隐藏红利：算术强度大幅提升

这是 MLA 最被低估的一点。Decode 时 Attention 的算术强度：

AI_attn = FLOPs / Bytes = 2 · n_h · (d_qk + d_v) / kv_bytes_per_token_per_layer
架构FLOPs / (query, ctx-token)Bytes / ctx-tokenAI
GQA (Llama-3-405B, 128h × d128, 8 KV)65,5364,09616 FLOPs/B
MLA (DeepSeek-V3, 128h, 192+128)81,920656125 FLOPs/B

对照 H200 的 ridge point 206 FLOPs/B：

  • GQA 的 Attention 在 16 FLOPs/B，比 ridge 低 13 倍——彻底被带宽卡死，算力利用率不到 8%。
  • MLA 的 Attention 在 125 FLOPs/B，接近 ridge 的 60%。

MLA 是典型的"用算力换带宽"：多付出了 128 个 head 各自上投影的 FLOPs（+25%），换来了 6.25× 的 KV 读取减少。而在 memory bound 的 decode 场景里，那些多出来的 FLOPs 几乎是免费的（Tensor Core 本来就在空转）。这是 MLA 在工程上如此成功的深层原因。

MLA 的代价：

  • 上投影 W_UK、W_UV 让每层的 Attention 参数量上升（DeepSeek-V3 每层 MLA ≈ 187M 参数）。
  • Prefill 阶段计算量增加；且上投影的中间结果需要额外显存。
  • 实现复杂度高：需要专门优化的 kernel（vLLM/SGLang 都为 MLA 写了独立的 attention kernel，无法直接复用 FlashAttention）。

2.4 第三刀 · Token 稀疏：NSA → DSA

MLA 把每 token 的成本压到了 576 元素，但读取量仍然是 O(L)。128K 上下文下，每 decode 一个 token 仍要搬 4.88 GB KV。这时候必须动"读多少个 token"。

2.4.1 NSA（Native Sparse Attention，2025.02）

NSA 的设计哲学是 "硬件对齐 + 原生可训练"——这两点缺一不可：

  • 硬件对齐：所有稀疏操作都按 GPU tile 尺寸（64×128）成块进行，避免出现"理论上 FLOPs 少了但 kernel 跑不快"的伪稀疏。NSA 论文报告在 64K 序列上相比 Full Attention 获得数倍加速（prefill / decode / 前向 / 反向均提速），且序列越长加速比越高。
  • 原生可训练：不是推理期的后处理剪枝，而是端到端预训练阶段就带着稀疏结构学。这避免了"训练时看全量、推理时看稀疏"的分布错配。

三分支结构（门控加权融合）：

1. 压缩分支 (Compression)：把每 l=32 个 token 的 K/V 池化成 1 个粗粒度 token
   → 全序列扫描成本降为 L/32
2. 选择分支 (Selection)：基于压缩表示打分，选出 top-n 个 64-token 块做细粒度 attention
   → 精读成本 = n × 64 × kv_bytes，与 L 无关
3. 滑窗分支 (Sliding Window)：保留最近 s 个 token
   → 局部性兜底，成本 O(1)

一阶带宽估算（DeepSeek-V3 口径，L=1M）：

Full MLA : 1,048,576 × 656 B × 61 层 = 39.1 GB / decoded token
NSA 近似 : (L/32 × 656 + 16×64×656 + 16×656) × 61 ≈ 1.26 GB / decoded token
                                                          → ≈ 31× 减少

NSA 的本质是把"精读"的成本从 O(L) 变成 O(1)，把"粗筛"的成本从 O(L) 变成 O(L/l)——用块级池化把粗筛也降了 32 倍。这是稀疏路线里最彻底的一种。

2.4.2 DSA（DeepSeek Sparse Attention，V3.2-Exp，2025.09）

DSA 是 NSA 思路的保守工业化版本：不改 attention 的结构，只加一个轻量索引器。

Lightning Indexer（每层附加模块）：
  q_I = W_I^Q · h_t          → 64 heads × 128 dim   (index_n_heads=64, index_head_dim=128)
  k_I = W_I^K · c_kv,t       → 128 dim，64 个 head 共享（MQA 式）
  score(t, s) = Σ_h q_I,t,h · k_I,s / √128 · scale
  → 取 top-k = 2048 个历史 token 送给主 MLA 做完整 attention

关键工程细节：Indexer 只缓存 k_I（128 个 FP8 值 = 128 B/token/层），不缓存 v，也不缓存 64 份 q。这让它成为一个极便宜的"粗筛器"。

训练方式：Indexer 用 KL 散度对齐 Full Attention 的注意力分布（warmup 阶段），使其学会"预测主 attention 会关注谁"。DeepSeek-V3.2 为此投入了 超过预训练成本 10% 的后训练算力，其中稀疏化训练阶段处理了 943.7B token。

量化收益：

复杂度从 O(L²) 降到 O(L·k)，k=2048。第三方复现报告 128K 下 decode 加速约 3.2×、attention 激活显存降 71%、总显存降 19%。

DSA 的一个重要局限（必须点明）：

Indexer 本身的扫描是 O(L) 的，且它每 (query, context-token) 对消耗 16,384 FLOPs / 128 Bytes，而主 MLA attention 消耗 81,920 FLOPs / 656 Bytes。两者比值恰好都是 1/5。

也就是说，DSA 把全量读取的成本转化成了 Top-K indexer 的成本，而这个转化只能带来约 5× 的常数折扣，渐近阶数并没有变：

DSA 总成本 ≈ L × (indexer成本) + k × (主attention成本)
           = L × 1/5 × C_full + O(1)

当 L → ∞，DSA 的加速比收敛到 5×，不会更多。想要更大收益，只有两条路：

  1. 进一步压小 indexer 维度（128 → 32），或让 indexer 也做块级压缩（这就走向 NSA）；
  2. 彻底换掉机制（这就走向 Linear Attention）。

这不是批评，而是理解成本结构的必要视角：DSA 用最小的架构改动（保留 MLA、只加索引器）换来了 5× 长上下文收益，并且没有引入 KV Cache 结构的碎片化（vLLM/SGLang 可以 day-0 支持）。这是典型的工程权衡。

2.5 第四刀 · 机制替换：Linear Attention / Gated DeltaNet / KDA

前三刀都在优化"如何更便宜地存/读 KV"。第四刀直接问：能不能不存 KV？

2.5.1 从 Softmax Attention 到线性递推

Softmax attention 的根本问题是 softmax(QK^T) 无法写成递推形式——必须保留所有历史 K/V 才能算归一化分母。Linear Attention 用核函数近似去掉 softmax：

\[ o_t = \sum_{s\le t} \phi(q_t)\cdot\phi(k_s)^T \cdot v_s \,\Big/\, \sum_{s\le t} \phi(q_t)\cdot\phi(k_s)^T = \phi(q_t)^T \cdot S_t \,\big/\, (\phi(q_t)^T \cdot z_t) \] \[ S_t = \sum_{s\le t} \phi(k_s)\, v_s^T \in \mathbb{R}^{d_k \times d_v} \quad (\text{状态矩阵}), \qquad z_t = \sum_{s\le t} \phi(k_s) \in \mathbb{R}^{d_k} \]

\( S_t \) 是一个 O(1) 的固定大小状态，与序列长度无关。这就是全部的魔法：把 O(L) 的 KV Cache 换成 O(1) 的 recurrent state，把 O(L) 的每步读取换成 O(1) 的状态读写。

2.5.2 Delta Rule 与门控：为什么需要 Gated DeltaNet

朴素的 Linear Attention 有个致命问题：S_t 是纯累加的，只增不减，很快就被历史信息污染（"记忆饱和"）。

DeltaNet 引入 delta rule——写入时先擦除该 key 方向上的旧记忆：

\[ S_t = \underbrace{S_{t-1}\,(I - \beta_t k_t k_t^T)}_{\text{擦除旧的}} + \underbrace{\beta_t k_t v_t^T}_{\text{写入新的}} \]

这让状态具备了可控覆写能力，等价于一个在线的、秩为 1 的增量最小二乘更新。

Gated DeltaNet 再叠加一个标量遗忘门 \( \alpha_t \)：

\[ S_t = \alpha_t \cdot S_{t-1}\,(I - \beta_t k_t k_t^T) + \beta_t k_t v_t^T \]
  • \( \alpha_t \) 控制全局时间衰减（多久忘掉所有东西）
  • \( \beta_t \) 控制局部精确覆写（这条 key 的记忆改多少）

这两个机制正交，一个管"泛化遗忘"一个管"精确改写"。此外，输出门控（output gating）消除了 attention sink 和 massive activation 现象——这是 Qwen3-Next 报告的大规模训练稳定性提升的直接来源。

KDA（Kimi Delta Attention）在此基础上做了两点强化：

  1. 更细粒度的门控：从标量门 \( \alpha_t \) 升级为逐通道（channel-wise）对角门，不同特征维度可以有独立的遗忘速率。
  2. DPLR 转移矩阵的特化变体：\( S_t = (D + UV^T)\,S_{t-1} + \dots \)，通过对 Diagonal-Plus-Low-Rank 结构做特化，使其能用 chunk-wise 并行算法高效训练（否则 DPLR 的递推很难并行化）。

2.5.3 状态成本的量化：Linear Attention 不是免费午餐

以 Qwen3-Next-80B-A3B 的 Gated DeltaNet 层为例（linear_num_value_heads=32, linear_num_key_heads=16, head_dim=128）：

每层状态 = 32 × 128 × 128 × 2 B(BF16) = 1.0 MiB
36 层总计 = 36.0 MiB / 序列     ← 与 L 完全无关

而它的 12 层 full attention 部分（2 KV heads × 256 dim）：

每 token = 2 × 2 × 256 × 2 B = 2048 B
12 层 = 24 KB / token          ← 与 L 线性相关

这里必须区分两个不同的盈亏平衡点：

① 容量平衡（KV Cache 占用 = 状态占用）：
   36 MiB = 24 KiB × L   →   L ≈ 1,536 tokens

② Decode 带宽平衡（每 token 读 KV = 每 token 读写状态）：
   24 KiB × L = 2 × 36 MiB = 72 MiB   →   L ≈ 3,072 tokens
   （状态需「读旧 + 写新」，故带宽平衡点是容量平衡点的 2 倍）

这揭示了一个常被忽略的事实：

Linear Attention 的省，本质是把 O(L) 的边际成本换成 O(1) 的固定成本。在短序列下它反而更贵。

具体地，decode 时每 token 的状态读写带宽恒为 2 × 36 MiB = 72 MiB，而 full attention 部分是 24 KiB × L：

上下文 LFull-attn 部分GDN 状态读写谁更贵
1K24 MiB72 MiBGDN 贵 3.0×
3K72 MiB72 MiB持平
32K786 MiB72 MiBFull-attn 贵 10.7×
256K6.3 GiB72 MiBFull-attn 贵 85×
1M25.2 GiB72 MiBFull-attn 贵341×

这精确解释了 Kimi Linear 的实验结论：1M 上下文下 decode 吞吐提升 6×，而短上下文下几乎没有提升。也解释了为什么所有落地方案都是 Hybrid 而非纯 Linear，以及为什么 Linear Attention 的收益随上下文长度单调放大——这是它与 MLA / GQA（收益是与 L 无关的纯常数折扣）最本质的区别。

2.5.4 Linear Attention 的代价：精确召回能力

状态矩阵 \( S \in \mathbb{R}^{d_k \times d_v} \) 是一个有损压缩的记忆。当需要在 100 万个 token 中精确找出某个 needle 时，固定大小的状态无法保证无损存储——这是 Linear Attention 在长上下文 recall 类任务上系统性弱于 full attention 的根本原因。

Hybrid 架构就是用少量 full attention 层做"精确召回兜底"。这是表达能力与存储成本的显式交换。

Hybrid 架构在模型侧是简单的一行配置，但在推理引擎侧是一个大坑：

  • 不同层的 KV Cache 形状、生命周期完全不同（有的按 token 增长，有的是固定状态，有的是滑动窗口会驱逐）。

  • Prefix Cache 的命中判定变复杂：需要同时匹配 global 层和 SWA/linear 层的缓存状态（vLLM 文档明确提到需要"求交集"）。

这是"架构激进程度受 Infra 能力约束"的一个典型案例（见第 7 章）。

3. FFN 演进：从"参数即算力"到"参数与算力解耦"

3.1 Dense FFN 的成本结构

FFN（MLP）是 Transformer 中参数最密集的模块。标准 SwiGLU FFN：

FFN(x) = (Swish(x W_gate) ⊙ (x W_up)) W_down

参数量 = 3 × d_model × d_ff

SwiGLU 用 3 个矩阵替代 GELU FFN 的 2 个，为保持参数量对齐，通常把 d_ff 从 4·d_model 缩到 (8/3)·d_model。

FFN 的参数量占比：

模型Attention 参数 / 层FFN 参数 / 层FFN 占比
Llama-3.1-405B（Dense）570 M2,617 M82.1%
DeepSeek-V3（MoE 稀疏层）187 M11,320 M98.4%

结论很直接：

想降参数量，就必须动 FFN。想降访存量，就必须动 Attention。

这就是为什么 MoE 和 MLA/Sparse/Linear 是两条并行且互补的演进主线，而不是互相替代。

3.2 MoE：把参数量和计算量拆开

Dense 模型的根本困境：参数量（知识容量）与计算量（每 token FLOPs）被强行绑定。想更聪明就必须更贵。

MoE 用条件计算打破这个绑定：

Dense FFN:   y = FFN(x)                    参数 P，计算 2P
MoE:         y = Σ_{i∈TopK(g(x))} g_i · E_i(x)    参数 N·P_e，计算 2·K·P_e

3.3 DeepSeekMoE：细粒度专家 + 共享专家

DeepSeekMoE 提出了两个至今仍是标准配置的设计：

① 细粒度专家切分（Fine-Grained Expert Segmentation）

不用少量大专家，而是用大量小专家（通过降低 d_ff 实现），激活更多个：

传统：8 个大专家，激活 2 个        → 组合数 C(8,2) = 28
细粒度：64 个小专家，激活 6 个      → 组合数 C(64,6) = 7.5×10⁷

在相同激活参数下，专家组合的多样性提升 6 个数量级——这意味着模型可以用更细的粒度组合出专门化的子网络，专家特化程度（expert specialization）显著提升。

DeepSeekMoE 16B 的实测结论（这是"40.5%"这个广为引用的数字的出处）：

DeepSeekMoE 16B（16.4B 总参 / 2.8B 激活 / 66 专家激活 8 个）仅用 40.5% 的计算量，达到了与 Llama2-7B Dense 基线相当的性能。

这就是"参数量与计算量分离"最直接的量化证据：省下的 59.5% 算力可以用来训更多数据，或训更大模型。

② 共享专家（Shared Experts）

隔离出 K_s 个专家永远激活，专门承载所有 token 都需要的通用知识：

路由专家：捕捉特化知识，稀疏激活
共享专家：捕捉公共知识，稠密激活

好处有三：

  • 减少路由专家的冗余：不用每个专家都重复学一遍"的/是/了"这类通用模式。
  • 稳定路由：共享专家提供了恒定的基线输出，降低了路由抖动的危害。
  • 降低 aux-loss 权重：通用知识不进路由，负载均衡压力自然减小。

3.5 MoE 把短板推向了"容量"与"网络"

这是理解 MoE 最关键的一节。MoE 消除了计算短板，但立即制造了两个新短板：

3.5.1 "激活参数"是一个 batch=1 的概念

\[ \mathbb{E}[\text{distinct}] = N \cdot \left(1 - \left(1 - \tfrac{k}{N}\right)^B\right) \]

3.5.2 训练侧：Expert Parallelism 的通信墙

  • 专家必须跨卡切分（EP），每个 MoE 层引入两次 all-to-all（dispatch + combine）。
  • 当 EP size 增大，all-to-all 的通信量随 B × d_model × k 增长，且是全连接模式，对网络拓扑极其敏感。
  • DeepSeek-V3 的应对：细粒度专家让单个专家的通信粒度更小、更均衡；重叠计算与通信；限制 EP 只在节点内 + 高速互联域。
  • 这也是为什么 MoE 训练对网络硬件的要求远高于 Dense，以及为什么"训练必须坚持同构"（第 6 章）。

3.6.3 稀疏与低精度：正交、可叠加

Sparse（DSA/NSA/MoE）：只处理 k/n 的元素        → 消除"量级冗余"
低精度（FP8/FP4）：    每元素占用 p/16 字节      → 消除"倍数冗余"

两者作用在成本公式的不同因子上，因此收益近似相乘：

Attention 带宽 = L × n_selected_ratio × kv_bytes_per_elem
                 └── Sparse 攻这里 ──┘   └── 低精度攻这里 ─┘

MoE 权重带宽 = N_experts_hit × expert_params × bytes_per_param
               └──── 路由攻这里 ────┘          └── 低精度攻这里 ──┘

DeepSeek-V3.2 就是这个叠加的活例子：MLA（维度压缩 3.56×）× FP8 KV（精度压缩 2×）× DSA（token 稀疏 5×）≈ 35× 的长上下文 attention 带宽压缩。

工程上必然同时采用——因为它们没有任何冲突。唯一需要注意的是量化敏感点：稀疏化的打分/索引模块（如 Lightning Indexer）本身对量化误差敏感，因为 top-k 选择的边界 token 可能因为量化噪声被误选，这是不可逆的错误传播。

3.7 FFN 与 Attention 演进的耦合

两条主线并非独立，它们在 2025 年出现了明显的协同设计：

Qwen3-Next 的组合拳：

              → KV Cache 从 48 层压到 12 层，24 KB/token

                换"少读几次权重"，直接提升算术强度

              → 消除 attention sink / massive activation，支撑大规模 RL 后训练

为什么必须协同？因为两者的短板会互相暴露：

  • 只压 Attention 不压 FFN → KV Cache 小了，但权重带宽成为新瓶颈（Decode 时 MoE 权重读取 656 GB/step 远超 KV）。

MTP 是一个特别值得注意的耦合点：它与 §2.3 的 MLA、§9.4 的 CSA/HCA 同属"用算力换带宽"这一贯穿全报告的母题——在 memory bound 的 decode 场景下，多付出的 FLOPs 近乎免费，省下的 bytes 才值钱。

4.3 Prefill 的计算结构

Prefill 的 FLOPs 由两部分组成（causal mask 下 Attention 对数 ≈ L²/2，每对 Q·K + softmax·V 各 2 FLOPs/维度，合并后系数为 1）：

  2. 为什么 Agent 时代 Sparse Attention 突然变得至关重要——L=142K（实测中位输入）时 Attention 占 Prefill FLOPs 的 83%，DSA 的 ~5× 加速直接对应 ~4× 端到端 Prefill 提速。
  3. 为什么 Prefill 侧的优化重点和 Decode 侧不同：Prefill 要降 FLOPs（稀疏化），Decode 要降 bytes（压缩 + 稀疏化 + 低精度）。

5.2 Prefill / Decode 解耦（PD Disaggregation）

为什么必须解耦？因为两个阶段的硬件诉求完全冲突：

PrefillDecode
计算特征大 GEMM，compute bound小 GEMV，memory bound
理想硬件高 FLOPS高 HBM 带宽 + 大容量
延迟指标TTFT（首 token 延迟）TPT / TPOT（每 token 延迟）

KV Cache生产者（写）消费者（读）

混部的问题：一个 142K token 的 prefill 会独占 GPU 数百毫秒，期间所有 decode 请求全部卡住 → TPT 尖刺，SLO 违约。

解耦方案（Mooncake / DistServe 等）：

图 5 · Mooncake 式 KVCache-centric PD 解耦：调度器把 KV Cache 当一等公民，Prefill 池（算力优化）与 Decode 池（带宽优化）经 RDMA 零拷贝迁移 KV，底座是 HBM → DRAM → NVMe 的分布式 KV 池与跨实例 Prefix Cache 复用。

关键设计：

  • KVCache-centric 而非 GPU-centric 调度：把 KV Cache 当作一等公民，围绕它的位置和复用性来调度计算。
  • RDMA 零拷贝传输：避免 KV Cache 在 Prefill→Decode 迁移时经过 CPU 内存和协议栈。
  • 多级存储：利用集群中闲置的 DRAM 和 NVMe 构建分布式 KV 池，让 Prefix Cache 跨实例共享。
  • SLO 感知调度：预测性地丢弃无法满足延迟要求的请求（overload-oriented scheduling）。

实测收益（Mooncake，Kimi 生产环境）：

  • 模拟场景吞吐提升最高 525%
  • 生产环境在满足 SLO 前提下多处理 75% 的请求
  • 长上下文场景收益尤其显著

5.3 架构级的 PD 解耦设计

系统层的解耦还不够。新一代架构开始在设计阶段就为 Prefill 和 Decode 准备不同的优化目标（DeepSeek V4.x 路线的核心思路）：

Prefill 侧优化目标：降低激活量 / 降低 O(L²) 计算
  → 更激进的 MoE 稀疏化（激活率 5.6% → 3.75%）
  → Sparse Attention（DSA / NSA）降低 L² 系数
  → MTP 提升单次前向的产出

Decode 侧优化目标：减小 KV Cache / 降低每步读取字节
  → MLA 维度压缩
  → Hybrid + Linear Attention 减少需要存 KV 的层
  → FP8 / FP4 KV 量化

为什么这样能"整体 KV Cache 再压缩一倍"？因为解除了单一架构必须同时满足两个阶段的约束：

  • 混部时，Prefill 层的 KV 必须按 Decode 的格式存（否则要重算），这限制了 Prefill 侧能用多激进的稀疏化。
  • 解耦后，Prefill 侧可以用临时的、激进的稀疏表示（反正算完就传走），Decode 侧则维持紧凑但完整的 KV 布局。
  • 更进一步：Prefill 阶段命中 Prefix Cache 的部分根本不需要重算，只需要把已有 KV 搬运过来 → 此时 KV 的存储格式和传输效率比计算效率更重要。

长短序列混合部署是解耦带来的另一个红利：

长序列请求（142K）→ 送入专门的长上下文实例（大 KV 池、激进稀疏）
短序列请求（2K）  → 送入高并发实例（大 batch、稠密 KV）

这直接提升了整体 batch size 和硬件利用率——因为不再需要用同一套配置去迁就两类极端负载。

2026.09 的实证：DeepSeek-V4.1-Flash 把这一设计做进了权重 🟢。其非对称 Causal Encoder-Decoder 中，prefill 激活 8B / decode 激活 16B——同一套权重、两套激活子集，按两阶段各自的 roofline 位置（prefill compute bound → 压激活；decode memory bound → 用更大激活抬高算术强度）分别定制。PD 解耦从"系统层调度"演进为"模型级结构"，详见 §9.1。

训练侧的诉求完全相反：

诉求原因
稳定性一次预训练 = 数千卡 × 数周 × 数百万美元。任何一次 loss spike 都可能毁掉整个 run
确定性需要可复现的消融实验来判断架构改动是否有效
Bitwise 训推一致见下

为什么训练不能容忍异构芯片的精度不对齐？

训练是一个 O(10⁶) 步的迭代过程，每步的参数更新量 ~10⁻⁴ 量级。

若某类算子在异构芯片上有 10⁻⁶ 的相对误差：
  → 单步看，完全无害
  → 但梯度下降是【正反馈】系统：参数偏移 → 激活分布偏移 → 梯度偏移 → 更大参数偏移
  → 10⁶ 步后，误差可能放大到改变模型收敛点的程度

更致命的是【不可归因性】：
  训练崩了，你无法知道是数据问题、超参问题、还是某块芯片的算子精度问题。
  在数千卡规模下，逐一排查的成本高于重训。

因此训练侧的红线是：必须做到 Bitwise 级别的训推一致 / 卡间一致。这直接排除了：

  • 不同厂商芯片混用（算子实现不同 → rounding 不同）
  • 激进的低精度训练（FP4 训练的数值稳定性尚未验证）
  • 非确定性的稀疏路由（同一 batch 在不同卡上路由到不同专家）

这也解释了架构设计的"激进程度不对称"：

推理侧：可以上 FP4、可以上激进稀疏、可以换硬件   → 迭代快、试错成本低
训练侧：必须 BF16/FP8、必须稠密可复现、必须同构   → 迭代慢、试错成本高

DeepSeek 的 UE8M0 FP8（scale 强制为 2 的幂）正是这个矛盾下的产物：它让量化操作在任何硬件上都 bitwise 可复现，从而在保持同构约束的前提下引入了低精度。

6.3 一个反直觉的推论

推理硬件可以比训练硬件领先一代。

因为推理是无状态的、可验证的、成本敏感的；训练是有状态的、难归因的、风险厌恶的。所以：

  • 新格式（NVFP4）总是先在推理落地，训练滞后 1-2 年。
  • 新架构（Linear Attention）总是先在推理验证收益，再决定是否用于预训练。
  • 异构芯片总是先切推理市场。

7. 工程方法论：掉点是怎么被"买回来"的

7.1 精度损失可以兑换成其他收益

架构激进化的标准流程：

① 提出激进架构（稀疏化 / Linear Attention / FP4）
② 测量精度损失（通常 0.5~2 分）
③ 测量效率收益（通常 2~5×）
④ 用效率收益【兑换】精度：
     - 提升 IO 效率 → 同样时间跑更多 step
     - 增加 RL 迭代轮次 → 用后训练补回预训练的损失
     - 扩大数据量 → 用更多 token 补回架构容量的损失
⑤ 若兑换后净收益为正 → 采纳

关键洞察：架构的"掉点"不是终点，而是一个可以用算力赎回的债务。DeepSeek-V3.2 为 DSA 投入了超过预训练成本 10% 的后训练算力（943.7B token 的稀疏化训练），本质上就是在偿还稀疏化带来的精度债务。

这要求：

  • 快速实验能力：能在几天内跑完一次小规模验证，而不是几个月。
  • 可靠的评估体系：能分辨 0.5 分的真实差异和噪声。
  • RL 后训练的成熟度：RL 是当前最有效的"精度赎回"工具。

7.2 Infra 话语权决定架构激进程度

这是一个组织层面的观察，但技术上完全成立：

架构团队说："改成 Linear Attention，KV Cache 降 75%"
Infra 团队说："PagedAttention 要重写、Hybrid KV Manager 要新做、
              Prefix Cache 命中逻辑要改、所有 attention kernel 要重写、
              精度对齐要重跑——三个月上线不了"
结果：架构方案被否决或降级

架构创新的可采纳性 = 技术收益 × Infra 可落地性。后者的权重常常被低估。

反例（成功的协同）：

  • DSA 能被 vLLM/SGLang day-0 支持，正是因为它保留了 MLA 的 KV Cache 结构，只额外增加一个 indexer cache。相比 NSA 需要全新的三分支 kernel，DSA 的落地阻力小一个数量级。这是"架构为 Infra 让步"的典型。
  • Qwen3-Next 的 Hybrid KV Cache Manager 是与 vLLM 团队协同设计的，架构发布时引擎支持已就绪。

8. 开放问题与展望

8.1 KV Cache 会被彻底消灭吗？

支持 Linear-only 的论据：

  • 状态大小与 L 无关，天然适合超长上下文和超大 batch。
  • Prefill 是 O(L) 而非 O(L²)，长文档处理成本骤降。
  • Kimi Linear / Qwen3-Next 已证明 3:1 混合下能力损失可控。

反对的论据：

  • 固定状态无法保证精确召回，"大海捞针"类任务是硬伤。
  • 状态读写是 O(1) 但常数很大（Qwen3-Next 每层 1 MiB），短序列场景反而更贵——存在两个盈亏平衡点：容量平衡 ~1.5K token、带宽平衡 ~3K token（详见 §2.5.3）。
  • Prefix Cache 无法复用（状态是路径依赖的，不能像 KV 那样按前缀切片共享）——这对 Agent 负载是致命的，因为 Agent 的核心红利就是 96% 的 prefix 命中。

判断：纯 Linear 短期内不会取代 Hybrid。Prefix Cache 的可复用性这个约束，可能比"表达能力"更能决定 Linear Attention 的采纳上限。这是一个尚未被充分讨论的架构约束。

8.2 稀疏化的渐近极限

DSA 的加速比收敛到 5×（indexer 维度 / MLA 维度），NSA 收敛到 l 倍（块长）。要突破，需要：

  • Indexer 也做块级压缩（DSA + NSA 融合）
  • 学习式的动态 k（简单 query 少读、复杂 query 多读）
  • 层级稀疏（先粗筛章节，再精读段落）

8.3 存储层级成为一等公民

HBM  (3-8 TB/s,  141 GB/卡)   ← 热 KV、活跃专家
 ↓
DRAM (~500 GB/s, TB 级)       ← 温 KV、冷专家、Prefix Cache
 ↓
NVMe (~10 GB/s,  PB 级)       ← 冷 KV、长期记忆
 ↓
跨数据中心                     ← 全局 KV Cache 池

已有研究开始讨论"跨数据中心的 KV Cache"。当 KV Cache 的搬运成本超过重算成本时，架构设计的边界会从"模型"扩展到"存储系统"。届时可能出现的新设计：

  • 可重算的 KV：故意不存某些层的 KV，需要时用便宜的计算重建（用 FLOPs 换容量）。
  • KV 的语义压缩：不是量化，而是把 KV 蒸馏成更少的"记忆 token"。
  • 前缀感知的架构：让模型结构本身对 prefix 复用友好（如 Linear Attention 的 checkpoint 化）。

8.4 训练与推理的架构会分叉吗？

当前是同一套权重跑训练和推理。但既然：

  • Prefill 和 Decode 已经解耦部署
  • 训练必须同构、推理可以异构
  • 训练必须 bitwise 确定、推理可以近似

那么逻辑上的下一步是：训练一个"母模型"，为不同推理场景蒸馏/编译出多个特化变体（长上下文变体、高并发变体、端侧变体）。这会进一步改变架构设计的自由度——母模型可以为"可特化性"而非"单一最优"而设计。

mHC（Manifold-Constrained Hyper-Connections）是 2026 年另一个被低估的创新

🟢（arXiv:2512.24880）。它不改 attention 也不改 MoE，而是改残差连接：

  • 把单一残差流换成 4 条并行流，用学习到的变换在流之间混合信息。
  • 关键约束：混合矩阵被限制为双随机矩阵（doubly stochastic）——保证信息重分配稳定，避免信号幅度爆炸。
  • 代价：训练时间 +6.7%；收益：早期 hyper-connection 实验显示达到 baseline 指标只需约一半训练 token。

为什么是"双随机矩阵"？（数学直觉）

双随机矩阵 = 每行和、每列和都为 1 的非负矩阵。它的关键性质是 保持向量的"总量"守恒：若混合矩阵 M 双随机，则 M·x 的元素和 = x 的元素和（1ᵀMx = 1ᵀx）。

  • 对照普通 Hyper-Connections：无约束的混合矩阵会让信号幅度逐层指数放大或衰减（类似 §6.2 讲的梯度正反馈失控）。
  • 双随机约束把混合限制在"信息重分配"而非"信息放大"——等价于一个马尔可夫链的状态转移，其平稳分布保证了跨深度的数值有界性（Birkhoff 定理：双随机矩阵是置换矩阵的凸组合，故谱半径 ≤ 1）。

这就是 mHC 能在 +6.7% 开销下换来训练稳定性的根本原因：它用一条数学约束，把"多流残差"这个容易发散的设计强行拉回了收敛域。

为什么重要：当 attention/FFN 的压缩逼近极限时，训练稳定性成了新的短板。mHC 开辟了一条正交于"降算/降存"的第三战线——"降训练发散风险"。这是 §7.3"模型迭代 ≈ 芯片流片"判断的延伸：流片成本越高，越需要在架构层面买保险。

Hybrid SSM + MoE 的殊途同归：2026 年 NVIDIA Nemotron 3 Nano、Qwen3.5、Mamba-3 三个独立团队都收敛到"混合状态空间模型 + 稀疏 MoE"。Qwen3.5（397B/17B，3:1 GDN + full attention，1M 上下文）是 Qwen3-Next 路线的生产级验证。这印证了 §2.6 的判断：纯 Linear 不会取代 Hybrid，但 Hybrid 的 "Linear 占比" 会持续上升。

9.2 低精度与压缩：从"推理 FP8"到"训练 FP4"

§3.6 预判的"FP4 进入生产"在 2026 年全面兑现，且战线从推理推进到了训练：

① NVFP4 预训练成为现实 🟢（NVIDIA, arXiv:2509.25149）：

  • 12B 模型、10T token 训练，NVFP4 与 FP8 baseline 精度相当。
  • 四个关键稳定性技术：
    • Random Hadamard Transform（RHT）：把 block 级 outlier 旋转成近似高斯分布，从而 bounded（有界化）量化误差。
    • 二维量化：保证前向/反向表示一致。
    • Stochastic rounding：梯度无偏估计。
    • 选择性高精度层：embedding / norm / 最后几层保留 FP8/BF16。
  • 意义：§3.6 的"低精度是正交于稀疏的第二战线"如今延伸到了训练侧——FP4 训练把 §6.2"训练必须同构 bitwise"的约束也松动了。

② FP8 KV Cache 成为长上下文默认起点 🟢（vLLM 官方工程博客, 2026.04）：

③ 4-bit KV 与新量化算法 🟡：

  • MXFP4（microscaling）：硬件原生 4-bit，block-32 共享 scale。🟢
  • ARCQuant（ACL 2026）：Augmented Residual Correction，给 NVFP4 加残差校正，进一步缩小精度损失。🟡

10.3 下一个短板是什么？三个候选

2026 年的进展把"容量"短板暂时压住后，报告识别出三个正在浮现的新短板，按确定性排序：

① 训练稳定性（确定性最高，已被 mHC 验证）

  • 当压缩逼近极限（KV 10%、FP4 训练），架构的发散风险成为主要矛盾。
  • mHC 的双随机约束、Muon 优化器、zero-centered LayerNorm 都是这条战线的产物。
  • 判断：§7.3"模型迭代 ≈ 芯片流片"的约束会越来越紧，"为训练稳定性买保险"会成为架构的一等目标，而非事后补救。

② Prefix 不可复用性（被低估，对 Agent 致命）

  • §8.1 已指出：Linear Attention 的状态是路径依赖的，无法像 KV 那样按前缀切片共享。
  • 而 §9.3 TraceLab 实测：Agent 负载 95.7% prefix 命中、60% 成本是重读历史——prefix 复用是 Agent 经济性的命脉。
  • 矛盾：越激进的 Linear/状态化压缩，越损害 prefix 复用。这是 Hybrid 路线（而非纯 Linear）成为共识的深层原因，也是 V4 选择"压缩 KV"而非"替换为状态"的关键——CSA/HCA 仍保留可按前缀切片的 KV 结构。
  • 判断：prefix 可复用性 会成为一个显式的架构设计约束，与"表达能力""存储成本"并列。

③ 精度债务的可验证性（preview 时代的隐忧）

  • §9.1 已点明：V4 preview 版未公布逐项 benchmark，"10% KV 是否付出召回代价"无一手数据可判。
  • 当压缩越来越激进，"掉点 0.5 分还是 2 分"的测量本身变得困难（§7.1 要求"能分辨 0.5 分的真实差异和噪声"）。
  • 判断：长上下文召回的标准评测（RULER / 大海捞针 / 多跳推理）会成为架构激进度的"刹车片"——没有可信评测，精度债务就无法定价，激进压缩就变成赌博。

10.4 一句话总结

LLM 架构演进的本质，是一场"短板迁移"的接力赛：每解决一个瓶颈，就暴露下一个。2026 年，容量短板被 HBM4（供给）和 CSA/HCA（需求）双向夹击而暂时缓解，接力棒正交向"训练稳定性"与"prefix 可复用性"——而后者的特殊之处在于，它不是一个工程问题，而是一个会反向约束架构选择的"硬约束"。
